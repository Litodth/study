# 01 · 哈希（3 题）

## 套路总纲

**识别信号**：题面出现「是否存在某个数 / 某种组合」「统计出现次数」「判断重复」「O(1) 查找」。

**核心思想**：哈希表把「查找」从 O(n) 降到 O(1)，代价是 O(n) 空间。刷题时的固定套问：

1. **我在重复查找什么？** 把它做成 key。
2. **key 该是什么？** 原值（题 1）、归一化后的特征（题 49 的排序字符串）、还是集合成员性（题 128）。
3. **value 存什么？** 下标、计数、还是分组列表。

**C++ 容器选择**：
- `unordered_map` / `unordered_set`：平均 O(1)，本专题默认选择。
- `map` / `set`：红黑树 O(log n)，只在需要**有序遍历**时用（本专题不需要）。
- key 是 `pair` 或 `vector` 时 `unordered_map` 无默认哈希，需自定义（见 [18-模板速查](18-模板速查.md)），临时救急可改用 `map`。

**递进关系**：1 是最朴素的「边走边记」；49 引入「设计 key」这一步；128 最难——它的哈希用法很隐蔽，靠的是集合成员性 + 只从序列起点出发的均摊分析。

### 1. 两数之和（简单）

**题意**  数组 `nums` 中找两个下标 `i != j`，使 `nums[i] + nums[j] == target`，返回这两个下标。保证恰有一解。

**暴力**  双层循环枚举所有下标对，O(n²) / O(1)。n ≤ 10⁴ 时能过，但这题的意义就在于优化。

为什么不够：内层循环每次都在**从头找** `target - nums[i]`，前面已经看过的数没被记住。

**关键洞察**

固定 `i`，需要的另一个数是确定的：`target - nums[i]`。所以问题从「枚举配对」变成「查找一个具体的值」——而查找正是哈希表的强项。

再进一步：不需要先把整个数组建表。遍历到 `i` 时，只需要在**它前面**的数里找补数；如果答案是 `(i, j)` 且 `i < j`，那么走到 `j` 时 `i` 必然已入表。所以**边查边插**，一趟即可，还天然避免了「同一个元素用两次」的问题。

**最优解（C++）**

```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        unordered_map<int, int> pos;              // 值 -> 下标
        for (int i = 0; i < nums.size(); ++i) {
            int need = target - nums[i];
            auto it = pos.find(need);
            if (it != pos.end()) return {it->second, i};  // 先查：表里只有 i 之前的元素
            pos[nums[i]] = i;                     // 后插：保证不会自己配自己
        }
        return {};
    }
};
```

**复杂度**  时间 O(n)，空间 O(n)。

**边界与坑**
- **必须先查后插**。反过来写，`nums = [3,3], target = 6` 会因为 `pos[3]` 被第二次覆盖而丢解；更糟的是 `target = 2*nums[i]` 时可能返回 `{i, i}`。
- 有重复值时 `pos[nums[i]] = i` 会覆盖旧下标，但不影响正确性：题目只要一个解，而后出现的下标同样能配对。
- `target - nums[i]` 在极端数据下可能溢出 `int`（如 `nums[i] = -2^31`、`target = 2^31-1`）。LeetCode 本题约束内安全，面试被追问就答「用 `long long` 算补数」。

**追问 / 变体**
- **数组已排序**（167）：改用双指针，O(1) 空间。
- **返回所有不重复的下标对**：仍用哈希，但要处理重复计数。
- **三数之和**（15）：套一层循环 + 双指针，见 [02-双指针](02-双指针.md)。
- **四数之和 II**（454）：分成两半各建哈希，是本题的高维推广。

### 49. 字母异位词分组（中等）

**题意**  把字符串数组按「互为字母异位词」（字母种类和个数完全相同、顺序可不同）分组返回。

**暴力**  两两判断是否为异位词（各自排序后比较），O(n² · k log k)。为什么不够：每个字符串被反复排序，且做了 n² 次两两比较，而「同组」本质是等价关系——等价关系应该用**代表元**而不是两两比较。

**关键洞察**

一组异位词需要一个**唯一的、可计算的身份标识（规范形式 / canonical form）**，让同组字符串算出同一个 key。有了 key，分组就是一次哈希表遍历。

两种 key 设计：

1. **排序后的字符串**：`"eat" → "aet"`，`"tea" → "aet"`。O(k log k) 一次算完，写法最短。
2. **26 字母计数签名**：`"eat" → "a1e1t1"` 或 `#1#0#0#0#1#...`。O(k) 更快，且不受 k 很大影响；缺点是 key 更长。

面试里先给排序版（清晰），再说明计数版把 `k log k` 降到 `k`。

**最优解（C++）**

```cpp
class Solution {
public:
    vector<vector<string>> groupAnagrams(vector<string>& strs) {
        unordered_map<string, vector<string>> groups;
        for (string& s : strs) {
            string key = s;
            sort(key.begin(), key.end());        // 规范形式：排序后的字符串
            groups[key].push_back(s);            // operator[] 不存在时自动建空 vector
        }
        vector<vector<string>> ans;
        ans.reserve(groups.size());
        for (auto& [_, group] : groups)          // C++17 结构化绑定
            ans.push_back(move(group));          // move 避免整组字符串深拷贝
        return ans;
    }
};
```

计数签名版的 key（当 k 很大时更优）：

```cpp
string makeKey(const string& s) {
    int cnt[26] = {0};
    for (char c : s) ++cnt[c - 'a'];
    string key;
    for (int i = 0; i < 26; ++i) {
        key += '#';                    // 分隔符必须有，否则 [1,11] 和 [11,1] 撞 key
        key += to_string(cnt[i]);
    }
    return key;
}
```

**复杂度**  排序版 O(n · k log k) 时间、O(n · k) 空间；计数版 O(n · k) 时间。n 为字符串个数，k 为平均长度。

**边界与坑**
- 计数签名**必须加分隔符**。不加的话计数 `[1,11,...]` 和 `[11,1,...]` 拼出同一个 key。这是这题最经典的错误。
- 输出顺序不影响判题，`unordered_map` 遍历顺序不确定没关系。
- 不要用「字母对应质数之积」当 key——想法优雅，但 26 个质数连乘会溢出，长字符串必错。面试提这个思路要主动说出溢出问题。
- 空字符串 `""` 是合法输入，key 为 `""`（或全 0 签名），能正确自成一组。

**追问 / 变体**
- **242 有效的字母异位词**：本题的单次判断版，直接比签名。
- **字符集扩到 Unicode**：签名数组换成 `unordered_map<char32_t,int>`，或者仍用排序版。
- **要求输出按组内字典序**：每组 `sort` 一下即可。
- 「找规范形式」这个套路在其他题也常用（如把分数化为最简形式当 key 判共线）。

### 128. 最长连续序列（中等）

**题意**  未排序数组中找最长的「数值连续」的元素序列长度（元素在数组中的位置无关）。要求 O(n)。

**暴力**  排序后线性扫，O(n log n)——但题目明确要求 O(n)，所以排序不是本题的答案（虽然能通过）。

更朴素的暴力：对每个数 `x`，不断查 `x+1, x+2, ...` 是否存在，用哈希集合查找。最坏 O(n²)：数组 `[1,2,3,...,n]` 时，从 1 出发走 n 步、从 2 出发走 n-1 步……总和 O(n²)。

**关键洞察**

浪费在于**从序列中间的数出发重复走了整条链**。既然从 2 出发走出的链是从 1 出发那条链的后缀，那就**只从每条链的起点出发**。

怎么判断 `x` 是不是起点？`x - 1` 不在集合里。这一个条件把总工作量变成了均摊 O(n)：每条长度 L 的链只被完整遍历一次（从它的起点），其他成员在 `if` 处就被跳过。所有链长之和 ≤ n，所以内层 `while` 的总步数 ≤ n。

这是本题的精髓——**哈希表提供 O(1) 成员查询，而正确性和复杂度来自「只从起点出发」的剪枝 + 均摊分析**。

**最优解（C++）**

```cpp
class Solution {
public:
    int longestConsecutive(vector<int>& nums) {
        unordered_set<int> st(nums.begin(), nums.end());  // 去重 + O(1) 查询
        int best = 0;
        for (int x : st) {                  // 遍历 st 而非 nums：重复元素只处理一次
            if (st.count(x - 1)) continue;  // x 不是链的起点，跳过（关键剪枝）
            int cur = x, len = 1;
            while (st.count(cur + 1)) { ++cur; ++len; }
            best = max(best, len);
        }
        return best;
    }
};
```

**复杂度**  时间 O(n) 均摊，空间 O(n)。

**边界与坑**
- 空数组返回 0，`best` 初值必须是 0 而不是 1。
- **遍历 `st` 而不是 `nums`**。`nums` 里有大量重复值时（如 10⁵ 个 1），遍历 `nums` 会做 10⁵ 次无用的 `st.count(0)` 查询——虽然仍是 O(n)，但白跑一遍；更重要的是遍历 `st` 让「每个不同值只处理一次」这个不变量显式化。
- `cur + 1` 在 `cur == INT_MAX` 时溢出（UB）。LeetCode 数据不会构造，严谨写法可判 `cur < INT_MAX`。
- 不要在循环里修改 `st`（比如「用过就删」），那会让 `for (int x : st)` 的迭代器失效。想用删除法优化，得改成 `while (!st.empty())` + 显式取元素。

**追问 / 变体**
- **返回序列本身**：记录最优链的起点和长度即可。
- **并查集解法**：把 `x` 和 `x+1` 合并，答案是最大连通块大小。O(n α(n))，思路更"重"但能应对动态插入。
- **动态版（流式插入，随时查最长连续长度）**：用 `unordered_map<int,int>` 存「以某端点为端的链长」，插入时合并左右两段——这是面试常见的进阶追问。
- **300 最长递增子序列**：名字像但完全不同（子序列 vs 数值连续），见 [15-动态规划](15-动态规划.md)。
