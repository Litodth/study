# 13 · 堆（3 题）

## 套路总纲

**识别信号**：题面出现「**第 K 大 / 第 K 小**」「**前 K 个**」「**动态维护最值**」「**数据流**」。

**堆的本质**：一棵完全二叉树，父节点恒 ≤（小顶堆）或 ≥（大顶堆）子节点。它只保证**堆顶是全局最值**，内部并非有序——这是它比排序快的原因（建堆 O(n)，而排序 O(n log n)）。

**核心操作复杂度**：`top()` O(1)、`push()` / `pop()` O(log n)、建堆 O(n)。

**C++ `priority_queue`（默认大顶堆，这点极易记错）**

```cpp
priority_queue<int> maxHeap;                                  // 大顶堆（默认）
priority_queue<int, vector<int>, greater<int>> minHeap;       // 小顶堆（要写全三个参数）

// 自定义比较（按 pair 的 second 排序，小顶堆）
auto cmp = [](const pair<int,int>& a, const pair<int,int>& b) {
    return a.second > b.second;        // 注意：返回 true 表示 a 优先级"更低"，会被排到后面
};
priority_queue<pair<int,int>, vector<pair<int,int>>, decltype(cmp)> pq(cmp);
```

> **比较器的方向是最大的坑**：`priority_queue` 的比较器语义与 `sort` **相反**。`sort` 里 `a < b` 表示升序；`priority_queue` 里 `a < b`（默认 `less`）得到的是**大顶堆**。记法：**「比较器说 a 排在 b 前面，堆就把 a 放在底部（最后出来）」**。写反了跑一遍样例立刻能发现，但现场纠错浪费时间——**建议死记：`greater` → 小顶堆**。

**「求第 K 大」的三条路（必须能说清取舍）**

| 方法 | 时间 | 空间 | 适用 |
|---|---|---|---|
| 排序后取下标 | O(n log n) | O(1) | 最简单，K 有多个查询时也够用 |
| **大小为 K 的小顶堆** | O(n log K) | **O(K)** | **数据流 / n 极大放不进内存** |
| **快速选择（quickselect）** | **O(n) 平均** | O(1) | **单次查询、数据全在内存**，最优 |

**关键口诀：求第 K 大用「大小为 K 的小顶堆」，求第 K 小用「大小为 K 的大顶堆」——方向是反的。**

为什么反着来？维护「K 个最大元素」的集合时，需要能快速踢掉其中**最小**的那个（因为它最容易被新元素挤掉），所以堆顶必须是这 K 个里的最小值 → **小顶堆**。想通这一点就永远不会记反。

**堆的三种典型用法**

1. **Top-K**（215、347）：固定大小 K 的堆，超了就弹堆顶。
2. **双堆求中位数**（295）：一个大顶堆管左半、一个小顶堆管右半，两堆堆顶夹住中位数。
3. **多路归并**（[23 合并 K 个升序链表](07-链表.md)）：K 个指针的当前值入堆，每次取最小。

**难度递进**：215 是 Top-K 模板（顺带学快速选择）→ 347 是 Top-K + 哈希计数（顺带学桶排序）→ 295 是双堆设计题（困难）。

### 215. 数组中的第 K 个最大元素（中等）

**题意**  返回数组中**第 k 个最大**的元素（排序后倒数第 k 个，**不去重**）。要求尽量优于 O(n log n)。

**暴力**  `sort` 后返回 `nums[n - k]`，O(n log n)。能过，但题目明确暗示要更好——完整排序做了多余的工作，我们只关心一个位置。

**关键洞察**

**思路一：大小为 K 的小顶堆（数据流场景的正解）**

维护一个只装 K 个元素的小顶堆，它始终保存「目前见过的最大的 K 个元素」：

- 新元素入堆；若堆大小超过 K，弹出堆顶（当前这 K+1 个里最小的）。
- 遍历结束后，堆里恰好是全局最大的 K 个，**堆顶就是其中最小的，即第 K 大**。

为什么正确：任何被弹出的元素，此刻至少有 K 个元素比它大，所以它**永远不可能**是第 K 大。

**思路二：快速选择（本题的最优解，O(n) 平均）**

借用快排的 `partition`：选一个基准 `pivot`，把数组分成「≥ pivot」和「< pivot」两部分。**分区后 pivot 落在它最终排序应有的位置上**——如果这个位置正好是我们要的下标，直接返回；否则**只递归有答案的那一侧**。

**这就是快速选择比快排快的原因**：快排要递归两侧（`T(n) = 2T(n/2) + O(n)` → O(n log n)），快速选择只递归一侧（`T(n) = T(n/2) + O(n)` → **O(n)**）。这个复杂度推导值得能现场说出来。

**必须随机化选 pivot**。固定取首/尾元素时，**有序数组会退化成 O(n²)**（每次只切掉一个元素）——LeetCode 本题就有卡这个的测试数据。随机化后期望 O(n)。

**最优解（C++，快速选择）**

```cpp
class Solution {
    // 把 a[l..r] 按随机基准分区，返回基准最终下标（降序：左边 >= 基准，右边 <= 基准）
    int partition(vector<int>& a, int l, int r) {
        int p = l + rand() % (r - l + 1);        // 随机基准，防有序数据退化
        swap(a[p], a[r]);                        // 基准挪到末尾
        int pivot = a[r], store = l;
        for (int i = l; i < r; ++i)
            if (a[i] > pivot) swap(a[i], a[store++]);   // 大的放左边（降序）
        swap(a[store], a[r]);                    // 基准归位
        return store;
    }
public:
    int findKthLargest(vector<int>& nums, int k) {
        int l = 0, r = nums.size() - 1, target = k - 1;   // 降序下第 k 大的下标是 k-1
        while (true) {
            int p = partition(nums, l, r);
            if (p == target) return nums[p];
            if (p < target) l = p + 1;           // 答案在右侧
            else            r = p - 1;           // 答案在左侧
        }
    }
};
```

**堆解法（数据流 / 内存受限时的正解）**

```cpp
int findKthLargest(vector<int>& nums, int k) {
    priority_queue<int, vector<int>, greater<int>> pq;   // 小顶堆，只留 K 个最大的
    for (int x : nums) {
        pq.push(x);
        if ((int)pq.size() > k) pq.pop();                // 超了就踢掉最小的
    }
    return pq.top();                                     // 堆顶 = 这 K 个里最小 = 第 K 大
}
```

**C++ 标准库一行版（面试可提，但要能手写上面两种）**

```cpp
int findKthLargest(vector<int>& nums, int k) {
    nth_element(nums.begin(), nums.begin() + k - 1, nums.end(), greater<int>());
    return nums[k - 1];        // nth_element 就是快速选择，平均 O(n)
}
```

**复杂度**  快速选择：平均 **O(n)**，最坏 O(n²)（随机化后概率极低）；空间 O(1)。堆解法：O(n log k) 时间、**O(k) 空间**。

**边界与坑**
- **`target = k - 1`**（降序分区下）。写成 `k` 或 `n - k` 是最常见的下标错误。**建议统一用降序分区 + `k-1`，别在升序/降序间来回换。**
- **必须随机化 pivot**。不随机的话有序数组退化 O(n²)，本题数据会卡。也可用「三数取中」代替随机。
- **不去重**！`[3,2,3,1,2,4,5,5,6], k=4` 的答案是 4（排序后 `6,5,5,4,...` 的第 4 个），**不是**去重后的第 4 大。看到"第 K 大"先确认是否去重。
- **堆解法用小顶堆**，别用大顶堆。大顶堆装 K 个会保留"最小的 K 个"，答案错。**"求第 K 大用小顶堆"要背下来。**
- `pq.size()` 返回 `size_t`，和 `k` 比较要强转 `(int)` 避免符号警告。
- 快速选择**会修改原数组**。若不允许修改，需先拷贝（多 O(n) 空间），面试要主动说明。
- `while (true)` 循环一定会终止（每轮 `l`、`r` 至少收缩 1，且 `target` 恒在 `[l, r]` 内），不需要额外的终止条件。
- 题目保证 `1 <= k <= n`，不必校验。

**追问 / 变体**
- **数据流中的第 K 大**（703）：**必须用堆**，快速选择无法处理动态插入。这是"什么时候堆优于快速选择"的标准答案。
- **n 极大（10⁹，放不进内存）**：用大小 K 的堆流式处理，只需 O(K) 内存。若 K 也很大，用**分布式 + 归并**或**二分答案 + 计数**。
- **347 前 K 个高频元素**：Top-K + 计数，见下题。
- **703 / 703 类在线维护**：同上。
- **求第 K 小**：改成大顶堆，或快速选择用升序分区 + `target = k - 1`。
- **最坏 O(n) 的确定性算法**：**中位数的中位数（BFPRT）**，把数组分成 5 个一组取中位数递归。理论优美但常数极大，实践中不如随机化。面试提到能加分。
- **为什么 `nth_element` 不保证完全有序**：它只保证第 n 个位置正确、左边都不大于它、右边都不小于它——正好是本题需要的。

### 347. 前 K 个高频元素（中等）

**题意**  返回数组中出现频率**前 k 高**的元素（顺序不限）。题目要求优于 O(n log n)。

**暴力**  用哈希表统计频次，然后把所有 `(元素, 频次)` 按频次排序取前 k 个。O(n log n)，能过但不满足"优于 O(n log n)"的要求。

**关键洞察**

题目天然分两步，**第一步无争议，第二步有三种做法**：

**第一步：统计频次。** `unordered_map<int,int> cnt`，一趟 O(n)。这步没有别的选择。

**第二步：从 m 个不同元素里选出频次最大的 k 个。** 这就是 Top-K 问题：

**① 大小为 K 的小顶堆 → O(m log k)**（推荐，通用）

和 [215](#215-数组中的第-k-个最大元素中等) 完全同构：堆里维护「当前频次最大的 k 个」，堆顶是这 k 个里频次**最小**的，新元素频次更大就替换它。**再次注意：求"最大的 k 个"用小顶堆。**

**② 桶排序 → O(n)**（本题的最优解，很漂亮）

**关键观察：频次的取值范围是有限的——最小 1，最大 n。** 所以可以开 `n+1` 个桶，`bucket[f]` 存所有出现 `f` 次的元素。然后**从高频桶往低频桶倒序遍历**，取够 k 个就停。

这就是**计数/桶排序**的思想：**当排序键的值域有限且不大时，可以用空间换掉 log 因子**。本题值域恰好是 `[1, n]`，完美适用。

**③ 快速选择 → O(m) 平均**：按频次对 `(元素, 频次)` 数组做快速选择，找第 k 大的频次。能达到线性，但代码比桶排序长。

**面试策略**：先说哈希 + 排序（基线），再给堆解法（通用、适合数据流），最后点出桶排序能做到 O(n) 并说明"因为频次值域有界"。**这个递进能完整展示思考过程。**

**最优解（C++，桶排序 O(n)）**

```cpp
class Solution {
public:
    vector<int> topKFrequent(vector<int>& nums, int k) {
        unordered_map<int, int> cnt;
        for (int x : nums) ++cnt[x];                  // 第一步：统计频次

        int n = nums.size();
        vector<vector<int>> bucket(n + 1);            // bucket[f] = 出现 f 次的所有元素
        for (auto& [val, c] : cnt) bucket[c].push_back(val);

        vector<int> ans;
        ans.reserve(k);
        for (int f = n; f >= 1 && (int)ans.size() < k; --f)   // 从高频往低频扫
            for (int val : bucket[f]) {
                ans.push_back(val);
                if ((int)ans.size() == k) return ans;         // 够 k 个就返回
            }
        return ans;
    }
};
```

**堆解法（更通用，适合数据流）**

```cpp
vector<int> topKFrequent(vector<int>& nums, int k) {
    unordered_map<int, int> cnt;
    for (int x : nums) ++cnt[x];

    // 小顶堆，按频次比较；pair 是 (频次, 元素值)
    priority_queue<pair<int,int>, vector<pair<int,int>>, greater<pair<int,int>>> pq;
    for (auto& [val, c] : cnt) {
        pq.push({c, val});
        if ((int)pq.size() > k) pq.pop();             // 踢掉频次最小的
    }
    vector<int> ans;
    while (!pq.empty()) { ans.push_back(pq.top().second); pq.pop(); }
    return ans;                                       // 注意：结果是频次升序
}
```

> `greater<pair<int,int>>` 会按 `first`（频次）升序建小顶堆，`first` 相同时比 `second`。本题不要求处理频次相同的顺序，所以够用。

**复杂度**  桶排序：时间 **O(n)**，空间 O(n)。堆：时间 O(n + m log k)（m 为不同元素个数），空间 O(n + k)。

**边界与坑**
- **桶的大小必须是 `n + 1`**，因为频次最大可能是 n（所有元素相同），而下标要能取到 n。开 `n` 个会越界。
- **桶要倒序遍历**（`f` 从 n 到 1），才是"从高频到低频"。正序遍历得到的是最低频的 k 个，答案完全反了。
- **`f >= 1` 而不是 `f >= 0`**：频次 0 的桶必然为空（`cnt` 里只有出现过的元素），扫它是无用功（虽然无害）。
- **堆解法用小顶堆**（`greater`），别用默认的大顶堆。大顶堆会保留频次最小的 k 个。
- **堆解法的结果顺序是频次升序**（堆顶最小先出）。题目说"顺序不限"所以没关系；若要求降序，最后 `reverse` 一下。
- `pq.size()` 与 `k` 比较记得强转 `(int)`。
- **题目保证答案唯一**（不存在频次并列导致歧义的情况），所以不用处理平局。若不保证，要明确平局规则。
- **不要用 `map` 代替 `unordered_map`**：`map` 是 O(log n) 插入，白多一个 log 因子（虽然仍能过）。
- 桶排序的空间是 O(n) —— 若 n 极大而 k 很小，堆解法的 O(k) 空间更优。**这是两种方法的真正取舍点。**

**追问 / 变体**
- **692 前 K 个高频单词**：要求**频次相同时按字典序**排列。堆的比较器要写成"频次相同时字典序大的优先级低"，比较器方向极易写错，是很好的练习。
- **数据流中的 Top-K**：必须用堆（桶排序需要知道全部数据）。工业界用 **Count-Min Sketch + 堆** 做近似 Top-K，内存 O(1)。**这是很好的系统设计延伸。**
- **k == m（不同元素总数）**：直接返回所有元素。
- **频次值域很大**（如统计的是权重和而非次数）：桶排序失效，只能用堆或快速选择。**这说明桶排序的适用条件是"键值域有界且不大"。**
- **1046 最后一块石头的重量**：纯堆模拟，是 `priority_queue` 的基础练习。
- **求前 K 小频次**：桶正序遍历，或改用大顶堆。

### 295. 数据流的中位数（困难）

**题意**  设计数据结构支持两个操作：`addNum(num)` 插入一个数，`findMedian()` 返回当前所有数的中位数。

**暴力**  用 `vector` 存所有数，每次 `findMedian` 时排序，O(n log n) 一次。或者插入时用二分找位置再 `insert` 保持有序——查中位数 O(1)，但 `vector::insert` 要挪动元素，**插入是 O(n)**。数据量大时不可接受。

**关键洞察**

**核心认识：求中位数并不需要整个序列有序，只需要知道「中间那一两个数」。**

于是想到把数据分成两半：

- **左半**（较小的一半）用**大顶堆** `lo` → 堆顶是左半的**最大值**
- **右半**（较大的一半）用**小顶堆** `hi` → 堆顶是右半的**最小值**

如果能维持两个不变量：

1. **`lo` 的所有元素 ≤ `hi` 的所有元素**（即左半整体不大于右半）
2. **两堆大小相差不超过 1**

那么**两个堆顶就恰好夹住中位数**：
- 总数为**奇数**时，让 `lo` 多一个，中位数 = `lo.top()`
- 总数为**偶数**时，两堆等大，中位数 = `(lo.top() + hi.top()) / 2.0`

**`findMedian` 变成 O(1)**，`addNum` 只需 O(log n) 的堆操作。这就是本题的全部。

**怎么维持不变量 1（最关键的一步）**

新元素不能随便扔进某个堆——它可能破坏"左半 ≤ 右半"。标准技巧是**"过一遍另一个堆"**：

```cpp
lo.push(num);              // 先无条件进左半
hi.push(lo.top());         // 把左半的最大值移交给右半
lo.pop();
if (lo.size() < hi.size()) { lo.push(hi.top()); hi.pop(); }   // 再平衡大小
```

**为什么这样一定对**：`num` 进 `lo` 后，`lo.top()` 是「左半所有元素 ∪ {num}」的最大值，把它移到 `hi` 就保证了留在 `lo` 的都不超过它，而 `hi` 里的都不小于它 → **不变量 1 自动成立**，完全不需要判断 `num` 该去哪边。

**这个"先都进 A、把 A 的极值让给 B、再平衡大小"的三步套路是双堆题的通用手法**，比手写 `if (num <= lo.top())` 分支更短且不会漏边界（比如 `lo` 为空时 `lo.top()` 是 UB）。

**最优解（C++，双堆）**

```cpp
class MedianFinder {
    priority_queue<int> lo;                                    // 大顶堆：较小的一半
    priority_queue<int, vector<int>, greater<int>> hi;         // 小顶堆：较大的一半
public:
    MedianFinder() {}

    void addNum(int num) {
        lo.push(num);                 // ① 无条件进左半
        hi.push(lo.top());            // ② 把左半最大值移交右半（保证左 <= 右）
        lo.pop();
        if (lo.size() < hi.size()) {  // ③ 平衡大小，让 lo 至多多一个
            lo.push(hi.top());
            hi.pop();
        }
    }

    double findMedian() {
        if (lo.size() > hi.size()) return lo.top();            // 奇数个：lo 多一个
        return (lo.top() + hi.top()) / 2.0;                    // 偶数个：取平均
    }
};
```

**显式判断版（逻辑更直白，但边界要小心）**

```cpp
class MedianFinder {
    priority_queue<int> lo;
    priority_queue<int, vector<int>, greater<int>> hi;
public:
    void addNum(int num) {
        if (lo.empty() || num <= lo.top()) lo.push(num);       // 空栈判断不能漏
        else hi.push(num);
        // 平衡：lo 最多比 hi 多 1
        if (lo.size() > hi.size() + 1) { hi.push(lo.top()); lo.pop(); }
        else if (hi.size() > lo.size()) { lo.push(hi.top()); hi.pop(); }
    }
    double findMedian() {
        if (lo.size() > hi.size()) return lo.top();
        return ((double)lo.top() + hi.top()) / 2.0;
    }
};
```

**复杂度**  `addNum` **O(log n)**，`findMedian` **O(1)**，空间 O(n)。

**边界与坑**
- **`lo` 必须是大顶堆、`hi` 必须是小顶堆**。反了就完全错——两个堆顶会是"左半最小"和"右半最大"，夹不住中位数。**记法：两个堆顶要「面对面」朝着中间。**
- **`(lo.top() + hi.top()) / 2.0` 可能溢出 `int`**：两个 `int` 相加超过 `INT_MAX` 时先溢出再转 `double`，结果错。本题 `num` 范围 ±10⁵ 所以安全，但**严谨写法是 `((double)lo.top() + hi.top()) / 2.0`** 或用 `long long`。面试主动提这点是加分项。
- **`/ 2.0` 的 `.0` 不能少**，否则整数除法把小数截断（`(1+2)/2 = 1` 而不是 1.5）。
- **`findMedian` 在空数据上是 UB**。题目保证先 `addNum` 再 `findMedian`，生产代码要判空。
- **`size()` 比较用无符号**：`lo.size() > hi.size() + 1` 里两边都是 `size_t`，安全；但 `lo.size() - hi.size() > 1` 在 `lo` 更小时会**下溢成巨大值**，判断全错。**别写减法，写加法。**
- 显式判断版的 `lo.empty() ||` 不能漏——第一次插入时 `lo.top()` 是 UB。三步套路版没有这个问题（`lo.push(num)` 保证非空），**这是它更稳的一个理由**。
- **两个平衡分支的顺序无所谓**，但条件必须精确：`lo.size() > hi.size() + 1`（lo 多了 2 个才调整）和 `hi.size() > lo.size()`（hi 只要多 1 个就调整）。写成对称的 `> +1` 会让 hi 比 lo 多 1 时不调整，`findMedian` 取错。
- 单个元素时 `lo` 有 1 个、`hi` 空，返回 `lo.top()`，正确。

**追问 / 变体**
- **480 滑动窗口中位数**：加上**删除**操作。`priority_queue` **不支持删除任意元素**，所以要么用 `multiset` + 迭代器（`lo`/`hi` 各一个，维护中间迭代器），要么用**懒删除**（用哈希表记录待删元素，堆顶命中就丢弃）。**这是双堆结构的主要局限，值得知道。**
- **数据流的第 K 大**（703）：单个小顶堆即可，见 [215](#215-数组中的第-k-个最大元素中等)。
- **求任意分位数（如 P99）**：两堆大小比例改成 `k : (n-k)` 而非 1:1，其余同理。
- **数据量极大（放不进内存）**：用近似算法 —— **t-digest** 或 **蓄水池采样 + 分位数估计**，工业监控系统（如 Prometheus 的 histogram）都是这么做的。**这是本题最好的系统设计延伸。**
- **数值范围有限（如都是 0-100 的整数）**：直接用**计数数组 + 前缀和**，`addNum` O(1)、`findMedian` O(值域)。**又一次"值域有界就能用桶"**（对照 [347](#347-前-k-个高频元素中等) 的桶排序）。
- **4 寻找两个正序数组的中位数**：静态的两个有序数组，用二分割点，见 [11-二分查找](11-二分查找.md)。**同样叫"中位数"，但静态 vs 流式导致解法完全不同。**
- **为什么不用平衡树（`multiset`）**：也可以——维护一个指向中位数的迭代器，插入后按需前后移动一格，同样 O(log n)。双堆的优势是常数更小、实现更短；`multiset` 的优势是**支持删除**（见 480）。
