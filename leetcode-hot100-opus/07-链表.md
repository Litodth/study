# 07 · 链表（14 题）

## 套路总纲

链表题机械但极高频，考的不是灵光一现，而是**指针操作的稳健度**。把下面四件套练到肌肉记忆，14 题去掉一大半难度。

**四件套**

1. **哨兵头节点（dummy）**
   ```cpp
   ListNode dummy(0, head);          // C++11 起 ListNode 有双参构造
   ListNode* p = &dummy;
   // ... 操作 ...
   return dummy.next;
   ```
   凡是**头节点可能被删除或改变**的题（2、19、21、23、24、25、148、203），一律先加哨兵。它把「头节点」这个特例变成普通节点，能消掉大半的 `if (head == nullptr)` 判断。

2. **快慢指针**
   - **判环**（141）：快走 2 慢走 1，相遇即有环。
   - **找中点**（148、234）：快走 2 慢走 1，快到头时慢在中点。`while (fast->next && fast->next->next)` 得到**左中点**（偶数长度时靠左）；`while (fast && fast->next)` 得到**右中点**。选哪个取决于题目，148 必须用左中点。
   - **找倒数第 k 个**（19）：快指针先走 k 步，然后同步走。

3. **原地反转**
   ```cpp
   ListNode *prev = nullptr, *cur = head;
   while (cur) {
       ListNode* next = cur->next;   // 先存后继，否则断链后找不回来
       cur->next = prev;             // 反转指向
       prev = cur;                   // 双指针前移
       cur = next;
   }
   return prev;                      // prev 是新头
   ```
   这 5 行是 206、25、234、143 的共同内核，**必须能闭着眼默写**。

4. **画图**。三个以上指针互相赋值时，在纸上画出「操作前 / 操作后」的箭头。链表题的 bug 几乎全是"顺序写反"或"提前断链"，画图能当场发现。

**难度递进**：160/206/141/21 是基本功 → 234/142/19/24/2 是组合应用 → 25/138/148/23/146 是硬题。**146 LRU 是面试出现频率最高的设计题**，务必吃透。

**节点定义**（本文件所有代码共用）

```cpp
struct ListNode {
    int val;
    ListNode* next;
    ListNode() : val(0), next(nullptr) {}
    ListNode(int x) : val(x), next(nullptr) {}
    ListNode(int x, ListNode* n) : val(x), next(n) {}
};
```

### 160. 相交链表（简单）

**题意**  两条单链表可能在某节点开始重合（**是同一个节点对象**，不是值相等），返回相交的起始节点；不相交返回 `nullptr`。

**暴力**  对 A 的每个节点，在 B 里遍历找是否相同，O(mn)。或用 `unordered_set` 存下 A 的所有节点指针再扫 B，O(m+n) 时间但 O(m) 空间。

**关键洞察**

不相交时两条链长度差异让指针无法对齐。核心技巧：**让两个指针走过相同的总路程**。

指针 `pa` 走完 A 后接着走 B，`pb` 走完 B 后接着走 A。若相交，各自的总路程都是 `lenA + lenB - common`（`common` 是公共部分长度），所以**必然在交点相遇**；若不相交，两者同时走到 `nullptr`（总路程都是 `lenA + lenB`），循环以 `nullptr == nullptr` 结束。

一个漂亮的地方：这个写法**不需要特判是否相交**，两种情况被同一段代码统一处理。

**最优解（C++）**

```cpp
class Solution {
public:
    ListNode* getIntersectionNode(ListNode* headA, ListNode* headB) {
        if (!headA || !headB) return nullptr;
        ListNode *pa = headA, *pb = headB;
        while (pa != pb) {                       // 相交则在交点相遇；不相交则同时为 nullptr
            pa = pa ? pa->next : headB;          // A 走完换到 B
            pb = pb ? pb->next : headA;          // B 走完换到 A
        }
        return pa;
    }
};
```

**复杂度**  时间 O(m + n)，空间 O(1)。

**边界与坑**
- **换链的条件是 `pa == nullptr`，不是 `pa->next == nullptr`**。写成后者会跳过尾节点，且不相交时死循环。
- 任一链为空则不可能相交，提前返回。
- 判断相交用**指针相等**（`pa != pb`），不是 `pa->val != pb->val`。题目考的就是这一点。
- 两条链完全相同（同一个 head）时返回 head，正确。

**追问 / 变体**
- **求长度差法**：先各自求长度，长的先走 `|m-n|` 步再同步走。同样 O(1) 空间，逻辑更直白，也是标准答案。
- **链表可能有环时求交点**：先各自判环，再分情况讨论，复杂得多。
- **142 环形链表 II** 用的也是"路程差"的数学分析，两题思路同源。

### 206. 反转链表（简单）

**题意**  反转单链表并返回新头。

**暴力**  把所有值存进 `vector` 再倒着重建，O(n) 空间。可行但没意义——本题就是考指针操作。

**关键洞察**

反转的本质是**逐个改写 `next` 指向**。难点在于：`cur->next = prev` 一执行，原来的后继就丢了。所以**必须先用临时变量保存 `cur->next`**。

三个指针的语义要清晰：`prev` = 已反转部分的头，`cur` = 待处理节点，`next` = 暂存的后继。循环不变量是「`prev` 指向的链已经是反转好的」。

**最优解（C++，迭代）**

```cpp
class Solution {
public:
    ListNode* reverseList(ListNode* head) {
        ListNode *prev = nullptr, *cur = head;
        while (cur) {
            ListNode* next = cur->next;   // ① 先存后继
            cur->next = prev;             // ② 反转指向
            prev = cur;                   // ③ prev 前移
            cur = next;                   // ④ cur 前移
        }
        return prev;                      // cur 为空时，prev 是最后一个节点 = 新头
    }
};
```

**对照解法（递归）**

```cpp
class Solution {
public:
    ListNode* reverseList(ListNode* head) {
        if (!head || !head->next) return head;     // base：空或单节点
        ListNode* newHead = reverseList(head->next);  // 先反转后面的部分
        head->next->next = head;                   // 让后继指回自己
        head->next = nullptr;                      // 断开原来的指向（否则成环）
        return newHead;                            // 新头一路透传上来
    }
};
```

**复杂度**  迭代 O(n) 时间 / O(1) 空间；递归 O(n) / O(n) 栈。

**边界与坑**
- **四步顺序不能变**。少存 `next` 或提前覆盖是链表题第一大 bug。
- 返回 `prev` 不是 `cur`——循环结束时 `cur == nullptr`。
- 递归版**必须写 `head->next = nullptr`**。不写的话头两个节点会互相指向形成环，`while (p)` 直接死循环。
- 递归版的 `head->next->next = head` 要在递归调用**之后**——此时 `head->next` 仍指向原后继（尚未被修改），正好是反转后链的尾巴。

**追问 / 变体**
- **92 反转链表 II**（反转 `[left, right]` 区间）：哨兵 + 先走到 `left-1`，然后头插法或标准反转后重接。
- **25 K 个一组翻转**：本题的分组版，见下文。
- **234 回文链表**：反转后半部分再比较。
- **递归 vs 迭代**：面试官常问"哪个更好"——迭代 O(1) 空间更优，但递归代码更短。链表很长时递归会栈溢出（10⁵ 层）。

### 234. 回文链表（简单）

**题意**  判断单链表是否为回文。进阶要求 O(n) 时间、O(1) 空间。

**暴力**  把值复制到 `vector` 再用双指针判回文，O(n) 时间 O(n) 空间。**面试先给这个**，它三行搞定且绝对正确。

**关键洞察**

O(1) 空间的困难在于：单链表**不能反向遍历**。既然不能倒着走，那就**把后半部分反转成正着能走的方向**。

三步：
1. **快慢指针找中点**（`while (fast->next && fast->next->next)` 拿左中点）
2. **反转后半部分**（复用 206）
3. **前后两半同时向后走并比较**

比较时的循环条件用**后半段**（`while (second)`），因为奇数长度时前半段比后半段多一个节点（中间节点），用前半段做条件会多比一次而越界。

**最优解（C++，O(1) 空间）**

```cpp
class Solution {
public:
    bool isPalindrome(ListNode* head) {
        if (!head || !head->next) return true;

        // ① 找左中点：偶数长度时 slow 停在前半段最后一个
        ListNode *slow = head, *fast = head;
        while (fast->next && fast->next->next) {
            slow = slow->next;
            fast = fast->next->next;
        }

        // ② 反转后半部分（从 slow->next 开始）
        ListNode *prev = nullptr, *cur = slow->next;
        while (cur) {
            ListNode* next = cur->next;
            cur->next = prev;
            prev = cur;
            cur = next;
        }

        // ③ 双向比较：以后半段（较短的那半）为循环条件
        ListNode *p1 = head, *p2 = prev;
        bool ok = true;
        while (p2) {
            if (p1->val != p2->val) { ok = false; break; }
            p1 = p1->next;
            p2 = p2->next;
        }
        return ok;
    }
};
```

**复杂度**  时间 O(n)，空间 O(1)。

**边界与坑**
- **中点取法要和后续逻辑配套**。用 `while (fast->next && fast->next->next)` 得左中点，后半段从 `slow->next` 起——这样奇数长度时中间节点留在前半段，不参与比较，正确。
- 比较循环用 `while (p2)` 而非 `while (p1 && p2)`（后者也对但多余）或 `while (p1)`（错，会越界）。
- **进阶要求：比较完把链表恢复原状**。面试官很可能追问「你破坏了输入，能修复吗」——再反转一次后半段接回去即可。生产代码中修改入参是坏味道，主动提这点是加分项。
- 单节点和空链表都是回文，提前返回。

**追问 / 变体**
- **恢复链表**：比较结束后 `slow->next = reverse(prev)`。
- **双向链表**：直接头尾双指针，O(1) 空间且不用反转。
- **143 重排链表**（L0→Ln→L1→Ln-1…）：找中点 + 反转后半 + 交替合并，是本题技巧的直接组合，强烈建议接着刷。

### 141. 环形链表（简单）

**题意**  判断链表中是否有环。

**暴力**  用 `unordered_set` 记录访问过的节点指针，重复出现即有环。O(n) 时间 O(n) 空间。

**关键洞察**

**Floyd 判圈算法（龟兔赛跑）**：慢指针一次一步，快指针一次两步。

- **无环**：快指针先到 `nullptr`，循环结束。
- **有环**：两者都会进入环。之后每一轮，快指针相对慢指针**多走一步**，所以它们的距离每轮减 1——距离必然减到 0，即**必定相遇**。

关键在于「相对速度差为 1」保证了不会"跨过而不相遇"。如果快指针一次走 3 步，距离每轮减 2，可能在环长为偶数时永远错过——**所以必须是 2 和 1**。

**最优解（C++）**

```cpp
class Solution {
public:
    bool hasCycle(ListNode* head) {
        ListNode *slow = head, *fast = head;
        while (fast && fast->next) {          // 快指针要走两步，两个都要判空
            slow = slow->next;
            fast = fast->next->next;
            if (slow == fast) return true;    // 相遇 => 有环
        }
        return false;                          // fast 到头 => 无环
    }
};
```

**复杂度**  时间 O(n)，空间 O(1)。

**边界与坑**
- 循环条件 `fast && fast->next` 两个都要判：`fast->next->next` 需要 `fast->next` 非空。少判一个就是空指针解引用。
- **判相遇要放在移动之后**。放在移动前的话，初始时 `slow == fast == head` 会直接返回 `true`。
- 也可以写成 `slow = head, fast = head->next` 然后 `while (slow != fast)`，但需要额外处理空链表，不如上面的写法干净。

**追问 / 变体**
- **142 返回入环节点**：见下文。
- **求环的长度**：相遇后固定一个指针，另一个绕一圈回来，计步数。
- **287 寻找重复数**：把数组 `nums[i] → i` 看成链表，转化为找环入口，是 Floyd 算法最惊艳的应用，见 [17-技巧](17-技巧.md)。

### 142. 环形链表 II（中等）

**题意**  返回链表开始入环的第一个节点；无环返回 `nullptr`。

**暴力**  哈希集合记录访问顺序，第一个重复的就是入口。O(n) 空间。

**关键洞察**

设：头到入环点距离 `a`，入环点到相遇点距离 `b`，相遇点回到入环点距离 `c`（环长 `= b + c`）。

相遇时：
- 慢指针走了 `a + b`
- 快指针走了 `a + b + k(b+c)`，`k ≥ 1`（在环里多绕了 k 圈）
- 快是慢的两倍：`2(a + b) = a + b + k(b + c)`

化简得：

```
a = k(b + c) - b = (k-1)(b+c) + c
```

**含义**：从**头节点**走 `a` 步，和从**相遇点**走 `c` 步（再加若干整圈）**会到达同一个位置——入环点**。

所以：相遇后，把一个指针放回头节点，两个指针**都以每次一步**前进，再次相遇处即为入环点。

这个推导是本题的全部，面试务必能现场写出来。

**最优解（C++）**

```cpp
class Solution {
public:
    ListNode* detectCycle(ListNode* head) {
        ListNode *slow = head, *fast = head;
        while (fast && fast->next) {
            slow = slow->next;
            fast = fast->next->next;
            if (slow == fast) {                  // 第一次相遇
                ListNode* p = head;
                while (p != slow) {              // 一个从头走，一个从相遇点走，同速
                    p = p->next;
                    slow = slow->next;
                }
                return p;                        // 相遇处即入环点
            }
        }
        return nullptr;
    }
};
```

**复杂度**  时间 O(n)，空间 O(1)。

**边界与坑**
- **第二阶段两个指针都是一次一步**，不是一快一慢。这里再用 2 倍速就错了。
- 第二阶段的循环条件是 `p != slow`，若入环点就是头节点（`a = 0`），循环不进入直接返回 `head`，正确。
- 必须在**确认相遇后**才进第二阶段，别把它写在循环外面。
- 无环时直接返回 `nullptr`。

**追问 / 变体**
- **能否用 O(1) 空间且不修改链表**：本解法正是。
- **不允许用 Floyd**：只能哈希集合。
- **287 寻找重复数**：数组版的本题。
- **手推公式**：面试官经常要求现场推导 `a = c + (k-1)(b+c)`，练熟。

### 21. 合并两个有序链表（简单）

**题意**  合并两条升序链表为一条升序链表（**复用原节点**，不新建）。

**暴力**  取出所有值排序后重建，O(n log n)。没必要——两条链已经有序。

**关键洞察**

归并排序的 merge 步骤。每次比较两条链的头，取较小的接到结果尾部。

**哨兵节点在这里的价值最明显**：没有它就要特判「结果链还是空的」，代码会多一层分支。有了 `dummy`，第一次接入和后续接入是同一段代码。

最后有一条链走完时，另一条剩下的部分**直接整段接上**（都比已接入的大且有序），不用逐个搬。

**最优解（C++，迭代）**

```cpp
class Solution {
public:
    ListNode* mergeTwoLists(ListNode* l1, ListNode* l2) {
        ListNode dummy;                       // 哨兵：省掉"结果为空"的特判
        ListNode* tail = &dummy;
        while (l1 && l2) {
            if (l1->val <= l2->val) { tail->next = l1; l1 = l1->next; }
            else                    { tail->next = l2; l2 = l2->next; }
            tail = tail->next;
        }
        tail->next = l1 ? l1 : l2;            // 剩下的整段接上
        return dummy.next;
    }
};
```

**对照解法（递归，代码极短）**

```cpp
class Solution {
public:
    ListNode* mergeTwoLists(ListNode* l1, ListNode* l2) {
        if (!l1) return l2;
        if (!l2) return l1;
        if (l1->val <= l2->val) { l1->next = mergeTwoLists(l1->next, l2); return l1; }
        else                    { l2->next = mergeTwoLists(l1, l2->next); return l2; }
    }
};
```

**复杂度**  时间 O(m + n)，空间 O(1) 迭代 / O(m+n) 递归栈。

**边界与坑**
- **用 `<=` 而非 `<`** 保证稳定性（相等时优先取 `l1`）。本题看不出差别，但归并排序里稳定性可能被要求。
- 最后的 `tail->next = l1 ? l1 : l2;` 不能漏，漏了会丢掉剩余部分。
- 哨兵用**栈对象** `ListNode dummy;` 而不是 `new ListNode()`，避免内存泄漏。
- 返回 `dummy.next`，不是 `&dummy`。

**追问 / 变体**
- **23 合并 K 个升序链表**：见下文。
- **合并两个有序数组**（88）：从后往前填，避免覆盖。
- **148 排序链表**：本题是它的 merge 子过程。

### 2. 两数相加（中等）

**题意**  两条链表按**逆序**存储两个非负整数的各位（个位在头），求和并以同样格式返回。

**暴力**  把两条链转成整数相加再转回链表 —— **错的**。数字可能有 100 位，任何整型都装不下。这个陷阱是题目的核心设计。

**关键洞察**

逆序存储恰好是**竖式加法的自然顺序**——从个位开始逐位相加并进位。所以边遍历边加即可，完全不需要转成整数。

三个细节：
- 两条链长度不同 → 短的那条用 0 补位（`p ? p->val : 0`）。
- 最高位可能产生进位 → 循环条件要带上 `carry`。
- 用哨兵简化建链。

**统一的循环条件 `while (p1 || p2 || carry)` 是本题最优雅的地方**——把「一条链走完」「进位未处理完」两种收尾情况合并成一个循环。

**最优解（C++）**

```cpp
class Solution {
public:
    ListNode* addTwoNumbers(ListNode* l1, ListNode* l2) {
        ListNode dummy;
        ListNode* tail = &dummy;
        int carry = 0;
        while (l1 || l2 || carry) {                 // 三个条件缺一不可
            int sum = carry;
            if (l1) { sum += l1->val; l1 = l1->next; }
            if (l2) { sum += l2->val; l2 = l2->next; }
            carry = sum / 10;
            tail->next = new ListNode(sum % 10);
            tail = tail->next;
        }
        return dummy.next;
    }
};
```

**复杂度**  时间 O(max(m, n))，空间 O(max(m, n))（输出链）。

**边界与坑**
- **循环条件必须带 `carry`**。`999 + 1 = 1000` 时，两条链都走完了但还有进位要处理，漏掉就得到 `000`。
- **不要先转整数**，见上。这是面试官埋的雷。
- `sum` 最大是 `9 + 9 + 1 = 19`，`carry` 只可能是 0 或 1。
- 结果链是新建的，不复用输入节点（题目允许）。

**追问 / 变体**
- **445 两数相加 II**（**正序**存储，高位在头）：三种解法——① 反转两条链再套本题；② 用两个栈；③ 递归。面试常考「不能反转链表怎么办」→ 用栈。
- **大数乘法**（43）：同样的按位模拟思路。
- **进位链的长度**：结果最多比较长的那条链多 1 位。

### 19. 删除链表的倒数第 N 个结点（中等）

**题意**  删除链表的倒数第 `n` 个节点并返回头。要求一趟扫描。

**暴力**  先遍历求长度 `L`，再走到第 `L - n` 个节点删除。两趟，O(n)——完全正确，只是题目想要一趟。

**关键洞察**

**双指针制造固定间距**。让 `fast` 先走 `n` 步，然后 `fast` 和 `slow` 同步前进。当 `fast` 走到末尾时，两者间距恒为 `n`，`slow` 正好在倒数第 `n+1` 个位置——也就是**待删节点的前驱**。

要删除节点必须拿到**前驱**，所以让 `slow` 停在前驱位置，而不是待删节点上。

**哨兵在这里是刚需**：删除的可能就是头节点（`n == 链表长度`），有了哨兵，"头节点的前驱"就存在了，不用特判。

**最优解（C++）**

```cpp
class Solution {
public:
    ListNode* removeNthFromEnd(ListNode* head, int n) {
        ListNode dummy(0, head);                 // 哨兵：处理"删除头节点"的情形
        ListNode *fast = &dummy, *slow = &dummy;
        for (int i = 0; i < n; ++i) fast = fast->next;   // fast 先走 n 步
        while (fast->next) {                     // fast 停在最后一个节点
            fast = fast->next;
            slow = slow->next;                   // slow 停在待删节点的前驱
        }
        ListNode* del = slow->next;
        slow->next = del->next;                  // 摘除
        delete del;                              // C++ 手动释放（LeetCode 不强制）
        return dummy.next;
    }
};
```

**复杂度**  时间 O(L)，空间 O(1)。

**边界与坑**
- **`fast` 和 `slow` 都从哨兵出发**，且 `fast` 先走 `n` 步（不是 `n+1` 步）。配合 `while (fast->next)` 的停止条件，`slow` 恰好落在前驱。这组「起点 + 步数 + 停止条件」是配套的，改一个就要改全部——建议用 `[1,2], n=2` 手推验证。
- 删除头节点时（`n == L`）必须靠哨兵，否则 `slow` 无处安放。
- 返回 `dummy.next` 而不是 `head`——`head` 可能已被删除。
- `delete del` 后不能再访问 `del`。LeetCode 上不写 `delete` 也能过，但面试写上是加分项（说明有内存意识）。
- 题目保证 `n` 有效，生产代码要判 `n > L`。

**追问 / 变体**
- **删除倒数第 n 个的两趟解法**：先求长度。面试可以先说这个再给一趟版。
- **237 删除链表中的节点**（只给待删节点，拿不到前驱）：把后继的值复制过来再删后继——很妙的偷梁换柱。
- **83/82 删除排序链表中的重复元素**：同样是删除操作，练前驱的维护。

### 24. 两两交换链表中的节点（中等）

**题意**  两两交换相邻节点并返回新头。**必须真的交换节点**，不能只改值。

**暴力**  交换值（`swap(p->val, p->next->val)`）——能过 LeetCode，但违背题意。面试这么写会被判不合格，因为真实场景里节点可能携带大量数据或被外部引用。

**关键洞察**

每组交换涉及**三个指针**：前驱 `prev`、第一个节点 `a`、第二个节点 `b`。交换后的连接关系：

```
交换前:  prev -> a -> b -> rest
交换后:  prev -> b -> a -> rest
```

三条赋值语句（顺序有讲究）：

```cpp
a->next = b->next;     // ① a 接上 rest（必须先做，否则 b->next 被改后就找不到 rest）
b->next = a;           // ② b 指向 a
prev->next = b;        // ③ prev 指向新的组头 b
```

然后 `prev` 移到 `a`（它现在是这组的尾巴），继续下一组。

哨兵同样是刚需——第一组交换会改变头节点。

**最优解（C++，迭代）**

```cpp
class Solution {
public:
    ListNode* swapPairs(ListNode* head) {
        ListNode dummy(0, head);
        ListNode* prev = &dummy;
        while (prev->next && prev->next->next) {    // 至少还有两个节点才交换
            ListNode* a = prev->next;
            ListNode* b = a->next;
            a->next = b->next;                      // ① 顺序不能变
            b->next = a;                            // ②
            prev->next = b;                         // ③
            prev = a;                               // a 现在是本组尾，作为下组的前驱
        }
        return dummy.next;
    }
};
```

**对照解法（递归，三行）**

```cpp
class Solution {
public:
    ListNode* swapPairs(ListNode* head) {
        if (!head || !head->next) return head;
        ListNode* b = head->next;
        head->next = swapPairs(b->next);   // head 接上"后面处理好的部分"
        b->next = head;
        return b;                          // b 是新的组头
    }
};
```

**复杂度**  时间 O(n)，空间 O(1) 迭代 / O(n) 递归。

**边界与坑**
- **三条赋值的顺序**：必须先 `a->next = b->next`。先写 `b->next = a` 会让 `b->next` 被覆盖，`rest` 永久丢失 → 链表截断或成环。
- 循环条件 `prev->next && prev->next->next`：奇数个节点时最后一个单独留下不交换。
- `prev = a`（交换后 `a` 在后面），别写成 `prev = b`。
- 返回 `dummy.next`。

**追问 / 变体**
- **25 K 个一组翻转**：本题是 `k = 2` 的特例。做完 24 直接上 25。
- **只交换值的写法为什么不好**：面试可能追问，答案是"节点可能携带额外数据 / 外部持有节点指针 / 题目明确禁止"。
- **奇数个节点时反过来（最后一组不足 k 个也翻转）**：25 的变体。

### 25. K 个一组翻转链表（困难）

**题意**  每 `k` 个节点一组进行翻转，不足 `k` 个的最后一组**保持原有顺序**。要求 O(1) 额外空间。

**暴力**  用数组暂存每组的 `k` 个节点再重建，O(k) 空间。可行但不满足进阶要求。

**关键洞察**

把问题拆成两层：

**外层：分组管理。** 维护 `groupPrev`（上一组的尾节点）。每轮：
1. 从 `groupPrev` 往后数 `k` 步，检查是否够 `k` 个。**不够就直接结束**（保持原序）。
2. 翻转这 `k` 个节点。
3. 重新连接，更新 `groupPrev`。

**内层：翻转 + 重连。** 这是最容易错的地方。设本组为 `[a ... b]`，下一组头是 `nextGroup`：

```
翻转前:  groupPrev -> a -> ... -> b -> nextGroup
翻转后:  groupPrev -> b -> ... -> a -> nextGroup
```

翻转 `k` 个节点时，把 `prev` 的**初值设为 `nextGroup`**（而不是 `nullptr`）——这样翻转完成的瞬间，`a->next` 就自动指向了 `nextGroup`，省掉一次手动重连。这个小技巧让代码干净很多。

然后 `groupPrev->next = b`（新组头），`groupPrev = a`（本组翻转后的尾 = 下组的前驱）。

**最优解（C++）**

```cpp
class Solution {
public:
    ListNode* reverseKGroup(ListNode* head, int k) {
        ListNode dummy(0, head);
        ListNode* groupPrev = &dummy;        // 上一组的尾节点

        while (true) {
            // ① 检查剩余节点是否够 k 个，同时找到本组最后一个节点 kth
            ListNode* kth = groupPrev;
            for (int i = 0; i < k && kth; ++i) kth = kth->next;
            if (!kth) break;                 // 不足 k 个，保持原序，结束

            ListNode* nextGroup = kth->next;
            ListNode* groupHead = groupPrev->next;   // 本组第一个节点（翻转后成为尾）

            // ② 翻转本组：prev 初值设为 nextGroup，翻转完自动接好后面
            ListNode* prev = nextGroup;
            ListNode* cur  = groupHead;
            while (cur != nextGroup) {
                ListNode* next = cur->next;
                cur->next = prev;
                prev = cur;
                cur = next;
            }

            // ③ 重连并前进：kth 现在是本组新头，groupHead 是本组新尾
            groupPrev->next = kth;
            groupPrev = groupHead;
        }
        return dummy.next;
    }
};
```

**复杂度**  时间 O(n)（每个节点被访问常数次：一次计数、一次翻转），空间 O(1)。

**边界与坑**
- **不足 k 个必须保持原序**。所以要**先数够 k 个再翻转**，不能边翻边数——翻到一半发现不够就回不去了。这是本题与 24 的关键差别。
- 翻转的 `prev` 初值是 `nextGroup` 不是 `nullptr`。用 `nullptr` 的话本组翻转后会与后面断开，需要额外一句 `groupHead->next = nextGroup` 补救（也对，但多一步）。
- 翻转循环的终止条件是 `cur != nextGroup`，不是 `cur != nullptr`——只翻本组。
- `groupPrev = groupHead`（翻转后的尾），不是 `kth`（翻转后的头）。这一步写反会让链表卡住。
- `k == 1` 时相当于不翻转，代码天然正确。
- 先数 k 个的循环里 `kth` 要判空：`i < k && kth`。

**追问 / 变体**
- **不足 k 个也翻转**：去掉 `if (!kth) break`，改为「不足时翻转剩余全部」，需要单独处理最后一组。
- **递归写法**：先数 k 个 → 翻转本组 → `groupHead->next = reverseKGroup(nextGroup, k)`。代码更短但 O(n/k) 栈空间。
- **92 反转链表 II**：反转指定区间，是本题的单组版。
- 本题是**链表专题的技术顶点**，24 → 92 → 25 这条线走完，链表指针操作基本无死角。

### 138. 随机链表的复制（中等）

**题意**  链表每个节点除 `next` 外还有一个 `random` 指针（指向链表中任意节点或 `null`），要求**深拷贝**整条链表。

**节点定义**

```cpp
class Node {
public:
    int val;
    Node* next;
    Node* random;
    Node(int _val) : val(_val), next(nullptr), random(nullptr) {}
};
```

**暴力/朴素**  两趟 + 哈希表：第一趟按 `next` 复制所有节点并建立 `原节点 → 新节点` 的映射；第二趟根据映射设置 `next` 和 `random`。O(n) 时间 O(n) 空间——**这是标准答案，面试给这个完全合格**。

**为什么需要映射**：`random` 可能指向**还没被创建的节点**（比如第一个节点的 random 指向最后一个）。所以必须先把所有节点建出来，才能设置指针。

**关键洞察（O(1) 空间的进阶解法）**

不用哈希表存映射，那就**把映射关系编码进链表结构本身**——把每个新节点**插在它的原节点后面**：

```
原链:  A → B → C
交织:  A → A' → B → B' → C → C'
```

这样 `原节点->next` 就是它的副本，映射关系是 O(1) 可查的，哈希表被省掉了。三步：

1. **交织**：遍历原链，每个节点后插入一个副本。
2. **设置 random**：`A'->random = A->random->next`（`A->random` 的副本正是它的 `next`）。**注意判空**。
3. **拆分**：把交织链拆回两条独立的链——原链要恢复原状。

**最优解（C++，O(1) 空间）**

```cpp
class Solution {
public:
    Node* copyRandomList(Node* head) {
        if (!head) return nullptr;

        // ① 交织：A -> A' -> B -> B' -> ...
        for (Node* p = head; p; p = p->next->next) {
            Node* copy = new Node(p->val);
            copy->next = p->next;
            p->next = copy;
        }

        // ② 设置副本的 random：原节点的 random 的"下一个"就是它的副本
        for (Node* p = head; p; p = p->next->next)
            if (p->random) p->next->random = p->random->next;
            // p->random 为空时，copy->random 已在构造时初始化为 nullptr

        // ③ 拆分，并恢复原链
        Node* newHead = head->next;
        for (Node* p = head; p; p = p->next) {
            Node* copy = p->next;
            p->next = copy->next;                      // 恢复原链
            copy->next = p->next ? p->next->next : nullptr;  // 连接副本链
        }
        return newHead;
    }
};
```

**对照解法（哈希表，更好写）**

```cpp
class Solution {
public:
    Node* copyRandomList(Node* head) {
        if (!head) return nullptr;
        unordered_map<Node*, Node*> mp;                 // 原节点 -> 新节点
        for (Node* p = head; p; p = p->next)            // 第一趟：只建节点
            mp[p] = new Node(p->val);
        for (Node* p = head; p; p = p->next) {          // 第二趟：连指针
            mp[p]->next   = p->next   ? mp[p->next]   : nullptr;
            mp[p]->random = p->random ? mp[p->random] : nullptr;
        }
        return mp[head];
    }
};
```

**复杂度**  交织法 O(n) 时间 / O(1) 额外空间；哈希法 O(n) / O(n)。

**边界与坑**
- **`p->random` 可能为 `nullptr`**，第二步必须判空，否则 `p->random->next` 崩溃。
- **第三步必须恢复原链**。题目虽然没明说，但修改输入是坏实践，且面试官会检查。
- 拆分时 `copy->next = p->next ? p->next->next : nullptr`——最后一个副本的 `next` 要设为 `nullptr`，不判会越界。
- 三步**必须严格分开**。想在一趟里同时设 `random` 和拆分是不行的：拆分会破坏"副本紧跟原节点"的性质，而设 `random` 依赖这个性质。
- 空链表返回 `nullptr`。
- 哈希法可以用 `mp[nullptr] = nullptr` 的技巧省掉判空（`unordered_map` 的 `operator[]` 会默认构造为 `nullptr`），代码更短：直接写 `mp[p]->random = mp[p->random]`。

**追问 / 变体**
- **递归 + 哈希的写法**：`copy(node)` 递归处理，用 map 记忆化避免无限递归。代码最短但有栈深度问题。
- **克隆图**（133）：同样是「带任意指针的深拷贝」，用哈希 + DFS/BFS。两题一起看能理解「深拷贝含环结构」的通法。
- **为什么交织法能省空间**：因为它把 O(n) 的映射信息藏在了链表的 `next` 指针里——这和 [05-普通数组](05-普通数组.md) 的 41 原地哈希、[06-矩阵](06-矩阵.md) 的 73 原地标记是同一种智慧。

### 148. 排序链表（中等）

**题意**  在 O(n log n) 时间内对链表排序。进阶要求 O(1) 空间。

**暴力**  值取出来放 `vector`，`sort` 后写回。O(n log n) 时间但 O(n) 空间，且没考到链表。

**关键洞察**

**为什么是归并排序而不是快排？**

- **快排**依赖随机访问（选 pivot、双向扫描），链表做不到高效；且链表快排最坏 O(n²)。
- **归并排序**只需要顺序访问，且链表 merge 是 O(1) 空间的（数组版需要 O(n) 临时数组）——**链表反而比数组更适合归并**。这是本题最值得说的观察。

自顶向下归并三步：
1. **找中点断开**（快慢指针，取**左中点**，然后 `slow->next = nullptr` 断链）
2. **递归排序两半**
3. **merge**（复用 21 题）

**必须断链**：不断开的话两半还连在一起，递归会无限进行下去。

**关于 O(1) 空间**：自顶向下递归有 O(log n) 栈空间。要真正 O(1) 得用**自底向上归并**（按步长 1,2,4,8... 迭代合并），代码长得多。面试先给自顶向下，被追问再讲自底向上。

**最优解（C++，自顶向下归并）**

```cpp
class Solution {
public:
    ListNode* sortList(ListNode* head) {
        if (!head || !head->next) return head;      // 0 或 1 个节点，已有序

        // ① 快慢指针找左中点并断开
        ListNode *slow = head, *fast = head->next;  // fast 先走一步 => slow 停在左中点
        while (fast && fast->next) {
            slow = slow->next;
            fast = fast->next->next;
        }
        ListNode* mid = slow->next;
        slow->next = nullptr;                       // 断链！否则递归不收敛

        // ② 分别排序
        ListNode* l = sortList(head);
        ListNode* r = sortList(mid);

        // ③ 合并
        return merge(l, r);
    }

private:
    ListNode* merge(ListNode* a, ListNode* b) {
        ListNode dummy;
        ListNode* tail = &dummy;
        while (a && b) {
            if (a->val <= b->val) { tail->next = a; a = a->next; }
            else                  { tail->next = b; b = b->next; }
            tail = tail->next;
        }
        tail->next = a ? a : b;
        return dummy.next;
    }
};
```

**复杂度**  时间 O(n log n)，空间 O(log n) 递归栈（自底向上可做到 O(1)）。

**边界与坑**
- **`slow->next = nullptr` 断链绝不能漏**。漏掉就是无限递归 → 栈溢出。这是本题头号 bug。
- **中点取法必须保证两半都非空**。用 `fast = head->next` 起步（或 `while (fast->next && fast->next->next)`）得到左中点，这样两个节点时会分成 `1 + 1`。若用 `fast = head` 且 `while (fast && fast->next)`，两个节点时 `slow` 会停在第二个，分成 `2 + 0` → **无限递归**。这个细节是链表归并的经典陷阱。
- base case 要判 `!head || !head->next`，只判 `!head` 会无限递归。
- merge 用 `<=` 保持稳定性。

**追问 / 变体**
- **自底向上归并（真 O(1) 空间）**：外层按 `size = 1, 2, 4, ...` 倍增，内层每次切出两段长度为 `size` 的链表合并。代码约 40 行，是本题的完整答案。
- **为什么链表快排不好**：见上。面试高频追问。
- **147 对链表进行插入排序**：O(n²)，但考察前驱查找。
- **21 合并两个有序链表**：本题的子过程。
- **23 合并 K 个升序链表**：merge 的多路版。

### 23. 合并 K 个升序链表（困难）

**题意**  合并 `k` 条升序链表为一条升序链表。

**暴力**  ① 全部节点取出排序重建：O(N log N)（N 为总节点数），O(N) 空间。② 逐条合并（`res = merge(res, lists[i])`）：第 `i` 次合并的代价是 `O(i·n)`，总和 **O(k²n) = O(kN)**，`k` 大时超时。

朴素法的问题在于：**逐条合并让前面的节点被反复扫描**——第一条链被扫了 k 次。

**关键洞察**

两条优化路线，都值得会：

**路线一：分治（两两归并）。** 把 k 条链两两配对合并，得到 k/2 条；再两两合并……共 `log k` 轮，每轮所有节点被扫一次 O(N)。总计 **O(N log k)**。这本质就是归并排序的合并树。

**路线二：最小堆。** 把 k 条链的**头节点**放进最小堆，每次弹出最小的接到结果，并把它的后继压入堆。堆里始终最多 k 个元素，每个节点进出堆各一次 → **O(N log k)**。

两者复杂度相同。分治不需要额外空间（除递归栈），堆更直观且适合"流式"场景。面试任选，能讲清另一种更好。

**最优解（C++，分治）**

```cpp
class Solution {
public:
    ListNode* mergeKLists(vector<ListNode*>& lists) {
        if (lists.empty()) return nullptr;
        return mergeRange(lists, 0, lists.size() - 1);
    }

private:
    ListNode* mergeRange(vector<ListNode*>& lists, int l, int r) {
        if (l == r) return lists[l];
        int mid = l + (r - l) / 2;
        ListNode* a = mergeRange(lists, l, mid);
        ListNode* b = mergeRange(lists, mid + 1, r);
        return merge(a, b);
    }

    ListNode* merge(ListNode* a, ListNode* b) {
        ListNode dummy;
        ListNode* tail = &dummy;
        while (a && b) {
            if (a->val <= b->val) { tail->next = a; a = a->next; }
            else                  { tail->next = b; b = b->next; }
            tail = tail->next;
        }
        tail->next = a ? a : b;
        return dummy.next;
    }
};
```

**对照解法（最小堆）**

```cpp
class Solution {
public:
    ListNode* mergeKLists(vector<ListNode*>& lists) {
        // greater<> 语义是"大的优先级低" => 小顶堆。C++ 优先队列的比较器方向反直觉！
        auto cmp = [](ListNode* a, ListNode* b) { return a->val > b->val; };
        priority_queue<ListNode*, vector<ListNode*>, decltype(cmp)> pq(cmp);

        for (ListNode* h : lists) if (h) pq.push(h);    // 必须判空，空链不能入堆

        ListNode dummy;
        ListNode* tail = &dummy;
        while (!pq.empty()) {
            ListNode* node = pq.top(); pq.pop();
            tail->next = node;
            tail = node;
            if (node->next) pq.push(node->next);        // 补充该链的下一个
        }
        tail->next = nullptr;                            // 收尾，防止悬挂
        return dummy.next;
    }
};
```

**复杂度**  两种都是 O(N log k) 时间；分治 O(log k) 栈空间，堆 O(k) 空间。

**边界与坑**
- **`lists` 可能为空**（`k == 0`），或含有**空链表**（`lists[i] == nullptr`）。堆解法必须 `if (h)` 判空才入堆；分治解法的 `merge` 天然处理 `nullptr`。这是本题最容易漏的边界。
- **`priority_queue` 的比较器方向是反的**：`greater`（或 `a->val > b->val`）得到的是**小顶堆**。C++ 的比较器语义是"返回 true 表示 a 排在 b 后面/优先级更低"。这个坑在 [13-堆](13-堆.md) 会再强调一次。
- 堆解法最后要 `tail->next = nullptr`——最后一个节点的 `next` 可能还指向旧数据。
- 分治的 `mid = l + (r-l)/2` 防溢出（本题 `k ≤ 10^4` 不会溢出，但习惯要养成）。
- `decltype(cmp)` 需要 C++11；C++20 起可以直接写 `priority_queue<ListNode*, vector<ListNode*>, decltype(cmp)> pq;`（lambda 可默认构造）。

**追问 / 变体**
- **为什么逐条合并是 O(kN)**：面试常要求分析。第 i 次合并结果链已有 `i·n` 个节点，全部被扫一遍。
- **21 合并两个有序链表**：k=2 的特例。
- **数据流场景**：k 条链是流式到来的 → 堆解法天然适用，分治不行。
- **归并 k 个有序数组**：同样两种解法。
- **373 查找和最小的 K 对数字** / **378 有序矩阵第 K 小**：都是"k 路归并 + 堆"的应用。

### 146. LRU 缓存（中等）

> **面试出现频率最高的设计题**。不只是算法题，更是「用哈希表 + 双向链表组合出 O(1) 操作」的经典范例。必须能在 15 分钟内手写完整。

**题意**  设计一个固定容量的缓存，支持 `get(key)` 和 `put(key, value)`，**两者都必须是 O(1)**。容量满时淘汰**最久未使用**的项。注意：`get` 命中也算"使用"，要更新其新鲜度。

**朴素思路的困境**

- 只用 `unordered_map`：`get`/`put` 是 O(1)，但**找不出"最久未使用"的是谁**——哈希表没有顺序信息。
- 只用**数组/vector 按使用顺序排列**：能找到最久未使用（队首），但 `get` 时要把元素移到队尾，需要 O(n) 搬移。
- 用 `list`（双向链表）：移动节点是 O(1)（只改指针），但**根据 key 找到节点**需要 O(n) 遍历。

**关键洞察**

**两个结构互补，合起来就都是 O(1)**：

```
unordered_map<int, Node*>   ——  key → 节点地址，解决"O(1) 定位"
双向链表（按使用时间排序）   ——  解决"O(1) 移动 / O(1) 找最旧"
```

- 链表**头部 = 最近使用**，**尾部 = 最久未使用**。
- `get(key)`：map 查到节点 → 把它移到头部 → 返回值。
- `put(key,v)`：存在则更新值 + 移到头部；不存在则新建插到头部，若超容量则**删尾节点**并**从 map 中擦除对应 key**。

**为什么必须是双向链表**：删除一个节点需要修改它的**前驱**的 `next`。单链表拿不到前驱（除非 O(n) 遍历），所以必须双向。

**为什么用两个哨兵（head/tail dummy）**：插入头部和删除尾部都不用判空，所有节点都有真实的前驱和后继。代码从"到处判 nullptr"变成无分支——这个技巧值 5 分钟的讲解时间。

**最优解（C++，手写双向链表）**

```cpp
class LRUCache {
    struct Node {
        int key, val;
        Node *prev, *next;
        Node(int k = 0, int v = 0) : key(k), val(v), prev(nullptr), next(nullptr) {}
    };

    int cap;
    unordered_map<int, Node*> mp;    // key -> 节点地址
    Node *head, *tail;               // 两个哨兵：head->next 是最新，tail->prev 是最旧

    void remove(Node* node) {        // 从链表中摘除（不释放内存）
        node->prev->next = node->next;
        node->next->prev = node->prev;
    }
    void addFront(Node* node) {      // 插到头部（最近使用）
        node->next = head->next;
        node->prev = head;
        head->next->prev = node;
        head->next = node;
    }

public:
    LRUCache(int capacity) : cap(capacity) {
        head = new Node();           // 哨兵，不存实际数据
        tail = new Node();
        head->next = tail;
        tail->prev = head;
    }

    ~LRUCache() {                    // 面试加分：别忘了释放
        Node* p = head;
        while (p) { Node* nx = p->next; delete p; p = nx; }
    }

    int get(int key) {
        auto it = mp.find(key);
        if (it == mp.end()) return -1;
        Node* node = it->second;
        remove(node);                // 摘除后重新插到头部 = 刷新为最近使用
        addFront(node);
        return node->val;
    }

    void put(int key, int value) {
        auto it = mp.find(key);
        if (it != mp.end()) {        // 已存在：更新值 + 刷新位置
            it->second->val = value;
            remove(it->second);
            addFront(it->second);
            return;
        }
        if ((int)mp.size() == cap) { // 容量满：淘汰尾部（最久未使用）
            Node* lru = tail->prev;
            remove(lru);
            mp.erase(lru->key);      // 关键：map 里的记录也要删！
            delete lru;
        }
        Node* node = new Node(key, value);
        mp[key] = node;
        addFront(node);
    }
};
```

**对照解法（用 `std::list`，代码短一半）**

```cpp
class LRUCache {
    int cap;
    list<pair<int, int>> lst;                              // (key, value)，头部最新
    unordered_map<int, list<pair<int,int>>::iterator> mp;  // key -> 链表迭代器
public:
    LRUCache(int capacity) : cap(capacity) {}

    int get(int key) {
        auto it = mp.find(key);
        if (it == mp.end()) return -1;
        lst.splice(lst.begin(), lst, it->second);   // O(1) 把节点移到表头，迭代器仍有效
        return it->second->second;
    }

    void put(int key, int value) {
        auto it = mp.find(key);
        if (it != mp.end()) {
            it->second->second = value;
            lst.splice(lst.begin(), lst, it->second);
            return;
        }
        if ((int)mp.size() == cap) {
            mp.erase(lst.back().first);             // 先用尾节点的 key 删 map
            lst.pop_back();
        }
        lst.push_front({key, value});
        mp[key] = lst.begin();
    }
};
```

`std::list::splice` 是这里的关键——它 O(1) 移动节点且**不使迭代器失效**，正是 LRU 需要的原语。

**复杂度**  `get` / `put` 均摊 O(1)，空间 O(capacity)。

**边界与坑**
- **淘汰时必须同时删 map 和链表**。只删链表的话，map 里留下野指针，下次 `get` 那个 key 会访问已释放内存 → 未定义行为。**这是本题头号 bug**，面试官必查。
- **淘汰要在插入新节点之前**，且要先用 `lru->key` 去 `mp.erase`，再 `delete lru`（删了就读不到 key 了）。
- **`get` 命中也要移到头部**。忘记这一步，缓存就退化成 FIFO 而不是 LRU。
- `put` 已存在的 key 时**不能只更新值**，也要刷新位置。
- 哨兵节点让 `remove`/`addFront` 无需判空——不用哨兵的话要写四五个分支。
- `mp.size() == cap` 用 `==` 即可（size 不会超过 cap），但强转 `(int)` 避免有符号/无符号比较警告。
- 容量为 0 的极端情况：题目保证 `capacity >= 1`。
- 用 `std::list` 版本要注意：`splice` 后迭代器**仍然有效**（这是 `list` 的保证），所以 map 里存的迭代器不用更新。换成 `vector` 就不成立了。

**追问 / 变体**
- **460 LFU 缓存**（困难）：按访问**频率**淘汰，频率相同再按时间。需要「频率 → 该频率的双向链表」的两层结构，是 LRU 的自然升级，也是高频面试题。
- **线程安全的 LRU**：加锁，或用分段锁（类似 ConcurrentHashMap）。系统设计里常问。
- **带过期时间的 LRU**：额外维护时间戳或小顶堆。
- **为什么不用 `map`（红黑树）**：那是 O(log n)，不满足题目的 O(1) 要求。
- **手写 vs 用 `std::list`**：面试建议**手写**——考的就是双向链表操作。用 `std::list` 可以作为"我知道标准库有现成的"的补充说明。
