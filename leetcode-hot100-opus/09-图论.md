# 09 · 图论（4 题）

## 套路总纲

HOT100 的图论只有 4 题，但覆盖了三个必会模型：**网格 DFS/BFS**、**拓扑排序**、**Trie**。共同点是「图」常常不以邻接表的形式出现——**网格就是图**（每个格子是点，上下左右是边），**依赖关系就是图**，**字符串前缀就是树**。识别出图结构是第一步。

**网格题的标准配置**（200、994 共用）

```cpp
int m = grid.size(), n = grid[0].size();
const int dx[4] = {-1, 1, 0, 0};
const int dy[4] = {0, 0, -1, 1};
for (int k = 0; k < 4; ++k) {
    int nx = x + dx[k], ny = y + dy[k];
    if (nx < 0 || nx >= m || ny < 0 || ny >= n) continue;   // 越界
    // ...
}
```

方向数组比手写四个 `if` 更短且不易漏；八连通就扩成 8 个元素。

**DFS 还是 BFS？**

| 需求 | 选择 | 理由 |
|---|---|---|
| 只要「连通块个数 / 大小」 | DFS（递归最短） | 200 |
| 要「最短步数 / 同时扩散」 | **必须 BFS** | 994、127 |
| 网格极大怕爆栈 | BFS 或显式栈 | DFS 深度可达 m×n |

**核心口诀：BFS 一层 = 一个时间单位。** 凡是「最少几步」「几分钟后」，一律 BFS 分层（`int sz = q.size()`），这和 [102 层序遍历](08-二叉树.md) 是同一个骨架。

**多源 BFS**（994 的关键）：把**所有**起点一次性全部入队再开始扩散，就能得到「到最近某个起点的距离」。不要对每个起点各跑一次 BFS（那是 O(源数 × mn)）。

**标记已访问的两种流派**
- 额外 `vector<vector<bool>> vis`：干净，不改输入。
- **直接改原网格**（把 `'1'` 改成 `'0'`）：省 O(mn) 空间，写法最短。面试要主动说明「这会修改输入，如果调用方还要用就得先拷贝」。

**拓扑排序模板**（207，Kahn 算法 / BFS 版）

```
1. 建邻接表 + 统计每个点的入度
2. 所有入度为 0 的点入队
3. 出队 u，答案计数 +1，对每条 u → v 做 --indeg[v]，减到 0 就入队
4. 最终计数 == 节点数 ⟺ 无环
```

**判环的本质**：有环则环上节点的入度永远减不到 0，一定进不了队列。这个「计数比对」的收尾是拓扑排序的标志性写法。

**难度递进**：200 是网格 DFS 的模板题 → 994 引入多源 BFS + 计时 → 207 是拓扑排序模板 → 208 是纯设计题（Trie），和前三题几乎无关，单独记。

### 200. 岛屿数量（中等）

**题意**  `'1'` 是陆地、`'0'` 是水，**四连通**的陆地组成一个岛，求岛的个数。

**暴力**  没有真正的暴力——这题本质是「求连通块个数」，DFS/BFS/并查集都是 O(mn)，区别只在写法。

**关键洞察**

把网格看成图：每个 `'1'` 是一个顶点，相邻的 `'1'` 之间有边。那么「岛的个数」= **连通分量的个数**，标准解法是：

> 遍历所有格子，遇到一个还没访问过的 `'1'` 就 `++ans`，然后**把它所在的整个连通块全部标记为已访问**（"淹掉"），保证同一个岛不会被重复计数。

关键在于**先计数、再淹没**：一次 DFS 负责吃掉一整个岛，所以外层循环里 `ans` 增加的次数恰好等于岛的个数。

**淹没的技巧**：直接把 `grid[x][y] = '0'`，用输入网格本身当访问标记。这样 DFS 里的四个条件（越界、已是水）就能合并成一个判断，代码极短，也省掉 `vis` 数组。

**最优解（C++，DFS 原地标记）**

```cpp
class Solution {
    void dfs(vector<vector<char>>& g, int x, int y) {
        if (x < 0 || x >= (int)g.size() || y < 0 || y >= (int)g[0].size() || g[x][y] != '1')
            return;                       // 越界 或 不是陆地（含已访问）→ 直接回
        g[x][y] = '0';                    // 淹掉，兼作"已访问"标记
        dfs(g, x - 1, y);
        dfs(g, x + 1, y);
        dfs(g, x, y - 1);
        dfs(g, x, y + 1);
    }
public:
    int numIslands(vector<vector<char>>& grid) {
        if (grid.empty() || grid[0].empty()) return 0;
        int ans = 0;
        for (int i = 0; i < (int)grid.size(); ++i)
            for (int j = 0; j < (int)grid[0].size(); ++j)
                if (grid[i][j] == '1') { ++ans; dfs(grid, i, j); }   // 先计数，再淹整块
        return ans;
    }
};
```

**BFS 版（大网格不怕爆栈，推荐生产环境）**

```cpp
int numIslands(vector<vector<char>>& grid) {
    int m = grid.size(), n = grid[0].size(), ans = 0;
    const int dx[4] = {-1,1,0,0}, dy[4] = {0,0,-1,1};
    queue<pair<int,int>> q;
    for (int i = 0; i < m; ++i)
        for (int j = 0; j < n; ++j) {
            if (grid[i][j] != '1') continue;
            ++ans;
            grid[i][j] = '0';
            q.push({i, j});
            while (!q.empty()) {
                auto [x, y] = q.front(); q.pop();
                for (int k = 0; k < 4; ++k) {
                    int nx = x + dx[k], ny = y + dy[k];
                    if (nx < 0 || nx >= m || ny < 0 || ny >= n) continue;
                    if (grid[nx][ny] != '1') continue;
                    grid[nx][ny] = '0';       // 入队时就标记（关键！）
                    q.push({nx, ny});
                }
            }
        }
    return ans;
}
```

**复杂度**  时间 O(mn)（每个格子最多入栈/入队一次），空间：DFS 递归栈最坏 O(mn)（整个网格都是陆地时），BFS 队列最坏 O(min(m,n))～O(mn)。

**边界与坑**
- **BFS 必须在「入队时」标记，不能在「出队时」标记**。出队才标记的话，同一个格子会被多个邻居重复入队，队列规模爆炸（虽然结果仍对，但可能 TLE/MLE）。这是 BFS 的通用铁律。
- **网格是 `char` 不是 `int`**，比较要用 `'1'` / `'0'` 带引号。写成 `g[x][y] != 1` 是本题最常见的编译期不报错的逻辑错误。
- `g[x][y] != '1'` 这一个条件同时排除了「是水」和「已访问」，比分开写两个判断更稳。
- **只算四连通**。斜对角不算相连，别把方向数组写成 8 个。
- 边界判断里 `(int)g.size()` 的强转别省，否则 `x < 0` 与无符号比较会出问题（`x` 是 int 和 size_t 比较时 int 被提升为无符号，负数变巨大值）。
- 空网格要提前返回，否则 `grid[0].size()` 越界。
- **原地修改会破坏输入**。面试要主动说：「如果不允许修改输入，我用一个 `vis` 数组，多 O(mn) 空间」。

**追问 / 变体**
- **695 岛屿的最大面积**：DFS 返回本块面积（`1 + 四个方向的返回值之和`），取最大。
- **463 岛屿的周长**：DFS 时统计「越界或遇到水」的边数。
- **1254 封闭岛屿数目**：先从边界出发淹掉所有连边界的岛，剩下的就是封闭的。**「先处理边界」是这类题的通用技巧**（130 被围绕的区域同理）。
- **并查集解法**：把相邻陆地 `union`，答案 = 陆地的连通分量数。代码更长，但**支持动态加陆地**（305 岛屿数量 II 必须用并查集）。
- **827 最多可以形成的最大岛**（翻转一个 0）：先给每块岛标编号并记面积，再枚举每个 0 看它能连接哪几块不同编号的岛。
- **矩阵极大放不进内存**：按行流式处理 + 并查集合并，是系统设计方向的追问。

### 994. 腐烂的橘子（中等）

**题意**  `0` 空、`1` 新鲜橘子、`2` 腐烂橘子。每分钟，每个腐烂橘子会让**四邻**的新鲜橘子腐烂。求所有橘子腐烂所需的分钟数；若有新鲜橘子永远烂不到，返回 `-1`。

**暴力**  反复扫描整个网格，每轮把当前腐烂橘子的邻居标记为腐烂，直到某轮没有变化。O((mn)²)——每轮 O(mn) 扫描，最多 mn 轮。能过（网格 ≤ 10×10），但没抓住问题结构。

**关键洞察**

两个关键认识：

**① 这是「最短时间」问题 → 必须用 BFS。** 腐烂过程是从腐烂橘子同时向外扩散，扩散了几层 = 过了几分钟。BFS 的层数天然对应时间。

**② 有多个初始腐烂源 → 多源 BFS。** 不要对每个腐烂橘子单独跑 BFS 再取 min（O(源数 × mn)）。正确做法是**把所有初始腐烂的橘子一次性全部入队**，然后一起扩散。

多源 BFS 为什么对？可以想象加一个"虚拟超级源点"，它到每个初始腐烂橘子的距离都是 0，那么从超级源点跑单源 BFS，得到的就是「每个格子到最近腐烂源的距离」。把所有源同时入队，效果完全等价。**这是多源 BFS 的正确性依据**，面试值得说出来。

**③ 判 -1 的技巧**：不需要 BFS 结束后再扫一遍网格。开始前统计新鲜橘子总数 `fresh`，每腐烂一个就 `--fresh`，最后 `fresh > 0` 就说明有橘子够不到，返回 -1。

**时间计数的边界**：用「层数 - 1」还是「每层结束前判断队列是否还有新增」是这题最容易 off-by-one 的地方。最稳的写法是**只在这一层真的腐烂了新橘子时才 `++minutes`**（见下方代码）；或者等价地，先无条件数层数再减 1。

**最优解（C++）**

```cpp
class Solution {
public:
    int orangesRotting(vector<vector<int>>& grid) {
        int m = grid.size(), n = grid[0].size();
        const int dx[4] = {-1,1,0,0}, dy[4] = {0,0,-1,1};
        queue<pair<int,int>> q;
        int fresh = 0;
        for (int i = 0; i < m; ++i)
            for (int j = 0; j < n; ++j) {
                if (grid[i][j] == 2) q.push({i, j});     // 所有腐烂源一次性入队
                else if (grid[i][j] == 1) ++fresh;
            }
        if (fresh == 0) return 0;                        // 没有新鲜橘子，0 分钟

        int minutes = 0;
        while (!q.empty() && fresh > 0) {                // fresh == 0 可提前结束
            int sz = q.size();                           // 固定本层（本分钟）的腐烂源
            for (int i = 0; i < sz; ++i) {
                auto [x, y] = q.front(); q.pop();
                for (int k = 0; k < 4; ++k) {
                    int nx = x + dx[k], ny = y + dy[k];
                    if (nx < 0 || nx >= m || ny < 0 || ny >= n) continue;
                    if (grid[nx][ny] != 1) continue;     // 只感染新鲜的
                    grid[nx][ny] = 2;                    // 入队时立刻标记
                    --fresh;
                    q.push({nx, ny});
                }
            }
            ++minutes;                                   // 这一层扩散完，时间 +1
        }
        return fresh == 0 ? minutes : -1;                // 还有剩余 → 永远烂不到
    }
};
```

**复杂度**  时间 O(mn)，空间 O(mn)（队列最坏装下所有格子）。

**边界与坑**
- **`fresh == 0` 必须提前返回 0**。全是空格或全是腐烂橘子时答案是 0；不特判的话上面的循环虽然也返回 0（`minutes` 没被 `++` 过就退出），但显式写出来更清楚，也避免"全是 2"时白跑一层导致答案 1。
- **循环条件加上 `fresh > 0`** 是防 off-by-one 的关键。如果只写 `while (!q.empty())`，最后一层腐烂橘子出队时不会再感染任何橘子，但 `++minutes` 仍会执行，答案多 1。加了 `fresh > 0` 后，最后一批感染完 `fresh` 变 0，`++minutes` 执行完就退出循环，恰好正确。
- **必须多源同时入队**，不能逐个源跑 BFS。
- **入队时标记 `grid[nx][ny] = 2`**，不是出队时（同 200）。
- **`sz` 要提前存**（同 [102](08-二叉树.md)），否则分层失效，`minutes` 会变成"腐烂橘子总数"。
- 只有新鲜橘子（`1`）会被感染，`0` 是空格不能传播——`grid[nx][ny] != 1` 一句同时排除了空格和已腐烂。
- 值是 `int` 不是 `char`（和 200 相反，容易串台）。
- **`-1` 的判定不能用「队列空了但还没到某个格子」的直觉去写**，用 `fresh` 计数最简洁可靠。

**追问 / 变体**
- **542 01 矩阵**（每个 0 到最近 1 的距离）：教科书级多源 BFS，把所有 `0` 入队。
- **1162 地图分析**：多源 BFS 求「离陆地最远的海洋」，取最后一层的距离。
- **286 墙与门**：多源 BFS，所有门入队。
- **127 单词接龙**：非网格的 BFS 求最短转换步数，说明 BFS 不只用于网格。
- **腐烂速度不同 / 有权边**：BFS 失效，要用 **Dijkstra**（优先队列）。这是「BFS 只适用于边权全为 1」的重要边界。
- **八连通**：方向数组扩成 8 个。
- **返回每个格子腐烂的时刻**：把 `grid[nx][ny] = 2` 改成记录距离数组 `dist[nx][ny] = dist[x][y] + 1`，这是更通用的写法。

### 207. 课程表（中等）

**题意**  `numCourses` 门课，`prerequisites[i] = [a, b]` 表示「学 a 之前必须先学 b」。判断能否学完所有课。

**暴力**  反复扫描：每轮找出所有「所有先修课都已学完」的课程标记为已学，直到某轮没有进展。若还有课没学完则有环。O(V·E)。这其实就是拓扑排序的低效版——它的问题是每轮都要重新检查所有课程，而实际上只有「刚被解锁的课的后继」值得重新检查。

**关键洞察**

先把题意翻译成图：`[a, b]` 是一条**有向边 b → a**（先修 b 才能学 a）。「能学完所有课」⟺ **这个有向图无环**（DAG）。

有环时环上的课程互为前提，永远无法开始——所以本题 = **判断有向图是否有环**。

**Kahn 算法（BFS 拓扑排序）** 的思路极其自然：

- 入度为 0 的课 = 没有未满足的先修条件 = **现在就能学**。
- 学完一门课 u，它的每个后继 v 少了一个前提 → `--indeg[v]`，减到 0 就可以学了，入队。
- 最终能学完的课程数 `cnt`，如果 `cnt == numCourses` 说明全部可学（无环）；否则剩下的课都在环里（它们的入度永远减不到 0）。

**「计数比对」这一步是 Kahn 判环的标志性收尾**，务必记住。它的正确性依据：环上任意节点的入度至少为 1（被环内前驱指着），而环内前驱又永远不会出队，所以入度永远减不到 0。

**建图注意方向**：题目给的是 `[后继, 前驱]`，边的方向和数组顺序是**反的**，写 `g[b].push_back(a)` 而不是 `g[a].push_back(b)`。方向搞反会得到反向图，虽然「有无环」的答案恰好相同（反向图的环一一对应），但一旦追问「输出学习顺序」（210 题）就全错了。

**最优解（C++，Kahn / BFS）**

```cpp
class Solution {
public:
    bool canFinish(int numCourses, vector<vector<int>>& prerequisites) {
        vector<vector<int>> g(numCourses);              // 邻接表：前驱 -> 后继
        vector<int> indeg(numCourses, 0);
        for (auto& p : prerequisites) {
            g[p[1]].push_back(p[0]);                    // 边 p[1] -> p[0]，注意方向
            ++indeg[p[0]];
        }
        queue<int> q;
        for (int i = 0; i < numCourses; ++i)
            if (indeg[i] == 0) q.push(i);               // 所有可直接学的课

        int cnt = 0;
        while (!q.empty()) {
            int u = q.front(); q.pop();
            ++cnt;                                      // 学完一门
            for (int v : g[u])
                if (--indeg[v] == 0) q.push(v);         // 解锁后继
        }
        return cnt == numCourses;                       // 关键收尾：能学完的数量对得上吗
    }
};
```

**DFS 三色标记法（另一条正路，必会）**

```cpp
class Solution {
    vector<vector<int>> g;
    vector<int> state;              // 0 未访问, 1 正在访问（在当前递归栈上）, 2 已完成
    bool hasCycle(int u) {
        state[u] = 1;
        for (int v : g[u]) {
            if (state[v] == 1) return true;             // 回边 → 找到环
            if (state[v] == 0 && hasCycle(v)) return true;
        }
        state[u] = 2;                                   // 本节点及其后代都无环
        return false;
    }
public:
    bool canFinish(int numCourses, vector<vector<int>>& prerequisites) {
        g.assign(numCourses, {});
        state.assign(numCourses, 0);
        for (auto& p : prerequisites) g[p[1]].push_back(p[0]);
        for (int i = 0; i < numCourses; ++i)
            if (state[i] == 0 && hasCycle(i)) return false;
        return true;
    }
};
```

**复杂度**  时间 O(V + E)，空间 O(V + E)（邻接表 + 队列/递归栈）。

**边界与坑**
- **建图方向别反**：`g[p[1]].push_back(p[0])`。判环时反了也能过，但 210 输出顺序就错，养成正确习惯。
- **`--indeg[v] == 0` 要写在一起**（先减再判）。写成 `if (indeg[v] == 0)` 后再减，或者减完不判，都会漏掉入队。
- **`cnt == numCourses` 这个收尾不能漏**。只跑完 BFS 不比对，等于什么都没判。
- **三色标记必须区分「1 正在访问」和「2 已完成」**。只用一个 `vis` 布尔数组是错的：遇到已访问节点无法区分它是「当前递归栈上的祖先」（→ 有环）还是「另一条路径上已经确认无环的节点」（→ 没事）。**只用 bool 会把 DAG 误判成有环**，例如菱形 `1→2, 1→3, 2→4, 3→4`。这是 DFS 判环的头号错误。
- 无先修关系（`prerequisites` 为空）时所有课入度为 0，返回 true。
- 图可能**不连通**，所以 DFS 版外层要对每个未访问节点都尝试一次。
- **自环** `[a, a]` 表示学 a 前要先学 a → 必然无解。Kahn 版天然处理（`indeg[a] >= 1` 永远进不了队）；DFS 版也对（`state[a] == 1` 时又遇到 a）。
- 可能有**重复边**。Kahn 版会让 `indeg` 多加，同一条边减两次也对得上，结果正确；不影响答案。

**追问 / 变体**
- **210 课程表 II**：输出任意一个合法学习顺序。把 Kahn 里出队的 `u` 依次 `push_back` 到答案；若 `ans.size() != numCourses` 返回空数组。**这时建图方向必须正确**。
- **630 课程表 III**：带截止时间，是贪心 + 堆，和拓扑排序无关，别被题名误导。
- **字典序最小的拓扑序**：把 `queue` 换成 `priority_queue<int, vector<int>, greater<int>>`。
- **判断拓扑序是否唯一**：若某一轮队列中同时有 ≥ 2 个入度 0 的点，则顺序不唯一。
- **无向图判环**：用并查集（合并时发现已同集合即有环），或 DFS 记录父节点避免走回头路。**不能直接套三色法**。
- **最长路径 / 关键路径**：DAG 上按拓扑序做 DP，是拓扑排序的经典下游应用。

### 208. 实现 Trie (前缀树)（中等）

**题意**  实现 `insert(word)`、`search(word)`（完整单词是否存在）、`startsWith(prefix)`（是否有单词以此为前缀）。只含小写字母。

**暴力**  用 `unordered_set<string>` 存所有单词：`insert`/`search` 是 O(L)，但 `startsWith` 必须遍历整个集合逐个比对前缀，O(N·L)——**这就是 Trie 存在的理由**：它让前缀查询也变成 O(L)，与集合规模无关。

**关键洞察**

核心思想：**把公共前缀合并成共享的路径**。

- 每个**节点**代表一个前缀（根代表空串）。
- 每条**边**代表加一个字符。所以「字符存在边上，不存在节点里」——这是理解 Trie 的关键，节点本身不需要存字符。
- 从根走到某节点的路径拼出的字符串，就是该节点代表的前缀。

于是三个操作统一成「沿着字符逐个往下走」：

| 操作 | 走法 | 判定 |
|---|---|---|
| `insert` | 缺路就建 | 终点 `isEnd = true` |
| `search` | 缺路就 false | 终点 `isEnd == true` |
| `startsWith` | 缺路就 false | 走到终点即 true |

**`search` 和 `startsWith` 的唯一区别就是最后要不要检查 `isEnd`**。所以抽出一个私有辅助函数 `find(word)` 返回终点节点指针（走不通返回 `nullptr`），两个公开方法各判一次即可——这是本题最干净的实现结构，面试官会认可这个抽象。

**为什么需要 `isEnd`**：插入 `"apple"` 后，路径上会经过代表 `"app"` 的节点，但 `"app"` 并不是一个被插入的单词。没有 `isEnd` 标记就无法区分「这是一个完整单词」和「这只是某个单词的前缀」。

**最优解（C++）**

```cpp
class Trie {
    struct Node {
        Node* child[26] = {};        // 26 个字母的出边，nullptr 表示无此路
        bool isEnd = false;          // 是否有单词在此结束
    };
    Node* root;

    Node* find(const string& s) {    // 沿路走，返回终点节点；走不通返回 nullptr
        Node* cur = root;
        for (char c : s) {
            int i = c - 'a';
            if (!cur->child[i]) return nullptr;
            cur = cur->child[i];
        }
        return cur;
    }
public:
    Trie() : root(new Node()) {}

    void insert(string word) {
        Node* cur = root;
        for (char c : word) {
            int i = c - 'a';
            if (!cur->child[i]) cur->child[i] = new Node();   // 缺路就建
            cur = cur->child[i];
        }
        cur->isEnd = true;           // 标记单词结尾
    }

    bool search(string word) {
        Node* p = find(word);
        return p && p->isEnd;        // 必须是完整单词
    }

    bool startsWith(string prefix) {
        return find(prefix) != nullptr;   // 走通就行，不看 isEnd
    }
};
```

**内存版本（用 `vector` + 下标代替指针，避免手动 `delete`，竞赛常用）**

```cpp
class Trie {
    vector<array<int, 26>> ch;       // ch[u][c] = 节点 u 沿字符 c 的子节点编号，0 表示无
    vector<bool> isEnd;
    int newNode() { ch.push_back({}); isEnd.push_back(false); return ch.size() - 1; }
public:
    Trie() { newNode(); }            // 节点 0 作为根
    void insert(string word) {
        int u = 0;
        for (char c : word) {
            int i = c - 'a';
            if (!ch[u][i]) ch[u][i] = newNode();
            u = ch[u][i];
        }
        isEnd[u] = true;
    }
    bool search(string word) {
        int u = 0;
        for (char c : word) { if (!ch[u][c - 'a']) return false; u = ch[u][c - 'a']; }
        return isEnd[u];
    }
    bool startsWith(string prefix) {
        int u = 0;
        for (char c : prefix) { if (!ch[u][c - 'a']) return false; u = ch[u][c - 'a']; }
        return true;
    }
};
```

**复杂度**  三个操作均为 **O(L)**（L 为字符串长度），**与已存单词数无关**——这是 Trie 对哈希集合的核心优势。空间最坏 O(总字符数 × 26)。

**边界与坑**
- **`search` 必须检查 `isEnd`**。只插入 `"apple"` 时 `search("app")` 必须返回 false，`startsWith("app")` 必须返回 true。混淆这两个是本题唯一的逻辑考点。
- **`Node* child[26] = {};` 的 `= {}` 不能省**。裸数组不初始化时里面是随机值，`if (!cur->child[i])` 判断完全失效，行为诡异且难查。用 `array<Node*,26> child{};` 更安全。
- 空字符串 `""`：`insert("")` 会把根的 `isEnd` 置 true，`search("")` 返回 true，`startsWith("")` 返回 true。逻辑自洽，本题约束里 `1 <= word.length`，但知道这个行为有好处。
- **内存泄漏**：上面的指针版没写析构。面试可以主动提「生产代码要写递归析构，或用 `unique_ptr<Node> child[26]`」。LeetCode 判题不查泄漏。
- **数组版用 0 表示"无子节点"**，所以**根必须是节点 0**且不能被任何边指向——`newNode()` 在构造函数里先建根，正是为此。
- 字符集不是小写字母时（含大小写、数字、Unicode），`child[26]` 要换成 `unordered_map<char, Node*>`：省空间但常数变大。
- 不要在每次 `search` 里重新遍历所有插入过的单词——那就退化成暴力了。

**追问 / 变体**
- **211 添加与搜索单词**（支持 `.` 通配符）：`search` 遇到 `.` 时要对 26 个子节点全部递归尝试，从循环变成 DFS。
- **212 单词搜索 II**：Trie + 网格回溯，用 Trie 剪掉不可能的前缀，是 Trie 最经典的组合应用（[79 单词搜索](10-回溯.md)的升级版）。
- **648 单词替换 / 720 词典中最长的单词**：前缀匹配的直接应用。
- **删除操作 `erase(word)`**：先把 `isEnd` 置 false，再自底向上删除「没有子节点且非单词结尾」的节点；需要记录路径或用引用计数。
- **统计以某前缀开头的单词数**：给每个节点加 `int cnt`，插入时沿路 `++cnt`。这个小改动让 Trie 能回答频次问题。
- **01-Trie**：把二进制位当字符，用于**最大异或对**（421）等问题——Trie 不只用于字符串。
- **压缩 Trie / 基数树（Radix Tree）**：把单链路径压成一个节点，省内存，是 IP 路由表的实际结构。
