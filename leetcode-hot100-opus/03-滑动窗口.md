# 03 · 滑动窗口（2 题）

## 套路总纲

**识别信号**：题面出现「连续子数组 / 连续子串」+「最长 / 最短 / 恰好满足某条件」。**"连续"是关键词**——不连续就是子序列问题，该找 DP。

**通用模板**（背下来，Hot 100 里 3、438、76、239、560 都是它的变形）：

```cpp
int left = 0;
for (int right = 0; right < n; ++right) {
    加入 s[right] 到窗口状态;
    while (窗口违规 / 窗口过大) {
        移出 s[left] 的贡献;
        ++left;
    }
    用当前窗口 [left, right] 更新答案;      // 求最长：放在 while 之后
}
```

**两种子类型**：

| 类型 | while 的作用 | 何时更新答案 | 例 |
|---|---|---|---|
| **变长窗口·求最长** | 窗口非法时收缩，直到重新合法 | 收缩之后（此时窗口合法） | 3 |
| **定长窗口** | 长度超过 k 时移出最左（用 `if` 即可） | 长度恰好为 k 时 | 438 |
| **变长窗口·求最短** | 窗口已满足条件时**尽量收缩** | 收缩过程中（每次满足就记录） | 76（见 [04-子串](04-子串.md)） |

**为什么是 O(n)**：`left` 和 `right` 各自单调不减，各走 n 步，总步数 ≤ 2n。**`left` 永不回退**——这是滑动窗口成立的前提，也是它区别于暴力枚举的根本。什么时候 `left` 可以不回退？当「窗口非法则更大的窗口也非法」（单调性）成立时。全为正数的和、字符不重复这类条件满足；含负数的和不满足（所以 560 用前缀和+哈希，而非滑窗）。

**递进关系**：3 是模板本身；438 引入「如何 O(1) 判断窗口状态相等」；到 [04-子串](04-子串.md) 的 76 才是完整形态（求最短 + 复杂条件判定）。

### 3. 无重复字符的最长子串（中等）

**题意**  找出字符串中不含重复字符的最长子串的长度。

**暴力**  枚举所有起点和终点 O(n²) 个子串，每个用 `set` 判重 O(n) → O(n³)。优化一点：固定起点向右扩，遇重复即停，O(n²)。

为什么不够：起点右移一格时，前面辛苦建立的「窗口内有哪些字符」信息被完全丢弃、从零重建。

**关键洞察**

关键是证明 `left` 不需要回退：

设以 `left` 为起点的最长无重复子串右端是 `right`（即 `s[right+1]` 与窗口内某字符重复）。那么起点变成 `left+1` 时，能到达的右端**至少**还是 `right`（去掉一个字符不会引入新重复），所以 `right` 也不必回退。两个指针都单调 → 滑动窗口成立。

窗口状态用什么维护？两种：

1. **`unordered_set`**：`while (set.count(s[right]))` 就移出 `s[left]`。逐步收缩，直观。
2. **`last[c]` 记录每个字符最后一次出现的下标**：发现 `s[right]` 在窗口内（`last[s[right]] >= left`）时，`left` **一步跳到** `last[s[right]] + 1`。少了循环，更快。

第二种更优雅，且是「窗口内位置信息」这一思路的通用形态。ASCII 输入可以直接用 `int last[128]`，比哈希表快得多。

**最优解（C++）**

```cpp
class Solution {
public:
    int lengthOfLongestSubstring(string s) {
        vector<int> last(128, -1);       // 字符 -> 最后出现的下标；-1 表示没出现过
        int best = 0, left = 0;          // 窗口 [left, right]
        for (int right = 0; right < s.size(); ++right) {
            char c = s[right];
            if (last[c] >= left)         // 上次出现在窗口内 => 冲突
                left = last[c] + 1;      // 一步跳过去，无需逐个收缩
            last[c] = right;
            best = max(best, right - left + 1);
        }
        return best;
    }
};
```

**对照解法（set 版，思路更贴模板）**

```cpp
class Solution {
public:
    int lengthOfLongestSubstring(string s) {
        unordered_set<char> win;
        int best = 0, left = 0;
        for (int right = 0; right < s.size(); ++right) {
            while (win.count(s[right])) win.erase(s[left++]);  // 收缩到不再冲突
            win.insert(s[right]);
            best = max(best, right - left + 1);
        }
        return best;
    }
};
```

**复杂度**  时间 O(n)，空间 O(min(n, |Σ|))——|Σ| 是字符集大小，本题最多 128。

**边界与坑**
- **`last[c] >= left` 这个判断不能省成 `last[c] != -1`**。字符可能出现在窗口**左边**（已被划出去了），那不算冲突。例如 `"abba"`：处理最后的 `'a'` 时 `last['a'] = 0`，但 `left` 已经是 2，`0 >= 2` 为假，正确地不收缩。**漏掉 `>= left` 是本题头号 bug**。
- `left` 只能前进不能后退。写成 `left = last[c] + 1` 时若 `last[c] < left` 就会让 `left` 倒退——这正是上一条要防的。
- 空串返回 0，模板天然处理。
- 题目字符集含字母、数字、符号、空格，用 `int last[128]` 覆盖 ASCII 就够；若是 Unicode 改 `unordered_map<char32_t,int>`。
- 别返回子串本身就好——题目只要长度。要子串就多记一个起点。

**追问 / 变体**
- **返回子串本身**：记录 `bestLeft`，最后 `s.substr(bestLeft, best)`。
- **340 至多含 K 个不同字符的最长子串**：状态从 set 变成计数 map，`while (map.size() > k)` 收缩。这是本题的直接推广，非常高频。
- **159 至多含 2 个不同字符**：K=2 的特例。
- **允许最多删除 k 个字符使其无重复**：变成更复杂的窗口问题，可先讲清 K 不同字符版。

### 438. 找到字符串中所有字母异位词（中等）

**题意**  在 `s` 中找出所有是 `p` 的字母异位词的子串，返回它们的起始下标。异位词 = 字母种类和个数完全相同、顺序任意。

**暴力**  枚举 `s` 中所有长度为 `m = p.size()` 的子串，各自统计 26 个字母的计数与 `p` 比较。O(n · m)（或 O(n·m log m) 若用排序）。n, m ≤ 3×10⁴ 时 9×10⁸，超时。

**关键洞察**

两个观察合起来给出 O(n) 算法：

1. **窗口长度固定为 m**——因为异位词长度必然等于 `p` 的长度。所以这是**定长窗口**：`right` 每前进一步，`left` 也前进一步，不需要 `while`。
2. **计数可以增量维护**。窗口右移一格 = 一个字符进、一个字符出，只需 O(1) 更新两个计数。

剩下的问题是：怎么 O(1) 判断「当前窗口的 26 维计数向量 == `p` 的计数向量」？直接比 26 个数是 O(26)——能过，但有更漂亮的办法：

维护 `diff` = **计数不同的字母种类数**。初始 `diff` 是 `p` 中出现的字母种类数（或者把 `need` 和 `win` 的差值统一处理）。每次某个字母的计数变化时，只检查它**是否刚好变得相等 / 刚好不再相等**，相应地 `--diff` / `++diff`。`diff == 0` 即匹配。这样每步 O(1)。

下面给出更常用、更不易错的写法：用一个差值数组 `cnt`，`p` 的字符做 `--`，窗口的字符做 `++`，并维护 `diff` 为 `cnt` 中非零项的个数。

**最优解（C++）**

```cpp
class Solution {
public:
    vector<int> findAnagrams(string s, string p) {
        int n = s.size(), m = p.size();
        vector<int> ans;
        if (n < m) return ans;

        vector<int> cnt(26, 0);                 // 窗口计数 - p 的计数
        for (char c : p) --cnt[c - 'a'];
        for (int i = 0; i < m; ++i) ++cnt[s[i] - 'a'];   // 先铺满第一个窗口

        int diff = 0;                           // cnt 中非零的字母种类数
        for (int i = 0; i < 26; ++i) if (cnt[i]) ++diff;
        if (diff == 0) ans.push_back(0);

        for (int right = m; right < n; ++right) {
            int in  = s[right] - 'a';           // 进窗口
            int out = s[right - m] - 'a';       // 出窗口
            if (in != out) {                    // 相同字符进出，状态不变，可直接跳过
                if (cnt[in]  == 0) ++diff;      // 0 -> 非0：多了一种不同
                ++cnt[in];
                if (cnt[in]  == 0) --diff;      // 非0 -> 0：少了一种不同

                if (cnt[out] == 0) ++diff;
                --cnt[out];
                if (cnt[out] == 0) --diff;
            }
            if (diff == 0) ans.push_back(right - m + 1);
        }
        return ans;
    }
};
```

**对照解法（直接比数组，O(26n)，面试可先给）**

```cpp
class Solution {
public:
    vector<int> findAnagrams(string s, string p) {
        int n = s.size(), m = p.size();
        vector<int> ans;
        if (n < m) return ans;
        vector<int> need(26, 0), win(26, 0);
        for (char c : p) ++need[c - 'a'];
        for (int i = 0; i < n; ++i) {
            ++win[s[i] - 'a'];
            if (i >= m) --win[s[i - m] - 'a'];      // 维持定长
            if (i >= m - 1 && win == need)          // vector 支持 == 逐元素比较
                ans.push_back(i - m + 1);
        }
        return ans;
    }
};
```

**复杂度**  `diff` 版 O(n + m) 时间；直接比较版 O(26n)。空间都是 O(26) = O(1)。

**边界与坑**
- **`n < m` 必须提前返回**，否则 `s[right - m]` 越界，或第一个窗口铺不满。
- 定长窗口用 `if` 而不是 `while` 收缩——写成 `while` 也对但没必要，容易带来困惑。
- 起始下标是 `right - m + 1`，不是 `right - m`。差一错误在这题很常见，用具体例子（`s="abab", p="ab"` → `[0,1,2]`）验证一遍。
- `diff` 版里 `if (in != out)` 这个判断不是必需的，但去掉后要保证「先加后减」的顺序不会误判——加上它更安全也更快。
- 直接比较版里 `win == need` 用的是 `std::vector` 的 `operator==`（逐元素比较），合法且清晰；如果用 `int[26]` 数组就不能这么写，得 `memcmp`。

**追问 / 变体**
- **567 字符串的排列**：完全同一题，只是问「是否存在」而非「返回所有下标」——找到一个立即 `return true`。
- **76 最小覆盖子串**：从"恰好相等"放宽为"至少覆盖"，窗口变长，是本题的困难版，见 [04-子串](04-子串.md)。
- **字符集扩大到 Unicode**：`vector<int>(26)` 换成 `unordered_map`，`diff` 逻辑不变（这时 `diff` 写法比直接比较更有优势）。
- **允许最多 k 个字母不匹配**：`diff <= k` 的判定要改成按数量差的总和衡量，是不错的现场发挥题。
