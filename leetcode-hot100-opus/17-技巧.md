# 17 · 技巧（5 题）

## 套路总纲

这 5 题的共同特点：**见过就会，没见过很难现场推**。它们不属于任何通用算法范式，而是各自依赖一个特定的"巧思"。所以本专题的正确学法是**记住技巧本身 + 理解它为什么成立**，而不是指望临场推导。

**五个技巧一览**

| 题 | 技巧 | 核心性质 |
|---|---|---|
| 136 只出现一次的数字 | **异或消消乐** | `a ^ a = 0`、`a ^ 0 = a` |
| 169 多数元素 | **Boyer-Moore 投票** | 多数元素出现 > n/2 次，抵消后必然剩它 |
| 75 颜色分类 | **三向切分（荷兰国旗）** | 三个指针把数组分成四段 |
| 31 下一个排列 | **从后找升点 + 交换 + 反转** | 字典序的构造性刻画 |
| 287 寻找重复数 | **把数组看成链表找环** | 值域 [1,n] 与下标构成函数图 |

**位运算速查**（136 及其变体的基础）

```cpp
a ^ a = 0            // 自反：相同的数异或为 0
a ^ 0 = a            // 单位元
a ^ b ^ a = b        // 满足交换律和结合律，顺序随意
x & (-x)             // 取最低位的 1（lowbit）
x & (x - 1)          // 消掉最低位的 1（可用于统计 1 的个数）
x >> 1               // 除以 2；x & 1 判奇偶
```

**「数组值域与下标有对应关系」是一个强烈信号**（287、[41 缺失的第一个正数](05-普通数组.md)）：值域是 `[1, n]` 而数组长度是 `n` 或 `n+1` 时，可以把「下标 → 值」看成一个函数，从而用**原地置换**或**找环**的技巧做到 O(1) 空间。**看到这种约束就要往这个方向想。**

**双指针/三指针的原地操作**（75、[283 移动零](02-双指针.md)）：核心是**维护若干个"分界指针"，用循环不变量描述每一段的含义**。写之前先把不变量写在注释里，能极大降低出错率。

**难度递进**：136 最简单（一行）→ 169 需要理解投票的正确性 → 75 要维护三指针的不变量 → 31 的三步法要背 → 287 是最巧的（Floyd 判环的迁移）。

### 136. 只出现一次的数字（简单）

**题意**  数组中除一个元素只出现**一次**外，其余每个元素都出现**两次**。找出那个只出现一次的。要求**线性时间、O(1) 额外空间**。

**暴力**  用 `unordered_set`：出现就插入、再出现就删除，最后集合里只剩一个。O(n) 时间但 **O(n) 空间**，不满足要求。或者排序后两两检查，O(n log n) 时间 O(1) 空间——也不满足线性时间。

**关键洞察**

**核心性质：异或（XOR）满足 `a ^ a = 0` 和 `a ^ 0 = a`，且满足交换律、结合律。**

于是把**所有元素异或到一起**：

```
a ^ b ^ b ^ c ^ c ^ a ^ x
= (a ^ a) ^ (b ^ b) ^ (c ^ c) ^ x        // 交换律重排
= 0 ^ 0 ^ 0 ^ x
= x
```

**成对出现的元素两两抵消为 0，只剩下那个孤单的元素。** 因为异或满足交换律和结合律，**元素的排列顺序完全不影响结果**——这是这个技巧成立的关键，也是为什么不需要排序或计数。

**一行代码，O(n) 时间 O(1) 空间，完美满足要求。**

**最优解（C++）**

```cpp
class Solution {
public:
    int singleNumber(vector<int>& nums) {
        int ans = 0;                    // 异或的单位元
        for (int x : nums) ans ^= x;    // 成对的自动抵消
        return ans;
    }
};
```

**用标准库更短**：

```cpp
int singleNumber(vector<int>& nums) {
    return accumulate(nums.begin(), nums.end(), 0, bit_xor<int>());
}
```

**复杂度**  时间 O(n)，空间 O(1)。**这是理论最优**——至少要读一遍所有元素。

**边界与坑**
- **`ans` 初值必须是 0**（异或的单位元）。写成 `nums[0]` 也对（然后从 `i=1` 开始），但要先判空数组。
- **本题严格依赖"其余元素恰好出现两次"**。若出现三次（[137 题](https://leetcode.cn/problems/single-number-ii/)），异或法失效——`a ^ a ^ a = a` 不会归零。**这是异或技巧的适用边界，必须清楚。**
- **元素可以是负数**。异或作用在补码位模式上，负数同样正确抵消。不需要特殊处理。
- 题目保证**恰好有一个**元素出现一次。若有两个（260 题），需要额外技巧（见下）。
- 不要用 `+`/`-` 代替 `^`——加法不满足自反性（`a + a ≠ 0`）。
- 不要试图排序或用哈希——那就浪费了本题的考点。**面试直接给异或解法，然后解释性质。**

**追问 / 变体**
- **137 只出现一次的数字 II**（其余出现**三次**）：异或失效。两种解法：① **按位统计**——对每个二进制位统计所有元素在该位上 1 的个数，`% 3` 的余数就是答案在该位的值，O(32n)；② **状态机**（用两个变量模拟"出现次数 mod 3"），代码很短但难想。**按位统计的思路更通用**（能推广到"其余出现 k 次"）。
- **260 只出现一次的数字 III**（有**两个**只出现一次的 a、b）：
  1. 全部异或得到 `a ^ b`（其余抵消）
  2. 取 `diff = (a^b) & -(a^b)`——**最低位的 1**，这一位上 a 和 b 必然不同
  3. 按这一位是 0 还是 1 把数组**分成两组**，各组内异或，分别得到 a 和 b

  **"用一个区分位把问题拆成两个 136"** 是很漂亮的构造，是本题最重要的追问。
- **268 丢失的数字**：`[0,n]` 中缺一个，把 `0..n` 和数组全部异或即得。**同一个技巧。**
- **645 错误的集合**（一个重复、一个缺失）：异或 + 分组，同 260。
- **判断数组中所有元素是否成对出现**：全部异或，结果为 0 则成对（但注意这不是充分条件，如 `[1,2,3]` 异或为 0）。**这个反例说明异或只能判必要条件。**
- **191 位 1 的个数 / 231 2 的幂**：`x & (x-1)` 的经典应用（`x & (x-1) == 0` 判 2 的幂）。

### 169. 多数元素（简单）

**题意**  找出数组中出现次数**超过 `⌊n/2⌋`** 的元素。题目保证这个元素**总是存在**。

**暴力**  用 `unordered_map` 统计频次再找最大的，O(n) 时间 **O(n) 空间**。或排序后取中位数 `nums[n/2]`——**O(n log n) 时间 O(1) 空间，而且这个解法很巧**（出现超过一半的元素排序后必然占据中间位置）。

**但本题的经典解法能做到 O(n) 时间 + O(1) 空间。**

**关键洞察**

**Boyer-Moore 投票算法。**

**核心直觉**：把多数元素看成"我方"，其余所有元素看成"敌方"。让它们**一对一同归于尽**——由于我方数量 > n/2 > 敌方总数，**最后场上剩下的必然是我方**。

具体实现只需两个变量：

- `candidate`：当前的候选者
- `count`：候选者的"净票数"（我方票数减敌方票数）

遍历时：
- `count == 0` → 场上没人了，**把当前元素立为新候选者**，`count = 1`
- 当前元素 == `candidate` → 友军，`++count`
- 当前元素 != `candidate` → 敌军，`--count`（一换一）

**为什么最后的 `candidate` 一定是答案**（正确性证明，面试务必能讲）：

设多数元素为 `m`，出现 `k > n/2` 次。把遍历过程按"`count` 归零"切成若干段。每一段内部，候选者的票数恰好被抵消完，说明**这一段里 `candidate` 的出现次数 == 其他元素的出现次数**。所以每一段中 `m` 最多占一半。

由于 `m` 总共占了超过一半，**它必然"溢出"到最后那个未被抵消的段里，并且是那一段的候选者**。所以最终 `candidate == m`。

**关键前提：多数元素必须存在。** 如果不存在，算法会返回一个无意义的值——**必须再扫一遍验证**（见追问）。

**最优解（C++，Boyer-Moore）**

```cpp
class Solution {
public:
    int majorityElement(vector<int>& nums) {
        int candidate = nums[0], count = 0;
        for (int x : nums) {
            if (count == 0) candidate = x;          // 场上无人，立新候选
            count += (x == candidate) ? 1 : -1;      // 友军 +1，敌军 -1
        }
        return candidate;                            // 题目保证存在，直接返回
    }
};
```

**排序取中位数（O(n log n)，但只有两行，面试可作为对比）**

```cpp
int majorityElement(vector<int>& nums) {
    nth_element(nums.begin(), nums.begin() + nums.size() / 2, nums.end());
    return nums[nums.size() / 2];      // 出现超过一半 → 必然占据中位数位置
}
```

用 `nth_element`（快速选择）而非完整排序，可以做到 **平均 O(n)**。**这个解法也很值得知道**——它把"多数元素"的性质用几何位置刻画了出来。

**位运算解法（按位投票，O(32n)）**

```cpp
int majorityElement(vector<int>& nums) {
    int n = nums.size(), ans = 0;
    for (int b = 0; b < 32; ++b) {                  // 逐位统计
        int ones = 0;
        for (int x : nums) if ((x >> b) & 1) ++ones;
        if (ones > n / 2) ans |= (1 << b);          // 该位上 1 占多数
    }
    return ans;
}
```

思路：多数元素在**每一个二进制位**上都是多数。这个解法能推广到"出现超过 n/3 次"等变体。

**复杂度**  Boyer-Moore：时间 O(n)，空间 O(1)。**这是理论最优。**

**边界与坑**
- **`count += (x == candidate) ? 1 : -1;` 必须在 `if (count == 0)` 之后**。顺序反了会让刚立的候选者立刻被自己减掉。
- **`candidate` 初值可以任意**（写 `nums[0]` 或 0 都行），因为第一次循环 `count == 0` 会立刻覆盖它。但**空数组会崩**（`nums[0]` 越界），题目保证 `n >= 1`。
- **本算法依赖"多数元素必然存在"**。若不保证，`[1,2,3]` 会返回 3（无意义）。**必须第二遍扫描验证 `count(candidate) > n/2`。** 这是最重要的追问点。
- **是"超过 n/2"而不是"至少 n/2"**。`[1,1,2,2]` 没有多数元素（各占一半）。这个严格性是算法正确性的基础。
- **不要用 `count > 0` 判断结果有效**——`count` 的最终值不代表出现次数，只是净票数。
- 排序解法**会修改输入数组**，面试要说明。
- 位运算解法处理**负数**时要小心符号位：上面的写法对第 31 位也统计，`ans |= (1<<31)` 得到负数，恰好正确（补码）。但 `1 << 31` 在 `int` 上是 UB（实践中可用），严谨要写 `1u << 31` 再转换。

**追问 / 变体**
- **229 求众数 II**（找出所有出现超过 `⌊n/3⌋` 次的元素）：**最多有两个**这样的元素，所以维护**两个**候选者和两个计数器，同时投票。**这是 Boyer-Moore 的推广版**，规律是：找出现超过 `n/k` 次的元素需要 `k-1` 个候选者。**这个推广是本题最有价值的追问。**
- **不保证多数元素存在**：加第二遍扫描验证。
- **分治解法**：左右两半各求多数元素，若相同则是答案，否则统计两者在整个区间的出现次数取大的。O(n log n)，思路有趣但不实用。
- **随机化解法**：随机取一个元素，验证它是否为多数元素。期望 2 次就能命中（因为超过一半），期望 O(n)。**很有趣的概率算法。**
- **数据流版本**：Boyer-Moore 天然支持流式处理（只需 O(1) 状态）。**这是它相对排序解法的核心优势。**
- **找出现次数最多的元素（不保证过半）**：投票法失效，必须用哈希计数或堆，见 [347](13-堆.md)。

### 75. 颜色分类（中等）

**题意**  原地把只含 0、1、2 的数组排序（0 全在前、1 在中、2 在后）。要求**不使用库排序函数**，**一趟遍历**、**O(1) 空间**。

**暴力**  计数排序（两趟）：先统计 0、1、2 各有多少个，再重写整个数组。O(n) 时间 O(1) 空间，**完全能过**，而且非常好写：

```cpp
void sortColors(vector<int>& nums) {
    int cnt[3] = {0};
    for (int x : nums) ++cnt[x];
    int k = 0;
    for (int v = 0; v < 3; ++v)
        for (int i = 0; i < cnt[v]; ++i) nums[k++] = v;
}
```

**面试先给这个**（正确且简单），然后说"题目的进阶要求是一趟完成，我可以用三向切分"。

**关键洞察**

**三向切分（荷兰国旗问题，Dijkstra 提出）。**

用**三个指针**把数组划分成**四个区域**，并维护如下**循环不变量**（写代码前先把这个写出来，是本题不出错的唯一办法）：

```
[0, low)        全是 0     ← 已确定
[low, mid)      全是 1     ← 已确定
[mid, high]     未知区域   ← 待处理
(high, n-1]     全是 2     ← 已确定
```

遍历时只看 `nums[mid]`：

| `nums[mid]` | 动作 | 为什么 |
|---|---|---|
| **0** | `swap(nums[low], nums[mid])`，`++low; ++mid` | 换来的必然是 1（因为 `[low,mid)` 全是 1），已确定，可安全前进 |
| **1** | `++mid` | 它已经在正确的区域，直接前进 |
| **2** | `swap(nums[mid], nums[high])`，`--high`，**`mid` 不动** | 换来的元素来自**未知区域**，还没检查过！ |

**最关键的一点：遇到 2 时 `mid` 不能前进。**

因为从 `high` 位置换过来的元素属于**未知区域**（还没被检查），必须留在原地重新判断。而遇到 0 时 `mid` 可以前进，是因为从 `low` 换过来的元素必然是 1（由不变量保证）——**这个不对称性是本题的精髓，也是最容易写错的地方。**

**循环条件是 `mid <= high`**（闭区间），不是 `mid < high`。因为 `high` 指向的位置也是未知的，必须被处理。

**最优解（C++，三向切分，一趟）**

```cpp
class Solution {
public:
    void sortColors(vector<int>& nums) {
        int low = 0, mid = 0, high = nums.size() - 1;
        while (mid <= high) {                        // 闭区间，high 也要处理
            if (nums[mid] == 0) {
                swap(nums[low], nums[mid]);
                ++low; ++mid;                        // 换来的必是 1，可前进
            } else if (nums[mid] == 1) {
                ++mid;                               // 已在正确区域
            } else {                                 // nums[mid] == 2
                swap(nums[mid], nums[high]);
                --high;                              // mid 不动！换来的元素未检查
            }
        }
    }
};
```

**复杂度**  时间 O(n)（每次循环 `mid` 前进或 `high` 后退，总步数 ≤ n），空间 O(1)。**一趟遍历，满足所有进阶要求。**

**边界与坑**
- **遇到 2 时 `mid` 绝对不能 `++`**。这是本题头号 bug，会漏掉从 `high` 换过来的元素。测试用例 `[2,0,1]` 专卡这个：若 `mid` 前进，0 就永远不会被处理。
- **循环条件是 `mid <= high` 不是 `<`**。用 `<` 会漏掉最后一个元素。测试用例 `[2,1]` 或 `[1,2]` 能暴露。
- **遇到 0 时 `low` 和 `mid` 都要 `++`**。只 `++low` 会死循环。
- **`swap(nums[low], nums[mid])` 在 `low == mid` 时是自交换**，无害（值不变，两个指针一起前进）。不需要特判。
- **`high` 初值是 `nums.size() - 1`**（最后一个有效下标），因为它指向"未知区域的右端"。
- **不要用两趟的双指针写法混淆**：有一种解法是"先把 0 全挪到前面，再把 1 挪到中间"（两趟），也对但不满足"一趟"要求。
- 空数组：`high = -1`，`mid = 0 > -1`，循环不执行，安全。
- **`nums.size()` 是无符号**，`nums.size() - 1` 在空数组时是巨大值——但赋给 `int high` 后在典型实现上得到 -1，恰好安全。**严谨写法是 `(int)nums.size() - 1`。**

**追问 / 变体**
- **只有两种颜色（0 和 1）**：退化成简单双指针（同 [283 移动零](02-双指针.md)）。
- **k 种颜色**：三向切分不能直接推广。用**计数排序**（O(n + k)）最简单，或者用 k-1 次划分（O(kn)）。**"三向切分只适用于 3 类"是它的局限。**
- **本题与快速排序的关系**：三向切分正是**处理大量重复元素的快排优化**（`< pivot`、`== pivot`、`> pivot` 三段）。标准快排在全等数组上退化成 O(n²)，三向切分快排是 O(n)。**这个联系很重要**，也是 [215](13-堆.md) 里 `partition` 的进阶版。
- **要求稳定排序**：三向切分**不稳定**（swap 会打乱相同元素的相对顺序）。本题元素只有值没有附加信息，所以不影响；若元素带 payload 且要求稳定，只能用计数排序 + 额外数组。
- **283 移动零**：把 0 挪到后面且保持其余相对顺序 → 只能用"两指针覆写"而不是 swap，见 [02-双指针](02-双指针.md)。**"要不要保持稳定"决定了用 swap 还是覆写。**
- **数据流版本**：无法原地（数据没有全部到达），只能计数。

### 31. 下一个排列（中等）

**题意**  原地把数组重排成**字典序中下一个更大的排列**；如果不存在（已是最大排列，即完全降序），则重排成**最小的排列**（完全升序）。要求 **O(1) 额外空间**。

**暴力**  生成所有 n! 个排列、排序、找到当前排列的下一个。O(n! · n)，完全不可行。**这题必须找到构造性的规律。**

**关键洞察**

**核心目标：找到"下一个"就意味着——增大的幅度要尽可能小。**

这个目标拆成两个子目标：

1. **要变大**，所以必须把某个位置的数字换成更大的。
2. **变得尽可能小**，所以：
   - 被修改的位置要**尽可能靠右**（越靠右影响越小）
   - 换上去的数字要是**大于原数字中最小的那个**
   - 修改位置**之后**的部分要变成**最小排列**（升序）

**三步法（必须背下来）**：

**① 从右往左找第一个"升点" `i`**，即满足 `nums[i] < nums[i+1]` 的最大下标 `i`。

**为什么**：`[i+1, n-1]` 这一段必然是**降序**的（否则 `i` 不是第一个升点），而降序段本身已经是它的最大排列，无法在内部变大。所以必须动 `nums[i]`。**`nums[i]` 就是那个"尽可能靠右的可修改位置"。**

**若找不到升点**（整个数组降序）→ 已是最大排列 → 直接整体反转成升序，返回。

**② 在 `[i+1, n-1]` 中从右往左找第一个大于 `nums[i]` 的元素 `nums[j]`，交换 `nums[i]` 和 `nums[j]`。**

**为什么从右找**：由于该段降序，**从右往左第一个大于 `nums[i]` 的元素，就是该段中所有大于 `nums[i]` 的元素里最小的那个**。换上它，增幅最小。✓

**③ 把 `[i+1, n-1]` 反转。**

**为什么**：交换后这一段**仍然是降序**的（可以证明：交换不破坏降序性），而我们需要它是最小排列 → 反转成升序。✓

**三步走完，得到的就是恰好的"下一个排列"。** 这个算法就是 C++ `std::next_permutation` 的实现。

**举例走一遍**（`[1,3,5,4,2]`）：
- ① 从右找升点：`nums[1]=3 < nums[2]=5` → `i = 1`
- ② 在 `[5,4,2]` 中从右找第一个 > 3 的：是 4（下标 3）→ 交换得 `[1,4,5,3,2]`
- ③ 反转 `[5,3,2]` → `[1,4,2,3,5]` ✓

**最优解（C++）**

```cpp
class Solution {
public:
    void nextPermutation(vector<int>& nums) {
        int n = nums.size();
        // ① 从右往左找第一个升点 i：nums[i] < nums[i+1]
        int i = n - 2;
        while (i >= 0 && nums[i] >= nums[i + 1]) --i;

        if (i >= 0) {
            // ② 在右段中从右往左找第一个大于 nums[i] 的元素，交换
            int j = n - 1;
            while (nums[j] <= nums[i]) --j;
            swap(nums[i], nums[j]);
        }
        // ③ 反转 [i+1, n-1]（i == -1 时反转整个数组 → 最小排列）
        reverse(nums.begin() + i + 1, nums.end());
    }
};
```

**注意 `i == -1` 的情况被优雅地统一了**：`reverse(nums.begin() + 0, nums.end())` 正好把整个降序数组反转成升序（最小排列）。**不需要额外的 if 分支**——这是本代码最漂亮的一点。

**用标准库（面试可提但不能只写这个）**

```cpp
void nextPermutation(vector<int>& nums) {
    next_permutation(nums.begin(), nums.end());     // 就是上面三步的实现
}
```

**复杂度**  时间 O(n)（三步各最多扫一遍），空间 O(1)。

**边界与坑**
- **第一步的条件是 `nums[i] >= nums[i+1]`（带等号）**。用 `>` 会在有重复元素时出错：`[1,1,5]` 时若不带等号会停在 `i=0`（`nums[0] == nums[1]` 不满足 `>`，循环继续才对）。**带等号意味着"跳过非严格降序"，是正确的。**
- **第二步的条件是 `nums[j] <= nums[i]`（带等号）**。要找**严格大于** `nums[i]` 的元素，所以跳过所有 `<=` 的。用 `<` 会错误地选中等于 `nums[i]` 的元素，交换后排列不变（或变小）。**这两处等号都不能少。**
- **第二步不需要判 `j >= 0`**。因为 `i` 是升点，`nums[i] < nums[i+1]`，所以在 `[i+1, n-1]` 中**必然存在**大于 `nums[i]` 的元素（至少 `nums[i+1]`），循环必然在 `j > i` 处停止。**这个保证很重要**，理解了就不会画蛇添足加判断。
- **`i == -1` 时不能执行第二步**（会访问 `nums[-1]`），所以 `if (i >= 0)` 不能漏。但第三步**要**执行（反转整个数组）。
- **第三步是 `reverse` 而不是 `sort`**。虽然结果相同，但 `reverse` 是 O(n) 而 `sort` 是 O(n log n)。**用 sort 会被追问"为什么不用 reverse"** ——因为该段保证降序，反转即得升序。
- **`i` 初值是 `n - 2`** 不是 `n - 1`（因为要访问 `nums[i+1]`）。
- 单元素数组：`i = -1`，反转单元素无变化，正确。
- 全相同元素 `[2,2,2]`：`i = -1`（无升点），反转后不变，正确（已是唯一排列）。

**追问 / 变体**
- **上一个排列**（前驱）：三步对称地反过来——找第一个"降点"（`nums[i] > nums[i+1]`），在右段找第一个**小于** `nums[i]` 的（从右往左找第一个 `< nums[i]`），交换后反转。**能自己推出来说明真懂了。**
- **46 全排列**：枚举所有排列，用回溯，见 [10-回溯](10-回溯.md)。**也可以用本题反复调用 n! 次**（需先排序成最小排列），这是生成全排列的另一条路，且不需要递归。
- **60 排列序列**（求第 k 个排列）：用**康托展开**直接构造，O(n²)，不能调用本题 k 次（k 可达 n!）。
- **556 下一个更大元素 III**（对整数的数位做本题操作）：把数字转成字符数组套本题，注意结果可能溢出 `int`。
- **判断两个数组是否互为排列**：排序或计数，与本题无关。
- **为什么这就是 `std::next_permutation`**：C++ 标准库的实现完全是这三步。**知道这一点能在面试中快速说清思路来源。**
- **`next_permutation` 的返回值**：若生成了下一个排列返回 `true`，若已是最大排列（重排为最小）返回 `false`。**可以用它写循环枚举所有排列。**

### 287. 寻找重复数（中等）

**题意**  数组 `nums` 有 `n + 1` 个整数，每个都在 `[1, n]` 范围内。已知**恰好有一个数字重复**（可能重复多次），找出它。要求：**不修改数组**、**只用 O(1) 额外空间**、时间复杂度低于 O(n²)。

**暴力**  双层循环两两比较，O(n²)。或者排序后找相邻相同的，O(n log n) 但**修改了数组**。或者用 `unordered_set`，O(n) 但 **O(n) 空间**。**三个约束（不改数组 + O(1) 空间 + 优于 O(n²)）同时满足才是本题真正的考点。**

**关键洞察**

**核心转换：把数组看成一个链表。**

因为值域是 `[1, n]` 而下标范围是 `[0, n]`，所以 `nums[i]` 总是一个**合法的下标**。定义映射：

```
i  →  nums[i]
```

从下标 0 出发不断跳转：`0 → nums[0] → nums[nums[0]] → ...`。**这构成一条链表**，其中「节点 `i` 的 next 指针」就是 `nums[i]`。

**关键论证：这条链表一定有环，且环的入口就是重复的数字。**

- **一定有环**：因为节点数有限（n+1 个），无限跳转必然重复访问某节点（鸽巢原理）。
- **从 0 出发不会立刻进环**：因为值域是 `[1, n]`，**没有任何 `nums[i]` 等于 0**，所以节点 0 **没有入边**，不可能是环的一部分 → 0 必然在"环外的尾巴"上。
- **环的入口是重复值**：环入口是**第一个有两条入边的节点**（两条不同的路径汇入它）。而"有两条入边"意味着存在 `i != j` 使 `nums[i] == nums[j] == 入口值` → **入口值就是重复的数字**。✓

于是问题变成了 **[142 环形链表 II](07-链表.md)——求环的入口**，用 **Floyd 判圈算法（快慢指针）**：

**阶段一**：快指针每次走 2 步、慢指针走 1 步，直到相遇（相遇点在环内某处，**不是入口**）。

**阶段二**：把其中一个指针**重置到起点**，两个指针都改成**每次走 1 步**，再次相遇的位置就是**环的入口**。

**为什么阶段二成立**（数学推导，面试值得说）：设起点到环入口距离 `a`，环入口到相遇点距离 `b`，环长 `L`。相遇时慢指针走了 `a + b`，快指针走了 `2(a + b)`，且快指针比慢指针多走了整数圈：`2(a+b) - (a+b) = a + b = kL`。所以 `a = kL - b`——**从起点走 `a` 步和从相遇点走 `a` 步（即 `kL - b`，绕 k 圈回到入口）会同时到达入口。** ✓

**最优解（C++，Floyd 判圈）**

```cpp
class Solution {
public:
    int findDuplicate(vector<int>& nums) {
        // 阶段一：快慢指针相遇（相遇点在环内）
        int slow = nums[0], fast = nums[nums[0]];
        while (slow != fast) {
            slow = nums[slow];              // 走 1 步
            fast = nums[nums[fast]];        // 走 2 步
        }
        // 阶段二：一个指针回到起点，同速前进，再次相遇即环入口
        slow = 0;                            // 回到起点（下标 0）
        while (slow != fast) {
            slow = nums[slow];
            fast = nums[fast];               // 都走 1 步
        }
        return slow;                         // 环入口 = 重复的数字
    }
};
```

**二分答案解法（更好想，O(n log n)，也满足所有约束）**

```cpp
int findDuplicate(vector<int>& nums) {
    int lo = 1, hi = nums.size() - 1;        // 答案在 [1, n] 范围
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        int cnt = 0;
        for (int x : nums) if (x <= mid) ++cnt;   // 统计 <= mid 的元素个数
        if (cnt > mid) hi = mid;             // 说明重复值在 [lo, mid]
        else lo = mid + 1;                    // 重复值在 [mid+1, hi]
    }
    return lo;
}
```

**二分的依据（鸽巢原理）**：若没有重复，`<= mid` 的元素恰好有 `mid` 个。**如果实际个数 `> mid`，说明重复值落在 `[1, mid]` 内。** 这个判定关于 `mid` 是单调的，所以可以二分。**这是"[二分答案](11-二分查找.md)"框架的漂亮应用**——二分的是**答案的值域**而不是数组下标。

**位运算解法（O(32n)，思路同 169 的按位统计）**

对每个二进制位，比较「数组中该位为 1 的元素个数」与「`1..n` 中该位为 1 的个数」。前者更多说明重复值在该位上是 1。

**面试策略**：**先给二分答案**（好想、好解释、复杂度达标），再说"还有 O(n) 的 Floyd 判圈解法，把数组看成链表"。**两个都会最理想；只会一个的话，二分更容易在压力下写对。**

**复杂度**  Floyd：时间 **O(n)**，空间 O(1)，**不修改数组** —— 三个约束全满足，是最优解。二分：时间 O(n log n)，空间 O(1)。

**边界与坑**
- **阶段一的初始化必须让快慢指针"错开一步"**。写成 `slow = fast = nums[0]` 会让 `while (slow != fast)` 立刻不成立、循环不执行。上面用 `slow = nums[0]`、`fast = nums[nums[0]]` 是标准写法。**另一种等价写法是用 do-while**：
  ```cpp
  int slow = 0, fast = 0;
  do { slow = nums[slow]; fast = nums[nums[fast]]; } while (slow != fast);
  ```
  **这个 do-while 版本更不容易错，推荐。**
- **阶段二必须把 `slow` 重置为 0（起点）**，不是 `nums[0]`。起点是**下标 0**这个节点。
- **阶段二两个指针都走 1 步**，不能还是 2 步。
- **本题严格依赖"值域 `[1, n]`、长度 `n+1`"**。若值域包含 0，节点 0 可能有入边，就不能保证 0 在环外，**Floyd 解法失效**。**这是最重要的前提条件，面试必须说清。**
- **不能修改数组**（题目要求），所以**不能用"原地置换/打标记"的做法**（如把访问过的数取负，或交换到对应位置）。那些解法虽然 O(n) O(1)，但违反约束。**面试提出来时要主动说明"这个解法修改了输入，不满足题目要求"。**
- **二分的是值域 `[1, n]` 而不是下标**。`hi` 初值是 `nums.size() - 1`（即 n），不是 `nums.size()`。
- **二分的判定条件是 `cnt > mid`**（严格大于）。用 `>=` 会错。
- 数组至少有 2 个元素（n ≥ 1），题目保证。
- **"恰好一个数字重复但可能重复多次"**：Floyd 和二分都能正确处理（环入口唯一；鸽巢判定不受重复次数影响）。

**追问 / 变体**
- **142 环形链表 II**：本题的原型，见 [07-链表](07-链表.md)。**287 → 142 的转换是本题的全部精髓**，两题必须一起理解。
- **41 缺失的第一个正数**：同样利用"值域与下标的对应关系"，但用**原地置换**（允许修改数组），见 [05-普通数组](05-普通数组.md)。**41 和 287 是"值域-下标对应"技巧的两面**：一个允许改数组用置换，一个不允许改数组用找环。
- **允许修改数组**：可以用"把 `nums[i]` 交换到下标 `i` 的位置，冲突即重复"的 O(n) 做法，代码短得多。
- **有多个重复数字**：Floyd 失效（可能有多个环或环入口不唯一），需要哈希或排序。
- **求所有重复数字**（442 数组中重复的数据）：用原地打负号标记，O(n) O(1)（但修改数组）。
- **136/137/260**（异或找单个数）：同属"位运算/数学技巧"家族，见 [136](#136-只出现一次的数字简单)。
- **为什么叫 Floyd 判圈 / 龟兔赛跑算法**：Robert Floyd 提出，用快慢两个指针（兔子和乌龟）检测环。**这个算法在密码学（求哈希碰撞）和随机数周期检测中也有实际应用。**
