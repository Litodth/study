# 04 · 子串（3 题）

## 套路总纲

官方把这三题单列为「子串」，因为它们各自代表一种**滑动窗口失效或需要升级**的情形：

| 题 | 为什么不能用普通滑窗 | 正确武器 |
|---|---|---|
| 560 和为 K 的子数组 | 数组含**负数** → 窗口和不单调，`left` 需要回退 | **前缀和 + 哈希表** |
| 239 滑动窗口最大值 | 窗口是定长的，但「最大值」在元素出窗时无法 O(1) 恢复 | **单调队列（双端队列）** |
| 76 最小覆盖子串 | 能用滑窗，但条件判定复杂、求的是**最短** | **变长窗口 + 计数 + valid 计数器** |

**必须记住的判据**：
- **「连续子数组和 == K」且有负数 → 前缀和 + 哈希**。`sum[j] - sum[i] == K` 变形为 `sum[i] == sum[j] - K`，于是「找一个历史前缀和」= 哈希查找。这是 Hot 100 里最重要的转化之一。
- **「窗口内的最值」→ 单调队列**。堆也能做（O(n log n)），但单调队列 O(n) 且是标准答案。
- **「最短的满足条件的窗口」→ 在窗口合法时收缩并记录答案**（与求最长相反：求最长在窗口合法时更新、非法时收缩）。

---

### 560. 和为 K 的子数组（中等）

**题意**  求数组中和为 `k` 的**连续**子数组的个数。元素可以是负数。

**暴力**  枚举左右端点 O(n²)，配前缀和可做到 O(n²) 时间 O(n) 空间。n ≤ 2×10⁴ 时 4×10⁸，勉强超时/极限。

**为什么不能滑动窗口**：滑窗成立要求「和随窗口扩大单调不减」。有负数时，窗口和忽大忽小，`left` 收缩后可能还需要退回来——单调性被破坏。这一点是本题的第一个考点，面试务必主动说明。

**关键洞察**

用前缀和 `pre[i] = nums[0] + ... + nums[i-1]`（`pre[0] = 0`）。子数组 `[i, j]` 的和为 `pre[j+1] - pre[i]`。

要求 `pre[j+1] - pre[i] == k`，固定右端 `j`，变形为：

```
pre[i] == pre[j+1] - k
```

于是问题变成：**遍历到每个右端点时，问「之前出现过多少次值为 `pre - k` 的前缀和」**。这正是哈希表的活——和 [01-哈希](01-哈希.md) 的两数之和是同一个套路（固定一端，把另一端的需求变成一次查找），只是这里存的是**出现次数**而不是下标，因为要计数而非返回一组解。

`mp[0] = 1` 这个初始化是精髓：它代表「空前缀」，使得从下标 0 开始的子数组也能被统计到（当 `pre == k` 时，`pre - k == 0` 需要能查到一次）。

**最优解（C++）**

```cpp
class Solution {
public:
    int subarraySum(vector<int>& nums, int k) {
        unordered_map<long long, int> cnt;   // 前缀和 -> 出现次数
        cnt[0] = 1;                          // 空前缀：让 pre == k 的情形能被统计
        long long pre = 0;
        int ans = 0;
        for (int x : nums) {
            pre += x;
            auto it = cnt.find(pre - k);
            if (it != cnt.end()) ans += it->second;   // 先查（只统计左端在当前之前的）
            ++cnt[pre];                               // 后插
        }
        return ans;
    }
};
```

**复杂度**  时间 O(n)，空间 O(n)。

**边界与坑**
- **`cnt[0] = 1` 不能漏**。漏掉的话 `nums = [1,2], k = 3` 会返回 0。
- **必须先查后插**。顺序反了，当 `k == 0` 时会把「当前前缀和自己」也算成一个解（长度为 0 的子数组），结果偏大。
- 前缀和用 `long long`：`n = 2×10⁴`，`|nums[i]| ≤ 1000`，和的范围 ±2×10⁷ 其实 `int` 够用；但 `pre - k` 里 `k` 可达 ±10⁷，仍安全。养成用 `long long` 的习惯，避免在约束更大的题上翻车。
- 答案计数本身可能很大（全 0 数组、`k=0` 时是 O(n²) 量级 = 2×10⁸），仍在 `int` 内，但要意识到这一点。
- 求「个数」用哈希计数；如果求「最长长度」（题 325）则要存**最早出现的下标**，且**只在第一次出现时插入**——两种需求下 map 的 value 含义完全不同，别混。

**追问 / 变体**
- **全为正数怎么办**：那时可以用滑动窗口 O(1) 空间（题 713 是乘积版）。面试问「有负数和无负数解法有何不同」是标准追问。
- **974 和可被 K 整除的子数组**：把 key 换成 `pre % k`（注意 C++ 负数取模要 `((pre % k) + k) % k`）。
- **523 连续子数组和**（长度至少 2 且和为 k 的倍数）：同余 + 存最早下标。
- **325 和等于 k 的最长子数组**：value 存最早下标，`ans = max(ans, i - mp[pre-k])`。
- **前缀和 + 哈希** 这个组合建议连着刷 560 → 974 → 523，一次性打通。

### 239. 滑动窗口最大值（困难）

**题意**  给定数组和窗口大小 `k`，返回每个大小为 `k` 的窗口中的最大值。

**暴力**  每个窗口扫一遍求最大值，O(n·k)。n ≤ 10⁵、k ≤ n，最坏 10¹⁰，超时。

为什么不够：相邻窗口重叠 `k-1` 个元素，最大值被反复重算。**但增量维护最大值有个难点**：新元素进来时 `max` 好更新，可**旧元素出去时，如果它正是当前最大值，就无法 O(1) 知道新的最大值是谁**——信息已经丢了。这是本题的核心困难。

**关键洞察**

既然出窗时可能丢失信息，那就**保留足够的"候选者"**，而不是只存一个最大值。

关键剪枝：若 `i < j` 且 `nums[i] <= nums[j]`，那么 `nums[i]` **永远不可能再成为答案**——因为任何包含 `i` 的窗口（在 `i` 还没出窗时）必然也包含 `j`（`j` 在 `i` 右边，且 `j` 更晚出窗），而 `nums[j]` 不小于它。所以 `nums[i]` 可以永久丢弃。

把这条规则贯彻到底，剩下的候选者从队首到队尾**严格递减**——这就是**单调队列**。于是：

- **队首**永远是当前窗口的最大值。
- 新元素 `nums[right]` 进队前，把队尾所有 `<= nums[right]` 的元素弹掉（它们已被上面的规则判死）。
- 队首元素下标 `< right - k + 1` 时出队（滑出窗口了）。

存**下标**而不是值，因为要判断是否滑出窗口。

每个元素最多入队一次、出队一次 → 总操作 O(n)，均摊 O(1)。

**最优解（C++）**

```cpp
class Solution {
public:
    vector<int> maxSlidingWindow(vector<int>& nums, int k) {
        deque<int> dq;                  // 存下标，对应值从队首到队尾单调递减
        vector<int> ans;
        ans.reserve(nums.size() - k + 1);
        for (int i = 0; i < nums.size(); ++i) {
            // 1. 队尾清理：比新元素小的都不可能再当最大值
            while (!dq.empty() && nums[dq.back()] <= nums[i]) dq.pop_back();
            dq.push_back(i);
            // 2. 队首清理：滑出窗口的下标
            if (dq.front() <= i - k) dq.pop_front();
            // 3. 窗口铺满后开始记录答案
            if (i >= k - 1) ans.push_back(nums[dq.front()]);
        }
        return ans;
    }
};
```

**对照解法（优先队列，O(n log n)，思路更朴素）**

```cpp
class Solution {
public:
    vector<int> maxSlidingWindow(vector<int>& nums, int k) {
        priority_queue<pair<int, int>> pq;      // (值, 下标)，默认大顶堆，按值排序
        vector<int> ans;
        for (int i = 0; i < nums.size(); ++i) {
            pq.emplace(nums[i], i);
            while (pq.top().second <= i - k) pq.pop();  // 惰性删除：堆顶过期才弹
            if (i >= k - 1) ans.push_back(pq.top().first);
        }
        return ans;
    }
};
```

**复杂度**  单调队列 O(n) 时间 / O(k) 空间；优先队列 O(n log n) / O(n)。

**边界与坑**
- **队尾清理用 `<=` 还是 `<`？** 用 `<=` 更好：等值时保留更靠右的（更晚出窗），队列更短。用 `<` 也能得到正确答案（等值元素都留着，队首出窗后下一个等值的顶上来），但队列更长。
- **存下标不存值**：存值就无法判断是否滑出窗口。这是最常见的思路错误。
- 队首清理的条件是 `dq.front() <= i - k`（窗口是 `[i-k+1, i]`）。写成 `< i - k` 会让一个过期元素多留一轮。
- 队首清理要放在**入队之后**——先入队再清首，或者先清首再入队都对，但清首必须在"取答案"之前。上面代码的顺序（入队 → 清首 → 取答案）最稳。
- `k == 1` 时答案就是原数组，代码天然正确。`k == n` 时只有一个答案。
- `deque` 而非 `queue`：需要两头操作。`vector` 模拟也行（手写头尾指针），常数更小，竞赛常用。

**追问 / 变体**
- **求窗口最小值**：把 `<=` 改成 `>=`，队列变递增。
- **239 的 O(n) 分块解法**：把数组按 k 分块预处理前后缀最大值，也是 O(n)，思路巧妙，是另一种标准答案。
- **单调队列优化 DP**：如 1425 带限制的子序列和、跳跃游戏 VI，都是「`dp[i] = max(dp[j]) + ...` 且 j 在滑动区间内」→ 单调队列把 O(nk) 降到 O(n)。这是单调队列真正的高频应用场景。
- **和 84/42 的单调栈的区别**：栈只在一端进出（处理"下一个更大元素"），队列两端都要动（处理"滑动区间最值"）。

### 76. 最小覆盖子串（困难）

**题意**  在 `s` 中找出**最短**的子串，使其包含 `t` 中所有字符（**含重复次数**，如 `t = "AABC"` 要求子串里至少两个 A）。不存在则返回 `""`。

**暴力**  枚举所有子串（O(n²) 个），每个 O(m + 26) 判断是否覆盖 → O(n²)。n ≤ 10⁵ 时必然超时。

**关键洞察**

这是滑动窗口的**完整形态**，比 [03-滑动窗口](03-滑动窗口.md) 的两题都难，难点有两个：

**难点一：求最短，窗口的动法反过来了。**

- 求**最长**（题 3）：窗口非法时收缩，在**合法状态**下更新答案。
- 求**最短**（本题）：窗口**先扩到合法**，然后**尽可能收缩**，收缩过程中每次仍合法就更新答案。

所以模板是：`right` 扩展 → `while (窗口已覆盖) { 更新答案; 收缩 left; }`。

**难点二：怎么 O(1) 判断"已覆盖"？**

不能每次比 26 个（或 128 个）计数——那是 O(n·|Σ|)，虽然能过但不优雅。引入 `valid` 计数器：

- `need[c]`：`t` 中字符 `c` 的需求数量。
- `win[c]`：窗口中 `c` 的数量。
- **`valid` = 已经"满足需求"的字符种类数**，即满足 `win[c] >= need[c]` 的 `c` 的个数。

更新规则（这里最容易写错）：加入 `c` 后，**只有当 `win[c]` 恰好达到 `need[c]` 时** `++valid`（用 `==` 不是 `>=`，否则超量时会重复累加）。移出时对称：**移出前** `win[c] == need[c]` 则 `--valid`。

`valid == need.size()` 即窗口已覆盖 `t`。

**最优解（C++）**

```cpp
class Solution {
public:
    string minWindow(string s, string t) {
        if (s.size() < t.size() || t.empty()) return "";
        unordered_map<char, int> need, win;
        for (char c : t) ++need[c];

        int left = 0, valid = 0;              // valid: 已满足需求的字符"种类"数
        int bestLen = INT_MAX, bestL = 0;

        for (int right = 0; right < s.size(); ++right) {
            char c = s[right];
            if (need.count(c)) {              // 只关心 t 里出现的字符
                ++win[c];
                if (win[c] == need[c]) ++valid;   // 恰好满足才计数，用 == 不是 >=
            }
            while (valid == (int)need.size()) {    // 窗口已覆盖 t：尝试变短
                if (right - left + 1 < bestLen) {  // 先记录答案
                    bestLen = right - left + 1;
                    bestL = left;
                }
                char d = s[left++];                // 再收缩
                if (need.count(d)) {
                    if (win[d] == need[d]) --valid;  // 移出前正好卡在需求线上 -> 破坏覆盖
                    --win[d];
                }
            }
        }
        return bestLen == INT_MAX ? "" : s.substr(bestL, bestLen);
    }
};
```

**复杂度**  时间 O(n + m)（每个字符最多进出窗口一次），空间 O(|Σ|)。

**边界与坑**
- **`win[c] == need[c]` 必须用 `==`**。用 `>=` 的话，窗口里有 3 个 A 而只需 2 个时，`valid` 会被加 3 次，永远达不到正确的判定。这是本题头号 bug。
- **移出时先判断再减**：`if (win[d] == need[d]) --valid; --win[d];` 顺序不能反。反了就变成「减到不足才发现」，`valid` 会错。
- **只处理 `t` 中出现的字符**（`if (need.count(c))`）。不判断的话 `win` 会塞进无关字符，虽然 `valid` 逻辑仍对，但 `need.size()` 的比较对象不受影响、其实也能过——不过显式判断更清晰且更快。注意**不能**用 `win.size() == need.size()` 当判定条件。
- **答案要在收缩循环内、收缩之前记录**。放在循环外就漏掉了最短的那个窗口。
- `bestLen` 用 `INT_MAX` 初始化，最后判断是否被更新过来决定返回 `""`。别用 `s.size()` 初始化——整个 `s` 本身可能就是答案。
- `need.size()` 要强转 `int` 再和 `valid` 比，否则 `size_t` 与 `int` 比较会有符号警告（本题不会出错，但是好习惯）。
- 大小写敏感：`t = "ABC"` 里的 `A` 和 `a` 不同，所以字符集是 52+ 而非 26，用 `unordered_map` 或 `int[128]` 都可以。

**追问 / 变体**
- **438 找异位词**：本题的"定长且恰好相等"版，简单得多。两题对照看能看清「恰好 vs 至少」「定长 vs 变长」两个维度。
- **567 字符串的排列**：同 438。
- **632 最小区间**（从 k 个有序列表各取一个数使区间最小）：同样是"最小覆盖"思想，但用堆实现。
- **用 `int cnt[128]` 代替两个 map**：合并成一个差值数组，代码更短更快（和 438 的写法一致），但可读性略降。面试建议先写清晰版。
