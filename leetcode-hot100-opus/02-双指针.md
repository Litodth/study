# 02 · 双指针（4 题）

## 套路总纲

**识别信号**：数组/字符串上「原地移动元素」「找一对满足条件的元素」「区间的两端」「O(1) 额外空间」。

**两大类**：

| 类型 | 指针走向 | 适用前提 | 本专题 |
|---|---|---|---|
| **快慢指针**（同向） | 都从左往右，快指针探路、慢指针记录写入位置 | 需要原地重排/去重 | 283 |
| **对撞指针**（相向） | 一左一右向中间收缩 | 有序，或有「移动哪边不会丢最优解」的单调性 | 11、15、42 |

**对撞指针的正确性论证**（面试必答）：每次收缩都要能证明「被丢掉的那些组合里不可能有更优解」。这是双指针题的灵魂——不是"两个指针动一动"，而是**每一步排除一整批候选**。

- 11：移动较矮的一侧，因为固定较矮边时，宽度只会减小、高度不会超过它 → 那一侧的所有其他组合都不可能更优。
- 15：排序后，`sum` 太小只能移左指针增大，太大只能移右指针减小 → 方向唯一。
- 42：`height[l] < height[r]` 时左边的答案已被 `height[l]` 完全决定，与右边具体多高无关。

**递进关系**：283 练手感；11 第一次遇到"排除一整批"的论证；15 是「排序 + 固定一维 + 双指针」的经典组合，去重是难点；42 是同一思想的最高形态（也可用单调栈，见 [12-栈](12-栈.md)）。

### 283. 移动零（简单）

**题意**  原地把所有 0 移到数组末尾，保持非零元素的相对顺序。

**暴力**  开一个新数组，先放非零再补零，然后拷回。O(n) 时间但 O(n) 空间，且题目要求原地。

另一种"原地"暴力：遇到 0 就把后面元素整体前移一位，O(n²)。

**关键洞察**

把问题反过来看：**不是"把 0 往后搬"，而是"把非零往前收"**。

维护一个慢指针 `slow`，含义是「下一个非零元素应该写入的位置」，同时也意味着 `[0, slow)` 已经是收集好的非零前缀。快指针 `fast` 扫一遍，遇到非零就写到 `slow` 并 `++slow`。扫完后 `[slow, n)` 全部置 0。

再优化一步：用 `swap` 代替「写入 + 末尾补零」，一趟完成。因为 `slow` 指向的一定是 0（或就是 `fast` 自己），交换后 0 自动被换到后面去了。

**最优解（C++）**

```cpp
class Solution {
public:
    void moveZeroes(vector<int>& nums) {
        int slow = 0;                              // 下一个非零元素的写入位置
        for (int fast = 0; fast < nums.size(); ++fast) {
            if (nums[fast] != 0) {
                swap(nums[slow], nums[fast]);      // slow==fast 时是自交换，无害
                ++slow;
            }
        }
    }
};
```

**复杂度**  时间 O(n)，空间 O(1)。交换次数等于非零元素个数。

**边界与坑**
- 全 0 或全非零都正确：全 0 时 `slow` 一直是 0，不发生交换；全非零时始终 `slow == fast`，自交换。
- **顺序必须保持**，所以不能用「左右对撞 + 交换」那种写法（那会打乱相对顺序）。
- 如果换成「写入 + 补零」两段式写法，第二段循环边界是 `for (int i = slow; i < n; ++i) nums[i] = 0;`，别写成 `i <= slow`。

**追问 / 变体**
- **26 删除有序数组中的重复项** / **27 移除元素** / **80 重复项最多保留两个**：同一个快慢指针骨架，只是「该写入」的判定条件不同。这四题一起看能彻底吃透快慢指针。
- **要求最小化写操作次数**：改用「只在必要时写」的版本（`if (slow != fast) nums[slow] = nums[fast]`），适合写入昂贵的场景（如 SSD）。
- **把 0 移到开头**：从右往左跑同样的逻辑。

### 11. 盛最多水的容器（中等）

**题意**  `height[i]` 是第 `i` 条竖线的高度，选两条线与 x 轴构成容器，求最大蓄水量。面积 = `(j - i) * min(height[i], height[j])`。

**暴力**  枚举所有 `(i, j)`，O(n²)。n ≤ 10⁵ 时必然超时（10¹⁰ 次运算）。

**关键洞察**

面积由两个因子决定：**宽度**和**较矮的那条边**。从最宽的状态（`l = 0, r = n-1`）出发，宽度只可能减小——所以要想面积变大，唯一希望是较矮边变高。

现在做排除论证：设 `height[l] < height[r]`，考虑所有以 `l` 为左边界的组合 `(l, k)`（`k < r`）。它们的宽度 `k - l < r - l`，高度 `min(height[l], height[k]) <= height[l]`。所以**没有一个能超过当前的 `(l, r)`**。既然 `l` 的最优搭档就是当前的 `r`，`l` 这条线可以彻底丢弃 → `++l`。

对称地，`height[r] <= height[l]` 时 `--r`。每步排除一整条线，n 步内结束。

**最优解（C++）**

```cpp
class Solution {
public:
    int maxArea(vector<int>& height) {
        int l = 0, r = height.size() - 1, best = 0;
        while (l < r) {
            int h = min(height[l], height[r]);
            best = max(best, (r - l) * h);         // 先结算当前组合
            if (height[l] < height[r]) ++l;        // 矮的一侧再无更优搭档，丢弃
            else --r;                              // 相等时丢哪边都行
        }
        return best;
    }
};
```

**复杂度**  时间 O(n)，空间 O(1)。

**边界与坑**
- **必须移动较矮的一侧**。移高的那侧会漏掉最优解——比如 `[1,8,6,2,5,4,8,3,7]`，一开始 `height[0]=1` 是矮边，如果去动右边就把真正的答案错过了。
- 两边相等时移动任意一边都对（可以证明另一边的对称组合不会更优），写 `<` 还是 `<=` 都能过。
- `(r - l) * h` 在 n 和高度都取极大值时是 `10^5 * 10^4 = 10^9`，**贴着 `int` 上限**（2.1×10⁹）但没溢出。若把约束放大就要 `long long`——面试提一句会加分。
- 循环条件是 `l < r` 不是 `l <= r`：`l == r` 时宽度为 0，无意义。

**追问 / 变体**
- **42 接雨水**：看似相似，实则不同——本题只用两条边，42 要累加每个位置的存水量。但两者都靠「较矮一侧决定结果」这个洞察，见下文。
- **证明为什么贪心不漏解**：面试高频追问，答案就是上面的「排除论证」，务必能口述。
- **三维版 / 容器加厚**：一般转为其他建模，不属于双指针。

### 15. 三数之和（中等）

**题意**  找出所有**不重复**的三元组 `[nums[i], nums[j], nums[k]]`，满足三者之和为 0，下标互不相同。

**暴力**  三层循环 O(n³)，再用 `set` 去重。n ≤ 3000 时 2.7×10¹⁰ 次运算，超时。

**关键洞察**

两步降维：

1. **排序**。排序带来两个好处：能用双指针（有序才有单调性），并且让重复元素相邻（去重变得可控）。代价只有 O(n log n)，被后面的 O(n²) 吸收。
2. **固定第一个数**，剩下的就是「在有序子数组里找两数之和为 `-nums[i]`」——这正是**两数之和 II（167）**，用对撞指针 O(n) 解决。

于是 O(n³) → O(n²)。

**去重是本题真正的难点**，分三处，每处的理由不同：

- **第一层**：`i > 0 && nums[i] == nums[i-1]` → `continue`。同样的首元素，第二次枚举产生的三元组是第一次的子集。
- **左指针**：找到答案后 `while (l < r && nums[l] == nums[l+1]) ++l`，跳过重复的第二元素。
- **右指针**：同理跳过重复的第三元素。

这样就不需要 `set` 去重（那会额外 O(log n) 且要排序三元组）。

另有一个提前退出：排序后 `nums[i] > 0` 时，三个非负数之和不可能为 0（除非全 0，但那时 `nums[i] == 0`），直接 `break`。

**最优解（C++）**

```cpp
class Solution {
public:
    vector<vector<int>> threeSum(vector<int>& nums) {
        sort(nums.begin(), nums.end());
        int n = nums.size();
        vector<vector<int>> ans;
        for (int i = 0; i + 2 < n; ++i) {
            if (nums[i] > 0) break;                        // 最小的已 > 0，之后不可能凑出 0
            if (i > 0 && nums[i] == nums[i - 1]) continue;  // 去重①：首元素不重复枚举
            int l = i + 1, r = n - 1;
            while (l < r) {
                int sum = nums[i] + nums[l] + nums[r];
                if (sum < 0) ++l;                           // 太小：只能让左边变大
                else if (sum > 0) --r;                      // 太大：只能让右边变小
                else {
                    ans.push_back({nums[i], nums[l], nums[r]});
                    while (l < r && nums[l] == nums[l + 1]) ++l;   // 去重②
                    while (l < r && nums[r] == nums[r - 1]) --r;   // 去重③
                    ++l; --r;                               // 收进下一对候选
                }
            }
        }
        return ans;
    }
};
```

**复杂度**  时间 O(n²)（排序 O(n log n) 被吸收），空间 O(log n)（排序递归栈，不计输出）。

**边界与坑**
- **找到答案后忘记 `++l; --r;`** → 死循环。去重的 `while` 只是把指针挪到"最后一个重复元素"上，还需要再走一步才能进入新候选。这是本题最常见的 bug。
- 去重 `while` 里必须带 `l < r` 条件，否则 `nums[l+1]` / `nums[r-1]` 越界。
- 第一层去重用 `nums[i] == nums[i-1]`（向前看）而不是 `nums[i] == nums[i+1]`（向后看）。向后看会跳过 `[0,0,0]` 这种合法答案。
- `sum` 三个 `int` 相加，极端值下可能溢出。本题约束 `|nums[i]| <= 10^5`，三数和最大 3×10⁵，安全。若约束改为 `10^9` 就必须 `long long`。
- `i + 2 < n` 保证至少有三个元素，也顺手处理了 `n < 3` 的情况。

**追问 / 变体**
- **18 四数之和**：再套一层循环 O(n³)，去重逻辑同理（第一、二层都要去重）。
- **16 最接近的三数之和**：不再要求恰好为 0，改为记录 `|sum - target|` 的最小值，指针移动规则不变。
- **不排序能做吗？** 可以用哈希，但去重会非常痛苦，且复杂度不优。这题就该排序。
- **允许下标重复使用**：变成完全不同的问题（组合总和类），见 [10-回溯](10-回溯.md) 的 39 题。

### 42. 接雨水（困难）

**题意**  `height` 表示每根柱子的高度（宽度均为 1），求下雨后能接住多少水。

**暴力**  位置 `i` 能存的水是 `min(左边最大值, 右边最大值) - height[i]`（负数记 0）。对每个 `i` 各扫一遍左右求最大值，O(n²) / O(1)。

为什么不够：**前缀最大值和后缀最大值被反复重算**。

**关键洞察**

先明确核心公式（这一步想不通，后面全白费）：

```
water[i] = max(0, min(leftMax[i], rightMax[i]) - height[i])
```

即某一列的水位由「它左边最高的柱子」和「右边最高的柱子」中**较矮的那个**决定——木桶效应。

从这里出发有两条优化路径：

**路径一（前缀数组，容易想）**：既然瓶颈是重算，那就预处理。`leftMax` 从左往右扫一遍，`rightMax` 从右往左扫一遍，然后 O(n) 累加。时间 O(n)，空间 O(n)。**面试先给这个**，它正确、好写、好解释。

**路径二（双指针，空间 O(1)）**：这才是本题的精华。注意公式里取的是 `min(leftMax, rightMax)`——**如果我已经知道哪一侧更矮，另一侧具体多高就不重要了**。

维护 `l, r` 和 `lmax = max(height[0..l])`、`rmax = max(height[r..n-1])`。若 `lmax < rmax`，那么位置 `l` 的真实 `rightMax` 一定 `>= rmax > lmax`，所以 `min(...)` 必然取 `lmax`——**当前的 `lmax` 就是位置 `l` 的最终水位**，可以直接结算并 `++l`。对称处理另一侧。

这个"提前确定"的推理和 11 题同源：都是靠「答案只由较矮一侧决定」把 O(n) 空间省掉。

**最优解（C++，双指针 O(1) 空间）**

```cpp
class Solution {
public:
    int trap(vector<int>& height) {
        int l = 0, r = height.size() - 1;
        int lmax = 0, rmax = 0, water = 0;
        while (l < r) {
            lmax = max(lmax, height[l]);
            rmax = max(rmax, height[r]);
            // 较矮的一侧水位已确定，先更新 max 再结算，保证差值非负
            if (lmax < rmax) water += lmax - height[l++];
            else             water += rmax - height[r--];
        }
        return water;
    }
};
```

**对照解法（前缀数组，更直观）**

```cpp
class Solution {
public:
    int trap(vector<int>& height) {
        int n = height.size();
        if (n < 3) return 0;
        vector<int> lmax(n), rmax(n);
        lmax[0] = height[0];
        for (int i = 1; i < n; ++i) lmax[i] = max(lmax[i - 1], height[i]);
        rmax[n - 1] = height[n - 1];
        for (int i = n - 2; i >= 0; --i) rmax[i] = max(rmax[i + 1], height[i]);
        int water = 0;
        for (int i = 0; i < n; ++i) water += min(lmax[i], rmax[i]) - height[i];
        return water;
    }
};
```

**复杂度**  双指针 O(n) / O(1)；前缀数组 O(n) / O(n)。

**边界与坑**
- **必须先更新 `lmax`/`rmax`，再算差值**。顺序反了会出现 `lmax < height[l]` 从而累加负数。这是双指针版最容易写错的地方。
- `n < 3` 时答案为 0。双指针版天然处理（循环不进入或不产生正贡献），前缀数组版建议显式判断。
- 循环条件 `l < r`。写成 `l <= r` 会把中间那一列重复结算一次（左右各算一遍）。
- 答案上界 `10^5 * 10^4 / 4`，`int` 够用。

**追问 / 变体**
- **单调栈解法**：维护高度递减的栈，遇到更高的柱子就"结算"被夹住的凹槽（横向按层算水）。O(n)/O(n)，和 84 题共用同一个骨架，见 [12-栈](12-栈.md)。三种解法都能讲是这题的加分项。
- **407 接雨水 II（二维）**：不能双指针了，改用**优先队列从边界向内 BFS**（木桶的短板是当前边界最小高度）。困难题，属于 42 的自然升级。
- **11 盛最多水的容器**：区别是那题只用两块板、中间不计，本题每一列都要算。
