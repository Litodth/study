# 15 · 动态规划（10 题）

## 套路总纲

DP 是刷题的分水岭。它不靠灵感，靠**流程**。每道题严格按下面四步走，写出来的概率远高于"盯着题想"。

**四步流程（务必按顺序）**

1. **状态定义**：`dp[i]` 表示**什么**？——**这是唯一真正需要思考的一步**，定义错了后面全废。
   写状态时用一句完整的话，且必须包含"以 i 结尾/前 i 个"这类**明确的边界语义**。
2. **状态转移**：`dp[i]` 怎么由更小的状态算出来？——把"最后一步怎么做的"枚举清楚。
3. **初始化**：最小的那些状态是多少？——**边界最容易错**，建议手算 n=0,1,2 验证。
4. **遍历顺序**：保证算 `dp[i]` 时它依赖的状态**都已算好**。

**两个最有用的思考角度**

- **「最后一步」分析法**：要求 `dp[i]`，问「到达状态 i 的最后一步有哪几种可能？」把它们全枚举出来取 max/min/sum，转移方程就出来了。70/198/322/279 都是这么推的。
- **「以 i 结尾」的状态定义**：当题目问「子数组/子串/子序列的最优值」时，把状态定义成**"以 i 结尾"**几乎总是对的（152、300、53）。这样"最后一步"就是明确的，而答案是 `max(dp[0..n-1])`。**如果定义成"前 i 个里的最优值"，转移往往说不清。**

**本专题的五个模型**

| 模型 | 状态 | 题 |
|---|---|---|
| **线性递推** | `dp[i]` 由 `dp[i-1]`、`dp[i-2]` 递推 | 70、198、32 |
| **完全背包**（可重复取） | `dp[j]` = 凑出 j 的最优/方案数 | 322、279、139 |
| **01 背包**（每个取一次） | `dp[j]`，**j 必须倒序** | 416 |
| **以 i 结尾的最优子结构** | `dp[i]` = 以 i 结尾的最优值 | 152、300、53 |
| **构造型** | 直接按定义生成 | 118 |

**背包问题的循环顺序（本专题最重要的机械规则，务必背下来）**

```cpp
// 完全背包（每个物品可用无限次）：容量正序
for (int i = 0; i < n; ++i)              // 物品
    for (int j = w[i]; j <= W; ++j)      // 容量【正序】
        dp[j] = max(dp[j], dp[j - w[i]] + v[i]);

// 01 背包（每个物品只能用一次）：容量倒序
for (int i = 0; i < n; ++i)
    for (int j = W; j >= w[i]; --j)      // 容量【倒序】
        dp[j] = max(dp[j], dp[j - w[i]] + v[i]);
```

**为什么 01 背包要倒序**：滚动数组里 `dp[j - w[i]]` 如果已被本轮更新过，就等于"物品 i 用了第二次"。倒序时 `dp[j - w[i]]` 还是上一轮（不含物品 i）的值，保证只用一次。**正序 = 完全背包，倒序 = 01 背包**，这一条记死就不会错。

**求"方案数"vs"最优值"的转移区别**
- **最优值**：`dp[j] = min/max(dp[j], dp[j-w] + 1)`
- **方案数**：`dp[j] += dp[j-w]`
- **组合数（不计顺序）**：外层物品、内层容量
- **排列数（计顺序）**：**外层容量、内层物品**（377 题）

**难度递进**：70/118 是入门 → 198/322/279/139 是模板应用 → 152/300 需要巧妙的状态定义 → 416 是 01 背包转化 → **32 是本专题最难的，要么用栈要么用非平凡的 DP**。

### 70. 爬楼梯（简单）

**题意**  每次可以爬 1 或 2 个台阶，问爬到第 n 阶有多少种不同方法。

**暴力**  递归枚举每一步爬 1 还是 2：`f(n) = f(n-1) + f(n-2)`，不加记忆化是 **O(2ⁿ)**（递归树有大量重复子问题，`f(5)` 会重复算 `f(3)` 两次）。n = 45 时约 10¹³ 次调用，必然超时。

**关键洞察**

**用「最后一步」分析法**：要到第 n 阶，**最后一步**只有两种可能：

- 从第 `n-1` 阶爬 1 步上来 → 有 `dp[n-1]` 种走法到达 `n-1`
- 从第 `n-2` 阶爬 2 步上来 → 有 `dp[n-2]` 种走法到达 `n-2`

两种情况**互斥且穷尽**，所以 `dp[n] = dp[n-1] + dp[n-2]`。

**这就是斐波那契数列**，但**不要因为"认出是斐波那契"就跳过推导**——面试要展示的是「用最后一步分析法推出转移方程」这个能力，这个方法在 198、322 上同样适用。

**为什么互斥**：因为"最后一步爬了几阶"是确定的，一种走法不可能既最后爬 1 阶又最后爬 2 阶。**转移方程用加法的前提就是各分支互斥。**

**空间优化**：`dp[i]` 只依赖前两项，所以**不需要整个数组**，两个变量滚动即可 → O(1) 空间。**"只依赖固定几个前项 → 滚动变量"是 DP 空间优化的第一招。**

**最优解（C++，滚动变量 O(1) 空间）**

```cpp
class Solution {
public:
    int climbStairs(int n) {
        if (n <= 2) return n;                // n=1 → 1 种；n=2 → 2 种
        int prev = 1, cur = 2;               // dp[1], dp[2]
        for (int i = 3; i <= n; ++i) {
            int next = prev + cur;           // dp[i] = dp[i-1] + dp[i-2]
            prev = cur;
            cur = next;
        }
        return cur;
    }
};
```

**标准数组版（先写这个，再优化）**

```cpp
int climbStairs(int n) {
    vector<int> dp(n + 1);
    dp[0] = 1;                    // 爬到第 0 阶（原地不动）算 1 种走法
    dp[1] = 1;
    for (int i = 2; i <= n; ++i) dp[i] = dp[i-1] + dp[i-2];
    return dp[n];
}
```

> **注意 `dp[0] = 1` 的含义**：不是"0 种"而是"1 种（什么都不做）"。这样 `dp[2] = dp[1] + dp[0] = 2` 才对。**初始化的语义要想清楚**，这是 DP 边界最容易糊涂的地方。

**矩阵快速幂（O(log n)，面试炫技）**

```
[dp[n]  ]   [1 1]^(n-1)   [dp[1]]
[dp[n-1]] = [1 0]       · [dp[0]]
```
用快速幂算矩阵的 n-1 次方，O(log n)。n 极大（10¹⁸）时必须用这个。

**复杂度**  时间 O(n)，空间 O(1)。矩阵快速幂 O(log n)。

**边界与坑**
- **`dp[0] = 1` 不是 0**。见上文，语义是"空方案算一种"。这个约定在**所有计数型 DP** 里都一样（322、139、416 的初始化同理）。
- **n = 1 和 n = 2 要能正确返回 1 和 2**。滚动版用 `if (n <= 2) return n` 处理；数组版要保证 `dp` 至少有 2 个元素（`n = 1` 时 `vector<int> dp(2)` 才不越界——上面代码 `dp(n+1)` 在 n=1 时只有 2 个元素，刚好；但 `dp[1] = 1` 的赋值需要 n ≥ 1）。**n=1 时要小心数组大小**，这是数组版的隐藏坑。
- **结果会溢出吗**：`dp[45] = 1836311903 < INT_MAX`，本题 `n <= 45` 恰好安全。**n = 46 就溢出了**——这就是为什么题目卡在 45。面试提这一点能显示细致。
- 别写成 `dp[i] = dp[i-1] + dp[i-2] + 1` 或其他变体，转移方程要严格按推导来。
- 朴素递归**必须加记忆化**，否则 O(2ⁿ) 超时。

**追问 / 变体**
- **每次可以爬 1、2 或 3 步**：`dp[i] = dp[i-1] + dp[i-2] + dp[i-3]`（泰波那契）。
- **每次可以爬 `steps` 数组里的任意步数**：变成**完全背包求方案数**，`for step: for i: dp[i] += dp[i-step]`。**这就是 322/139 的模型**，70 是它的特例。
- **746 使用最小花费爬楼梯**：从"计数"变成"求最小值"，转移里的 `+` 变成 `min`。
- **有些台阶坏了不能踩**：`dp[坏台阶] = 0`。
- **n 极大（10¹⁸）**：矩阵快速幂或斐波那契通项公式（后者有浮点精度问题，不推荐）。
- **返回所有具体走法**：那是回溯题（指数级输出），见 [10-回溯](10-回溯.md)。**"计数用 DP、枚举用回溯"这条界线在本专题反复出现。**

### 118. 杨辉三角（简单）

**题意**  返回杨辉三角的前 `numRows` 行。每个数是它左上方和右上方数字之和。

**关键洞察**

这题没有"暴力 vs 最优"的对立——**它是最纯粹的"按定义递推"**，价值在于练习**二维 DP 的边界处理**。

递推关系直接来自定义：

```
dp[i][j] = dp[i-1][j-1] + dp[i-1][j]        （左上 + 右上）
dp[i][0] = dp[i][i] = 1                      （每行首尾都是 1）
```

**关键是想清楚每行的长度**：第 `i` 行（0-indexed）有 `i + 1` 个元素。所以 `j` 的范围是 `[0, i]`，中间部分是 `[1, i-1]`。

**边界的处理有两种流派**：

1. **先填充 1，再算中间**（推荐）：`row.assign(i+1, 1)` 直接把首尾和中间都置 1，然后只更新 `j ∈ [1, i-1]`。**这样完全不需要判断 `j == 0` 或 `j == i`**，代码最短。
2. **逐个判断**：`if (j == 0 || j == i) row[j] = 1; else ...`。更啰嗦但更显式。

**用第一种**——这是"用初始化消灭特判"的好例子（和 [08 二叉树的 base case](08-二叉树.md) 消灭特例是同一思路）。

**最优解（C++）**

```cpp
class Solution {
public:
    vector<vector<int>> generate(int numRows) {
        vector<vector<int>> ans(numRows);
        for (int i = 0; i < numRows; ++i) {
            ans[i].assign(i + 1, 1);                 // 第 i 行有 i+1 个元素，全填 1
            for (int j = 1; j < i; ++j)              // 只更新中间部分，首尾保持 1
                ans[i][j] = ans[i-1][j-1] + ans[i-1][j];
        }
        return ans;
    }
};
```

**复杂度**  时间 O(numRows²)（元素总数是 `1+2+...+n = n(n+1)/2`），空间 O(numRows²) 用于输出。**这已是最优**——光是输出所有元素就需要 O(n²)。

**边界与坑**
- **第 `i` 行有 `i + 1` 个元素**（0-indexed）。写成 `i` 个会全错。
- **内层循环是 `j < i` 不是 `j <= i`**。`j == i` 是行尾，必须保持 1；写成 `<=` 会越界访问 `ans[i-1][i]`（上一行只有 `i` 个元素，最大下标 `i-1`）。**这是本题唯一的崩溃点。**
- **`assign(i+1, 1)` 的 1 同时处理了首尾**。别再额外写 `row[0] = 1; row[i] = 1;`（无害但多余）。
- `i = 0` 时内层循环不执行（`j` 从 1 开始但 `1 < 0` 为假），第 0 行就是 `[1]`，正确。
- `numRows = 1` 返回 `[[1]]`。题目保证 `numRows >= 1`。
- **数值会溢出吗**：第 34 行（0-indexed）的最大值 `C(34,17) = 2333606220` 才首次超过 `INT_MAX`（第 33 行是 1166803110，仍安全）。本题 `numRows <= 30`，最大值 `C(29,14) = 77558760`，安全。
- 不要用 `dp[i][j]` 的完整二维数组再拷贝——直接在答案数组上原地构造。

**追问 / 变体**
- **119 杨辉三角 II**（只返回第 k 行，要求 O(k) 空间）：**用一维数组倒序更新**！
  ```cpp
  vector<int> getRow(int k) {
      vector<int> row(k + 1, 0);
      row[0] = 1;
      for (int i = 1; i <= k; ++i)
          for (int j = i; j >= 1; --j)       // 倒序！否则 row[j-1] 已被本轮覆盖
              row[j] += row[j - 1];
      return row;
  }
  ```
  **这个"一维数组倒序更新"和 [01 背包的倒序](#套路总纲) 是完全同一个原理**——避免同一轮的新值被重复使用。两题对照能彻底理解倒序的必要性。
- **直接用组合数公式**：第 `n` 行第 `k` 个是 `C(n, k)`，可以 O(k) 算出一行，但要注意大数和整除顺序（先乘后除会溢出，边乘边除要保证整除）。
- **杨辉三角的性质**：第 n 行之和为 2ⁿ；斜对角线是三角形数；模 2 后是谢尔宾斯基三角形。面试闲聊可提。
- **求第 n 行第 k 个元素（n 很大）**：用组合数 + 快速幂求模逆元。

### 198. 打家劫舍（中等）

**题意**  数组表示每个房子的现金，**不能偷相邻的两间**，求能偷到的最大金额。

**暴力**  枚举所有"不含相邻元素"的子集，O(2ⁿ)。或者回溯：每间房选偷/不偷，偷了就跳过下一间。n = 100 时 2¹⁰⁰ 不可行。

**关键洞察**

**用「最后一步」分析法**：考虑最后一间房 `i`，只有两种情况：

- **偷 `i`**：那么 `i-1` 不能偷，收益 = `nums[i] + dp[i-2]`
- **不偷 `i`**：收益 = `dp[i-1]`

取两者最大值：**`dp[i] = max(dp[i-1], nums[i] + dp[i-2])`**

**状态定义要精确**：`dp[i]` = 「**考虑前 `i+1` 间房（下标 0..i），能偷到的最大金额**」。

注意这里**不要求必须偷第 i 间**——这是本题状态定义的关键。如果定义成"必须偷第 i 间"，那答案就得是 `max(dp[0..n-1])` 而不是 `dp[n-1]`，转移也要跟着改（见 152/300 那种定义）。**两种定义都能做出来，但要前后一致。**

**为什么不需要考虑"隔两间、隔三间"的情况**：因为 `dp[i-1]`（不偷 i）已经包含了所有更远的组合。**"最后一步只看相邻的约束，更远的交给子问题"是 DP 的核心思想。**

**空间优化**：只依赖 `dp[i-1]` 和 `dp[i-2]` → 两个滚动变量，O(1) 空间。

**最优解（C++，O(1) 空间）**

```cpp
class Solution {
public:
    int rob(vector<int>& nums) {
        int prev2 = 0, prev1 = 0;            // prev2 = dp[i-2], prev1 = dp[i-1]
        for (int x : nums) {
            int cur = max(prev1, prev2 + x); // 不偷当前 or 偷当前
            prev2 = prev1;
            prev1 = cur;
        }
        return prev1;
    }
};
```

**数组版（先写这个更清晰）**

```cpp
int rob(vector<int>& nums) {
    int n = nums.size();
    if (n == 1) return nums[0];
    vector<int> dp(n);
    dp[0] = nums[0];
    dp[1] = max(nums[0], nums[1]);           // 前两间只能偷一间，取大的
    for (int i = 2; i < n; ++i)
        dp[i] = max(dp[i-1], nums[i] + dp[i-2]);
    return dp[n-1];
}
```

**复杂度**  时间 O(n)，空间 O(1)。

**边界与坑**
- **滚动版的初值都是 0**，这样第一间房自然得到 `max(0, 0 + nums[0]) = nums[0]`，**不需要任何特判**（n=1 也对）。**这是滚动版比数组版优越的地方**——数组版必须单独处理 `dp[0]`、`dp[1]`。
- **数组版的 `dp[1] = max(nums[0], nums[1])`**，不是 `nums[1]`。写错会漏掉"只偷第一间更优"的情况（如 `[5, 1]`）。
- **数组版 n = 1 时 `dp[1]` 越界**，必须提前 `if (n == 1) return nums[0]`。
- **`prev2` 和 `prev1` 的更新顺序不能反**。必须先算出 `cur`，再 `prev2 = prev1`，最后 `prev1 = cur`。写反会用错值。
- **金额都是非负的**（题目保证 `nums[i] >= 0`），所以"不偷"的收益 0 是安全下界。若允许负数，`dp` 初值和转移都要重新考虑。
- 不要贪心地"偷所有奇数位或偶数位"！`[2,1,1,2]` 的答案是 4（偷第 0 和第 3 间），而奇偶位分别是 3 和 3。**这是很好的"为什么不能贪心"的反例。**
- 空数组返回 0。

**追问 / 变体**
- **213 打家劫舍 II**（**环形**排列，首尾相邻）：把问题拆成两个线性子问题——「偷 `[0, n-2]`」和「偷 `[1, n-1]`」，各跑一次本题取 max。**因为首尾不能同时偷，所以必然至少有一间不偷，枚举"不偷第一间"和"不偷最后一间"即可覆盖。** 这个拆解思路很典型。
- **337 打家劫舍 III**（**二叉树**结构）：树形 DP，每个节点返回 `{偷它的最大值, 不偷它的最大值}` 两个值，在后序位置汇总。**和 [124 最大路径和](08-二叉树.md) 一样是"后序位置汇总 + 多返回值"。**
- **可以偷相邻但不能偷相隔 k 以内**：转移变成 `dp[i] = max(dp[i-1], nums[i] + dp[i-k-1])`。
- **返回具体偷了哪几间**：从 `dp[n-1]` 倒推，比较 `dp[i]` 是否等于 `dp[i-1]` 来判断第 i 间是否被偷。
- **740 删除并获得点数**：先按值统计总和，转化成本题（值相邻的不能同时取）。**能认出这个转化是很好的能力体现。**

### 279. 完全平方数（中等）

**题意**  给正整数 `n`，返回**和为 `n` 的完全平方数的最少数量**（可以重复使用同一个平方数）。

**暴力**  回溯枚举所有组合，指数级。或者贪心"每次减最大的平方数"——**这是错的**：`n = 12` 时贪心得 `9 + 1 + 1 + 1 = 4` 个，而最优是 `4 + 4 + 4 = 3` 个。**这个反例说明本题不能贪心，必须 DP。**

**关键洞察**

**用「最后一步」分析法**：要凑出 `n`，最后加上的那个平方数是某个 `j²`（`j² <= n`）。那么剩下的 `n - j²` 需要的最少个数就是 `dp[n - j²]`。枚举所有可能的 `j` 取最小：

```
dp[i] = min(dp[i - j*j] + 1)   对所有 j 满足 j*j <= i
```

**状态定义**：`dp[i]` = 「凑出和为 `i` 所需的最少完全平方数个数」。

**这就是完全背包求最小值**：
- **物品** = 完全平方数 `1, 4, 9, 16, ...`（每个可用无限次）
- **容量** = `n`
- **目标** = 最少个数（而不是最大价值）

**为什么这是"完全"背包而不是"01"背包**：同一个平方数可以重复用（`4 + 4 + 4`），所以是完全背包 → **容量正序遍历**。

**初始化的关键**：`dp[0] = 0`（凑出 0 需要 0 个数），其余全部初始化为**一个足够大的值**（表示"暂时无解"）。**用 `INT_MAX` 会在 `dp[...] + 1` 时溢出**，所以用 `n + 1`（因为答案最多是 n，全用 1² 相加），或者用 `INT_MAX - 1`。**推荐用 `n + 1` 作为"无穷大"**，既安全又有意义。

**本题保证有解**（任何正整数都能用若干个 1² 凑出），所以不需要判无解。

**最优解（C++）**

```cpp
class Solution {
public:
    int numSquares(int n) {
        vector<int> dp(n + 1, n + 1);        // n+1 当"无穷大"（答案最多是 n，全用 1）
        dp[0] = 0;                            // 凑 0 需要 0 个
        for (int i = 1; i <= n; ++i)
            for (int j = 1; j * j <= i; ++j)  // 枚举最后加的那个平方数 j*j
                dp[i] = min(dp[i], dp[i - j * j] + 1);
        return dp[n];
    }
};
```

**背包写法（外层物品、内层容量正序，和 322 完全同构）**

```cpp
int numSquares(int n) {
    vector<int> dp(n + 1, n + 1);
    dp[0] = 0;
    for (int j = 1; j * j <= n; ++j)              // 物品：平方数 j*j
        for (int i = j * j; i <= n; ++i)          // 容量【正序】= 完全背包
            dp[i] = min(dp[i], dp[i - j * j] + 1);
    return dp[n];
}
```

**两种写法完全等价**（因为求 min 时顺序无关），但**背包写法更容易和 322 对照记忆**。

**数学解法（拉格朗日四平方和定理，O(√n)）**

任何正整数都可表示为**最多 4 个**平方数之和，且：
- 答案为 **1** ⟺ n 本身是完全平方数
- 答案为 **4** ⟺ `n = 4^a × (8b + 7)`（三平方和定理的反面）
- 答案为 **2** ⟺ 存在 `a, b` 使 `a² + b² = n`（枚举 `a` 到 √n 检验）
- 否则答案为 **3**

```cpp
int numSquares(int n) {
    auto isSquare = [](int x) { int r = (int)sqrt((double)x); return r * r == x; };
    if (isSquare(n)) return 1;
    int m = n;
    while (m % 4 == 0) m /= 4;                          // 去掉 4^a
    if (m % 8 == 7) return 4;
    for (int a = 1; a * a <= n; ++a)
        if (isSquare(n - a * a)) return 2;
    return 3;
}
```

**面试策略**：先给 DP（展示 DP 功底），再提"其实有 O(√n) 的数论解法"。**主动说出数学解法能显著加分，但不要一上来就写它**——面试官想考的是 DP。

**复杂度**  DP：时间 O(n√n)（外层 n，内层 √n），空间 O(n)。数学解法：时间 O(√n)，空间 O(1)。

**边界与坑**
- **"无穷大"不能用 `INT_MAX`**。`dp[i - j*j] + 1` 在前者是 `INT_MAX` 时**溢出成负数**，`min` 会选中这个负数，结果全错。用 `n + 1` 或 `INT_MAX - 1`。**这是本题头号 bug，而且症状诡异（答案变成负数或 0）。**
- **`dp[0] = 0` 必须显式设置**（初始化时它也被设成了 `n+1`）。
- **内层条件是 `j * j <= i` 不是 `j <= i`**。写错会访问负下标。
- **`j` 从 1 开始不是 0**。`j = 0` 时 `j*j = 0`，`dp[i] = dp[i] + 1` 会让答案无限增大（虽然 `min` 挡住了，但语义错误）。
- **`j * j` 可能溢出吗**：本题 `n <= 10^4`，`j <= 100`，安全。n 很大时（10⁹）要用 `long long` 或改条件为 `j <= i / j`。
- **不能贪心**！见"暴力"部分的 `n = 12` 反例。这是本题最重要的认识。
- 数学解法里 `sqrt` 的**浮点精度问题**：大数时 `(int)sqrt(x)` 可能差 1，稳妥写法是算完再校验 `r*r == x`（上面代码已做），或者检查 `r-1, r, r+1`。

**追问 / 变体**
- **322 零钱兑换**：把"平方数"换成任意硬币面额，**完全同构**，见下题。**两题一起写能彻底掌握完全背包求最小值。**
- **求方案数而非最少个数**：转移变成 `dp[i] += dp[i - j*j]`，初始化 `dp[0] = 1`。**注意此时循环顺序决定算组合数还是排列数**（见 [套路总纲](#套路总纲)）。
- **返回具体的分解**：额外记录 `from[i] = j`，从 `dp[n]` 倒推。
- **限制最多用 k 个**：加一维 `dp[i][k]`，变成二维 DP。
- **n 极大（10⁹）**：DP 的 O(n√n) 不可行，必须用数论解法。
- **为什么 DP 一定对而贪心不对**：DP 枚举了"最后一步"的**所有**可能，贪心只试了一种。**这是"贪心可能错、DP 一定对"的具体体现。**

### 322. 零钱兑换（中等）

**题意**  给定硬币面额数组 `coins`（每种**无限供应**）和金额 `amount`，求凑出该金额所需的**最少硬币数**；凑不出返回 **-1**。

**暴力**  回溯枚举每种硬币用几个，指数级。贪心"每次用最大面额"**是错的**：`coins = [1, 3, 4], amount = 6` 时贪心得 `4 + 1 + 1 = 3` 枚，最优是 `3 + 3 = 2` 枚。**这个反例必须记住**——它解释了为什么现实中的货币系统（1/5/10/25）能贪心，而任意面额不能。

**关键洞察**

**这是完全背包求最小值的模板题**，和 [279](#279-完全平方数中等) 完全同构（279 的"硬币"是平方数）。

**用「最后一步」分析法**：凑出金额 `i` 的最后一枚硬币是某个 `c ∈ coins`（且 `c <= i`），那么之前需要凑出 `i - c`：

```
dp[i] = min(dp[i - c] + 1)   对所有 c ∈ coins 且 c <= i
```

**状态定义**：`dp[i]` = 「凑出金额 `i` 所需的最少硬币数，凑不出则为 ∞」。

**"凑不出"的处理是本题相对 279 的唯一新增点**：279 保证有解，本题可能无解（如 `coins=[2], amount=3`）。做法是：
- 初始化 `dp[i] = amount + 1`（一个不可能达到的值，因为最少也是 1 枚面额 1 的硬币，最多 `amount` 枚）
- **转移时要判 `dp[i - c] != amount + 1`**（或者干脆让 `amount+1` 参与运算——加 1 变成 `amount+2` 仍然是"无穷大"，不影响正确性）
- 最后 `dp[amount] > amount` 就返回 -1

**用 `amount + 1` 当无穷大的好处**：即使不判断也不会溢出（`amount+1 + 1` 还在 int 范围内），且最终判断 `> amount` 就能识别无解。**这个技巧让代码更干净。**

**为什么完全背包是容量正序**：同一面额可以重复用，正序时 `dp[i - c]` 可能已在本轮被更新（即已经用过这个硬币），正好允许重复使用。**对比 [416 的 01 背包倒序](#416-分割等和子集中等) 能彻底理解。**

**最优解（C++）**

```cpp
class Solution {
public:
    int coinChange(vector<int>& coins, int amount) {
        vector<int> dp(amount + 1, amount + 1);      // amount+1 作"无穷大"
        dp[0] = 0;                                    // 凑 0 元需要 0 枚
        for (int i = 1; i <= amount; ++i)
            for (int c : coins)
                if (c <= i)
                    dp[i] = min(dp[i], dp[i - c] + 1);
        return dp[amount] > amount ? -1 : dp[amount]; // 超过 amount 说明凑不出
    }
};
```

**背包写法（外层物品、内层容量正序）**

```cpp
int coinChange(vector<int>& coins, int amount) {
    vector<int> dp(amount + 1, amount + 1);
    dp[0] = 0;
    for (int c : coins)                              // 物品：硬币
        for (int i = c; i <= amount; ++i)            // 容量【正序】= 完全背包
            dp[i] = min(dp[i], dp[i - c] + 1);
    return dp[amount] > amount ? -1 : dp[amount];
}
```

**BFS 视角（另一个漂亮的思路）**

把「当前剩余金额」看成图上的节点，「用一枚硬币」看成一条边（边权都是 1），那么求最少硬币数就是**求最短路 → BFS**：

```cpp
int coinChange(vector<int>& coins, int amount) {
    if (amount == 0) return 0;
    vector<bool> vis(amount + 1, false);
    queue<int> q;
    q.push(0); vis[0] = true;
    int steps = 0;
    while (!q.empty()) {
        int sz = q.size();
        ++steps;                                     // 又用了一枚硬币
        for (int k = 0; k < sz; ++k) {
            int cur = q.front(); q.pop();
            for (int c : coins) {
                int next = cur + c;
                if (next == amount) return steps;    // 到达目标
                if (next > amount || vis[next]) continue;
                vis[next] = true;
                q.push(next);
            }
        }
    }
    return -1;
}
```

**边权全为 1 → BFS 求最短路**，这和 [45 跳跃游戏 II](14-贪心算法.md)、[994 腐烂的橘子](09-图论.md) 是同一条原则。BFS 版在**答案很小而 amount 很大**时更快（不必填满整个 dp 表）。

**复杂度**  时间 O(amount × coins.size())，空间 O(amount)。

**边界与坑**
- **"无穷大"用 `amount + 1` 而非 `INT_MAX`**。用 `INT_MAX` 时 `dp[i-c] + 1` 溢出成负数，`min` 选中负数，答案错乱。**同 279 的头号坑。**
- **最终判断是 `dp[amount] > amount`**，不是 `== amount + 1`。虽然本代码中无解时恰好是 `amount+1`，但如果转移里让"无穷大 + 1"传播过，值可能变大，用 `>` 更稳。
- **`dp[0] = 0` 必须显式设置。**
- **`amount = 0` 要返回 0**。本代码 `dp[0] = 0`，循环不执行，返回 0，正确。BFS 版必须显式特判（否则从 0 出发找不到目标 0）。
- **`if (c <= i)` 不能漏**，否则 `dp[i - c]` 负下标越界。背包写法里用 `for (i = c; ...)` 天然满足。
- **不能贪心**！见"暴力"部分的 `[1,3,4]` 凑 6 的反例。**如果面试写了贪心，一定会被这个用例打回。**
- **硬币面额可能重复或含大于 amount 的**：都无害（大面额的 `if (c <= i)` 直接跳过）。
- 硬币面额为 0 会死循环——题目保证 `coins[i] >= 1`。

**追问 / 变体**
- **518 零钱兑换 II**（求**方案数**）：转移变 `dp[i] += dp[i - c]`，`dp[0] = 1`。**且循环顺序必须是「外层物品、内层容量」**——反过来会把 `1+2` 和 `2+1` 算成两种（那是排列数，即 377 题）。**这是背包问题最容易错的地方，务必分清。**
- **377 组合总和 IV**（其实求的是**排列数**）：外层容量、内层物品。**518 和 377 的唯一区别就是循环顺序**，对照着写一遍能彻底搞懂。
- **279 完全平方数**：本题的特例，见上题。
- **每种硬币数量有限**：变成**多重背包**，需要二进制拆分或单调队列优化。
- **返回具体用了哪些硬币**：记录 `from[i] = c`，从 `dp[amount]` 倒推。
- **amount 极大（10⁹）而面额很少**：DP 不可行，需要数学方法（如 Frobenius 数）或矩阵快速幂。
- **为什么现实货币能贪心**：1/5/10/25 这类面额满足"**正规系统（canonical coin system）**"性质，贪心恰好最优。判断一个面额集合是否 canonical 本身是个有趣的问题。**面试提这个能体现深度。**

### 139. 单词拆分（中等）

**题意**  给字符串 `s` 和字典 `wordDict`，判断 `s` 能否被拆分成字典中若干单词的序列（**单词可重复使用**）。

**暴力**  回溯：枚举第一个单词的所有可能，剩下的递归判断。最坏 O(2ⁿ)——`s = "aaaa...a"`、字典 `["a","aa","aaa"]` 时分割方式指数级。

浪费在哪：**同一个后缀被反复判断**。`"aaaa"` 拆成 `"a"+"aaa"` 和 `"aa"+"aa"` 之后，都要判断剩下的部分，而这些子问题重复了。**加记忆化就变成了 DP。**

**关键洞察**

**状态定义**：`dp[i]` = 「`s` 的**前 `i` 个字符** `s[0..i-1]` 能否被成功拆分」。

**注意 `dp[i]` 用的是"长度"而不是"下标"**——这让 `dp[0] = true`（空串可拆分）成为自然的边界，也让转移里的下标运算更顺。**"前 i 个字符"这种长度型状态定义在字符串 DP 里非常常用**（1143、72 也是），值得固定下来。

**用「最后一步」分析法**：如果前 `i` 个字符能拆分，那么**最后一个单词**必然是某个 `s[j..i-1]`（`0 <= j < i`），且：

1. `s[j..i-1]` 在字典里，**且**
2. 前 `j` 个字符也能拆分（即 `dp[j] == true`）

所以：

```
dp[i] = OR over j∈[0,i) of ( dp[j] && s.substr(j, i-j) ∈ dict )
```

**这是"分割型 DP"的通用形式**：枚举最后一段的起点 `j`，检查「前半段可行」+「后半段合法」。[131 分割回文串](10-回溯.md) 的 DP 版、132 都是同一个模式。

**两个工程要点**：

1. **字典转 `unordered_set`**，把查找从 O(字典大小 × 单词长度) 降到 O(单词长度)。
2. **限制内层枚举范围**：最后一个单词的长度不可能超过字典中的最长单词，所以 `j >= i - maxLen`。这个剪枝在字典单词都很短而 `s` 很长时提速明显。

**最优解（C++）**

```cpp
class Solution {
public:
    bool wordBreak(string s, vector<string>& wordDict) {
        unordered_set<string> dict(wordDict.begin(), wordDict.end());
        int maxLen = 0;
        for (const string& w : wordDict) maxLen = max(maxLen, (int)w.size());

        int n = s.size();
        vector<bool> dp(n + 1, false);
        dp[0] = true;                                    // 空串可拆分
        for (int i = 1; i <= n; ++i)
            for (int j = max(0, i - maxLen); j < i; ++j) // 枚举最后一个单词的起点
                if (dp[j] && dict.count(s.substr(j, i - j))) {
                    dp[i] = true;
                    break;                               // 找到一种即可，剪枝
                }
        return dp[n];
    }
};
```

**Trie 优化版（字典很大时更优，避免 `substr` 的字符串构造）**

```cpp
class Solution {
    struct Node { Node* ch[26] = {}; bool isEnd = false; };
public:
    bool wordBreak(string s, vector<string>& wordDict) {
        Node* root = new Node();
        for (const string& w : wordDict) {               // 建 Trie
            Node* cur = root;
            for (char c : w) {
                if (!cur->ch[c - 'a']) cur->ch[c - 'a'] = new Node();
                cur = cur->ch[c - 'a'];
            }
            cur->isEnd = true;
        }
        int n = s.size();
        vector<bool> dp(n + 1, false);
        dp[0] = true;
        for (int i = 0; i < n; ++i) {
            if (!dp[i]) continue;                        // 前 i 个不可拆，跳过
            Node* cur = root;
            for (int j = i; j < n; ++j) {                // 从 i 开始沿 Trie 走
                cur = cur->ch[s[j] - 'a'];
                if (!cur) break;                         // Trie 上无路，后面都不用试
                if (cur->isEnd) dp[j + 1] = true;        // 找到一个单词
            }
        }
        return dp[n];
    }
};
```

**Trie 版的优势**：不需要 `substr`（避免 O(L) 的字符串拷贝），且一旦前缀不在 Trie 里就 `break`，剪枝更强。**这是 [208 Trie](09-图论.md) 的实际应用。**

**复杂度**  时间 O(n² · L)（n² 个 `(i,j)` 对，每次 `substr` + 哈希是 O(L)），空间 O(n + 字典总长)。Trie 版时间 O(n²)，无 `substr` 开销。

**边界与坑**
- **`dp[0] = true` 必须设置**，语义是"空串可以拆分（不需要任何单词）"。漏了会让 `dp` 全是 false。**这是所有"分割型 DP"的统一边界**（同 [70 的 `dp[0]=1`](#70-爬楼梯简单)）。
- **`substr(j, i - j)` 的第二个参数是长度**，不是结束下标。`s[j..i-1]` 的长度是 `i - j`。**这个和 [131](10-回溯.md) 是同一个坑。**
- **`dp` 用"长度"索引，`s` 用"下标"索引**，两者错开 1。`dp[i]` 对应 `s[0..i-1]`。**混淆这两套索引是本题最容易犯的错。** 建议写代码时在注释里标清。
- **`break` 只能跳出内层**，是找到一种拆分方式后的剪枝，正确。
- **单词可重复使用**，所以不需要"已用过"的标记。若每个单词只能用一次，问题变难得多（要状压或匹配）。
- **`maxLen` 剪枝要用 `max(0, i - maxLen)`**，防止负下标。
- 字典可能包含重复单词——`unordered_set` 自动去重，无害。
- 字典可能为空 → `maxLen = 0` → 内层循环 `j` 从 `i` 开始（`max(0, i-0) = i`），`j < i` 为假，不执行 → `dp[n] = false`（除非 n=0）。正确。

**追问 / 变体**
- **140 单词拆分 II**（返回**所有**拆分方案）：**必须用回溯 + 记忆化**（记忆化存"从位置 i 开始的所有拆分结果"）。**"判断可行性用 DP、枚举所有方案用回溯"再次出现**（对照 [78 → 416](10-回溯.md)）。
- **131 分割回文串**：同样的分割型结构，"在字典里"换成"是回文"，见 [10-回溯](10-回溯.md)。
- **132 分割回文串 II**（最少分割次数）：转移里的 `||` 换成 `min(dp[j] + 1)`。
- **返回一种具体拆分**：记录 `from[i] = j`，从 `dp[n]` 倒推。
- **字典单词极多（10⁶ 级）**：必须用 Trie 或 AC 自动机，`unordered_set` 的哈希开销会成为瓶颈。
- **`s` 极长而字典很小**：`maxLen` 剪枝让复杂度降到 O(n × maxLen × L)，接近线性。
- **为什么不能贪心（每次取最长匹配）**：`s = "aaab"`，字典 `["aaa","aa","b"]`。贪心先取 `"aaa"` 剩下 `"b"` 恰好成功；但改成 `s="aaab"`、字典 `["aaa","aab"]`（无 `"b"`）时，贪心取 `"aaa"` 后剩 `"b"` 失败，而正确解是 `"a"+"aab"`——可惜 `"a"` 不在字典。构造更明确的反例：`s="aab"`、字典 `["aa","a","ab"]`，贪心取 `"aa"` 后剩 `"b"` 失败，正解是 `"a"+"ab"`。**这说明必须枚举所有分割点，不能贪心。**

### 300. 最长递增子序列（中等）

**题意**  返回最长**严格递增子序列**（**子序列**可以不连续，但顺序不能变）的长度。

**暴力**  枚举所有 2ⁿ 个子序列检查是否递增，O(2ⁿ · n)。n = 2500 时不可行。

**关键洞察**

**① 状态定义是本题的核心难点。**

朴素的想法 `dp[i] = 「前 i 个元素的 LIS 长度」` **行不通**——转移时不知道前面那个 LIS 的**结尾是多少**，无法判断 `nums[i]` 能否接上。

正确的定义必须携带"结尾"信息：

> **`dp[i]` = 「以 `nums[i]` 结尾的最长递增子序列的长度」**

**「以 i 结尾」这个定语是关键**，它让"能否接上"变成可判断的（比较 `nums[j] < nums[i]`）。**这是 DP 状态定义的通用经验：当转移需要某个信息时，就把它塞进状态定义里。**

代价是：答案不再是 `dp[n-1]`，而是 **`max(dp[0..n-1])`**——因为 LIS 可能在任何位置结尾。**这一点极易忘。**

**转移**：`nums[i]` 前面可以接任何满足 `nums[j] < nums[i]` 的 `dp[j]`：

```
dp[i] = 1 + max{ dp[j] : j < i 且 nums[j] < nums[i] }     （没有这样的 j 时 dp[i] = 1）
```

O(n²)。n = 2500 时约 6×10⁶，能过。

**② O(n log n) 的贪心 + 二分（进阶，面试加分）**

维护数组 `tails`，其中 **`tails[k]` = 「长度为 `k+1` 的递增子序列中，最小可能的结尾值」**。

关键性质：**`tails` 一定是严格递增的**（可以反证：若 `tails[k] >= tails[k+1]`，则长度 k+2 的序列去掉最后一项得到长度 k+1 的序列，其结尾比 `tails[k]` 小，矛盾）。所以可以二分。

处理每个 `x = nums[i]`：
- 用 `lower_bound` 找第一个 **`>= x`** 的位置 `p`
- 若 `p == tails.size()`，说明 `x` 比所有结尾都大 → **可以接在最长的后面**，`tails.push_back(x)`，LIS 长度 +1
- 否则 **`tails[p] = x`** —— 用更小的结尾替换，为将来留出更多空间

**答案就是 `tails.size()`**。

**为什么"替换"是对的**：`tails[p] = x` 不改变已有的 LIS 长度，但让"长度为 p+1 的序列"有了更小的结尾，后续元素更容易接上去。**这是典型的贪心——保持每个长度的"最优结尾"。**

**⚠️ 重要**：`tails` **本身不是**一个合法的 LIS，只是各长度的最优结尾值。**想输出 LIS 本身必须额外记录前驱，不能直接返回 `tails`。** 这是最常见的误解。

**必须用 `lower_bound`（第一个 `>=`）而不是 `upper_bound`**：因为要求**严格**递增，相等的元素不能接。用 `upper_bound` 会得到"最长非递减子序列"。**这一个函数的差别就是"严格"和"非严格"的分界。**

**最优解（C++，O(n log n)）**

```cpp
class Solution {
public:
    int lengthOfLIS(vector<int>& nums) {
        vector<int> tails;                    // tails[k] = 长度 k+1 的 LIS 的最小结尾
        for (int x : nums) {
            auto it = lower_bound(tails.begin(), tails.end(), x);   // 第一个 >= x
            if (it == tails.end()) tails.push_back(x);              // x 最大，接在末尾
            else *it = x;                                           // 替换成更小的结尾
        }
        return tails.size();
    }
};
```

四行，但每一行都需要上面的推导才能理解。

**O(n²) DP 版（面试先写这个，思路清晰）**

```cpp
int lengthOfLIS(vector<int>& nums) {
    int n = nums.size();
    vector<int> dp(n, 1);                     // 每个元素自身就是长度 1 的 LIS
    int best = 1;
    for (int i = 1; i < n; ++i) {
        for (int j = 0; j < i; ++j)
            if (nums[j] < nums[i])            // 严格小于才能接
                dp[i] = max(dp[i], dp[j] + 1);
        best = max(best, dp[i]);              // 答案是所有 dp[i] 的最大值
    }
    return best;
}
```

**复杂度**  DP 版 O(n²) 时间 O(n) 空间；贪心 + 二分版 **O(n log n)** 时间 O(n) 空间。

**边界与坑**
- **答案是 `max(dp[i])` 不是 `dp[n-1]`**。这是 O(n²) 版的头号错误。`[1,3,6,7,9,4,10,5,6]` 中 LIS 结尾不是最后一个元素。
- **`dp` 初值全为 1**（每个元素自成长度 1 的子序列），不是 0。
- **必须 `nums[j] < nums[i]` 严格小于**。用 `<=` 会得到最长**非递减**子序列，答案偏大。测试用例 `[2,2]` 的答案是 1 不是 2。
- **二分版必须用 `lower_bound` 不是 `upper_bound`**。见上文，这决定了"严格"还是"非严格"。**求最长非递减子序列时才用 `upper_bound`**——记住这个对应关系，就能一招应对两类题。
- **`tails` 不是 LIS 本身**。`[10,9,2,5,3,7,101,18]` 处理完 `tails = [2,3,7,18]`，长度 4 正确，但原数组里 `[2,3,7,18]` 恰好也是一个 LIS——**这只是巧合**。反例：`[3,4,1]` 处理完 `tails = [1,4]`，但 `[1,4]` 在原数组里不是子序列（1 在 4 后面）。**面试若问"能否输出 LIS"，必须说明需要额外记录前驱。**
- 空数组返回 0（`tails` 为空）；O(n²) 版的 `best = 1` 初值在空数组时会错，需要特判 `if (n == 0) return 0`。
- **子序列 ≠ 子数组**。子序列可以跳着取，子数组必须连续。**看到"子序列"就不要想滑动窗口。**

**追问 / 变体**
- **输出 LIS 本身**：O(n²) 版记录 `from[i]`（转移来源）倒推最简单。二分版需要额外记录每个元素被放在 `tails` 的哪个位置 + 前驱链，较繁琐。
- **最长非递减子序列**：`lower_bound` → `upper_bound`，或 O(n²) 版的 `<` → `<=`。
- **最长递减子序列**：数组取反，或反向遍历。
- **673 最长递增子序列的个数**：额外维护 `cnt[i]` = 以 i 结尾的 LIS 数量，转移时相等则累加、更大则重置。
- **354 俄罗斯套娃信封**：二维版——**按宽升序、宽相同时按高降序**排序，然后对高求 LIS。**"高降序"是精髓**：保证宽相同的信封不会互相嵌套。**这是 300 最重要的应用题。**
- **1143 最长公共子序列**：名字像但完全不同（两个序列），见 [16-多维动态规划](16-多维动态规划.md)。**LIS 可以转化成"原数组与其排序去重后数组的 LCS"，但那是 O(n²)，不如直接做。**
- **128 最长连续序列**：数值连续而非位置递增，用哈希，见 [01-哈希](01-哈希.md)。**名字容易和本题混。**
- **n 达到 10⁶**：必须用 O(n log n) 版。

### 152. 乘积最大子数组（中等）

**题意**  找出数组中乘积最大的**非空连续子数组**，返回该乘积。

**暴力**  枚举所有子数组 `[i, j]` 算乘积，O(n²)。n = 2×10⁴ 时约 4×10⁸，会超时。

**关键洞察**

先想 [53 最大子数组和](05-普通数组.md) 的思路：`dp[i] = max(nums[i], dp[i-1] + nums[i])`。照搬到乘积上会**错**：

```cpp
dp[i] = max(nums[i], dp[i-1] * nums[i]);   // ✗ 错！
```

**反例**：`[-2, 3, -4]`。按上式 `dp[0] = -2`，`dp[1] = max(3, -6) = 3`，`dp[2] = max(-4, -12) = -4`。答案 3。但真实答案是 **24**（`-2 × 3 × -4`）。

**为什么错**：**负数乘负数变正数**。`dp[1]` 只记录了"最大值 3"，丢弃了"最小值 -6"——而正是这个 -6 乘上 -4 才得到 24。

**核心洞察：负号会让"最小"变成"最大"，所以必须同时维护最大值和最小值。**

定义两个状态（都带"以 i 结尾"的定语）：
- `maxP[i]` = 以 `nums[i]` 结尾的子数组的**最大**乘积
- `minP[i]` = 以 `nums[i]` 结尾的子数组的**最小**乘积（可能是很大的负数）

转移时，以 `i` 结尾的乘积只有三种可能来源：

```
maxP[i] = max( nums[i],  maxP[i-1] * nums[i],  minP[i-1] * nums[i] )
minP[i] = min( nums[i],  maxP[i-1] * nums[i],  minP[i-1] * nums[i] )
```

- `nums[i]` 单独成段（前面的乘积不要了）
- 接在前面的最大乘积后（`nums[i] > 0` 时通常是这个）
- 接在前面的**最小**乘积后（`nums[i] < 0` 时可能翻身成最大）

**三项一起取 max/min，就不需要判断 `nums[i]` 的正负号**——这是最干净的写法。有些题解会按符号分支或者交换 max/min，容易写错，**统一三项取极值更稳**。

答案是 `max(maxP[0..n-1])`（同 300，答案不是最后一项）。

**0 的处理是免费的**：`nums[i] == 0` 时三项都是 0，`maxP[i] = minP[i] = 0`，相当于自动"重新开始"。**不需要特判 0。**

**最优解（C++，O(1) 空间）**

```cpp
class Solution {
public:
    int maxProduct(vector<int>& nums) {
        int best = nums[0];
        int curMax = nums[0], curMin = nums[0];
        for (int i = 1; i < (int)nums.size(); ++i) {
            int x = nums[i];
            int a = curMax * x, b = curMin * x;
            curMax = max({x, a, b});          // 三项取最大
            curMin = min({x, a, b});          // 三项取最小
            best = max(best, curMax);
        }
        return best;
    }
};
```

**注意 `curMax` 和 `curMin` 必须"同时"更新**——先用 `a`、`b` 存好旧值算出的两个乘积，再赋值。**若直接写 `curMax = max({x, curMax*x, curMin*x}); curMin = min({x, curMax*x, curMin*x});`，第二行用的就是已被覆盖的新 `curMax`，结果错。这是本题头号 bug。**

**数组版（更显式）**

```cpp
int maxProduct(vector<int>& nums) {
    int n = nums.size();
    vector<int> maxP(n), minP(n);
    maxP[0] = minP[0] = nums[0];
    int best = nums[0];
    for (int i = 1; i < n; ++i) {
        maxP[i] = max({nums[i], maxP[i-1] * nums[i], minP[i-1] * nums[i]});
        minP[i] = min({nums[i], maxP[i-1] * nums[i], minP[i-1] * nums[i]});
        best = max(best, maxP[i]);
    }
    return best;
}
```

**复杂度**  时间 O(n)，空间 O(1)。

**边界与坑**
- **必须同时维护最大和最小**，只维护最大是错的（见"关键洞察"的反例）。
- **更新时必须用旧值**。先算 `a = curMax * x`、`b = curMin * x`，再更新两个变量。**顺序写错是最高频错误。**
- **`best` 初值是 `nums[0]`，不是 0 或 `INT_MIN`**。子数组**非空**，全负数组（如 `[-2]`）答案是 -2。初值 0 会错答 0。
- **答案是 `max(maxP[i])` 不是 `maxP[n-1]`**（同 300）。
- **乘积可能溢出 `int`**：本题保证「答案在 32 位整数范围内」，但**中间结果可能溢出**！例如 `[2,3,-2,4,...]` 长数组的中间乘积可能超范围。LeetCode 的数据保证不会（约束里明确"任何前缀或后缀的乘积都在 32 位整数范围内"），但**面试要主动指出这个风险**，并说"稳妥起见可用 `long long` 存 `curMax`/`curMin`，最后再转回"。
- **0 不需要特判**，三项取极值天然处理。
- **`max({a,b,c})` 需要 `<algorithm>` 且是 C++11 的初始化列表版本**。写 `max(a, max(b, c))` 等价。
- 单元素数组返回该元素。

**追问 / 变体**
- **53 最大子数组和**：本题的加法版，只需一个状态，见 [05-普通数组](05-普通数组.md)。**53 → 152 的难度跃升全部来自"负负得正"，这个对比非常经典。**
- **返回具体的子数组**：记录 `curMax` 被更新为 `x`（重新开始）时的位置作为左端点。
- **子数组长度至少为 k**：加一维或用前缀积 + 单调队列。
- **允许删除一个元素**（1186 类）：增加"已删除一个"的状态维度。
- **求乘积最小的子数组**：答案是 `min(minP[i])`，同一套代码。
- **628 三个数的最大乘积**：只取三个数，用排序或一次遍历维护最大三个 + 最小两个。**同样是"负负得正"的陷阱**，但不需要 DP。
- **元素为浮点数**：思路不变，但要注意精度和下溢。

### 416. 分割等和子集（中等）

**题意**  判断非空正整数数组能否被分割成**两个和相等**的子集。

**暴力**  枚举所有 2ⁿ 个子集，看有没有和等于 `sum/2` 的。n = 200 时不可行。**这就是 [78 子集](10-回溯.md) 的枚举，但本题只问"存在性"，不需要列出方案 → 应该用 DP。**

**关键洞察**

**① 问题转化（本题的第一步，也是最关键的一步）**

「分成两个和相等的子集」⟺ 「**存在一个子集，其和恰好等于 `sum / 2`**」。

因为选出的子集和为 `sum/2` 时，剩下的自然也是 `sum/2`。**这一步把"分割"问题转成了"子集和"问题。**

**两个立刻可做的剪枝**：
- **`sum` 为奇数 → 直接返回 false**（无法平分）。
- 若某个 `nums[i] > sum/2` → 也不可能（本题元素为正，可选做剪枝）。

**② 这是 01 背包的判定版**

- **物品** = 数组元素，**每个只能用一次** → **01 背包**
- **容量** = `sum / 2`
- **问题** = 能否恰好装满

状态定义：`dp[j]` = 「能否从已考虑的物品中选出若干个，使其和恰好为 `j`」。

转移（考虑物品 `nums[i]`）：

```
dp[j] = dp[j]  (不选 nums[i])  ||  dp[j - nums[i]]  (选 nums[i])
```

**③ 必须倒序遍历容量（本题的核心技术点）**

```cpp
for (int x : nums)
    for (int j = target; j >= x; --j)      // 【倒序】
        dp[j] = dp[j] || dp[j - x];
```

**为什么倒序**：滚动数组里 `dp[j - x]` 必须是"**还没考虑物品 x**"时的值。倒序时 `j - x < j`，而更小的下标本轮还没被更新过，所以读到的是上一轮的值 ✓。

**如果正序**：`dp[j - x]` 可能在本轮已被更新（即已经用过 x 一次），此时再用就是"用了两次 x" → **变成完全背包**。例如 `nums = [3]`、`target = 6`，正序会让 `dp[3] = true` 然后 `dp[6] = dp[6] || dp[3] = true`，错误地认为 3 能凑出 6。

**"01 背包倒序、完全背包正序"是本专题最重要的机械规则**，和 [322 零钱兑换](#322-零钱兑换中等)（完全背包，正序）恰好构成对照。**两题对着写一遍，这个规则就永远不会忘。**

**最优解（C++）**

```cpp
class Solution {
public:
    bool canPartition(vector<int>& nums) {
        int sum = 0;
        for (int x : nums) sum += x;
        if (sum % 2 != 0) return false;               // 奇数无法平分
        int target = sum / 2;

        vector<bool> dp(target + 1, false);
        dp[0] = true;                                  // 和为 0 恒可达（空集）
        for (int x : nums)
            for (int j = target; j >= x; --j)          // 【倒序】= 01 背包
                if (dp[j - x]) dp[j] = true;
        return dp[target];
    }
};
```

**bitset 优化版（极快，位运算并行处理所有容量）**

```cpp
bool canPartition(vector<int>& nums) {
    int sum = 0;
    for (int x : nums) sum += x;
    if (sum % 2) return false;
    bitset<10001> dp;              // 本题 sum <= 200*100 = 20000，target <= 10000
    dp[0] = 1;
    for (int x : nums) dp |= dp << x;    // 一条指令同时更新所有 dp[j]
    return dp[sum / 2];
}
```

`dp |= dp << x` 的含义：**对所有 `j`，若 `dp[j-x]` 为真则 `dp[j]` 置真**——正是转移方程，但一次处理 64 个 bit。**复杂度 O(n × target / 64)，快约 64 倍。这是竞赛常用技巧，面试提出来很亮眼。** 注意 bitset 版**不需要倒序**（位移运算天然用的是旧值，整体右移不存在"本轮已更新"的问题）。

**复杂度**  时间 O(n × sum/2)，空间 O(sum/2)。本题 n ≤ 200、`sum ≤ 20000`，约 2×10⁶ 次操作，很快。bitset 版 O(n × sum / 128)。

**边界与坑**
- **`sum` 为奇数必须提前返回 false**。不判的话 `target = sum/2` 会因整数除法丢失精度，得到错误答案（如 `[1,2]`，`sum=3`，`target=1`，`dp[1]=true` 错答 true）。**这是本题头号坑。**
- **必须倒序遍历 `j`**。正序会退化成完全背包（元素可重复使用），答案偏 true。
- **`dp[0] = true` 必须设置**（空集的和是 0）。
- **内层循环下界是 `j >= x`**，防止 `j - x` 负下标。
- **`dp` 用 `vector<bool>`** 是可以的（本题只需布尔）。注意 `vector<bool>` 是位压缩特化，访问稍慢但省内存；换成 `vector<char>` 会更快一点。
- **元素必须是正整数**（题目保证 `nums[i] >= 1`）。**若允许 0**，答案不变（0 加不加都行）；**若允许负数**，`sum/2` 可能为负，背包模型失效，需要偏移值域。
- **不要用回溯枚举子集**——O(2²⁰⁰) 不可行。**"只问存在性/计数/最优值 → 换 DP"**，这是本题存在的意义。
- `sum` 累加可能溢出吗：200 × 100 = 20000，安全。

**追问 / 变体**
- **698 划分为 k 个相等的子集**：k > 2 时**不能**简单套背包（要同时满足 k 个约束），需要**状压 DP** 或**回溯 + 强剪枝**。**这说明 416 能用背包正是因为 k = 2 的特殊性**（选出一半，剩下的自动成立）。
- **494 目标和**（给每个数加 +/- 号使和为 target）：转化成「选出和为 `(sum + target) / 2` 的子集」，然后是 **01 背包求方案数**（`dp[j] += dp[j-x]`）。**这个转化很经典。**
- **1049 最后一块石头的重量 II**：转化成「尽可能把石头分成两堆重量接近」= 求不超过 `sum/2` 的最大子集和，同一个背包。
- **474 一和零**：二维费用的 01 背包（同时限制 0 的个数和 1 的个数），两层倒序。
- **返回具体的分割方案**：需要二维 `dp[i][j]` 记录（不能用滚动数组），然后倒推。**这是"滚动数组省空间的代价"**——丢失了路径信息。
- **和不能整除但求最接近的分割**：改成求 `max{ j : j <= sum/2 且 dp[j] }`，即 1049。
- **78 子集**：枚举所有子集用回溯，见 [10-回溯](10-回溯.md)。**78 → 416 是"枚举 → DP"的标准跃迁，本专题反复强调。**

### 32. 最长有效括号（困难）

**题意**  只含 `(` 和 `)` 的字符串，求**最长有效（格式正确且连续）括号子串**的长度。

**暴力**  枚举所有子串（O(n²) 个），用 [20 题](12-栈.md) 的计数法判断是否有效（O(n)），总 O(n³)。优化成"边扩展边计数"可降到 O(n²)：对每个起点向右扫，维护 `balance`，`balance == 0` 时更新答案，`balance < 0` 时 break。n = 3×10⁴ 时 O(n²) 约 10⁹，会超时。

**关键洞察**

本题有**三种正解**，各有各的巧妙，建议都掌握——面试写栈法最稳。

---

**思路一：栈存下标（最推荐，最好想）**

关键设计：**栈里存的不是括号，而是下标**；栈底放一个**哨兵 `-1`**，代表「最后一个未匹配的右括号的位置」。

- 遇到 `(` → 压入它的下标（等待匹配）。
- 遇到 `)` → 弹出栈顶：
  - 若栈**变空**了，说明这个 `)` 没有左括号与之匹配，它成为新的"分界点" → **压入它的下标**（更新哨兵）。
  - 若栈**非空**，说明匹配成功，当前有效长度 = **`i - st.top()`**（`st.top()` 是当前这段有效子串左边界的**前一个**位置）。

**核心理解**：**栈底元素始终是"当前有效段的左边界之前的那个位置"**。所以 `i - st.top()` 直接给出以 `i` 结尾的有效长度，不需要额外记录。哨兵 `-1` 让第一段（从下标 0 开始）也能正确计算：`i - (-1) = i + 1`。

**这个"栈底存分界点 + 哨兵"的设计是本题最优雅的地方。**

---

**思路二：DP**

**状态定义**：`dp[i]` = 「**以 `s[i]` 结尾**的最长有效括号子串长度」。

**关键观察：`dp[i] = 0` 当 `s[i] == '('`** —— 以左括号结尾的子串永远无效。所以只需处理 `s[i] == ')'` 的情况，分两种：

1. **`s[i-1] == '('`** → 形如 `...()`，这两个刚好配对：
   ```
   dp[i] = dp[i-2] + 2
   ```

2. **`s[i-1] == ')'`** → 形如 `...))`。要让它有效，前面那段有效子串（长度 `dp[i-1]`）之前必须有一个 `(` 与当前的 `)` 配对。那个位置是 `i - dp[i-1] - 1`：
   ```
   若 s[i - dp[i-1] - 1] == '('：
       dp[i] = dp[i-1] + 2 + dp[i - dp[i-1] - 2]
   ```
   最后那项 `dp[i - dp[i-1] - 2]` 是**把这一段之前紧邻的有效子串也接上**——例如 `()(())`，不接就会漏掉前面的 `()`。**这一项最容易漏。**

答案是 `max(dp[i])`。

---

**思路三：两次遍历计数（O(1) 空间，最巧）**

从左到右扫，维护 `left`（`(` 的个数）和 `right`（`)` 的个数）：
- `left == right` 时更新答案 `2 * right`
- `right > left` 时说明右括号过多，**整段作废**，两个计数器归零

**但只从左到右会漏掉 `"(()"` 这种情况**（左括号永远多于右括号，`left == right` 从未成立于最优段）。所以**再从右到左扫一遍**，对称地在 `left > right` 时归零。**两次遍历合起来覆盖所有情况。**

**为什么两次就够**：任何有效子串要么在"右括号先超"的边界内被第一次扫描捕获，要么在"左括号先超"的边界内被第二次捕获。

**最优解（C++，栈存下标）**

```cpp
class Solution {
public:
    int longestValidParentheses(string s) {
        stack<int> st;
        st.push(-1);                        // 哨兵：有效段左边界的前一个位置
        int best = 0;
        for (int i = 0; i < (int)s.size(); ++i) {
            if (s[i] == '(') {
                st.push(i);                 // 左括号入栈等待匹配
            } else {
                st.pop();                   // 尝试匹配
                if (st.empty()) st.push(i); // 无法匹配 → 它成为新的分界点
                else best = max(best, i - st.top());   // 匹配成功，算长度
            }
        }
        return best;
    }
};
```

**DP 版**

```cpp
int longestValidParentheses(string s) {
    int n = s.size(), best = 0;
    vector<int> dp(n, 0);                   // dp[i] = 以 s[i] 结尾的最长有效长度
    for (int i = 1; i < n; ++i) {
        if (s[i] != ')') continue;          // 以 '(' 结尾必然是 0
        if (s[i-1] == '(') {
            dp[i] = (i >= 2 ? dp[i-2] : 0) + 2;              // 形如 ...()
        } else {
            int j = i - dp[i-1] - 1;        // 待匹配的左括号位置
            if (j >= 0 && s[j] == '(')
                dp[i] = dp[i-1] + 2 + (j >= 1 ? dp[j-1] : 0);// 形如 ...((...))
        }
        best = max(best, dp[i]);
    }
    return best;
}
```

**两次遍历版（O(1) 空间）**

```cpp
int longestValidParentheses(string s) {
    int n = s.size(), best = 0;
    int left = 0, right = 0;
    for (int i = 0; i < n; ++i) {                    // 从左到右
        if (s[i] == '(') ++left; else ++right;
        if (left == right) best = max(best, 2 * right);
        else if (right > left) left = right = 0;     // 右括号超了，作废重来
    }
    left = right = 0;
    for (int i = n - 1; i >= 0; --i) {               // 从右到左
        if (s[i] == '(') ++left; else ++right;
        if (left == right) best = max(best, 2 * left);
        else if (left > right) left = right = 0;     // 对称条件
    }
    return best;
}
```

**复杂度**  栈法：O(n) 时间 O(n) 空间；DP：O(n) 时间 O(n) 空间；两次遍历：**O(n) 时间 O(1) 空间**（三者中最优）。

**边界与坑**
- **栈法的哨兵 `-1` 不能省**。没有它，第一段有效子串（如 `"()"`）会算错：弹出后栈空，无法算 `i - st.top()`。**这是栈法的核心设计。**
- **栈法遇到 `)` 时是"先 pop 再判空"**，顺序不能反。`pop` 掉的可能是哨兵，此时栈空说明无法匹配。
- **栈里存下标不存字符**。存字符就算不出长度了。
- **DP 版的第二种情况必须加上 `dp[j-1]`**。漏了这一项，`"()(())"` 会算出 4 而不是 6。**这是 DP 版头号 bug。**
- **DP 版的下标要防越界**：`i >= 2`、`j >= 0`、`j >= 1` 三处判断都不能省。
- **两次遍历版必须扫两遍**。只扫一遍时 `"(()"` 会错答 0（正确是 2）——因为 `left` 始终大于 `right`，`left == right` 从未成立。**这是这个解法最容易被忽略的地方。**
- **两次遍历版第二遍的更新用 `2 * left`**（不是 `2 * right`），且归零条件是 `left > right`。**两遍的条件和统计量都是对称相反的**，抄错就废。
- 空串返回 0；`"("` 或 `")"` 返回 0。
- **答案是"长度"不是"对数"**，所以是 `2 * right` 而不是 `right`。
- **别和 [20 有效的括号](12-栈.md) 混**：20 判断**整个串**是否有效（返回 bool），本题求**最长有效子串**（返回长度），解法完全不同。

**追问 / 变体**
- **20 有效的括号**：判断整串，用栈匹配，见 [12-栈](12-栈.md)。
- **22 括号生成**：生成所有有效组合，用回溯，见 [10-回溯](10-回溯.md)。**20/22/32 三题都是括号，但分别对应"判断/生成/最优子串"三种问法，解法各不相同——这个对比很值得梳理。**
- **返回最长有效子串本身**：栈法里记录更新 `best` 时的 `st.top() + 1` 作为起点。
- **多种括号类型**（`()[]{}`）：栈里要存字符类型，且不匹配时整段作废。DP 法难以推广。
- **1249 移除无效括号 / 921 使括号有效的最少添加**：都是计数器贪心，O(1) 空间。
- **允许删除 k 个字符求最长有效**：加一维状态 `dp[i][k]`。
- **为什么三种解法都是 O(n)**：栈法每个下标入栈出栈各一次；DP 法一次遍历；计数法两次遍历。**三种思路殊途同归，但计数法空间最优——面试可以先写栈法（好解释），再提计数法（O(1) 空间）作为优化。**
