# 12 · 栈（5 题）

## 套路总纲

栈的用途高度集中在两类，**认出属于哪一类，题就解了一半**。

**类型一：括号 / 嵌套结构匹配**（20、394）

**识别信号**：题面出现「括号」「嵌套」「成对」「优先级」「层层包裹」。

核心思想：**后进先出正好对应"最内层的先结算"**。遇到开始符号就入栈保存现场，遇到结束符号就弹栈结算。394 字符串解码是这个模式的完整形态——**入栈保存现场、出栈恢复现场**。

**类型二：单调栈**（739、84；以及 [42 接雨水](02-双指针.md)）

**识别信号**：**「下一个更大 / 更小的元素」「左右第一个比它 X 的位置」「以某元素为最值的最大区间」**。看到这类描述，几乎一定是单调栈。

**单调栈模板（求"下一个更大元素"，栈内递减）**

```cpp
vector<int> nextGreater(vector<int>& a) {
    int n = a.size();
    vector<int> ans(n, -1);              // 默认没有更大的
    stack<int> st;                       // 存下标，不存值（这样能算距离）
    for (int i = 0; i < n; ++i) {
        while (!st.empty() && a[st.top()] < a[i]) {   // 当前元素比栈顶大
            ans[st.top()] = i;           // 栈顶等到了它的"下一个更大元素"
            st.pop();
        }
        st.push(i);
    }
    return ans;
}
```

**单调栈的核心理解**（想通这一点就不用背了）：

> 栈里存的是**「还在等待结果的元素」**。一个元素被弹出，意味着**它的答案在此刻被确定了**。

- 求**下一个更大** → 栈内**单调递减**，遇到更大的就弹（弹出者找到了答案）。
- 求**上一个更大** → 同样栈内递减，但答案在**入栈时**看栈顶。
- 求**下一个更小** → 栈内**单调递增**。

**存下标而不是存值**：这样既能取到值 `a[st.top()]`，又能算距离 `i - st.top()`。**这是单调栈的固定写法**，739 求的就是距离。

**84 的关键升级**：需要同时知道「左边第一个更小」和「右边第一个更小」。技巧是**在弹栈的那一刻，左右边界同时就位**——弹出元素的右边界是当前 `i`，左边界是弹出后的新栈顶。这个"一次遍历同时拿到两侧边界"的手法是单调栈的精髓，务必吃透。

**类型三：辅助栈设计**（155）

**识别信号**：要求某个查询是 O(1)，而栈本身只支持顶部操作。

核心思想：**用第二个栈同步维护"到当前状态为止的某个聚合量"**。因为栈的变化是严格 LIFO 的，历史状态可以被完整保存和恢复——**这是"栈能做 O(1) 历史查询"的根本原因**（数组/队列做不到）。

**C++ 提示**
- `stack<int>` 默认底层是 `deque`。想更快可用 `stack<int, vector<int>>`。
- **`st.top()` 在空栈上是未定义行为**，每次访问前必须 `!st.empty()`。这是本专题最常见的崩溃原因。
- `pop()` 返回 `void`，要先 `top()` 取值再 `pop()`。

**难度递进**：20 是最基础的匹配 → 155 是设计题 → 394 是嵌套 + 现场保存 → 739 是单调栈模板 → 84 是单调栈的困难应用。**84 吃透了，[42 接雨水](02-双指针.md) 也就通了。**

### 20. 有效的括号（简单）

**题意**  判断只含 `()[]{}` 的字符串是否有效：括号必须以正确的顺序闭合。

**暴力**  反复扫描删除相邻的 `()`、`[]`、`{}` 直到无法删除，最后看是否为空串。O(n²)，思路正确但低效——它的每一轮都在重新扫描整个串。

**关键洞察**

**核心认识：最近打开的括号必须最先关闭。** 这正是**后进先出**的定义，所以用栈。

- 遇到**左括号** → 入栈（记录"有一个待关闭的括号"）。
- 遇到**右括号** → 它必须匹配**栈顶**那个左括号。匹配则弹栈，不匹配则整个串无效。

**三种失败情形要全部覆盖**（漏一种就是常见 bug）：

1. **类型不匹配**：`([)]` —— 遇到 `)` 时栈顶是 `[`。
2. **右括号多余**：`())` —— 遇到 `)` 时栈已空（没有待匹配的左括号）。
3. **左括号多余**：`(()` —— 扫描结束时栈非空。**这一条最容易忘**，必须在最后 `return st.empty()`。

**长度为奇数必然无效**，可以在开头 O(1) 剪掉。

**最优解（C++）**

```cpp
class Solution {
public:
    bool isValid(string s) {
        if (s.size() % 2 == 1) return false;          // 奇数长度必然无效
        unordered_map<char, char> pairs = {           // 右括号 -> 对应的左括号
            {')', '('}, {']', '['}, {'}', '{'}
        };
        stack<char> st;
        for (char c : s) {
            auto it = pairs.find(c);
            if (it == pairs.end()) {                  // 是左括号
                st.push(c);
            } else {                                  // 是右括号
                if (st.empty() || st.top() != it->second) return false;  // 空栈 或 类型不符
                st.pop();
            }
        }
        return st.empty();                            // 关键：不能有剩余的左括号
    }
};
```

**不用哈希表的紧凑版（switch 直接压入期待的右括号）**

```cpp
bool isValid(string s) {
    stack<char> st;
    for (char c : s) {
        if (c == '(') st.push(')');                   // 压入"我期待看到的右括号"
        else if (c == '[') st.push(']');
        else if (c == '{') st.push('}');
        else {                                        // 遇到右括号
            if (st.empty() || st.top() != c) return false;
            st.pop();
        }
    }
    return st.empty();
}
```

**这个写法很讨巧**：入栈时直接存"期待的闭合符"，比较时一个 `!=` 就够，不需要映射表。面试写这个能省不少时间。

**复杂度**  时间 O(n)，空间 O(n)（最坏全是左括号，如 `"((((("`）。

**边界与坑**
- **`return st.empty()` 不能写成 `return true`**。`"(("` 会被错判为有效。**这是本题头号 bug。**
- **`st.top()` 前必须先判 `st.empty()`**。`")"` 这个输入会直接崩溃（UB）。**短路求值 `st.empty() || ...` 的顺序不能反。**
- 空串 `""` 是**有效**的（返回 true），符合题意。
- 奇数长度剪枝是优化不是必需，但能省一半无用功。
- **不要只统计各种括号的数量**。`)(` 数量平衡但无效，`([)]` 也是。**顺序信息必须靠栈保留**，计数法从根本上不行——这是很好的"为什么需要栈"的解释。
- 题目保证只有这六种字符。若含其他字符（如字母），要明确它们是"忽略"还是"非法"，`pairs.find` 版本会把它们当左括号压栈导致出错，需要额外判断。

**追问 / 变体**
- **22 括号生成**：本题的"生成"版，用回溯，见 [10-回溯](10-回溯.md)。**20 判断 + 22 生成，一起看能加深理解。**
- **32 最长有效括号**：求最长有效子串长度，栈或 DP，见 [15-动态规划](15-动态规划.md)。
- **921 使括号有效的最少添加 / 1249 移除无效括号**：只有一种括号时可以退化成**两个计数器**（`open`、`need`），O(1) 空间。**单一括号类型不需要栈**，这个优化值得知道。
- **1541 平衡括号字符串的最少插入次数**：加权匹配（一个 `(` 需要两个 `)`）。
- **含通配符 `*`**（678 有效的括号字符串）：`*` 可当左、右或空，用贪心维护 `[minOpen, maxOpen]` 区间。
- **表达式求值中的括号**：见 394 和 224，栈的用法更复杂（需要保存运算符和中间结果）。

### 155. 最小栈（中等）

**题意**  设计支持 `push`、`pop`、`top`、`getMin` 的栈，**四个操作都要 O(1)**。

**暴力**  `getMin` 时遍历整个栈找最小值，O(n)。或者维护一个变量 `minVal`：`push` 时更新是 O(1)，但**`pop` 弹出的恰好是最小值时，就不知道次小值是多少了**，必须重新遍历 → O(n)。

**这个失败正是本题的关键**：单个变量无法"恢复历史"。

**关键洞察**

**核心认识：栈的操作是严格 LIFO 的，所以「每个时刻的最小值」可以被完整地保存和恢复。**

具体做法：**用一个辅助栈，同步记录「当栈里有前 i 个元素时，最小值是多少」**。

- `push(x)`：主栈压 `x`，辅助栈压 `min(x, 当前最小值)`。
- `pop()`：**两个栈同时弹**。这样辅助栈的新栈顶自动就是"剩余元素的最小值"——**历史被自动恢复了**。
- `getMin()`：返回辅助栈顶，O(1)。

**为什么这样是对的**：两个栈**高度始终相同**，`minStack[i]` 的语义是「主栈前 `i+1` 个元素的最小值」。因为 pop 只会从顶部移除，所以底下那些"历史最小值"始终有效，不需要重算。**这是"栈的 LIFO 性质使得历史可复用"的直接体现。**

**空间优化（进阶）**：辅助栈只在「新元素 ≤ 当前最小值」时才压入，`pop` 时只有「弹出的值 == 辅助栈顶」才同时弹。这样重复的最小值不会占空间，但**必须用 `<=` 而不是 `<`**（见"边界与坑"）。

**最优解（C++，双栈同步，最稳）**

```cpp
class MinStack {
    stack<int> st;        // 主栈
    stack<int> mn;        // 辅助栈：mn.top() 恒为 st 中所有元素的最小值
public:
    MinStack() {}

    void push(int val) {
        st.push(val);
        mn.push(mn.empty() ? val : min(val, mn.top()));   // 同步压入"当前最小值"
    }

    void pop() {
        st.pop();
        mn.pop();                                          // 两栈同步弹出
    }

    int top()    { return st.top(); }
    int getMin() { return mn.top(); }
};
```

**空间优化版（辅助栈只存"最小值变化点"）**

```cpp
class MinStack {
    stack<int> st, mn;
public:
    void push(int val) {
        st.push(val);
        if (mn.empty() || val <= mn.top()) mn.push(val);    // 必须是 <= ！
    }
    void pop() {
        if (st.top() == mn.top()) mn.pop();                 // 弹出的是当前最小值
        st.pop();
    }
    int top()    { return st.top(); }
    int getMin() { return mn.top(); }
};
```

**单栈 + 差值法（O(1) 额外空间，炫技向）**

```cpp
class MinStack {
    stack<long long> st;       // 存的是 val - minVal 的差值
    long long minVal = 0;
public:
    void push(int val) {
        if (st.empty()) { st.push(0); minVal = val; return; }
        st.push((long long)val - minVal);                  // 存差值
        if (val < minVal) minVal = val;                    // 更新最小值
    }
    void pop() {
        long long diff = st.top(); st.pop();
        if (diff < 0) minVal -= diff;                      // 弹出的是最小值，恢复上一个
    }
    int top() {
        long long diff = st.top();
        return (int)(diff > 0 ? diff + minVal : minVal);
    }
    int getMin() { return (int)minVal; }
};
```

思路：栈里存的是**相对当前最小值的差值**。差值为负说明这个元素当时刷新了最小值，弹出时可以据此**反推**出上一个最小值（`minVal_prev = minVal - diff`）。**必须用 `long long`**，因为两个 `int` 相减可能溢出。这个解法很妙，但面试首选双栈版——清晰、不易错。

**复杂度**  四个操作均 **O(1)**。空间 O(n)（双栈版最多 2n，优化版和差值版更省）。

**边界与坑**
- **空间优化版必须用 `val <= mn.top()`，不能用 `<`**。反例：`push(1), push(1), pop()`。用 `<` 时辅助栈只有一个 1，第一次 `pop` 就把它弹掉了，之后 `getMin` 读到的是空栈/错误值。**用 `<=` 保证重复的最小值都被记录，每次 pop 都能正确对应。这是本题最经典的坑。**
- **双栈同步版必须两栈同时 pop**。只弹主栈会让高度不一致，`getMin` 全错。
- `mn.empty() ? val : min(val, mn.top())` 的三目不能漏——第一次 push 时辅助栈是空的，`mn.top()` 是 UB。
- 题目保证 `pop`/`top`/`getMin` **只在非空栈上调用**，所以不用额外判空。但生产代码应该判。
- 差值法**必须用 `long long`**。`val - minVal` 在 `val = INT_MIN, minVal = INT_MAX` 时溢出 `int`。
- 不要试图用「一个变量存最小值」——见"暴力"部分，pop 掉最小值后无法恢复。**想清这一点是解题的起点。**
- `getMin` 不改变栈的状态（只读）。

**追问 / 变体**
- **最大栈**（716）：对称地维护最大值。注意 716 还要求 `popMax()`，那需要更复杂的结构（双向链表 + 有序集合），难度陡增。
- **支持 O(1) 求和 / 求平均**：辅助栈存前缀和，同理。**"任何可增量维护的聚合量都能这样做"是本题的推广。**
- **最小队列**（用两个栈实现队列 + 各自维护最小值，或用单调双端队列）：队列不是 LIFO，历史无法简单恢复，所以要用**单调队列**，见 [239 滑动窗口最大值](04-子串.md)。**这个对比很能说明"为什么栈比队列容易"。**
- **232 用栈实现队列 / 225 用队列实现栈**：容器互相模拟的经典设计题。
- **多线程安全的最小栈**：加锁，或用无锁的 CAS 结构。
- **为什么不用 `priority_queue`**：堆能 O(1) 取最小，但**无法高效删除"栈顶那个特定元素"**（需要 O(n) 查找或额外的懒删除机制），不匹配栈的语义。这是个好的反向追问。

### 394. 字符串解码（中等）

**题意**  解码形如 `k[encoded_string]` 的字符串，表示方括号内的内容重复 `k` 次。可以**嵌套**，如 `"3[a2[c]]"` → `"accaccacc"`。

**暴力**  反复用正则/字符串查找找到**最内层**的 `k[...]`（内层的特征是括号内无其他括号），展开后替换，重复直到没有括号。可行但每轮都要重新扫描，且字符串反复拷贝，效率低、实现也麻烦。

**关键洞察**

**嵌套结构 = 栈。** 关键在于想清楚**"入栈时保存什么、出栈时恢复什么"**——这是所有"嵌套解析"题的通用框架。

遇到 `[` 时，我们要暂时**离开当前的工作现场**去处理内层。那么"现场"包括两样东西：

1. **`[` 之前已经拼好的字符串**（外层的前缀）
2. **这个 `[` 对应的重复次数 `k`**

处理完内层、遇到 `]` 时，把内层结果重复 `k` 次，**追加到恢复出来的外层前缀后面**。

所以用两个栈（也可以用一个存 pair 的栈）：

| 字符 | 动作 |
|---|---|
| 数字 | 累积 `num = num * 10 + (c - '0')`（**可能是多位数！**） |
| `[` | `numStack.push(num)`、`strStack.push(cur)`，然后 **`num = 0`、`cur = ""`**（清空，开始新的内层） |
| `]` | 取出 `k = numStack.top()` 和 `prev = strStack.top()`，`cur = prev + cur × k` |
| 字母 | `cur += c` |

**最关键的两处**：
- `[` 时**必须清空 `cur` 和 `num`**，否则内层会继承外层的内容。
- `]` 时是 `cur = prev + cur * k`，**顺序是「外层前缀 + 重复后的内层」**，写反就全乱了。

**数字要累积成多位数**：`"100[a]"` 里的 `k` 是 100 不是 1、0、0。`num = num * 10 + (c - '0')` 是标准写法。

**最优解（C++）**

```cpp
class Solution {
public:
    string decodeString(string s) {
        stack<int> numStack;          // 保存各层的重复次数
        stack<string> strStack;       // 保存各层的"[ 之前的前缀"
        string cur;                   // 当前层正在拼接的结果
        int num = 0;                  // 当前累积的数字

        for (char c : s) {
            if (isdigit(c)) {
                num = num * 10 + (c - '0');      // 多位数累积
            } else if (c == '[') {
                numStack.push(num);              // 保存现场
                strStack.push(cur);
                num = 0;                         // 清空，进入内层
                cur.clear();
            } else if (c == ']') {
                int k = numStack.top(); numStack.pop();
                string prev = strStack.top(); strStack.pop();
                string repeated;
                repeated.reserve(cur.size() * k);
                while (k--) repeated += cur;     // 内层重复 k 次
                cur = prev + repeated;           // 恢复现场：外层前缀 + 重复结果
            } else {
                cur += c;                        // 普通字母
            }
        }
        return cur;
    }
};
```

**递归版（思路更直白，用下标引用推进）**

```cpp
class Solution {
    string parse(const string& s, int& i) {       // i 传引用，保证子调用推进后外层能接着走
        string res;
        int num = 0;
        while (i < (int)s.size() && s[i] != ']') {
            char c = s[i];
            if (isdigit(c)) { num = num * 10 + (c - '0'); ++i; }
            else if (c == '[') {
                ++i;                              // 跳过 '['
                string inner = parse(s, i);       // 递归处理内层
                ++i;                              // 跳过 ']'
                while (num--) res += inner;
                num = 0;
            } else { res += c; ++i; }
        }
        return res;
    }
public:
    string decodeString(string s) { int i = 0; return parse(s, i); }
};
```

**递归和栈是同一件事**——递归用调用栈自动保存现场，显式栈是手动保存。两种都值得会：递归版更短，栈版不怕深度嵌套爆栈。

**复杂度**  时间 O(最终结果长度 × 嵌套深度) 上界；实际主要开销是字符串拼接。空间 O(最终长度 + 嵌套深度)。

> 严格分析：每层的内容可能被外层反复拷贝，所以最坏是 O(L · d)（L 为结果长度，d 为深度）。面试如实说「主要开销在字符串拼接，最坏 O(结果长度 × 深度)」即可。

**边界与坑**
- **`[` 时必须同时清空 `cur` 和 `num`**。不清 `cur`，内层会带上外层已有的字符（`"2[a]3[b]"` 会出错）；不清 `num`，下一个数字会接在旧数字后面。
- **`]` 时的拼接顺序是 `prev + repeated`**，不是 `repeated + prev`。写反会把外层前缀挪到后面。
- **数字必须累积多位**：`num = num * 10 + (c - '0')`。只写 `num = c - '0'` 时 `"12[a]"` 会当成 2 次。
- **`while (k--) repeated += cur;` 会修改 `k`**，如果后面还要用 `k` 就得存副本。这里用完即弃，没问题。
- **`isdigit` 需要 `<cctype>`**，且参数是负值 `char` 时是 UB（本题只有 ASCII，安全）。手写 `c >= '0' && c <= '9'` 更保险。
- 题目保证输入**合法**（括号匹配、`k` 是正整数、方括号内无数字），所以不需要错误处理。若不保证，要加空栈检查。
- **`k` 可能是 0 吗**：题目说 `1 <= k <= 300`，所以不会。若允许 0，`while(k--)` 正确地什么都不做。
- 递归版的 **`int& i` 必须传引用**。传值会让外层的 `i` 不前进，死循环。**这是"用引用共享解析位置"的经典写法**，写解析器时非常常用。
- 结果可能很长（`k` 最大 300、可嵌套），但题目保证输出长度不超过 10⁵。

**追问 / 变体**
- **嵌套深度很大（10⁴ 级）**：递归版会**爆栈**，必须用显式栈版。这是选择显式栈的实际理由。
- **726 原子的数量**：化学式解析，`Mg(OH)2` 这类，同样的"栈保存现场"框架 + 需要合并计数。
- **224 基本计算器 / 227 计算器 II**：带 `+-*/` 和括号的表达式求值。同样是栈保存现场，但要额外处理运算符优先级。**394 是学这类题的最佳起点。**
- **反向操作（编码/压缩）**：求最短的编码表示，是困难的（涉及最优分解）。
- **输出长度爆炸**（如 `300[300[300[a]]]`）：结果有 2.7×10⁷ 个字符，必须改成**只求长度**（`len = k * innerLen`，不实际拼接）或流式输出。**"能识别出何时不该真的构造结果"是很好的工程直觉。**
- **1096 花括号展开 II**：更复杂的嵌套语法，需要集合运算。

### 739. 每日温度（中等）

**题意**  数组 `temperatures`，对每一天求「**还要等几天**才会遇到更高的温度」；若之后都不更高，填 0。

**暴力**  对每个 `i` 向右扫描找第一个更大的元素，O(n²)。n = 10⁵ 时 10¹⁰ 次操作，必然超时。

浪费在哪：`[70, 71, 72, ..., 100]` 这种递增数据，每个位置都要扫到很远，且**扫描过程中获得的信息被完全丢弃了**——第 `i` 天扫过的那些"比它小的天"，其实对第 `i+1` 天的判断也有用。

**关键洞察**

这是**单调栈的模板题**：「求下一个更大元素的距离」。

**核心思路**：维护一个栈，**存的是「还没找到更高温度的那些天的下标」**。

- 新的一天 `i` 到来时，**它可能就是栈里某些天等待的答案**。
- 所以：只要 `t[i] > t[栈顶]`，就说明栈顶这一天等到了更高温度，**弹出它并记录答案 `ans[栈顶] = i - 栈顶`**。反复弹，直到栈顶温度 ≥ `t[i]`。
- 然后把 `i` 入栈（它开始等待自己的答案）。

**为什么栈里一定是单调递减的**：能留在栈里的元素都"没被弹出"，说明后来的每一天都不比它高。所以从栈底到栈顶，温度严格递减（相等时也留着，见下）。

**为什么复杂度是 O(n)**：每个下标**最多入栈一次、出栈一次**，总操作 2n。虽然内层是 `while` 循环，但所有 `while` 的总迭代次数被"总弹出次数 ≤ n"限制住了——**这是典型的均摊分析**，和 [128 最长连续序列](01-哈希.md) 的均摊思路异曲同工。

**为什么存下标而不是温度**：答案要的是**距离** `i - st.top()`，必须有下标。**这是单调栈的标准做法。**

**最优解（C++）**

```cpp
class Solution {
public:
    vector<int> dailyTemperatures(vector<int>& temperatures) {
        int n = temperatures.size();
        vector<int> ans(n, 0);              // 默认 0：之后没有更高温度
        stack<int> st;                      // 存下标；栈内对应温度单调递减
        for (int i = 0; i < n; ++i) {
            while (!st.empty() && temperatures[st.top()] < temperatures[i]) {
                ans[st.top()] = i - st.top();     // 栈顶等到了答案，距离是 i - 栈顶
                st.pop();
            }
            st.push(i);                     // 自己开始等待
        }
        return ans;                         // 留在栈里的天数保持 0
    }
};
```

**从右往左的写法（等价，有人觉得更直观）**

```cpp
vector<int> dailyTemperatures(vector<int>& t) {
    int n = t.size();
    vector<int> ans(n, 0);
    stack<int> st;
    for (int i = n - 1; i >= 0; --i) {
        while (!st.empty() && t[st.top()] <= t[i]) st.pop();   // 弹掉不可能成为答案的
        if (!st.empty()) ans[i] = st.top() - i;                // 栈顶就是下一个更大元素
        st.push(i);
    }
    return ans;
}
```

**注意两种写法的不等号方向不同**：从左往右用 `<`（严格大于才弹），从右往左用 `<=`（相等也要弹，因为相等的不是"更高温度"）。**混用会错**，这是很容易踩的坑。

**复杂度**  时间 **O(n)** 均摊，空间 O(n)（栈最坏装下所有下标，如单调递减数组）。

**边界与坑**
- **不等号必须是严格 `<`**（从左往右版）。题目要"更高"的温度，温度**相等不算**。写成 `<=` 会让相等的那天被错误地当成答案。测试用例 `[73,73,75]` 专卡这个：第 0 天的答案应是 2 不是 1。
- **`ans` 初值必须是 0**，且**留在栈里的元素不要额外处理**——它们的答案天然是 0。
- **存下标不存温度**。存温度就算不出距离了。
- **`st.top()` 前必须判 `!st.empty()`**，且短路顺序不能反。
- **答案是 `i - st.top()` 不是 `i`**，也不是 `st.top() - i`（从左往右版里 `i > st.top()`）。**方向搞反会得到负数。**
- 从右往左版**必须先弹完再判空取答案**，且要用 `<=`。两种写法的逻辑不能混。
- 内层是 `while` 不是 `if`——一个新元素可能一次性解决多个等待者（如 `[75,74,73,76]`，76 一次弹出三个）。写成 `if` 只弹一个，答案全错。
- n = 1 时返回 `[0]`。

**追问 / 变体**
- **496 下一个更大元素 I**（在另一个数组里找）：先用单调栈求出 `nums2` 每个元素的下一个更大元素存进哈希表，再查询。
- **503 下一个更大元素 II**（**循环数组**）：把数组"逻辑上遍历两遍"（`for i in [0, 2n)`，用 `i % n` 访问），第二遍只弹不压。**这个"遍历两遍模拟循环"的技巧很常用。**
- **901 股票价格跨度**：求"上一个更大元素"的距离，单调栈的镜像版（在**入栈前**看栈顶）。
- **42 接雨水**：单调栈的经典应用（也可用双指针），见 [02-双指针](02-双指针.md)。
- **84 柱状图中最大的矩形**：单调栈的困难应用，见下题。**739 → 42 → 84 是单调栈的标准进阶路径。**
- **求下一个更小元素**：栈内改成**单调递增**，弹出条件改成 `t[st.top()] > t[i]`。**"要什么单调性，取决于要求的是更大还是更小"**——这条规律记住就不用背四种模板了。
- **1019 链表中的下一个更大节点**：同样的单调栈，只是遍历链表。

### 84. 柱状图中最大的矩形（困难）

**题意**  给定 n 个非负整数表示柱状图各柱子的高度（宽度均为 1），求能勾勒出的**最大矩形面积**。

**暴力一（枚举左右边界）**  枚举所有区间 `[i, j]`，面积 = `(j - i + 1) × min(h[i..j])`。O(n³)，或边扫边维护最小值降到 O(n²)。n = 10⁵ 时必然超时。

**暴力二（枚举高度，更接近正解）**  **换个角度**：枚举「以哪根柱子的高度作为矩形的高」。对每根柱子 `i`，向左右尽可能扩展，直到遇到比它矮的柱子为止，面积 = `h[i] × 宽度`。O(n²)。

**为什么暴力二是正确的思路**：任何一个最大矩形，它的高度**必然等于其中某根柱子的高度**（否则可以往上抬高，仍然合法，矛盾）。所以只枚举 n 种高度就够了，不需要枚举 O(n²) 个区间。**这个转换是本题的第一个关键洞察。**

**关键洞察**

暴力二的瓶颈是「向左右扩展」要 O(n)。而它要找的东西恰好是：

> **对每根柱子 `i`，找左边第一个比它矮的位置 `L`，和右边第一个比它矮的位置 `R`。**
> 那么以 `h[i]` 为高的最大矩形宽度就是 `R - L - 1`，面积 `h[i] × (R - L - 1)`。

「左/右第一个更小的元素」——**这正是单调栈的标准问题**（[739](#739-每日温度中等) 求的是"更大"，这里求"更小"，把不等号反过来即可）。

**核心技巧：一次遍历同时拿到两侧边界。**

维护一个**栈内高度单调递增**的栈（存下标）。当遇到 `h[i] < h[栈顶]` 时，栈顶元素被弹出，**此刻它的两侧边界同时就位**：

- **右边界**就是当前的 `i`（第一个比它矮的）。
- **左边界**就是**弹出它之后的新栈顶**（栈内递增，所以新栈顶是它左边第一个比它矮的）。

于是宽度 = `i - newTop - 1`，面积 = `h[popped] × 宽度`。

**"弹出的那一刻，答案就能算出来"** —— 这是单调栈最精妙的地方，也是本题从 O(n²) 到 O(n) 的全部原因。想通这一句，题就解了。

**哨兵技巧（强烈推荐）**：在数组**首尾各加一个高度 0 的柱子**：

- **末尾的 0** 保证所有元素最终都会被弹出并结算（否则遍历结束后栈里还剩一堆递增元素需要额外循环处理）。
- **开头的 0** 保证栈永不为空，`newTop` 总能取到，省掉 `st.empty()` 的特判。

**加了两个哨兵，代码从十几行的边界处理缩到一个干净的循环** —— 这是本题最值得学的工程技巧。

**最优解（C++，单调栈 + 双哨兵）**

```cpp
class Solution {
public:
    int largestRectangleArea(vector<int>& heights) {
        vector<int> h;
        h.reserve(heights.size() + 2);
        h.push_back(0);                              // 左哨兵：保证栈非空
        for (int x : heights) h.push_back(x);
        h.push_back(0);                              // 右哨兵：保证全部结算

        int n = h.size(), best = 0;
        stack<int> st;                               // 存下标；栈内高度单调递增
        for (int i = 0; i < n; ++i) {
            while (!st.empty() && h[st.top()] > h[i]) {
                int top = st.top(); st.pop();        // top 的高度作为矩形高
                int left = st.top();                 // 弹出后的新栈顶 = 左边第一个更矮
                int width = i - left - 1;            // 右边界 i，左边界 left，都不含
                best = max(best, h[top] * width);
            }
            st.push(i);
        }
        return best;
    }
};
```

**不加哨兵的版本（对照，能看出哨兵省了多少事）**

```cpp
int largestRectangleArea(vector<int>& h) {
    int n = h.size(), best = 0;
    stack<int> st;
    for (int i = 0; i <= n; ++i) {
        int cur = (i == n) ? 0 : h[i];               // 虚拟的右哨兵
        while (!st.empty() && h[st.top()] > cur) {
            int top = st.top(); st.pop();
            int left = st.empty() ? -1 : st.top();   // 空栈时左边界视为 -1
            best = max(best, h[top] * (i - left - 1));
        }
        st.push(i);
    }
    return best;
}
```

注意 `i == n` 时 `st.push(i)` 会压入越界下标，但之后循环结束不再访问，无害；严谨起来可加 `if (i < n) st.push(i);`。

**复杂度**  时间 **O(n)**（每个下标入栈出栈各一次，均摊），空间 O(n)。

**边界与坑**
- **宽度是 `i - left - 1`，不是 `i - left`**。`left` 和 `i` 都是**边界外**的位置（分别是左边第一个更矮和右边第一个更矮），所以矩形实际占据 `(left, i)` 这个开区间，宽度是 `i - left - 1`。**这个 -1 是本题最高频的错误。** 建议用 `h = [2,1,2]` 手算验证一遍。
- **左边界必须是"弹出之后"的栈顶**。先 `pop()` 再取 `st.top()`，顺序不能反。写成先取 `top` 的下一个元素（不弹）会拿到自己。
- **右哨兵 0 不能省**。否则 `[1,2,3,4,5]` 这种递增数组结束时栈里还有 5 个元素从未结算，答案错成 0。
- **左哨兵让 `st.top()` 永远安全**。不加就必须写 `st.empty() ? -1 : st.top()`。
- **`h[st.top()] > h[i]` 用严格大于**。相等时**不弹**（留着），这样等高的柱子会被后面的元素一起结算，宽度自动累计正确。用 `>=` 也能得到正确答案（因为相等的柱子中最后一个会算出完整宽度），但会多做无用的弹栈——**结论：`>` 更好，`>=` 不会错**。这一点值得知道，因为很多题解两种都有。
- **`h[top] * width` 可能溢出 `int`**：本题 `h[i] <= 10^4`、`n <= 10^5`，最大面积 10⁹ < `INT_MAX`(≈2.1×10⁹)，**刚好安全**。但如果高度上限提到 10⁵ 就会溢出，稳妥起见可用 `long long`。面试主动提这一点是加分项。
- 全 0 数组返回 0；单根柱子返回它的高度。
- **拷贝数组加哨兵会多用 O(n) 空间**。若要求严格 O(1) 额外空间（除栈外），用不加哨兵的版本。

**追问 / 变体**
- **85 最大矩形**（0/1 矩阵中的最大全 1 矩形）：**把每一行看作"柱状图的底"**，`heights[j]` = 从当前行往上连续 1 的个数，然后对每一行跑一次本题的 O(n) 算法，总复杂度 O(mn)。**这是 84 最重要的应用，两题必须一起刷。**
- **42 接雨水**：同样是单调栈（也可双指针），但求的是"凹陷"而非"矩形"，栈内单调性相反（递减）。见 [02-双指针](02-双指针.md)。**42 和 84 是单调栈的两面，对比着看能彻底吃透。**
- **1793 好子数组的最大分数**：固定必须包含某个下标，是本题的变形。
- **分治解法**：找区间最小值，答案 = `max(跨过最小值的矩形, 左半递归, 右半递归)`。平均 O(n log n)，最坏 O(n²)（有序数组时），且需要 RMQ 优化才实用。**面试可以提这个思路作为对比，说明为什么单调栈更优。**
- **只求最大正方形**（221）：约束变成宽高相等，改用 DP `dp[i][j] = min(上, 左, 左上) + 1`，思路完全不同。
- **在线版本（柱子动态加入）**：需要平衡树或线段树维护，单调栈不适用（它依赖离线的一次性遍历）。
- **为什么"最大矩形的高必是某根柱子的高"**：反证——若矩形顶部没有碰到任何柱子的顶，可以整体上移直到碰到，面积更大，矛盾。**这个论证是暴力二成立的基础，面试值得说出来。**
