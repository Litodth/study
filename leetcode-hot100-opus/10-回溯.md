# 10 · 回溯（8 题）

## 套路总纲

回溯 = **DFS + 撤销选择**。它系统性地枚举所有候选解，一旦发现当前分支不可能成功就立刻退回。8 道题几乎共用同一个骨架，**把模板背下来，剩下的只是填三个空**。

**通用模板**

```cpp
void backtrack(状态) {
    if (满足终止条件) { ans.push_back(path); return; }
    for (每个候选选择 c) {
        if (c 不合法) continue;        // 剪枝
        path.push_back(c);             // ① 做选择
        backtrack(新状态);             // ② 递归进入下一层
        path.pop_back();               // ③ 撤销选择 ← 回溯的灵魂
    }
}
```

**三个必答的问题**（每道题只需回答这三个）

1. **路径 `path` 是什么？** 已经做出的选择序列。
2. **候选集是什么？** 当前这一层可以选哪些？——`for` 循环的范围。
3. **终止条件是什么？** 什么时候 `path` 是一个完整答案？

**做选择 / 撤销选择必须严格配对**。`push_back` 和 `pop_back` 之间夹着递归调用，形成完美对称。忘记撤销是回溯的头号 bug，症状是答案里出现越来越长的脏路径。

**四种「候选集」模式**（决定了 `for` 的起点，这是排列/组合/子集类题目的分水岭）

| 模式 | for 起点 | 典型题 | 含义 |
|---|---|---|---|
| **排列** | 每层从 0 开始 + `used[]` 标记 | 46、51 | 顺序有意义，每个元素用一次 |
| **组合/子集** | 每层从 `start` 开始 | 78、39、131 | 顺序无意义，靠 `start` 单向前进防重复 |
| **可重复选取** | 递归传 `i` 而非 `i + 1` | 39 | 同一元素可反复用 |
| **多叉映射** | 由当前下标决定候选 | 17、22、79 | 每层的候选集由题目结构给出 |

**「start 参数」是组合类题目的核心**：它保证了每个组合只按下标升序生成一次，从而**天然去重**，不需要 `set`。这一点务必想清——`{1,2}` 和 `{2,1}` 在组合里是同一个，靠的就是"绝不回头看"。

**去重的两种情况（极易混淆）**
- **元素不重复但要避免重复使用**（46）：用 `used[]` 数组。
- **输入含重复元素**（40、47、90，本专题的 131 不涉及）：**先排序**，然后 `if (i > start && a[i] == a[i-1]) continue;` 跳过同层的相同值。注意条件是 `i > start`（同层去重）而**不是** `i > 0`（那会连不同层的合法重复也跳掉）。

**剪枝是回溯题的分数线**。三种常见剪枝：
1. **可行性剪枝**：当前状态已违反约束（51 的皇后冲突、22 的括号数）。
2. **越界剪枝**：剩余元素不够凑成答案（39 的 `target < 0`）。
3. **排序 + 提前 break**：排序后一旦 `a[i] > target` 就 `break`（不只是 `continue`），因为后面的更大（39）。

**复杂度怎么估**：回溯的复杂度 = **解的个数 × 生成每个解的代价**。子集 O(2ⁿ·n)、排列 O(n!·n)。看到 `n <= 20` 基本就是在暗示指数级算法可以接受（见 [README 复杂度速查](README.md)）。

**难度递进**：46/78 是两个基本骨架（排列 vs 组合）→ 17/39/22 是模板变形 → 79/131 要结合别的知识（网格 / 回文判断）→ 51 是集大成的困难题。

### 46. 全排列（中等）

**题意**  给定**互不相同**的整数数组，返回所有可能的全排列。

**暴力**  随机打乱 + 去重直到收集到 `n!` 个——不可控且低效。或者用 `next_permutation` 循环（需先排序），但那绕开了本题要考的递归结构。

**关键洞察**

排列的定义是「顺序有意义、每个元素恰好用一次」。所以：

- **每一层的候选集是「所有还没用过的元素」** → `for` 必须**从 0 开始遍历全部下标**，而不是从某个 `start` 开始。这是排列与组合最本质的区别：排列需要回头去拿前面的元素（先选 2 再选 1 是一个新排列），而组合永不回头。
- 「还没用过」需要一个 `used[]` 布尔数组来记录。

递归树的形状：第一层有 n 个分支，第二层每个节点有 n-1 个分支……总叶子数 n!，正好对应答案个数。

终止条件：`path.size() == n`，此时所有元素都用上了。

**最优解（C++）**

```cpp
class Solution {
    vector<vector<int>> ans;
    vector<int> path;
    vector<bool> used;
    void backtrack(vector<int>& nums) {
        if (path.size() == nums.size()) {       // 用完所有元素 → 一个完整排列
            ans.push_back(path);
            return;
        }
        for (int i = 0; i < (int)nums.size(); ++i) {
            if (used[i]) continue;              // 跳过已用元素
            used[i] = true;                     // ① 做选择
            path.push_back(nums[i]);
            backtrack(nums);                    // ②
            path.pop_back();                    // ③ 撤销（两个状态都要撤）
            used[i] = false;
        }
    }
public:
    vector<vector<int>> permute(vector<int>& nums) {
        used.assign(nums.size(), false);
        backtrack(nums);
        return ans;
    }
};
```

**交换法（O(1) 额外空间，不需要 `used`）**

```cpp
class Solution {
    vector<vector<int>> ans;
    void backtrack(vector<int>& nums, int k) {   // 前 k 个位置已定好
        if (k == (int)nums.size()) { ans.push_back(nums); return; }
        for (int i = k; i < (int)nums.size(); ++i) {
            swap(nums[k], nums[i]);              // 把 nums[i] 换到第 k 位
            backtrack(nums, k + 1);
            swap(nums[k], nums[i]);              // 换回来
        }
    }
public:
    vector<vector<int>> permute(vector<int>& nums) { backtrack(nums, 0); return ans; }
};
```

思路：第 k 层决定「谁站在第 k 个位置」，候选是 `[k, n)` 里的任意一个，用 `swap` 把它换过来。这个写法省掉了 `path` 和 `used`，但**输出顺序不是字典序**。

**复杂度**  时间 O(n · n!)（n! 个排列，每个拷贝一次 O(n)），空间 O(n)（递归栈 + `path`，不含答案）。

**边界与坑**
- **`for` 必须从 0 开始**。写成 `for (int i = start; ...)` 就变成了子集/组合，只能得到 `n` 个升序序列。
- **两个状态都要撤销**：`path.pop_back()` 和 `used[i] = false`。只撤一个是最常见的 bug。
- 终止时 `ans.push_back(path)` 是**值拷贝**，必须拷贝——如果存引用或指针，`path` 后续被修改会污染已保存的答案。
- **本题保证元素互不相同**。若有重复元素（47 题），必须**先排序**再加同层去重：
  ```cpp
  sort(nums.begin(), nums.end());
  // 循环内：
  if (used[i]) continue;
  if (i > 0 && nums[i] == nums[i-1] && !used[i-1]) continue;   // 同层去重
  ```
  这里 `!used[i-1]` 的含义是「前一个相同值在**本层**还没被选」，说明当前是同一层的重复分支，跳过。这个条件极易写错，务必理解。
- 交换法的 `swap` 回退不能忘，否则数组顺序被破坏，后续分支全错。
- n = 1 时返回 `[[x]]`；空数组返回 `[[]]`（`path.size() == 0 == nums.size()` 立即命中终止条件），符合数学定义。

**追问 / 变体**
- **47 全排列 II**（含重复元素）：见上，排序 + 同层去重。
- **31 下一个排列**：只求下一个而非全部，是 O(n) 的贪心，见 [17-技巧](17-技巧.md)。
- **60 第 k 个排列**：用康托展开直接算，不必枚举，O(n²)。
- **字符串全排列**：完全同构，把 `vector<int>` 换成 `string`。
- **只输出字典序第一个 / 按字典序输出**：`used` 版本天然按字典序（若输入已排序），交换法不是。
- **n 很大（> 12）**：n! 爆炸，说明题目要的不是枚举而是数学解。

### 78. 子集（中等）

**题意**  给定**互不相同**的整数数组，返回所有可能的子集（幂集），共 2ⁿ 个。

**暴力**  用二进制枚举：`i` 从 0 到 2ⁿ-1，第 `j` 位为 1 表示选 `nums[j]`。这**不是**暴力而是本题的另一个标准解，且非常优雅（见下）。

**关键洞察**

子集问题的关键：**顺序无意义**，`{1,2}` 和 `{2,1}` 是同一个子集。所以必须避免重复生成，办法就是**规定只按下标升序选取**——引入 `start` 参数，每层的候选集是 `[start, n)`，递归时传 `i + 1`（下一层从 `i` 之后开始，绝不回头）。

**和 46 的对比要刻在脑子里**：
- 排列：`for (i = 0; i < n; ++i)` + `used[]` —— 要回头拿前面的元素。
- 子集/组合：`for (i = start; i < n; ++i)` + 递归传 `i + 1` —— 永不回头。

第二个关键：**每个节点都是一个答案**，不是只有叶子才是。所以 `ans.push_back(path)` 写在函数**入口**、`for` 循环之前，而不是在某个终止条件里。这是子集题与组合题（77、39）的区别——后者只在 `path` 满足特定条件（长度够、和为 target）时才收集。

递归树的形状：从根（空集）出发，每往下走一层就多选一个元素，走到的**每一个节点**都是一个子集，共 2ⁿ 个节点。

**最优解（C++，回溯）**

```cpp
class Solution {
    vector<vector<int>> ans;
    vector<int> path;
    void backtrack(vector<int>& nums, int start) {
        ans.push_back(path);                    // 每个节点都是答案（含空集）
        for (int i = start; i < (int)nums.size(); ++i) {
            path.push_back(nums[i]);            // ① 选
            backtrack(nums, i + 1);             // ② 下一层从 i+1 开始，不回头
            path.pop_back();                    // ③ 撤销
        }
    }
public:
    vector<vector<int>> subsets(vector<int>& nums) {
        backtrack(nums, 0);
        return ans;
    }
};
```

**位运算枚举（迭代，无递归，更快）**

```cpp
vector<vector<int>> subsets(vector<int>& nums) {
    int n = nums.size();
    vector<vector<int>> ans;
    ans.reserve(1 << n);
    for (int mask = 0; mask < (1 << n); ++mask) {     // 每个 mask 对应一个子集
        vector<int> cur;
        for (int j = 0; j < n; ++j)
            if (mask & (1 << j)) cur.push_back(nums[j]);
        ans.push_back(move(cur));
    }
    return ans;
}
```

**迭代扩展法（每来一个新元素，把已有子集全部复制一份并加上它）**

```cpp
vector<vector<int>> subsets(vector<int>& nums) {
    vector<vector<int>> ans = {{}};                   // 从空集开始
    for (int x : nums) {
        int sz = ans.size();                          // 先固定，否则无限循环
        for (int i = 0; i < sz; ++i) {
            ans.push_back(ans[i]);
            ans.back().push_back(x);
        }
    }
    return ans;
}
```

这个写法直接体现了「2ⁿ 是怎么来的」——每加一个元素，答案数量翻倍。

**复杂度**  时间 O(n · 2ⁿ)（2ⁿ 个子集，每个拷贝 O(n)），空间 O(n) 递归栈。这是**理论下界**——光是输出答案就需要 O(n·2ⁿ)。

**边界与坑**
- **`ans.push_back(path)` 必须在 `for` 之前、函数入口处**。放在 `for` 里面或加终止条件判断，会漏掉空集和中间节点。
- **递归传 `i + 1` 而不是 `start + 1`**。传 `start + 1` 会让候选集不前进，产生大量重复。这是本题最隐蔽的错误——写 `backtrack(nums, start + 1)` 时循环变量 `i` 的推进被无视了。
- **不需要显式的终止条件**。`start == n` 时 `for` 循环自然不执行，函数返回，天然终止。写 `if (start == nums.size()) return;` 也对但多余（且如果写在 `push_back` 之前，会漏掉最后一个满集）。
- 迭代扩展法里 `int sz = ans.size()` **必须提前存**，否则循环里 `push_back` 让 `size()` 不断增长，死循环。（同 [102 层序遍历](08-二叉树.md) 的 `sz` 陷阱。）
- 位运算版当 n > 31 时 `1 << n` 溢出。本题 `n <= 10`，安全；n 更大时 2ⁿ 本身也不可能枚举完。
- **含重复元素时**（90 子集 II）：先排序，再加 `if (i > start && nums[i] == nums[i-1]) continue;`。注意是 `i > start`（同层去重）不是 `i > 0`。
- 空数组返回 `[[]]`（只有空集），不是 `[]`。

**追问 / 变体**
- **90 子集 II**（含重复元素）：见上。
- **77 组合**（从 1..n 选 k 个）：同一个骨架，但只在 `path.size() == k` 时收集，且可加剪枝 `i <= n - (k - path.size()) + 1`。
- **39 组合总和**：候选可重复选，见下题。
- **416 分割等和子集**：判断是否存在和为 `sum/2` 的子集。子集枚举是 O(2ⁿ) 会超时，必须转成 **01 背包 DP**，见 [15-动态规划](15-动态规划.md)。**这是"子集类问题什么时候该换成 DP"的分界线：只要问的是"存在性/计数/最优值"而不是"列出所有方案"，就应该考虑 DP。**
- **子集和的第 k 大 / 所有子集和**：位运算枚举更方便。
- **n 达到 40 的子集和问题**：折半枚举（meet in the middle），把 2⁴⁰ 降到 2²⁰。

### 17. 电话号码的字母组合（中等）

**题意**  输入 2-9 的数字串，按九宫格键盘映射返回所有可能的字母组合。

**暴力**  如果数字个数固定（比如 3 个），可以写三层嵌套循环。但长度是变量，**嵌套循环的层数无法在编译期确定** —— 这正是需要递归的信号。

**关键洞察**

**「层数不固定的多重循环」= 递归**。这是本题最重要的一课：每当你想写「n 层 for 循环」但 n 是运行时变量，答案就是 DFS/回溯。

具体到本题，结构非常清晰：

- **第 `i` 层负责决定第 `i` 个数字选哪个字母**。
- **候选集由当前数字决定**：`digits[i]` 映射到的那 3～4 个字母。这和 46/78 不同——候选集不是"剩余元素"，而是**由题目结构直接给出的**。
- **终止条件**：`i == digits.size()`，此时 `path` 长度等于数字个数，是一个完整答案。

所以不需要 `used[]`（每层的候选集互不相干），也不需要 `start`（层与层之间由下标 `i` 推进）。这是回溯模板里最简单的一种形态。

映射表用 `string mapping[10]` 或 `vector<string>` 存，下标就是数字，索引直接 O(1)。`"2"` 对应下标 2，所以 0、1 位置填空串占位。

**最优解（C++）**

```cpp
class Solution {
    const string mp[10] = {"", "", "abc", "def", "ghi", "jkl",
                           "mno", "pqrs", "tuv", "wxyz"};   // 下标 = 数字
    vector<string> ans;
    string path;
    void backtrack(const string& digits, int i) {
        if (i == (int)digits.size()) {          // 每个数字都定了字母
            ans.push_back(path);
            return;
        }
        for (char c : mp[digits[i] - '0']) {    // 候选集 = 当前数字对应的字母
            path.push_back(c);                  // ① 选
            backtrack(digits, i + 1);           // ② 下一个数字
            path.pop_back();                    // ③ 撤销
        }
    }
public:
    vector<string> letterCombinations(string digits) {
        if (digits.empty()) return {};          // 空输入返回空数组，不是 {""}
        backtrack(digits, 0);
        return ans;
    }
};
```

**迭代版（BFS 式逐层扩展，思路同 78 的迭代扩展法）**

```cpp
vector<string> letterCombinations(string digits) {
    if (digits.empty()) return {};
    const string mp[10] = {"", "", "abc", "def", "ghi", "jkl", "mno", "pqrs", "tuv", "wxyz"};
    vector<string> ans = {""};
    for (char d : digits) {
        vector<string> next;
        for (const string& prefix : ans)
            for (char c : mp[d - '0'])
                next.push_back(prefix + c);
        ans = move(next);                       // 每处理一个数字，答案数量乘以 3 或 4
    }
    return ans;
}
```

**复杂度**  时间 O(4ⁿ · n)（n 为数字个数，每个数字最多 4 个字母，最后拷贝字符串 O(n)），空间 O(n) 递归栈。答案总数最坏 4ⁿ，这是输出规模决定的下界。

**边界与坑**
- **空输入必须返回 `{}` 而不是 `{""}`**。不特判的话，`backtrack` 立刻命中 `i == 0 == size()`，把空串塞进答案，返回 `[""]`，判错。**这是本题唯一的边界坑，也是必考点。**
- `digits[i] - '0'` 做字符转数字，别忘了减 `'0'`。
- 映射表**必须给下标 0 和 1 占位**（空串），否则 `mp[2]` 拿到的是 `"abc"` 之外的东西。用 `mp[d - '2']` 配合 8 元素数组也行，但容易算错偏移，不推荐。
- 输入保证只含 2-9，不必处理 0、1。若要健壮，可在循环里跳过 `mp[x].empty()` 的数字。
- `path` 用成员变量 + `push_back`/`pop_back`，比每层传值 `string path` 更省（避免每层拷贝字符串）。但传值写法也能过，且更不易错——面试可以先写传值版。
- 迭代版每轮都重建 `next`，空间峰值是答案总量，比回溯版大；但避免了递归。

**追问 / 变体**
- **输出顺序有要求**：按上面的遍历顺序天然是"字典序 by 键盘顺序"，符合 LeetCode 期望。
- **加上字典过滤**（只保留是真实单词的组合）：结合 Trie 剪枝——每加一个字母就检查前缀是否还在 Trie 里，不在就整枝剪掉。这就是 T9 输入法的原理，也是很好的追问。
- **93 复原 IP 地址**：同样是"分段 + 每段候选有限"的回溯，剪枝更多（每段 ≤ 255、不能有前导 0）。
- **迭代 vs 递归**：面试可以两个都写，说明"递归写法更贴合问题结构，迭代写法避免栈开销"。
- **求组合总数而不列出**：直接把每个数字的字母数相乘，O(n)，不需要枚举。**这是"计数 vs 枚举"的典型对比**。

### 39. 组合总和（中等）

**题意**  给定**无重复元素**的正整数数组 `candidates` 和目标 `target`，返回所有和为 `target` 的组合。**同一个数字可以无限次重复选取**。答案不能有重复组合。

**暴力**  枚举每个元素选 0 次、1 次、2 次……直到超过 target，做笛卡尔积后去重。可行但难写且低效，而且"去重"这一步就说明思路不对——好的枚举方式应该**天然不产生重复**。

**关键洞察**

两个要点，一个是"可重复选"，一个是"组合去重"。

**① 可重复选取 → 递归传 `i` 而不是 `i + 1`。**

这是本题相对 78 的唯一结构性改动。传 `i + 1` 表示"下一层不能再用第 i 个元素"（每个元素最多用一次），传 `i` 表示"下一层还可以继续用第 i 个元素"。**一个字符的差别，决定了是组合还是可重复组合。**

**② 去重仍然靠 `start`（绝不回头）。**

`[2,2,3]` 和 `[2,3,2]` 是同一个组合。靠 `for (i = start; ...)` 保证每个组合都以**下标非递减**的方式生成，只会出现一次。所以**不需要任何 `set` 去重**。

**③ 剪枝**（本题的加分项）：

- **基础剪枝**：`target - candidates[i] < 0` 时这个分支无望，跳过。写成递归入口判 `if (target < 0) return;` 也行，但**在循环里提前判断能少一层递归调用**。
- **排序 + `break`**：先把 `candidates` 排序，那么一旦 `candidates[i] > target`，**后面的元素只会更大**，可以直接 `break` 而不是 `continue`。这个剪枝在数据较大时提速明显，也是面试的区分点。

**用「剩余量 target」而不是「累计和 sum」**：递归时传 `target - candidates[i]`，终止条件就是 `target == 0`，比维护 `sum` 再和原 target 比更简洁。

**最优解（C++）**

```cpp
class Solution {
    vector<vector<int>> ans;
    vector<int> path;
    void backtrack(vector<int>& c, int start, int target) {
        if (target == 0) {                      // 恰好凑出 → 收集
            ans.push_back(path);
            return;
        }
        for (int i = start; i < (int)c.size(); ++i) {
            if (c[i] > target) break;           // 排序后：更大的也不行，整段剪掉
            path.push_back(c[i]);               // ① 选
            backtrack(c, i, target - c[i]);     // ② 传 i：允许重复选自己
            path.pop_back();                    // ③ 撤销
        }
    }
public:
    vector<vector<int>> combinationSum(vector<int>& candidates, int target) {
        sort(candidates.begin(), candidates.end());   // 为 break 剪枝服务
        backtrack(candidates, 0, target);
        return ans;
    }
};
```

**复杂度**  时间上界 O(n^(target/min)) —— 递归树的深度最多 `target / min(candidates)`，每层最多 n 个分支；实际因剪枝远小于此。空间 O(target / min) 递归深度。

> 精确复杂度难以给出紧界，面试如实说明「指数级，上界为 O(n^(T/M))，剪枝后实际远小于此」即可，比硬套一个错的公式更好。

**边界与坑**
- **递归必须传 `i`，不是 `i + 1`**。传 `i + 1` 就变成"每个元素只能用一次"（对应 40 题），答案会少一大半。这是本题的核心考点。
- **也不能传 `start`**（写成 `backtrack(c, start, ...)`）：那样候选集永远不前进，会生成 `[2,3]` 和 `[3,2]` 两份，产生重复。**`i` 和 `start` 差一个字，含义天差地别** —— `i` 是"当前选的这个"，`start` 是"这一层允许的最小下标"。
- **`break` 依赖已排序**。不排序只能用 `continue`（跳过这一个但继续看后面的），少了整段剪枝的效果。**排序 + `break` 是配套的，别只做一半。**
- **元素必须为正数**。题目保证 `candidates[i] >= 2`。若允许 0，同一个 0 可以无限选，答案无穷；若允许负数，`c[i] > target` 的剪枝失效，且可能无限递归。面试被问「有负数怎么办」，正确答案是**问题无界，除非限制组合长度**。
- `target == 0` 的终止要写在函数入口。写成 `if (target <= 0)` 也能过（负数分支已被 `break`/`continue` 挡住），但语义不清。
- 单个元素就等于 target 时（如 `candidates=[7], target=7`）能正确得到 `[[7]]`。
- 答案里同一个组合的**元素顺序**是升序（因为按下标升序选且已排序），LeetCode 不校验组内顺序，但升序更易读。

**追问 / 变体**
- **40 组合总和 II**：每个元素只能用一次，且**输入含重复元素**。两处改动：递归传 `i + 1`，并加同层去重 `if (i > start && c[i] == c[i-1]) continue;`。**这两道题对着写一遍，就彻底搞清了「传 i vs 传 i+1」和「start 去重 vs 同值去重」的区别。**
- **216 组合总和 III**：限定用 1-9 且恰好 k 个数，多一个长度约束。
- **377 组合总和 IV**：求**排列**数（顺序不同算不同方案）且只要计数 → 回溯会超时，必须用**完全背包 DP**（`dp[t] += dp[t - c]`，外层遍历 target、内层遍历物品）。**这是又一个"只要计数就换 DP"的例子**，和 78 → 416 的转变同理。
- **322 零钱兑换**（求最少硬币数）：同样是"可重复选取"，但求最优值 → DP，见 [15-动态规划](15-动态规划.md)。**39/377/322 三题的候选集完全一样，问法不同导致算法完全不同，非常值得对比。**
- **返回组合数量而非列表**：DP，O(n·target)。
- **target 很大（10⁵ 级）**：回溯的解数会爆炸，只能是 DP 或数学。

### 22. 括号生成（中等）

**题意**  给定 `n` 对括号，生成所有**有效**的括号组合。

**暴力**  生成全部 2^(2n) 个长度为 2n 的 `(`/`)` 串，再逐个用栈判断是否有效。O(2^(2n) · n)，n = 8 时是 65536 × 16，能过但极浪费——**绝大多数生成的串都是无效的**（n=3 时 64 个串里只有 5 个有效）。

**关键洞察**

暴力的问题是「先生成再验证」。回溯的威力在于**边生成边验证，把无效分支在萌芽时就剪掉**——一旦前缀已经非法，它的所有后续都不用看了。

那么，什么样的前缀是"还有救"的？只需两个计数器 `open`（已用左括号数）、`close`（已用右括号数），两条规则：

1. **`open < n`** 才能放 `(`。左括号总数不能超过 n。
2. **`close < open`** 才能放 `)`。**这是核心洞察**：任何有效括号串的任意前缀中，右括号数必须 **≤** 左括号数。如果 `close == open`，此刻放 `)` 会让右括号数超过左括号数，前缀立即非法且**永远无法挽回**。

这两个条件把递归树从 2^(2n) 个叶子剪到只剩 Catalan(n) 个——n=3 时从 64 剪到 5，完全没有一次无效生成。

**终止条件**：`path.size() == 2n`。此时必然 `open == close == n`（由规则保证），是一个有效串。用 `open == n && close == n` 判断等价。

**为什么不需要显式判"有效性"**：两条 `if` 就是有效性的**充分必要**刻画。这是本题最漂亮的地方——**约束被编码进了候选集的生成规则里，而不是事后检查**。这个思想在 51 N 皇后里会再次出现。

**最优解（C++）**

```cpp
class Solution {
    vector<string> ans;
    string path;
    void backtrack(int n, int open, int close) {
        if ((int)path.size() == 2 * n) {        // 长度够了 → 必然有效
            ans.push_back(path);
            return;
        }
        if (open < n) {                         // 还能放左括号
            path.push_back('(');
            backtrack(n, open + 1, close);
            path.pop_back();                    // 撤销
        }
        if (close < open) {                     // 关键：右括号不能超过左括号
            path.push_back(')');
            backtrack(n, open, close + 1);
            path.pop_back();
        }
    }
public:
    vector<string> generateParenthesis(int n) {
        backtrack(n, 0, 0);
        return ans;
    }
};
```

**另一种视角：按「剩余可用数」写**（等价，有人觉得更直观）

```cpp
void backtrack(int left, int right) {           // left/right = 还剩多少个可放
    if (left == 0 && right == 0) { ans.push_back(path); return; }
    if (left > 0)      { path += '('; backtrack(left - 1, right); path.pop_back(); }
    if (right > left)  { path += ')'; backtrack(left, right - 1); path.pop_back(); }
}
// 调用 backtrack(n, n)
```

注意这里条件变成 `right > left`（剩余右括号多于剩余左括号，说明已放的左括号有盈余）。**两种写法的条件是对偶的，别混着写**。

**复杂度**  时间 O(4ⁿ / √n · n)——有效组合数是第 n 个**卡特兰数** `C(2n,n)/(n+1) ≈ 4ⁿ/(n^1.5√π)`，每个答案拷贝 O(n)。空间 O(n) 递归栈。

**边界与坑**
- **`close < open` 不能写成 `close < n`**。写成 `close < n` 就退化成"只保证总数正确"，会生成 `())(` 这样的非法串。这是本题唯一但致命的考点。
- 两个 `if` 是**并列**关系，不是 `if / else`。每一层可能既能放左又能放右，两个分支都要探索。写成 `else if` 会漏掉一半答案。
- **每个 `if` 内部都要配对 `push_back` / `pop_back`**。共用一次撤销是错的。
- `n >= 1`（题目保证），所以不用担心 n = 0。若 n = 0，本代码返回 `[""]`。
- 用 `string path` 成员变量 + 手动撤销，比传值拷贝省内存；但传值版 `backtrack(n, open, close, string path)` 更不容易漏撤销，面试可任选，说清取舍即可。
- `path.size()` 返回 `size_t`，和 `2 * n` 比较时最好强转 `(int)`，避免符号警告。

**追问 / 变体**
- **20 有效括号**（判断给定串是否有效）：用栈，见 [12-栈](12-栈.md)。本题是它的"生成"版。
- **32 最长有效括号**：求最长有效子串长度，是 DP / 栈题，见 [15-动态规划](15-动态规划.md)。
- **多种括号类型**（`()[]{}`）：候选集变多，且右括号必须匹配栈顶类型，需要维护一个栈而不只是计数器。
- **只求方案数**：直接算卡特兰数 `C(2n,n)/(n+1)`，O(n)，不需枚举。**又一个"计数 vs 枚举"的对比**。
- **241 为运算表达式设计优先级**：本质也是卡特兰数结构的枚举。
- **1249 移除无效括号**：给定串删最少字符使其有效，是贪心/栈题。

### 79. 单词搜索（中等）

**题意**  在字符网格中判断能否找到给定单词。**相邻**（上下左右）字母连成路径，**同一个格子不能重复使用**。

**暴力**  以每个格子为起点做 DFS 尝试匹配。这就是本题的标准解——**没有更优的多项式算法**，优化空间全在剪枝。

**关键洞察**

这题是**回溯 + 网格 DFS 的结合**（[200 岛屿数量](09-图论.md) 的升级版），关键区别在于**必须撤销标记**。

对比 200：那里把访问过的陆地永久"淹掉"，因为一个格子属于哪个岛是确定的、不需要重来。而这里，一个格子在**这条尝试路径**里被占用，但如果这条路径失败了，回退之后它对**另一条路径**应该重新可用。所以：

```cpp
grid[x][y] = '#';        // 标记本条路径已占用
...递归四个方向...
grid[x][y] = saved;      // 恢复！← 这就是"回溯"，200 里没有这一步
```

**忘记恢复就会漏掉本该找到的答案**——这是本题最核心的考点，也是「回溯」和「一次性遍历」的分界线。

**用原地改字符当标记**（改成 `'#'` 这种不会出现在单词里的字符）省掉了 `vis` 数组，且天然满足"不能重复使用"。

**剪枝**（决定是否 TLE）：

1. **首字符不匹配就不要启动 DFS**：`if (board[i][j] != word[0]) continue;`
2. **每层先判字符是否匹配再递归**，不匹配立刻返回 false。
3. **`k == word.size()` 提前返回 true**，并且一旦某方向成功就立即 `return true`，不再尝试其他方向（短路）。
4. **进阶剪枝**：先统计网格里各字母的出现次数，如果 word 里某字母的需求量超过网格供给量，直接返回 false。这个剪枝对卡时间的测试用例（比如 `"aaaa...b"` 而网格全是 a）非常有效，是加分项。

**最优解（C++）**

```cpp
class Solution {
    int m, n;
    bool dfs(vector<vector<char>>& b, const string& w, int x, int y, int k) {
        if (x < 0 || x >= m || y < 0 || y >= n) return false;   // 越界
        if (b[x][y] != w[k]) return false;                     // 字符不匹配（含已访问的 '#'）
        if (k == (int)w.size() - 1) return true;               // 最后一个字符也匹配 → 成功

        char saved = b[x][y];
        b[x][y] = '#';                                         // ① 标记占用
        bool found = dfs(b, w, x - 1, y, k + 1)                // ② 四个方向，短路求值
                  || dfs(b, w, x + 1, y, k + 1)
                  || dfs(b, w, x, y - 1, k + 1)
                  || dfs(b, w, x, y + 1, k + 1);
        b[x][y] = saved;                                       // ③ 撤销 ← 关键！
        return found;
    }
public:
    bool exist(vector<vector<char>>& board, string word) {
        m = board.size(); n = board[0].size();
        if ((int)word.size() > m * n) return false;            // 单词比格子还多，不可能
        for (int i = 0; i < m; ++i)
            for (int j = 0; j < n; ++j)
                if (board[i][j] == word[0] && dfs(board, word, i, j, 0))
                    return true;                               // 找到一个就够
        return false;
    }
};
```

**字母计数剪枝（加在 `exist` 开头，对付极端数据）**

```cpp
int cnt[128] = {0};
for (auto& row : board) for (char c : row) ++cnt[(int)c];
for (char c : word) if (--cnt[(int)c] < 0) return false;   // 供给不足，直接判否
```

**复杂度**  时间 O(m · n · 3^L)（L 为单词长度；起点 mn 个，之后每步最多 3 个新方向——不会走回来路，因为来路已被标 `'#'`），空间 O(L) 递归栈。

**边界与坑**
- **`b[x][y] = saved` 的恢复不能漏**，也不能写在 `return true` 之后（那样成功路径上的标记不会被清，虽然本题找到就返回、影响不大，但习惯要正确）。上面的写法先算 `found` 再恢复再返回，是最稳的结构。
- **`if (k == w.size() - 1) return true` 必须在标记之前判断**。写在标记之后就会在成功时留下未清理的 `'#'`（同上，本题无害但不严谨）。更重要的是**顺序不能反**：先判越界、再判字符匹配、再判是否到末尾。任意两步调换都可能越界访问或误判。
- **`w.size() - 1` 要强转 `(int)`**：`size()` 是无符号，空串时 `size()-1` 是巨大值。题目保证 `word` 非空，但习惯要好。
- **`'#'` 不能是 word 里可能出现的字符**。题目保证只有字母，所以安全。用 `vis` 数组则完全没这个顾虑。
- **短路求值 `||` 是有意的**：一旦某个方向成功，后面三个方向根本不会被调用，省下大量搜索。别改成先算四个再 `||`。
- 不需要 `dx/dy` 数组也行（四行展开更直白）；用数组的话记得 `for (k=0;k<4;k++) if (dfs(...)) { b[x][y]=saved; return true; }` 别忘恢复。
- 起点循环里加 `board[i][j] == word[0]` 判断是重要剪枝，但注意 `dfs` 内部也会判——重复判无害，去掉外层判也正确，只是慢。
- 网格可能是 1×1；单词可能长度 1（此时起点匹配即成功，由 `k == size()-1` 处理）。

**追问 / 变体**
- **212 单词搜索 II**（同时搜多个单词）：不能对每个单词各跑一遍（O(words × mn × 3^L) 会 TLE）。正解是**把所有单词建成 Trie**，然后在网格上 DFS 时同步在 Trie 上走，一旦 Trie 上无路就整枝剪掉。**这是 Trie + 回溯的经典组合**，见 [208](09-图论.md)。
- **允许重复使用格子**：去掉标记与恢复，但要防无限递归（限制步数 = word 长度即可自然终止）。
- **八连通**：方向从 4 扩到 8，复杂度变 O(mn · 7^L)。
- **返回路径本身**：加一个 `path` 记录坐标，成功时保存。
- **判断是否存在环路 / 最长路径**：网格上求最长简单路径是 NP-hard，说明这类题只能指数级。
- **为什么是 3^L 不是 4^L**：走过来的那一格已被标记，所以每步实际只有 3 个新选择。这个细节面试值得说出来。

### 131. 分割回文串（中等）

**题意**  把字符串 `s` 分割成若干**子串**，使每个子串都是回文串，返回所有可能的分割方案。

**暴力**  枚举所有 2^(n-1) 种切割方式（每两个字符之间切或不切），对每种方案检查所有段是否都回文。O(2ⁿ · n²)。问题在于「先切完再验证」——绝大多数方案在前几段就已经失败了。

**关键洞察**

**① 分割问题就是组合问题。**

把「在哪些位置切」看成「选择每一段的结束位置」，就变成了标准的组合型回溯：

- **第 `start` 层负责决定「从 `start` 开始的这一段切到哪」**。
- **候选集是所有可能的段末位置** `i ∈ [start, n)`，对应子串 `s[start..i]`。
- **递归传 `i + 1`**（下一段从 `i` 之后开始，段与段不重叠、不回头）。
- **终止条件 `start == n`**：整个串都被划分完了。

这个「`for (i = start; i < n; ++i)` + 递归传 `i + 1`」的骨架和 [78 子集](#78-子集中等) 完全一致，只是「选一个元素」变成了「选一段」。**认出这一点，题就一半解决了。**

**② 边切边验证，把不回文的段立刻剪掉。**

`if (!isPalindrome(s, start, i)) continue;` —— 这一句是回溯优于暴力的全部原因。`s[start..i]` 不回文时，这个分支的所有后续切法都不用尝试。

**③ 用 DP 预处理回文判断（本题的加分项）。**

朴素的 `isPalindrome` 每次 O(n)，总复杂度带一个 n 的因子。可以先用区间 DP 在 O(n²) 时间内预计算 `pal[i][j]` = `s[i..j]` 是否回文：

```
pal[i][j] = (s[i] == s[j]) && (j - i < 2 || pal[i+1][j-1])
```

注意**遍历顺序**：`pal[i][j]` 依赖 `pal[i+1][j-1]`（更短的区间、更大的 i），所以 **i 必须倒序遍历**。这个 DP 与 [5 最长回文子串](16-多维动态规划.md) 是同一个递推，可以对照记忆。

预处理后回文判断变 O(1)，回溯部分的常数大幅下降。

**最优解（C++，DP 预处理 + 回溯）**

```cpp
class Solution {
    vector<vector<string>> ans;
    vector<string> path;
    vector<vector<bool>> pal;                   // pal[i][j]: s[i..j] 是否回文

    void backtrack(const string& s, int start) {
        if (start == (int)s.size()) {           // 整串切完 → 一个完整方案
            ans.push_back(path);
            return;
        }
        for (int i = start; i < (int)s.size(); ++i) {
            if (!pal[start][i]) continue;       // 这一段不回文，剪掉
            path.push_back(s.substr(start, i - start + 1));   // ① 选这一段
            backtrack(s, i + 1);                                // ② 下一段从 i+1 开始
            path.pop_back();                                    // ③ 撤销
        }
    }
public:
    vector<vector<string>> partition(string s) {
        int n = s.size();
        pal.assign(n, vector<bool>(n, false));
        for (int i = n - 1; i >= 0; --i)            // i 倒序：依赖 pal[i+1][...]
            for (int j = i; j < n; ++j)
                pal[i][j] = (s[i] == s[j]) && (j - i < 2 || pal[i + 1][j - 1]);
        backtrack(s, 0);
        return ans;
    }
};
```

**不预处理的简版（面试可先写这个）**

```cpp
bool isPal(const string& s, int l, int r) {
    while (l < r) if (s[l++] != s[r--]) return false;
    return true;
}
```

**复杂度**  时间 O(n · 2ⁿ)——最坏情况（如 `"aaaa...a"`）有 2^(n-1) 种分割方案，每个方案拷贝 O(n)；DP 预处理 O(n²) 被主项吸收。空间 O(n²)（`pal` 表）+ O(n) 递归栈。

**边界与坑**
- **递归传 `i + 1` 而不是 `i`**。传 `i` 会让下一段从当前段的最后一个字符开始，段之间重叠，答案完全错。
- **`substr(start, i - start + 1)` 的长度参数容易错**。`substr` 的第二个参数是**长度**不是结束下标；`[start, i]` 的长度是 `i - start + 1`。写成 `i - start` 会漏掉最后一个字符。**这是本题最高频的 bug。**
- **DP 的 `i` 必须倒序遍历**。正序会读到还未计算的 `pal[i+1][j-1]`（此时是初始的 `false`），导致长回文被误判为非回文，答案变少。
- **`j - i < 2` 处理长度 1 和 2 的基础情况**：长度 1 必回文；长度 2 只需两字符相等（此时 `pal[i+1][j-1]` 的下标 `i+1 > j-1` 是无效区间，不能读）。写成 `j - i <= 2` 会错误地把长度 3 的情况也短路掉（长度 3 恰好只需首尾相等 + 中间单字符必回文，结果碰巧对；但语义错了，容易在别的题上踩雷）。**标准写法是 `j - i < 2`。**
- 终止条件是 `start == n`，不是 `start >= n` 之外的什么条件；`start` 不会越过 n（因为 `i < n` 保证 `i + 1 <= n`）。
- 单字符串 `"a"` 返回 `[["a"]]`。
- **`ans.push_back(path)` 是值拷贝**，必须拷贝。
- 不要用 `set<vector<string>>` 去重——本题的分割方案天然互不相同（切割位置不同），不存在重复。

**追问 / 变体**
- **132 分割回文串 II**（求最少分割次数）：只要**最优值**不要方案 → 回溯会超时，改用 DP：`dp[i] = min(dp[j] + 1)` 对所有 `pal[j][i-1]` 成立的 `j`。**又一个"只求最优值就换 DP"的例子**（对照 78 → 416、39 → 322）。
- **1278 分割回文串 III / 1745 回文串分割 IV**：固定分割段数，二维 DP。
- **5 最长回文子串**：本题用到的 `pal` 表就是它的解法之一，见 [16-多维动态规划](16-多维动态规划.md)。
- **93 复原 IP 地址**：同构的分割型回溯——分成 4 段、每段有取值约束，是很好的配套练习。
- **139 单词拆分**：也是分割问题，但问「能否分割」（存在性）→ DP，见 [15-动态规划](15-动态规划.md)。**140 单词拆分 II** 要返回所有方案 → 回溯 + 记忆化。
- **用 Manacher 算法预处理回文**：O(n) 求出所有回文中心，比 O(n²) DP 更快，但本题瓶颈在 2ⁿ 的输出规模，优化预处理没有意义。**能识别"优化非瓶颈部分是无用功"也是能力的体现。**

### 51. N 皇后（困难）

**题意**  在 `n × n` 棋盘上放 `n` 个皇后，使任意两个不能互相攻击（不同行、不同列、不同对角线），返回所有解的棋盘表示。

**暴力**  从 n² 个格子里选 n 个，`C(n², n)` 种方案逐一验证。n = 8 时 `C(64,8) ≈ 4.4×10⁹`，不可行。

**关键洞察**

**① 先用约束压缩搜索空间：一行恰好放一个皇后。**

n 个皇后放在 n 行且不同行 → **每行必有且仅有一个**。于是搜索从「选 n 个格子」变成「为每一行选一个列号」，方案数从 `C(n²,n)` 降到 `nⁿ`，再加上列不重复的约束就是 `n!`（n=8 时 40320）。**这个建模是本题的第一步，也是最重要的一步。**

于是回溯结构变得和 [46 全排列](#46-全排列中等) 几乎一样：**第 `row` 层决定第 `row` 行的皇后放在哪一列**，候选集是所有"还没被攻击"的列。

**② 三个 O(1) 的冲突判定（本题的技术核心）**

如果每次放皇后都遍历已放的皇后检查冲突，是 O(n) 一次。更好的办法是用三个布尔数组，把冲突判定降到 **O(1)**：

- **列冲突**：`cols[c]`。同列即冲突，直接用列号索引。
- **主对角线（↘ 方向）**：同一条主对角线上 **`row - col` 是常数**。因为可能为负，偏移成 `row - col + n - 1`，范围 `[0, 2n-2)`。
- **副对角线（↙ 方向）**：同一条副对角线上 **`row + col` 是常数**，范围 `[0, 2n-2)`。

> **推导**：沿 ↘ 方向走一步，行 +1、列 +1，所以 `row - col` 不变；沿 ↙ 方向走一步，行 +1、列 -1，所以 `row + col` 不变。**记住"主减副加"**，这是 N 皇后的标志性技巧，也常出现在其他棋盘题里。

**③ 不需要检查行**：因为每层只放一个、且逐行推进，行冲突被结构性地排除了。**约束被编码进搜索结构，而不是靠检查**——和 [22 括号生成](#22-括号生成中等) 是同一个思想。

**最优解（C++）**

```cpp
class Solution {
    int n;
    vector<vector<string>> ans;
    vector<int> queenCol;                 // queenCol[row] = 该行皇后所在列
    vector<bool> cols, diag1, diag2;      // 列、主对角线(row-col)、副对角线(row+col)

    void backtrack(int row) {
        if (row == n) {                   // n 行都放好了 → 一个解
            vector<string> board(n, string(n, '.'));
            for (int r = 0; r < n; ++r) board[r][queenCol[r]] = 'Q';
            ans.push_back(move(board));
            return;
        }
        for (int c = 0; c < n; ++c) {
            int d1 = row - c + n - 1;     // 主对角线编号（偏移防负）
            int d2 = row + c;             // 副对角线编号
            if (cols[c] || diag1[d1] || diag2[d2]) continue;   // 被攻击，跳过
            cols[c] = diag1[d1] = diag2[d2] = true;            // ① 放皇后
            queenCol[row] = c;
            backtrack(row + 1);                                // ② 下一行
            cols[c] = diag1[d1] = diag2[d2] = false;           // ③ 撤销（三个都要撤）
        }
    }
public:
    vector<vector<string>> solveNQueens(int nn) {
        n = nn;
        queenCol.assign(n, 0);
        cols.assign(n, false);
        diag1.assign(2 * n - 1, false);
        diag2.assign(2 * n - 1, false);
        backtrack(0);
        return ans;
    }
};
```

**位运算版（竞赛写法，常数极小）**

```cpp
class Solution {
    int n, cnt = 0;
    void dfs(int row, int cols, int d1, int d2) {
        if (row == n) { ++cnt; return; }
        int avail = ~(cols | d1 | d2) & ((1 << n) - 1);   // 可放位置的位掩码
        while (avail) {
            int p = avail & (-avail);                     // 取最低位的 1（最右可用位置）
            avail ^= p;                                   // 去掉这一位
            dfs(row + 1, cols | p, (d1 | p) << 1, (d2 | p) >> 1);
        }
    }
public:
    int totalNQueens(int nn) { n = nn; dfs(0, 0, 0, 0); return cnt; }
};
```

思路：用整数的位表示每列是否被占。`d1 << 1` / `d2 >> 1` 巧妙地表达了「对角线约束下移一行后左移/右移一格」，不需要显式的对角线编号。这是 **52 N 皇后 II** 的最优解。

**复杂度**  时间 O(n!)（上界；实际因剪枝远小于此），空间 O(n)（递归栈 + 三个标记数组，不含答案）。构造答案棋盘每次 O(n²)。

**边界与坑**
- **对角线数组大小是 `2n - 1` 不是 `n`**。主对角线共有 `2n-1` 条（`row - col` 取值 `-(n-1)` 到 `n-1`）。开小了会越界，是本题最常见的崩溃原因。
- **`row - col` 必须偏移**（`+ n - 1`）才能当数组下标，否则负下标 UB。用 `unordered_set<int>` 存 `row - col` 则不需偏移，但常数更大。
- **撤销时三个标记都要还原**。漏掉任何一个，后续分支会误判"该位置不可用"，答案变少。
- **别忘了 `queenCol[row] = c`**，否则构造棋盘时读到的是旧值/垃圾值。（严格说 `queenCol` 不需要撤销，因为下次进入同一行会被覆盖；但写上 `queenCol[row] = c` 这一句不能漏。）
- **不需要检查行冲突**，但也**不能**在同一行放两个——`for` 循环里 `continue` 而不是继续放，且每层只递归一次，结构上已保证。
- **"主减副加"别记反**。记反了会把两条对角线搞混，n ≤ 3 时看不出问题（无解），n = 4 时才暴露。
- n = 1 时答案是 `[["Q"]]`；n = 2、3 时**无解**，返回空数组——这是很好的自测用例。
- 位运算版 `avail & (-avail)` 取最低位 1 的技巧（等价于 `avail & (~avail + 1)`），配合 `avail ^= p` 逐个枚举，是位运算枚举子集的标准手法。

**追问 / 变体**
- **52 N 皇后 II**（只求解的个数）：不需要构造棋盘，用上面的位运算版，n = 15 也能快速跑完。
- **n 很大（> 20）**：n! 爆炸，枚举全部解不可行。但**求任意一个解**有 O(n) 的构造性数学解法（按 n mod 6 分情况直接给出列排列）。**「所有解」和「一个解」的难度差异是本题的深层考点。**
- **对称性剪枝**：解具有左右镜像对称性，只搜第一行的前一半列，答案数量翻倍（n 为奇数时中间列单独处理）。能提速约 2 倍。
- **37 解数独**：同构的约束满足问题，用三组标记（行、列、3×3 宫）+ 回溯；进阶用「最少候选优先」的启发式排序大幅提速。
- **36 有效的数独**：只验证不搜索，是 37 的前置。
- **一般化的约束满足（CSP）**：N 皇后是 CSP 的教科书例子，工业界用 SAT/SMT 求解器处理这类问题。
- **和 46 全排列的关系**：N 皇后的解一定是 `0..n-1` 的一个排列（每行一个、每列一个），所以可以看成「在全排列基础上加对角线约束」。想清这层关系，两题就串起来了。
