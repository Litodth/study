# 16 · 多维动态规划（5 题）

## 套路总纲

「多维」= 状态需要**两个下标**才能描述。5 道题里有 3 道是**双序列 DP**（1143、72，以及某种意义上的 5），2 道是**网格 DP**（62、64）。

**网格 DP（62、64）**

状态天然是 `dp[i][j]`（走到格子 `(i,j)` 的方案数 / 最小代价）。转移只看**上方和左方**（因为只能向右/向下走）：

```cpp
dp[i][j] = f(dp[i-1][j], dp[i][j-1])        // f 是 + 或 min
```

**遍历顺序**：从上到下、从左到右——保证算 `dp[i][j]` 时上方和左方都已算好。

**空间优化到一维**：`dp[i][j]` 只依赖上一行和本行左边，所以可以用一维滚动数组，**正序遍历**：

```cpp
for (int i = 0; i < m; ++i)
    for (int j = 0; j < n; ++j)
        // 此刻 dp[j] 还是"上一行的 dp[i-1][j]"，dp[j-1] 已是"本行的 dp[i][j-1]"
        dp[j] = f(dp[j], dp[j-1]);
```

**这里正序是对的**（和 [01 背包的倒序](15-动态规划.md) 相反）——因为我们**同时需要**上一行的同列值和本行的左邻值，正序恰好让 `dp[j]` 保持旧值（上一行）而 `dp[j-1]` 已更新（本行）。**想清这一点，网格 DP 的一维优化就不会写错。**

**双序列 DP（1143、72）**

**识别信号**：输入是**两个**字符串/数组，问「公共」「编辑」「匹配」「转换」。

**状态定义（固定套路）**：

> **`dp[i][j]` = 「`s1` 的前 `i` 个字符」与「`s2` 的前 `j` 个字符」的答案**

**注意用「前 i 个」（长度）而不是「下标 i」**。这样 `dp[0][j]` 和 `dp[i][0]` 天然表示"一方为空串"的边界，非常好初始化。**代价是 `s1[i-1]` 才是"第 i 个字符"，下标要减 1** —— 这是双序列 DP 唯一的记账负担，但换来干净的边界，非常值得。

**转移的通用思路：看两个末尾字符**

```
若 s1[i-1] == s2[j-1]：  从 dp[i-1][j-1] 转移（两个末尾配对/无需操作）
否则：                    从 dp[i-1][j]、dp[i][j-1]（、dp[i-1][j-1]）中取最优
```

**表格大小是 `(m+1) × (n+1)`**，第 0 行第 0 列是边界。

**区间 DP（5 题）**

状态是 `dp[i][j]` = 「子串 `s[i..j]` 的性质」。转移依赖**更短的区间** `dp[i+1][j-1]`，所以**遍历顺序必须保证短区间先算**：要么 `i` 倒序 + `j` 正序，要么按区间长度从小到大枚举。**这是区间 DP 最容易错的地方。**

**难度递进**：62 是最简单的网格计数 → 64 换成求最小值 → 1143 是双序列 DP 的模板题 → 5 是区间 DP（也可中心扩展）→ **72 是双序列 DP 的巅峰，三个转移方向要想清楚**。

**共同的空间优化思路**：二维 DP 若只依赖上一行，就能压成一维（62、64、1143、72 都可以）。但**压缩后丢失路径信息**，需要输出方案时必须保留二维表。

### 62. 不同路径（中等）

**题意**  `m × n` 网格，从左上角走到右下角，每次**只能向右或向下**，问有多少条不同路径。

**暴力**  DFS 枚举所有路径，路径总数就是答案本身（组合级），`m = n = 10` 时约 4.8×10⁴ 还行，但 `m = n = 100` 时是天文数字，必然超时。**"答案本身是指数级 → 必须计数而非枚举"**，这是本题的第一个认识。

**关键洞察**

**用「最后一步」分析法**：要到达格子 `(i, j)`，最后一步只有两种可能：

- 从上方 `(i-1, j)` 向下走一步
- 从左方 `(i, j-1)` 向右走一步

两者**互斥且穷尽**，所以：

```
dp[i][j] = dp[i-1][j] + dp[i][j-1]
```

**初始化**：第一行只能一路向右到达 → 全是 1；第一列只能一路向下 → 全是 1。

**这就是杨辉三角的另一种排列**（[118 题](15-动态规划.md)），所以也有组合数解法：总共要走 `m-1` 步向下 + `n-1` 步向右，共 `m+n-2` 步，从中选哪几步向下 → **`C(m+n-2, m-1)`**。

**最优解（C++，一维滚动数组）**

```cpp
class Solution {
public:
    int uniquePaths(int m, int n) {
        vector<int> dp(n, 1);                 // 第一行全是 1
        for (int i = 1; i < m; ++i)
            for (int j = 1; j < n; ++j)
                dp[j] += dp[j - 1];           // dp[j](上一行) + dp[j-1](本行左边)
        return dp[n - 1];
    }
};
```

**这三行代码值得逐字理解**：`dp[j] += dp[j-1]` 执行时，`dp[j]` 还是上一行的值（即 `dp[i-1][j]`），`dp[j-1]` 已经是本行的值（即 `dp[i][j-1]`）——**正序遍历恰好让两者各就各位**。

**二维版（先写这个，更直观）**

```cpp
int uniquePaths(int m, int n) {
    vector<vector<int>> dp(m, vector<int>(n, 1));   // 第一行第一列都初始化为 1
    for (int i = 1; i < m; ++i)
        for (int j = 1; j < n; ++j)
            dp[i][j] = dp[i-1][j] + dp[i][j-1];
    return dp[m-1][n-1];
}
```

**组合数解法（O(min(m,n)) 时间 O(1) 空间）**

```cpp
int uniquePaths(int m, int n) {
    long long ans = 1;
    int k = min(m - 1, n - 1);                // 取小的那个减少乘法次数
    for (int i = 1; i <= k; ++i)
        ans = ans * (m + n - 2 - k + i) / i;  // 边乘边除，保证每步整除
    return (int)ans;
}
```

**为什么"边乘边除"能保证整除**：这是计算 `C(n, k)` 的标准技巧——第 `i` 步算的是 `C(m+n-2-k+i, i)`，它总是整数。**如果先把分子全乘完再除，会溢出。** 这个细节是组合数解法的关键。

**复杂度**  DP：时间 O(mn)，空间 O(n)（一维版）。组合数：时间 O(min(m,n))，空间 O(1)。

**边界与坑**
- **第一行和第一列必须初始化为 1**，不是 0。它们代表"只有一条路"（一直向右/向下）。一维版的 `vector<int> dp(n, 1)` 已经完成了这件事。
- **循环从 `i = 1`、`j = 1` 开始**，跳过已初始化的第一行第一列。从 0 开始会越界访问 `dp[-1]`。
- **`m = 1` 或 `n = 1` 时答案是 1**。一维版天然正确（循环不执行，返回 `dp[n-1] = 1`）。
- **结果会溢出吗**：本题 `m, n <= 100`，最大 `C(198, 99) ≈ 2.2×10^58`——**远超 int**！但 LeetCode 保证「答案小于等于 2×10⁹」，即测试数据不会给出溢出的组合。**面试要主动提这个风险**，说明"若不保证，需要用 `long long` 或大数/取模"。
- **组合数解法必须用 `long long`** 且边乘边除，否则中间结果溢出。
- 网格是 `m` 行 `n` 列，别把 m、n 搞反（虽然答案对称，但一维数组大小要用 `n`）。

**追问 / 变体**
- **63 不同路径 II**（有障碍物）：障碍格 `dp[i][j] = 0`。**注意第一行/第一列遇到障碍后，后面全是 0**（走不过去），所以初始化不能简单地全填 1，要边填边判断。**这是 62 → 63 最主要的坑。**
- **64 最小路径和**：把 `+` 换成 `min` 并加上格子代价，见下题。
- **可以向四个方向走**：路径可能无限长（可以绕圈），问题变成图上路径计数，需要限制或改成最短路。
- **980 不同路径 III**（必须经过所有格子）：变成**回溯**（哈密顿路径），指数级。**"计数用 DP、要求经过所有点就得搜索"。**
- **返回一条具体路径**：从终点倒推，看 `dp[i][j]` 是从上还是从左来的。
- **m、n 极大（10⁹）**：DP 不可行，必须用组合数 + 模逆元。

### 64. 最小路径和（中等）

**题意**  `m × n` 非负整数网格，从左上走到右下（只能向右或向下），求路径上数字总和的**最小值**。

**暴力**  DFS 枚举所有路径取最小，O(2^(m+n))。或贪心"每步选较小的邻居"——**这是错的**：局部选小可能导致后续被迫走大数。反例：
```
1 2 100
1 100 1
1 1  1
```
从 `(0,0)` 贪心向下（1 < 2），但最优路径需要看全局。**贪心失效，必须 DP。**

**关键洞察**

和 [62](#62-不同路径中等) 完全同构，只是把「方案数求和」换成「代价求最小」：

```
dp[i][j] = grid[i][j] + min(dp[i-1][j], dp[i][j-1])
```

**状态定义**：`dp[i][j]` = 「从起点走到 `(i,j)` 的最小路径和」。

**为什么 DP 对而贪心错**：`dp[i][j]` 枚举了到达 `(i,j)` 的**所有**方式（只有两种来源）并取最优，而贪心只看了一步。**这是"贪心可能错、DP 一定对"的又一个例子**（对照 [322 零钱兑换](15-动态规划.md)）。

**初始化是本题相对 62 的主要区别**：
- `dp[0][0] = grid[0][0]`
- **第一行**：只能从左边来 → `dp[0][j] = dp[0][j-1] + grid[0][j]`（前缀和）
- **第一列**：只能从上面来 → `dp[i][0] = dp[i-1][0] + grid[i][0]`

**不能简单填 1 或 0**，必须累加。这是最容易错的地方。

**最优解（C++，一维滚动数组）**

```cpp
class Solution {
public:
    int minPathSum(vector<vector<int>>& grid) {
        int m = grid.size(), n = grid[0].size();
        vector<int> dp(n);
        dp[0] = grid[0][0];
        for (int j = 1; j < n; ++j) dp[j] = dp[j-1] + grid[0][j];   // 第一行前缀和
        for (int i = 1; i < m; ++i) {
            dp[0] += grid[i][0];                                    // 第一列只能从上来
            for (int j = 1; j < n; ++j)
                dp[j] = grid[i][j] + min(dp[j], dp[j-1]);           // 上 vs 左
        }
        return dp[n-1];
    }
};
```

**原地修改版（O(1) 额外空间，直接改 grid）**

```cpp
int minPathSum(vector<vector<int>>& grid) {
    int m = grid.size(), n = grid[0].size();
    for (int i = 0; i < m; ++i)
        for (int j = 0; j < n; ++j) {
            if (i == 0 && j == 0) continue;
            else if (i == 0) grid[i][j] += grid[i][j-1];            // 第一行
            else if (j == 0) grid[i][j] += grid[i-1][j];            // 第一列
            else grid[i][j] += min(grid[i-1][j], grid[i][j-1]);
        }
    return grid[m-1][n-1];
}
```

**面试要主动说明「这会修改输入」**，并提出"若不允许修改就用一维 dp 数组，额外 O(n) 空间"。

**复杂度**  时间 O(mn)，空间 O(n)（一维版）或 O(1)（原地版）。

**边界与坑**
- **第一行和第一列必须用前缀和初始化**，不能填 0 或 1。这是与 62 最大的区别，也是本题头号错误。
- **`dp[0] += grid[i][0]` 这一句不能漏**（一维版）。漏了第一列就没被累加，`min(dp[0], dp[-1])` 还会越界。
- **一维版内层从 `j = 1` 开始**（`j = 0` 已在上面单独处理）。
- **`min(dp[j], dp[j-1])` 中 `dp[j]` 是上一行的值、`dp[j-1]` 是本行的值**——正序遍历保证的（同 62）。**这个"新旧混用"是一维优化的精髓，也是最容易糊涂的地方。**
- **网格值非负**（题目保证）。若允许负数，"只能向右下"仍然让 DP 成立（无环），但不能做任何"提前剪枝"的优化。
- **不能贪心**，见"暴力"部分的反例。
- 单格网格返回 `grid[0][0]`。
- 空网格要提前判（题目保证非空）。

**追问 / 变体**
- **62 不同路径**：计数版，见上题。**62/64 一起写能看清"同一个网格结构，+变min就换了问题"。**
- **63 不同路径 II**（障碍）：障碍格设为不可达（`dp = 0` 或 `INF`）。
- **120 三角形最小路径和**：网格变成三角形，转移方向略变，**从下往上递推可以免掉边界判断**，是很漂亮的技巧。
- **931 下降路径最小和**（可向左下/下/右下）：三个方向取 min。
- **返回具体路径**：必须保留二维表，从终点倒推比较 `dp[i-1][j]` 和 `dp[i][j-1]`。**一维优化后无法倒推，这是空间优化的代价。**
- **可以向四个方向移动**：有环，DP 失效，必须用 **Dijkstra**（边权为格子值）。**这个界线很重要：单向 → DP，任意方向 → 最短路算法。**
- **求最大路径和**：`min` 换 `max`。若含负数且可任意方向，则是 NP-hard。
- **1631 最小体力消耗路径**：路径代价定义为"最大单步差值"，用 Dijkstra 或二分 + BFS。

### 5. 最长回文子串（中等）

**题意**  返回字符串 `s` 中最长的**回文子串**（连续）。

**暴力**  枚举所有 O(n²) 个子串，每个 O(n) 判断是否回文 → O(n³)。n = 1000 时 10⁹ 次操作，超时。

**关键洞察**

有三种解法，**面试推荐中心扩展**（O(1) 空间、好写），但区间 DP 的思想也必须掌握（[131 分割回文串](10-回溯.md) 会用到）。

---

**思路一：中心扩展（推荐，O(n²) 时间 O(1) 空间）**

**关键认识：每个回文串都有一个"中心"，从中心向两边扩展。**

- **奇数长度**回文的中心是**一个字符**（如 `"aba"` 的中心是 `b`）
- **偶数长度**回文的中心是**两个字符之间的缝隙**（如 `"abba"` 的中心在两个 `b` 之间）

所以中心共有 **`2n - 1`** 个（n 个字符 + n-1 个缝隙）。对每个中心向两侧扩展，直到字符不等或越界，记录最长的。

**为什么这样不漏解**：任何回文子串都有唯一的中心，而我们枚举了所有可能的中心 → 覆盖完整。**这个"枚举中心"的转换是本题的核心**，它把 O(n³) 降到 O(n²)，且不需要任何额外空间。

---

**思路二：区间 DP（O(n²) 时间 O(n²) 空间）**

**状态定义**：`pal[i][j]` = 「`s[i..j]` 是否是回文」。

**转移**：

```
pal[i][j] = (s[i] == s[j]) && (j - i < 2 || pal[i+1][j-1])
```

- 首尾字符必须相等
- **且**去掉首尾之后的内部也是回文
- `j - i < 2` 处理长度 1 和 2 的基础情况（长度 1 必回文；长度 2 只需两字符相等，此时 `i+1 > j-1` 是无效区间不能读）

**遍历顺序是本解法的关键**：`pal[i][j]` 依赖 `pal[i+1][j-1]`（**更大的 i**、更小的 j），所以 **`i` 必须倒序遍历**，`j` 正序。写正序会读到还没算的值（初始 `false`），导致长回文被误判。

**这个 DP 表和 [131 分割回文串](10-回溯.md) 用的预处理完全一样**，两题对照记忆。

---

**思路三：Manacher 算法（O(n)，竞赛用）**

在字符间插入分隔符（如 `#`）把所有回文统一成奇数长度，然后利用已算出的回文信息避免重复扩展，做到线性。**面试提一句"存在 O(n) 的 Manacher 算法"即可，通常不要求手写。**

**最优解（C++，中心扩展）**

```cpp
class Solution {
    // 从 (l, r) 向两侧扩展，返回回文长度
    int expand(const string& s, int l, int r) {
        while (l >= 0 && r < (int)s.size() && s[l] == s[r]) { --l; ++r; }
        return r - l - 1;                       // 退出时 s[l] != s[r]，有效区间是 [l+1, r-1]
    }
public:
    string longestPalindrome(string s) {
        int start = 0, best = 0;
        for (int i = 0; i < (int)s.size(); ++i) {
            int len1 = expand(s, i, i);         // 奇数长度，中心是字符 i
            int len2 = expand(s, i, i + 1);     // 偶数长度，中心在 i 和 i+1 之间
            int len = max(len1, len2);
            if (len > best) {
                best = len;
                start = i - (len - 1) / 2;      // 由中心和长度反推起点
            }
        }
        return s.substr(start, best);
    }
};
```

**`start = i - (len - 1) / 2` 的推导**（本题最容易错的一行）：
- 奇数 `len`（如 3，中心 i）：`start = i - 1` ✓
- 偶数 `len`（如 4，中心在 i 和 i+1 之间）：`start = i - 1` ✓（`(4-1)/2 = 1`，整数除法向下取整）

**整数除法恰好统一了两种情况**，不需要分支。**建议用 `"babad"` 和 `"cbbd"` 各手算一遍验证。**

**区间 DP 版**

```cpp
string longestPalindrome(string s) {
    int n = s.size();
    if (n < 2) return s;
    vector<vector<bool>> pal(n, vector<bool>(n, false));
    int start = 0, best = 1;
    for (int i = n - 1; i >= 0; --i)               // i 必须倒序！
        for (int j = i; j < n; ++j) {
            pal[i][j] = (s[i] == s[j]) && (j - i < 2 || pal[i+1][j-1]);
            if (pal[i][j] && j - i + 1 > best) {
                best = j - i + 1;
                start = i;
            }
        }
    return s.substr(start, best);
}
```

**复杂度**  中心扩展：O(n²) 时间、**O(1) 空间**。区间 DP：O(n²) 时间、O(n²) 空间。Manacher：O(n) 时间、O(n) 空间。

**边界与坑**
- **必须同时处理奇数和偶数两种中心**。只做 `expand(s, i, i)` 会漏掉 `"cbbd"` 里的 `"bb"`，答案错成 `"b"`。**这是本题头号 bug。**
- **`expand` 返回 `r - l - 1`**。循环退出时 `l` 和 `r` 已经各多走了一步（指向不匹配的位置），所以有效长度是 `(r-1) - (l+1) + 1 = r - l - 1`。写成 `r - l` 或 `r - l + 1` 都会偏。
- **`start = i - (len - 1) / 2`** 的整数除法不能改成 `len / 2`。用 `"cbbd"` 验证：`i=1, len2=2`，`(2-1)/2 = 0`，`start = 1` ✓；而 `2/2 = 1` 会得到 `start = 0` ✗。
- **区间 DP 的 `i` 必须倒序**。正序会读到未初始化的 `pal[i+1][j-1]`。
- **`j - i < 2` 不能写成 `j - i <= 2`**。后者会把长度 3 的情况也短路成"只看首尾"——**结果碰巧对**（长度 3 确实只需首尾相等），但语义错误，换到别的题（如统计回文数）就会出错。**标准写法是 `< 2`。**
- **`best` 初值**：中心扩展版可以是 0（因为单字符必然给出 len ≥ 1）；区间 DP 版要设为 1 且 `start = 0`（保证空/单字符时返回合法结果）。
- 空串返回空串；单字符返回自身。
- **答案要返回子串本身**而不是长度，别忘了 `substr`。
- **`substr(start, best)` 的第二个参数是长度**（同 [131](10-回溯.md) 的坑）。

**追问 / 变体**
- **647 回文子串**（统计回文子串**个数**）：中心扩展时每成功扩展一次就 `++count`，一行改动。**是本题最好的配套练习。**
- **131 分割回文串 / 132 分割回文串 II**：用本题的 `pal` 表预处理，见 [10-回溯](10-回溯.md)。
- **516 最长回文子序列**（**子序列**不要求连续）：完全不同的题！是双序列 DP 的思路——`dp[i][j] = (s[i]==s[j]) ? dp[i+1][j-1]+2 : max(dp[i+1][j], dp[i][j-1])`。**"子串"和"子序列"一字之差，解法完全不同**，务必分清。
- **最长回文子序列 = s 与 reverse(s) 的 LCS**：这个转化很漂亮（见 [1143](#1143-最长公共子序列中等)）。
- **214 最短回文串**（在前面加字符使整串回文）：用 KMP 求「s 的最长回文前缀」。
- **n 达到 10⁶**：必须用 Manacher，O(n²) 不可行。
- **为什么中心扩展比 DP 好**：同样 O(n²) 时间，但空间 O(1) vs O(n²)，且常数更小（DP 要填满整个表，中心扩展遇到不匹配立刻停）。**面试首选中心扩展。**

### 1143. 最长公共子序列（中等）

**题意**  返回两个字符串的**最长公共子序列**的长度。子序列可以不连续，但**顺序不能变**。

**暴力**  枚举 `text1` 的所有 2^m 个子序列，检查是否是 `text2` 的子序列，O(2^m · n)。不可行。

**关键洞察**

**这是双序列 DP 的模板题**，务必把状态定义和转移背下来——72 编辑距离是它的直接升级。

**状态定义（严格按套路）**：

> **`dp[i][j]` = 「`text1` 的前 `i` 个字符」与「`text2` 的前 `j` 个字符」的 LCS 长度**

**用"前 i 个"（长度）而不是"下标 i"**，所以第 `i` 个字符是 `text1[i-1]`。**这个减 1 是双序列 DP 的固定记账方式。**

**转移：看两个末尾字符**

**情况一：`text1[i-1] == text2[j-1]`**（末尾字符相同）

这两个字符**一定可以配对**加入 LCS（可以证明：把它们配对不会比不配对差）：

```
dp[i][j] = dp[i-1][j-1] + 1
```

**情况二：末尾字符不同**

这两个字符**不可能同时**是 LCS 的末尾。所以至少要"放弃"一个：

```
dp[i][j] = max( dp[i-1][j],    // 放弃 text1 的第 i 个字符
                dp[i][j-1] )   // 放弃 text2 的第 j 个字符
```

**为什么不需要 `dp[i-1][j-1]`**：它已经被上面两项包含了（`dp[i-1][j] >= dp[i-1][j-1]`，因为多考虑一个字符不会变差）。**写上也不错，但多余。**

**初始化**：`dp[0][j] = dp[i][0] = 0`——一方为空串时 LCS 为 0。**用"前 i 个"的定义，这个边界是免费的**（`vector` 默认初始化为 0 即可）。

**最优解（C++）**

```cpp
class Solution {
public:
    int longestCommonSubsequence(string text1, string text2) {
        int m = text1.size(), n = text2.size();
        vector<vector<int>> dp(m + 1, vector<int>(n + 1, 0));   // 边界天然为 0
        for (int i = 1; i <= m; ++i)
            for (int j = 1; j <= n; ++j) {
                if (text1[i-1] == text2[j-1])                    // 注意 -1
                    dp[i][j] = dp[i-1][j-1] + 1;                 // 末尾配对
                else
                    dp[i][j] = max(dp[i-1][j], dp[i][j-1]);      // 放弃其中一个
            }
        return dp[m][n];
    }
};
```

**一维滚动数组版（O(min(m,n)) 空间）**

```cpp
int longestCommonSubsequence(string text1, string text2) {
    if (text1.size() < text2.size()) swap(text1, text2);        // 让 text2 更短
    int m = text1.size(), n = text2.size();
    vector<int> dp(n + 1, 0);
    for (int i = 1; i <= m; ++i) {
        int prevDiag = 0;                    // 保存 dp[i-1][j-1]
        for (int j = 1; j <= n; ++j) {
            int tmp = dp[j];                 // 当前 dp[j] 还是 dp[i-1][j]，先存下来
            if (text1[i-1] == text2[j-1]) dp[j] = prevDiag + 1;
            else dp[j] = max(dp[j], dp[j-1]);
            prevDiag = tmp;                  // 它将成为下一轮的 dp[i-1][j-1]
        }
    }
    return dp[n];
}
```

**一维版必须手动保存"左上角"的值**（`prevDiag`），因为 `dp[j-1]` 在本轮已被更新成 `dp[i][j-1]`，而我们需要的是 `dp[i-1][j-1]`。**这是一维优化最容易错的地方**，比网格 DP（62/64）复杂，因为多了对角线依赖。

**复杂度**  时间 O(mn)，空间 O(mn) 或 O(min(m,n))（一维版）。

**边界与坑**
- **字符下标是 `text1[i-1]` 不是 `text1[i]`**。因为 `dp[i]` 表示"前 i 个字符"。**这个 off-by-one 是双序列 DP 的头号错误**，每次写都要提醒自己。
- **DP 表大小是 `(m+1) × (n+1)`**。开成 `m × n` 会越界。
- **循环从 1 开始到 `<= m`**（不是 `< m`）。
- **相等时是 `dp[i-1][j-1] + 1`**，不是 `dp[i-1][j] + 1` 或 `max(...) + 1`。
- **一维版必须用 `prevDiag` 暂存左上角值**，且 `prevDiag` 要在每行开始时重置为 0（即 `dp[i-1][0] = 0`）。漏掉重置会让每行的第一个计算出错。
- **子序列不要求连续**。若要求连续（**最长公共子串**），转移变成：相等时 `dp[i][j] = dp[i-1][j-1] + 1`，**不相等时 `dp[i][j] = 0`**（断了就得重新开始），且答案是 `max(dp[i][j])` 而不是 `dp[m][n]`。**这个区别极其重要，两题经常一起考。**
- 空串输入返回 0。

**追问 / 变体**
- **最长公共子串**（连续）：见上，不相等时置 0 且答案取全表最大值。
- **返回 LCS 本身**：从 `dp[m][n]` 倒推——相等就取该字符并往左上走，否则往 `dp` 值大的方向走。**需要保留二维表**（一维优化后无法倒推）。
- **72 编辑距离**：本题的升级版，见下题。**1143 → 72 是双序列 DP 的自然进阶。**
- **583 两个字符串的删除操作**：答案 = `m + n - 2 × LCS`。**一行转化。**
- **516 最长回文子序列**：等价于「`s` 与 `reverse(s)` 的 LCS」。**这个转化很漂亮，值得记。**
- **1035 不相交的线**：换了包装的 LCS 原题。
- **三个字符串的 LCS**：三维 DP，O(mnp)。
- **m、n 达到 10⁵**：O(mn) 不可行。**一般情况下 LCS 没有亚二次算法**（有理论下界），但若字符集小或序列有特殊结构（如都是排列），可转化成 LIS 用 O(n log n) 解决。**这个知识点面试提出来很亮眼。**

### 72. 编辑距离（中等）

> 官方标注中等，但实际难度接近困难——三个转移方向 + 非零边界，是双序列 DP 的集大成者。

**题意**  求把 `word1` 转换成 `word2` 所需的**最少操作数**。允许三种操作：**插入**一个字符、**删除**一个字符、**替换**一个字符。

**暴力**  DFS 枚举每一步做哪种操作，O(3^max(m,n))。加记忆化就成了 DP。

**关键洞察**

**这是双序列 DP 的巅峰题**，在 [1143](#1143-最长公共子序列中等) 的框架上把"两种放弃"扩展成"三种操作"。

**状态定义（同 1143 的套路）**：

> **`dp[i][j]` = 把「`word1` 的前 `i` 个字符」转换成「`word2` 的前 `j` 个字符」所需的最少操作数**

**转移：看两个末尾字符**

**情况一：`word1[i-1] == word2[j-1]`**（末尾字符已经相同）

**不需要任何操作**，直接继承：

```
dp[i][j] = dp[i-1][j-1]
```

**情况二：末尾字符不同**——三种操作各对应一个来源，取最小：

```
dp[i][j] = 1 + min( dp[i-1][j-1],    // 替换：把 word1[i-1] 改成 word2[j-1]
                    dp[i][j-1],       // 插入：在 word1 末尾插入 word2[j-1]
                    dp[i-1][j] )      // 删除：删掉 word1[i-1]
```

**三个方向的含义必须想清楚**（这是本题最核心也最容易混的地方）：

| 来源 | 操作 | 直觉解释 |
|---|---|---|
| `dp[i-1][j-1]` | **替换** | 两个末尾都"处理掉"了，代价 1 |
| `dp[i-1][j]` | **删除** | 删掉 `word1` 的末尾，`word2` 还剩 j 个待匹配 |
| `dp[i][j-1]` | **插入** | 给 `word1` 补上 `word2` 的末尾，`word1` 原有的 i 个还没动 |

**记忆技巧**：**`i` 变小 = 删除（word1 少一个），`j` 变小 = 插入（word2 少一个待匹配），两个都变小 = 替换。**

**初始化（本题相对 1143 的关键区别）**

1143 的边界全是 0，但本题不是：

- **`dp[i][0] = i`**：把长度 i 的串变成空串，需要**删除 i 次**
- **`dp[0][j] = j`**：把空串变成长度 j 的串，需要**插入 j 次**

**这个初始化不能漏**，否则整张表全错。这也是"为什么用『前 i 个』的定义很方便"的又一个体现——边界含义一目了然。

**最优解（C++）**

```cpp
class Solution {
public:
    int minDistance(string word1, string word2) {
        int m = word1.size(), n = word2.size();
        vector<vector<int>> dp(m + 1, vector<int>(n + 1, 0));
        for (int i = 0; i <= m; ++i) dp[i][0] = i;      // 全删
        for (int j = 0; j <= n; ++j) dp[0][j] = j;      // 全插

        for (int i = 1; i <= m; ++i)
            for (int j = 1; j <= n; ++j) {
                if (word1[i-1] == word2[j-1])
                    dp[i][j] = dp[i-1][j-1];            // 末尾相同，免费
                else
                    dp[i][j] = 1 + min({ dp[i-1][j-1],  // 替换
                                         dp[i-1][j],    // 删除
                                         dp[i][j-1] }); // 插入
            }
        return dp[m][n];
    }
};
```

**一维滚动数组版（O(n) 空间）**

```cpp
int minDistance(string word1, string word2) {
    int m = word1.size(), n = word2.size();
    vector<int> dp(n + 1);
    for (int j = 0; j <= n; ++j) dp[j] = j;             // 第 0 行
    for (int i = 1; i <= m; ++i) {
        int prevDiag = dp[0];                            // 保存 dp[i-1][j-1]
        dp[0] = i;                                       // 本行第 0 列 = i（全删）
        for (int j = 1; j <= n; ++j) {
            int tmp = dp[j];                             // 现在的 dp[j] 是 dp[i-1][j]
            if (word1[i-1] == word2[j-1]) dp[j] = prevDiag;
            else dp[j] = 1 + min({ prevDiag, dp[j], dp[j-1] });
            prevDiag = tmp;
        }
    }
    return dp[n];
}
```

**一维版有两个易错点**：① `prevDiag` 必须在更新 `dp[0]` **之前**保存旧值；② `dp[0] = i` 这一句不能漏（本行的第 0 列）。**比 1143 的一维版更容易错，面试建议直接写二维版。**

**复杂度**  时间 O(mn)，空间 O(mn) 或 O(n)（一维版）。

**边界与坑**
- **初始化 `dp[i][0] = i` 和 `dp[0][j] = j` 不能漏**，也不能都设成 0（那是 1143 的边界）。**这是本题头号 bug。**
- **相等时是 `dp[i][j] = dp[i-1][j-1]`，不加 1**。写成 `dp[i-1][j-1] + 1` 会让每个字符都多算一次操作。
- **不相等时的 `1 +` 要加在 `min` 外面**，三个来源共享这一次操作代价。
- **三个方向别搞混**。特别是 `dp[i-1][j]` 是删除、`dp[i][j-1]` 是插入——**很多人会记反**。用"i 变小=删 word1 的字符"来推导，比死记更可靠。
- **字符下标是 `word1[i-1]`**（同 1143 的 off-by-one）。
- **`min({a,b,c})` 需要初始化列表版本**（C++11），或写 `min(a, min(b, c))`。
- 空串输入：`word1 = ""` 时答案是 `word2.size()`（全插），由初始化直接给出。
- **本题的三种操作代价都是 1**。若代价不同（如插入 2、删除 1、替换 3），转移里换成对应权重即可，框架不变。
- **注意"替换"也可以理解成"删除 + 插入"（代价 2）**，所以有替换操作时答案 ≤ 无替换时的答案。这解释了为什么 583 题（只允许删除）的答案更大。

**追问 / 变体**
- **583 两个字符串的删除操作**（只允许删除）：答案 = `m + n - 2 × LCS`，或去掉转移里的"替换"分支。
- **712 两个字符串的最小 ASCII 删除和**：代价从"1 次"变成"字符的 ASCII 值"，框架完全一样。**很好地说明了"代价可配置"。**
- **1143 最长公共子序列**：本题的"兄弟题"，见上题。**1143 求最大、72 求最小，转移结构高度相似，一起写能彻底掌握双序列 DP。**
- **返回具体的操作序列**：保留二维表，从 `dp[m][n]` 倒推，看它是从哪个方向来的。**这是编辑器 diff 功能的原理。**
- **只允许插入和删除**：即 583，去掉替换分支。
- **Levenshtein 距离的变体**：加上"交换相邻字符"操作 → **Damerau-Levenshtein 距离**，多一个来源 `dp[i-2][j-2] + 1`。拼写检查器常用。
- **m、n 达到 10⁵**：O(mn) 不可行。若**距离本身很小（≤ k）**，可用 **Ukkonen 的带状 DP**，只计算主对角线附近的 O(k) 条带，复杂度 O(k × min(m,n))。**这是实际工程（如 diff 工具、模糊搜索）的做法，面试提出来很有分量。**
- **应用场景**：拼写纠错、DNA 序列比对、`git diff`、模糊搜索。**能说出实际应用是加分项。**
