# 11 · 二分查找（6 题）

## 套路总纲

二分的思想人人会说，但**边界写对**才是分数线。本专题的目标：**把一套写法固定下来，以后每题不再重新想边界**。

**为什么会写错**：`left <= right` 还是 `left < right`？`mid` 要不要 `+1`？返回 `left` 还是 `right`？组合起来有十几种排列，每次现场推必然出错。解决办法是**只记两个模板**，其余全部化归。

**模板一：闭区间 `[left, right]`，查找精确值**

```cpp
int search(vector<int>& a, int target) {
    int l = 0, r = a.size() - 1;             // 闭区间，r 指向最后一个有效元素
    while (l <= r) {                         // 区间非空的条件（l == r 时仍有一个元素）
        int mid = l + (r - l) / 2;           // 防溢出
        if (a[mid] == target) return mid;
        if (a[mid] < target) l = mid + 1;    // 舍弃 mid 及左侧
        else r = mid - 1;                    // 舍弃 mid 及右侧
    }
    return -1;
}
```

**模板二：左闭右开 `[left, right)`，查找边界（更通用，强烈推荐）**

```cpp
// 找第一个满足 check(i) == true 的位置；若都不满足返回 n
int lowerBound(vector<int>& a, int target) {
    int l = 0, r = a.size();                 // 注意 r = n，不是 n-1
    while (l < r) {                           // l == r 时区间空，退出
        int mid = l + (r - l) / 2;
        if (a[mid] < target) l = mid + 1;     // mid 不满足，答案在右边
        else r = mid;                         // mid 可能是答案，保留它
    }
    return l;                                 // l == r，即答案位置
}
```

**模板二是本专题的主力**。它的核心不变量：**`[0, l)` 全部不满足，`[r, n)` 全部满足**。循环结束时 `l == r`，正好是分界点。因为 `r = mid`（不是 `mid - 1`），所以**答案永不被丢弃**。

**「二分答案」的思维框架**（本专题的统一视角）

不要想「怎么二分」，要想**「有没有一个单调的判定函数」**：

> 把问题变成：找一个分界点，使得左边全 `false`、右边全 `true`。

一旦能定义出这样的 `check(x)`，二分就是机械的。例如：
- 34 找左边界：`check(i) = (a[i] >= target)`
- 34 找右边界：`check(i) = (a[i] > target)`，答案是这个位置 -1
- 35 插入位置：`check(i) = (a[i] >= target)`，就是 `lower_bound`
- 153 找最小值：`check(i) = (a[i] <= a[n-1])`

**「有序」不是二分的必要条件，「单调可判定」才是。** 33 和 153 的数组不是全局有序，但仍能二分，因为「在哪一半」这个判定是可以 O(1) 做出的。这是本专题最重要的一课。

**三条铁律**

1. **`mid = l + (r - l) / 2`**，不写 `(l + r) / 2`（`l + r` 可能溢出 `int`）。
2. **每一轮必须缩小区间**。`l = mid` 是死循环的常见来源（当 `l == mid` 时区间不变）；需要 `l = mid` 时必须配 `mid = l + (r - l + 1) / 2`（向上取整）。
3. **循环不变量要能用一句话说清**。说不清就是没想明白，必错。

**C++ 标准库**（面试可用，但要能手写）

```cpp
lower_bound(a.begin(), a.end(), x);   // 第一个 >= x 的位置
upper_bound(a.begin(), a.end(), x);   // 第一个 >  x 的位置
// x 的出现次数 = upper_bound - lower_bound
```

**难度递进**：35 是纯模板 → 74 是坐标映射 → 34 是双边界 → 33/153 破除"必须有序"的执念 → 4 是困难题（二分割点）。

### 35. 搜索插入位置（简单）

**题意**  升序无重复数组中，返回 `target` 的下标；若不存在，返回它**按序插入后**应处的下标。

**暴力**  线性扫描找第一个 `>= target` 的位置，O(n)。题目要求 O(log n)。

**关键洞察**

这题是 `lower_bound` 的定义题，也是理解二分的最佳起点。

**关键转化**：不要分「找到了」和「没找到」两种情况来写——那会让代码变复杂。统一成一个问题：

> **找第一个 `>= target` 的位置。**

- 如果 `target` 存在，第一个 `>= target` 的就是它本身 ✓
- 如果不存在，第一个 `>= target` 的位置正是它该插入的地方（插在这里，比它小的都在左边）✓
- 如果所有元素都 `< target`，返回 `n`（插在末尾）✓

**一个判定统一了三种情况**，这就是「二分答案」框架的威力：先想清"我在找哪个分界点"，代码自然就出来了。

用模板二，`check(i) = (a[i] >= target)`：左边全是 `< target`，右边全是 `>= target`，`l` 收敛到分界点。

**最优解（C++）**

```cpp
class Solution {
public:
    int searchInsert(vector<int>& nums, int target) {
        int l = 0, r = nums.size();               // 左闭右开 [0, n)
        while (l < r) {
            int mid = l + (r - l) / 2;
            if (nums[mid] < target) l = mid + 1;  // mid 太小，答案在右边
            else r = mid;                          // mid 可能就是答案，保留
        }
        return l;                                  // 第一个 >= target 的位置
    }
};
```

**闭区间写法（模板一变体，结果相同）**

```cpp
int searchInsert(vector<int>& nums, int target) {
    int l = 0, r = nums.size() - 1;
    while (l <= r) {
        int mid = l + (r - l) / 2;
        if (nums[mid] < target) l = mid + 1;
        else r = mid - 1;
    }
    return l;              // 循环结束时 l 就是插入位置（此时 l == r + 1）
}
```

**复杂度**  时间 O(log n)，空间 O(1)。

**边界与坑**
- **`r` 的初值是 `n` 不是 `n - 1`**（模板二）。写成 `n - 1` 时，若 `target` 比所有元素都大，答案 `n` 永远取不到，会错答 `n - 1`。**这是本题最经典的错误**，测试用例 `nums=[1,3], target=5` 专卡这个。
- **`r = mid` 不是 `r = mid - 1`**（模板二）。写 `mid - 1` 会跳过可能是答案的 `mid`。
- **循环条件是 `l < r` 不是 `l <= r`**（模板二）。写 `<=` 配合 `r = mid` 会死循环（`l == r == mid` 时区间不缩小）。**条件、更新、初值三者必须成套**，混搭必错。
- 闭区间写法**返回 `l` 而不是 `r`**。循环退出时 `l == r + 1`，`l` 才是插入位置。
- `mid = l + (r - l) / 2` 的防溢出写法：本题 n ≤ 10⁴ 不会溢出，但要养成习惯。
- 空数组返回 0（模板二天然正确：`l = r = 0`，循环不执行）。

**追问 / 变体**
- **手写 `lower_bound` / `upper_bound`**：本题就是 `lower_bound`。`upper_bound` 只需把 `<` 改成 `<=`（找第一个 `> target` 的位置）。**这一个字符的差别要能立刻说出。**
- **有重复元素时**：本题保证无重复；有重复时返回的是**最左**的位置（因为 `r = mid` 保留了更左的候选）。
- **34 查找元素的第一个和最后一个位置**：本题的双边界版，见下文。
- **在旋转数组里插入**：先找旋转点，再决定在哪一段二分。
- **浮点数二分**（如求平方根）：循环条件改成 `while (r - l > eps)` 或固定迭代次数（如 100 次），不能用整数的 `l < r`。

### 74. 搜索二维矩阵（中等）

**题意**  `m × n` 矩阵，**每行升序**，且**每行第一个元素大于上一行最后一个元素**（即整体展平后是全局升序）。判断 `target` 是否存在。

**暴力**  逐行扫描，O(mn)。或者对每一行做二分，O(m log n)。都能过，但没利用「全局有序」这个强条件。

**关键洞察**

题目条件「每行首元素 > 上一行末元素」的真正含义是：**把矩阵按行拼接展平后，得到一个完全升序的一维数组**。

那么问题就变成了「在长度 `m*n` 的升序数组里二分查找」——**唯一的工作是把一维下标翻译回二维坐标**：

```
一维下标 idx  →  行 = idx / n，列 = idx % n
```

（`n` 是**列数**，即每行的长度。）

这个「**降维映射**」是本题的全部技巧，也是很通用的手法：只要能建立一维索引和目标结构的一一对应，就能直接套一维算法，不必重新设计。

**为什么不需要真的展平数组**：`get(idx) = matrix[idx / n][idx % n]` 是 O(1) 的虚拟访问，不占额外空间。

**最优解（C++，一次二分）**

```cpp
class Solution {
public:
    bool searchMatrix(vector<vector<int>>& matrix, int target) {
        int m = matrix.size(), n = matrix[0].size();
        int l = 0, r = m * n;                          // 左闭右开 [0, m*n)
        while (l < r) {
            int mid = l + (r - l) / 2;
            int val = matrix[mid / n][mid % n];        // 一维下标 → 二维坐标
            if (val == target) return true;
            if (val < target) l = mid + 1;
            else r = mid;
        }
        return false;
    }
};
```

**两次二分版（先定位行，再行内查找；更易解释）**

```cpp
bool searchMatrix(vector<vector<int>>& matrix, int target) {
    int m = matrix.size(), n = matrix[0].size();
    // 第一次：找最后一个"首元素 <= target"的行
    int lo = 0, hi = m - 1, row = -1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (matrix[mid][0] <= target) { row = mid; lo = mid + 1; }
        else hi = mid - 1;
    }
    if (row == -1) return false;                       // target 比所有元素都小
    // 第二次：在该行内二分
    lo = 0; hi = n - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (matrix[row][mid] == target) return true;
        if (matrix[row][mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return false;
}
```

**复杂度**  时间 O(log(mn))（= O(log m + log n)，两种写法同阶），空间 O(1)。

**边界与坑**
- **`n` 必须是列数**（`matrix[0].size()`），映射才对。用行数 `m` 去除会得到完全错误的坐标。**这是本题唯一的核心坑**。
- **`r` 初值是 `m * n` 不是 `m * n - 1`**（模板二的一贯要求）。
- **`m * n` 可能溢出**吗？本题 `m, n <= 100`，最大 10⁴，安全。若约束放大到 10⁵ × 10⁵ 就要用 `long long`。
- 空矩阵要提前判：`if (matrix.empty() || matrix[0].empty()) return false;`。LeetCode 本题保证非空。
- **别和 240 搞混**！240 的矩阵只保证「每行升序、每列升序」，**行与行之间没有全局顺序**（第二行第一个可能小于第一行最后一个），所以**不能展平二分**。240 的正解是从**右上角**出发的阶梯搜索 O(m+n)，见 [06-矩阵](06-矩阵.md)。**混用这两题的解法是高频错误**，面试务必先确认矩阵满足哪种性质。
- 两次二分版里 `row == -1` 的判断不能漏（target 小于所有元素时）。

**追问 / 变体**
- **240 搜索二维矩阵 II**：见上，阶梯搜索，见 [06-矩阵](06-矩阵.md)。
- **返回下标而非布尔**：把 `return true` 改成 `return {mid / n, mid % n}`。
- **统计 `<= target` 的元素个数**：把二分改成 `upper_bound` 语义，返回 `l`。
- **每行升序但行间无序**：只能对每行各二分，O(m log n)。
- **杨氏矩阵求第 k 小**（378）：二分答案 + 每次 O(m+n) 统计不超过 mid 的个数，是「二分答案」框架的漂亮应用。
- **三维有序数组**：同样的降维思路，`idx → (idx/(n*p), idx/p%n, idx%p)`。

### 34. 在排序数组中查找元素的第一个和最后一个位置（中等）

**题意**  升序数组（**可含重复**）中找 `target` 的起始和结束下标；不存在返回 `[-1, -1]`。要求 O(log n)。

**暴力**  先普通二分找到任意一个 `target`，再向左右线性扩展。最坏 O(n)——全数组都是同一个值时（`[2,2,2,...,2]` 查 2），扩展要走遍整个数组。**这个反例说明"找到后线性扩展"不满足 O(log n) 要求**，必须用两次二分。

**关键洞察**

**关键转化：把「找边界」变成「找分界点」。**

普通二分在 `a[mid] == target` 时就返回了，所以拿到的是**任意一个**位置。要拿到**最左**的位置，就不能在相等时停下，而要**继续向左收缩**。

用「二分答案」框架看，两个边界各对应一个判定函数：

| 目标 | 判定函数 `check(i)` | 返回 |
|---|---|---|
| 左边界（第一个 `== target`） | `a[i] >= target` | `l`（即 `lower_bound`） |
| 右边界（最后一个 `== target`） | `a[i] > target` | `l - 1`（即 `upper_bound - 1`） |

**右边界的推导值得说清**：`upper_bound` 给出第一个 **`> target`** 的位置，那么它前一个位置就是最后一个 `<= target` 的元素。如果 `target` 确实存在，这个元素必然等于 `target`，所以 `右边界 = upper_bound - 1`。

**所以本题 = 手写一遍 `lower_bound` + 一遍 `upper_bound`**，两者只差一个字符（`<` vs `<=`）。这是本题的全部内容，也是为什么它是巩固二分模板的最佳练习。

**存在性判断**：拿到 `lo = lower_bound(target)` 后，只需检查 `lo < n && a[lo] == target`。**不能只看 `lo < n`**（可能 `a[lo] > target`，即 target 不存在但插入位置合法）。

**最优解（C++）**

```cpp
class Solution {
    int lowerBound(vector<int>& a, int target) {      // 第一个 >= target 的位置
        int l = 0, r = a.size();
        while (l < r) {
            int mid = l + (r - l) / 2;
            if (a[mid] < target) l = mid + 1;
            else r = mid;
        }
        return l;
    }
public:
    vector<int> searchRange(vector<int>& nums, int target) {
        int lo = lowerBound(nums, target);
        if (lo == (int)nums.size() || nums[lo] != target) return {-1, -1};   // 不存在
        int hi = lowerBound(nums, target + 1) - 1;    // 巧解：第一个 >= target+1 的位置 - 1
        return {lo, hi};
    }
};
```

> **`lowerBound(target + 1)` 的妙处**：在整数数组里，「第一个 `> target`」等价于「第一个 `>= target + 1`」，所以**一个函数就能同时求出两个边界**，不用写两份二分。这个小技巧很值得记。（注意 `target + 1` 的溢出问题，见下。）

**显式写两个二分的版本（更通用，不依赖整数性质）**

```cpp
class Solution {
public:
    vector<int> searchRange(vector<int>& nums, int target) {
        int n = nums.size();
        // 左边界：第一个 >= target
        int l = 0, r = n;
        while (l < r) { int m = l + (r - l) / 2; if (nums[m] < target) l = m + 1; else r = m; }
        int lo = l;
        if (lo == n || nums[lo] != target) return {-1, -1};
        // 右边界：第一个 > target，再减 1
        l = 0; r = n;
        while (l < r) { int m = l + (r - l) / 2; if (nums[m] <= target) l = m + 1; else r = m; }
        return {lo, l - 1};                    // 唯一的差别：上面 <，这里 <=
    }
};
```

**复杂度**  时间 O(log n)（两次二分），空间 O(1)。

**边界与坑**
- **存在性判断必须是 `lo == n || nums[lo] != target` 两个条件**。只判 `lo == n` 会在「target 不存在但小于某些元素」时错答（如 `[1,3]` 查 2，`lo = 1` 但 `nums[1] = 3 != 2`）。**这是本题头号 bug。**
- **`target + 1` 可能溢出**：当 `target == INT_MAX` 时 `target + 1` 变成 `INT_MIN`，结果全错。本题约束 `target <= 10^9 < INT_MAX`，安全；但严谨写法应该用显式的第二个二分（`<=` 版本），或者把参数提升为 `long long`。**面试用了 `target+1` 技巧，一定要主动提这个风险**——这是体现严谨性的好机会。
- **右边界不要用 `l` 而要用 `l - 1`**。`upper_bound` 返回的是"第一个大于"的位置，是**开区间右端**，不是答案本身。
- **别在 `a[mid] == target` 时提前 `return`**。那样拿到的是任意位置，边界就丢了。**"相等时也要继续收缩"是找边界二分的核心。**
- 两次二分的 `r` 初值都是 `n`（不是 `n-1`），循环条件都是 `l < r`，更新都是 `r = mid`——**三者成套，别混搭**。
- 空数组返回 `[-1,-1]`（`lo = 0 == n`，第一个条件命中）。
- 只用一次二分再线性扩展**不满足 O(log n)**，见"暴力"部分的反例。面试写了这个会被追问。

**追问 / 变体**
- **统计 target 的出现次数**：`hi - lo + 1`，或直接 `upper_bound - lower_bound`。
- **用标准库**：`auto lo = lower_bound(a.begin(), a.end(), target); auto hi = upper_bound(...);` 然后判 `lo == a.end() || *lo != target`。面试可以先写库函数版说明思路，再手写。
- **浮点数 / 自定义比较**：`lower_bound` 的第四个参数可传比较器；降序数组要传 `greater<int>()`。
- **在旋转排序数组里找边界**：先找旋转点，再在对应段内二分。
- **278 第一个错误的版本 / 875 爱吃香蕉的珂珂**：都是「找第一个满足条件的位置」，本题的判定函数换成别的单调谓词即可。**认出"所有这类题都是同一个模板"是本专题的最大收获。**

### 33. 搜索旋转排序数组（中等）

**题意**  升序**无重复**数组被在某个下标处旋转（如 `[0,1,2,4,5,6,7]` → `[4,5,6,7,0,1,2]`），找 `target` 的下标，不存在返回 -1。要求 O(log n)。

**暴力**  线性扫描 O(n)。或者先 O(log n) 找旋转点，再在两段里各二分——正确但要写三段二分，繁琐。

**关键洞察**

这题打破了「二分必须全局有序」的直觉。**真正的要求是：每一步能 O(1) 判断出「答案在哪一半」。**

关键观察：**用 `mid` 把数组切成两半，至少有一半是完全有序的。**（因为只旋转了一次，最多只有一个"断点"，它只能落在其中一半里。）

于是判定流程变成：

1. **先判断哪一半有序**：比较 `a[mid]` 和 `a[l]`（左端点）。
   - `a[l] <= a[mid]` → **左半 `[l, mid]` 有序**
   - 否则 → **右半 `[mid, r]` 有序**（断点在左半）
2. **在有序的那一半里判断 target 是否落在其范围内**（因为有序，只需比较两端）：
   - 落在里面 → 收缩到这一半
   - 不在里面 → 收缩到另一半

**为什么必须"先找有序的一半"**：只有在有序区间内，「target 是否在此区间」才能靠两端点比较 O(1) 判定。无序的那一半没法这样判断，所以只能通过排除法进入。

**为什么用 `<=` 而不是 `<`**（`a[l] <= a[mid]`）：当 `l == mid`（区间只剩两个元素）时，左半只有一个元素，它当然是"有序"的。用 `<` 会漏掉这种情况导致判断错误。**这是本题最容易忽略的边界。**

**最优解（C++，闭区间）**

```cpp
class Solution {
public:
    int search(vector<int>& nums, int target) {
        int l = 0, r = nums.size() - 1;
        while (l <= r) {
            int mid = l + (r - l) / 2;
            if (nums[mid] == target) return mid;
            if (nums[l] <= nums[mid]) {                    // 左半 [l, mid] 有序
                if (nums[l] <= target && target < nums[mid]) r = mid - 1;   // 落在左半
                else l = mid + 1;                                            // 去右半
            } else {                                        // 右半 [mid, r] 有序
                if (nums[mid] < target && target <= nums[r]) l = mid + 1;   // 落在右半
                else r = mid - 1;                                            // 去左半
            }
        }
        return -1;
    }
};
```

**先找旋转点的两段式（思路更朴素，代码更长）**

```cpp
int search(vector<int>& nums, int target) {
    int n = nums.size();
    // 1. 找最小值下标（旋转点），见 153 题
    int l = 0, r = n - 1;
    while (l < r) {
        int mid = l + (r - l) / 2;
        if (nums[mid] > nums[r]) l = mid + 1;
        else r = mid;
    }
    int pivot = l;
    // 2. 用"旋转后的下标映射"在虚拟有序数组上二分
    l = 0; r = n - 1;
    while (l <= r) {
        int mid = l + (r - l) / 2;
        int real = (mid + pivot) % n;              // 映射回真实下标
        if (nums[real] == target) return real;
        if (nums[real] < target) l = mid + 1;
        else r = mid - 1;
    }
    return -1;
}
```

第二种写法的思路很有启发性：**通过下标映射 `(i + pivot) % n`，把旋转数组"虚拟地"还原成有序数组**，然后套最普通的二分。这和 [74 的降维映射](#74-搜索二维矩阵中等) 是同一种"化归"思想。

**复杂度**  时间 O(log n)，空间 O(1)。

**边界与坑**
- **`nums[l] <= nums[mid]` 的 `=` 不能少**。区间剩两个元素时 `mid == l`，此时左半就是单元素，必须判为"有序"。写成 `<` 会走错分支。
- **两个内层判断的不等号要精确**：
  - 左半有序时：`nums[l] <= target && target < nums[mid]`（`mid` 已经在开头判过不等于 target，所以用 `<`）
  - 右半有序时：`nums[mid] < target && target <= nums[r]`
  **一头闭一头开是刻意的**，把 `mid` 排除在外（它已被检查过）。写成两头都闭也能过（多判一次无害），但两头都开就会漏解。
- **必须先判 `nums[mid] == target` 再做分支**。否则 `mid` 恰好是答案时会被两个分支都排除掉。
- **本题要求无重复**。有重复时（81 题）`nums[l] == nums[mid]` 无法区分哪半有序（如 `[1,1,1,0,1,1]`），必须加 `if (nums[l] == nums[mid]) { ++l; continue; }` 退化处理，**最坏变成 O(n)**。这是 33 → 81 的核心难点，值得知道。
- 用 `nums[l]` 比较还是 `nums[r]` 比较都行，但**判断条件要相应改写**，别混搭。用 `nums[l]` 时判"左半有序"，用 `nums[r]` 时判"右半有序"（`nums[mid] <= nums[r]`）。
- 数组未旋转（旋转 0 次）时代码依然正确：整个数组"左半有序"，退化成普通二分。
- 单元素数组：`l == r == mid`，直接比较即可。

**追问 / 变体**
- **81 搜索旋转排序数组 II**（含重复）：见上，最坏 O(n)。**"为什么有重复就退化成 O(n)"是很好的追问**——因为无法判定哪半有序，最坏必须逐个排除。
- **153 寻找旋转排序数组中的最小值**：只找最小值，更简单，见下题。
- **154 寻找最小值 II**（含重复）：同样退化成最坏 O(n)。
- **旋转次数未知但要求出来**：就是求最小值的下标（153）。
- **两次旋转 / 多次旋转**：多个断点，二分失效（无法保证"至少一半有序"），只能 O(n)。**这说明本题的解法严格依赖"只旋转一次"这个条件。**
- **山脉数组查找**（852、1095）：也是"局部单调可判定"的二分，思路相通。

### 153. 寻找旋转排序数组中的最小值（中等）

**题意**  升序**无重复**数组被旋转若干次，返回最小元素。要求 O(log n)。

**暴力**  线性扫描取 min，O(n)；或者找「第一个 `a[i] < a[i-1]` 的位置」，同样 O(n)。

**关键洞察**

最小值就是那个**"断点"**——旋转后唯一的下降处。关键是找到一个**能判断"最小值在 mid 的哪一侧"的 O(1) 条件**。

**核心技巧：拿 `a[mid]` 和 `a[r]`（右端点）比较，而不是和 `a[l]` 比。**

- **`a[mid] > a[r]`** → `mid` 落在**左段**（较大的那段）。断点必在 `mid` 右边，所以 `l = mid + 1`（`mid` 本身不可能是最小值，可以安全排除）。
- **`a[mid] < a[r]`** → `mid` 落在**右段**（较小的那段）。`mid` **可能就是最小值**，所以 `r = mid`（保留它）。

循环不变量：**最小值始终在 `[l, r]` 内**。当 `l == r` 时收敛到答案。

**为什么必须和 `a[r]` 比而不是 `a[l]` 比？**

这是本题最精妙的一点。如果和 `a[l]` 比：
- `a[mid] > a[l]` 时无法判断——数组**未旋转**（如 `[1,2,3,4,5]`）时也满足这个条件，但此时最小值在**左边**；而真正旋转过时最小值在**右边**。同一个条件对应两种相反的结论，**判定失效**。

和 `a[r]` 比就没有这个歧义：未旋转时 `a[mid] < a[r]` 恒成立，会一路 `r = mid` 收缩到下标 0，**正确返回 `a[0]`**。**"与右端点比较能统一处理未旋转的情况"是本题的关键设计。**

**最优解（C++）**

```cpp
class Solution {
public:
    int findMin(vector<int>& nums) {
        int l = 0, r = nums.size() - 1;         // 闭区间，但配 l < r + r = mid
        while (l < r) {
            int mid = l + (r - l) / 2;
            if (nums[mid] > nums[r]) l = mid + 1;   // mid 在左段，最小值在右侧
            else r = mid;                            // mid 在右段，可能是答案，保留
        }
        return nums[l];                          // l == r，收敛到最小值
    }
};
```

只有五行，但每一行都不能动。

**复杂度**  时间 O(log n)，空间 O(1)。

**边界与坑**
- **必须和 `nums[r]` 比，不能和 `nums[l]` 比**，见上文推导。这是本题唯一但决定性的考点。
- **`r` 的初值是 `n - 1`**（真实的右端点），因为要拿 `nums[r]` 做比较，必须是有效下标。**这里和模板二的 `r = n` 不同**——凡是循环里要访问 `a[r]` 的写法，`r` 都必须是有效下标。
- **循环条件是 `l < r` 不是 `l <= r`**。用 `<=` 配 `r = mid` 会死循环（`l == r == mid` 时区间不缩小）。
- **`else` 分支是 `r = mid` 不是 `r = mid - 1`**。写 `mid - 1` 会跳过可能是最小值的 `mid`。
- **不需要判断 `nums[mid] == nums[r]`**（题目保证无重复）。有重复时（154 题）必须加 `else if (nums[mid] == nums[r]) --r;`，**最坏退化成 O(n)**（如 `[1,1,1,1]`）。原因同 [33 → 81](#33-搜索旋转排序数组中等)：相等时无法判定在哪一段。
- **未旋转的数组**（`[1,2,3]`）代码正确返回 `nums[0]`——这是"与右端点比较"带来的免费好处，不需要特判。
- 单元素数组：`l == r == 0`，循环不执行，直接返回。
- 别试图先判断"是否旋转过"再分情况——本代码已统一处理，加特判反而容易出错。

**追问 / 变体**
- **154 寻找最小值 II**（含重复）：见上，最坏 O(n)。
- **求旋转次数**：就是最小值的下标 `l`。
- **33 搜索旋转排序数组**：找特定值而非最小值，见上题。也可以「先用本题求出 pivot，再映射下标做普通二分」。
- **求最大值**：最大值是最小值的前一个位置 `(l - 1 + n) % n`。
- **数组降序旋转**：把所有不等号反向。
- **852 山脉数组的峰顶索引**：判定条件换成 `a[mid] < a[mid+1]`，同一个"找分界点"框架。

### 4. 寻找两个正序数组的中位数（困难）

**题意**  两个升序数组 `nums1`（长 m）、`nums2`（长 n），返回合并后的中位数。要求时间复杂度 **O(log(m+n))**。

**暴力**  合并两个数组再取中间，O(m+n) 时间 O(m+n) 空间。或者用双指针走到第 `(m+n)/2` 个元素，O(m+n) 时间 O(1) 空间。**都不满足题目的 O(log) 要求**，但面试务必先说这个思路作为基线。

**关键洞察**

O(log) 的要求排除了「逐个走」的思路，必须**每次砍掉一半**。有两条主流思路，**推荐先掌握"二分割点"法**（更快、更优雅）。

**思路：把「找中位数」转化为「找一条分割线」**

中位数的本质定义：一条把合并后数组分成**左右两半**的线，满足

1. **左半元素个数 = 右半元素个数**（或左比右多一个，取决于奇偶）
2. **左半的所有元素 ≤ 右半的所有元素**

现在在两个数组里各画一刀：`nums1` 前 `i` 个归左，`nums2` 前 `j` 个归左。

- **条件 1 确定了 `j`**：左半总数必须是 `(m+n+1)/2`，所以 **`j = (m+n+1)/2 - i`**。于是只剩一个自由变量 `i`——**这就是能二分的原因**。
- **条件 2 化为两个不等式**（只需检查跨越分割线的相邻元素）：
  ```
  nums1[i-1] <= nums2[j]     ①（左1 的最大 ≤ 右2 的最小）
  nums2[j-1] <= nums1[i]     ②（左2 的最大 ≤ 右1 的最小）
  ```

**关键的单调性**：`i` 增大 → `j` 减小 → `nums1[i-1]` 变大而 `nums2[j]` 变小 → 条件 ① 更难满足。**所以「① 是否成立」关于 `i` 是单调的**，可以二分！

- 若 ① 不成立（`nums1[i-1] > nums2[j]`）→ `i` 取大了，往左找。
- 若 ② 不成立（`nums2[j-1] > nums1[i]`）→ `i` 取小了，往右找。
- 两个都成立 → 找到了。

**找到后取值**：
- `(m+n)` 为**奇数**：左半多一个，答案 = `max(左半的两个末尾) = max(nums1[i-1], nums2[j-1])`
- `(m+n)` 为**偶数**：答案 = `(max(左半末尾) + min(右半开头)) / 2.0`

**边界的处理**：`i` 可以取 0 或 m（一刀切在数组外），此时 `nums1[i-1]` 或 `nums1[i]` 不存在。用**哨兵值**处理：不存在的左边界当 `INT_MIN`（不会违反 ①），不存在的右边界当 `INT_MAX`（不会违反 ②）。**这个哨兵技巧让代码免掉一堆 `if`，是本题的关键工程手法。**

**只在较短的数组上二分**：保证 `m <= n`，这样 `j = (m+n+1)/2 - i` 永远非负（不会越界），且复杂度是 O(log(min(m,n)))，比 O(log(m+n)) 还好。**若不交换，`j` 可能算出负数导致越界**——这是必须做的一步。

**最优解（C++，二分割点）**

```cpp
class Solution {
public:
    double findMedianSortedArrays(vector<int>& nums1, vector<int>& nums2) {
        if (nums1.size() > nums2.size()) return findMedianSortedArrays(nums2, nums1);
        int m = nums1.size(), n = nums2.size();
        int half = (m + n + 1) / 2;              // 左半应有的元素总数
        int l = 0, r = m;                        // i 的取值范围 [0, m]，闭区间
        while (l <= r) {
            int i = l + (r - l) / 2;             // nums1 取前 i 个
            int j = half - i;                    // nums2 取前 j 个
            // 四个跨界元素，越界用哨兵
            long long L1 = (i == 0) ? LLONG_MIN : nums1[i - 1];
            long long R1 = (i == m) ? LLONG_MAX : nums1[i];
            long long L2 = (j == 0) ? LLONG_MIN : nums2[j - 1];
            long long R2 = (j == n) ? LLONG_MAX : nums2[j];

            if (L1 > R2)      r = i - 1;         // i 太大，左1 的最大越界了
            else if (L2 > R1) l = i + 1;         // i 太小
            else {                                // 找到合法分割
                long long maxLeft = max(L1, L2);
                if ((m + n) % 2 == 1) return (double)maxLeft;     // 奇数：左半末尾
                long long minRight = min(R1, R2);
                return (maxLeft + minRight) / 2.0;                // 偶数：取平均
            }
        }
        return 0.0;                              // 不会到达（输入合法时必有解）
    }
};
```

**复杂度**  时间 **O(log(min(m, n)))**，空间 O(1)。优于题目要求的 O(log(m+n))。

**边界与坑**
- **必须保证在较短数组上二分**（开头那次 swap 递归）。否则 `j = half - i` 可能为负或超过 `n`，越界。
- **`half = (m + n + 1) / 2` 的 `+1` 是为奇数情况服务的**：让左半比右半多一个，这样奇数时答案就是"左半的最大值"，统一了两种情况的取值方式。写成 `(m+n)/2` 会让奇数时的答案变成"右半的最小值"，代码要跟着改，容易乱。**记住 `+1` 版本，配 `max(左半)`。**
- **哨兵必须用 `LLONG_MIN` / `LLONG_MAX` 或至少 `long long`**。如果用 `INT_MIN` / `INT_MAX` 而数组里真的含 `INT_MIN` / `INT_MAX`，比较会出错（`L1 > R2` 在两者都是 `INT_MAX` 时误判）。用 `long long` 从根本上避免。
- **`(maxLeft + minRight) / 2.0` 要注意溢出**：两个 `int` 相加可能超 `int` 范围，所以变量声明为 `long long`。写成 `(L1 + R1) / 2.0` 且都是 `int` 时是隐患。
- **`i` 的二分区间是闭区间 `[0, m]`**（可以取到 m），配 `while (l <= r)` 和 `r = i - 1` / `l = i + 1`。三者成套。
- **两个数组之一为空**要能正确处理：若 `nums1` 空（m=0），则 `i` 只能是 0，`j = half`，退化成在 `nums2` 里取中位数。哨兵机制天然处理。
- 返回值类型是 `double`，奇数情况也要 `(double)` 转换（否则整数除法）。偶数情况的 `/ 2.0` 里的 `.0` 不能少。
- **不要用「合并后取中间」通过测试就以为对了**——那是 O(m+n)，面试官问的就是能不能做到 O(log)。

**替代思路：递归求第 k 小（更容易记，稍慢）**

把问题一般化为「求两个有序数组合并后的第 k 小元素」，每次比较两个数组的第 `k/2` 个元素，**较小的那一侧的前 `k/2` 个元素必然都不是第 k 小**（因为它们前面至多有 `k/2 - 1 + k/2 - 1 < k - 1` 个元素），直接排除，`k` 减半。

```cpp
class Solution {
    // 求 a[ai..] 和 b[bi..] 合并后的第 k 小（k 从 1 开始）
    int kth(vector<int>& a, int ai, vector<int>& b, int bi, int k) {
        if (ai >= (int)a.size()) return b[bi + k - 1];        // a 用尽
        if (bi >= (int)b.size()) return a[ai + k - 1];        // b 用尽
        if (k == 1) return min(a[ai], b[bi]);
        int half = k / 2;
        // 各取第 half 个（不足则用 INT_MAX 表示"这边不够，别砍这边"）
        int va = (ai + half - 1 < (int)a.size()) ? a[ai + half - 1] : INT_MAX;
        int vb = (bi + half - 1 < (int)b.size()) ? b[bi + half - 1] : INT_MAX;
        if (va <= vb) return kth(a, ai + half, b, bi, k - half);   // 砍掉 a 的前 half 个
        else          return kth(a, ai, b, bi + half, k - half);
    }
public:
    double findMedianSortedArrays(vector<int>& nums1, vector<int>& nums2) {
        int total = nums1.size() + nums2.size();
        if (total % 2 == 1) return kth(nums1, 0, nums2, 0, total / 2 + 1);
        return (kth(nums1, 0, nums2, 0, total / 2)
              + kth(nums1, 0, nums2, 0, total / 2 + 1)) / 2.0;
    }
};
```

这个版本的复杂度是 O(log(m+n))，偶数时调用两次（可优化）。**优点是思路线性、容易在面试现场推出来；缺点是常数更大、边界（`INT_MAX` 占位）也不好想。** 两种都值得会，割点法用于展示最优解，第 k 小法用于讲清思路。

**追问 / 变体**
- **求第 k 小元素**：上面的 `kth` 函数就是，是更一般的问题。
- **k 个有序数组的中位数**：割点法难以推广（自由变量变成 k-1 个），改用「二分答案」——二分中位数的**值**，每次用 O(k log n) 统计有多少元素不超过它。
- **数据流的中位数**（295）：完全不同的题型，用**双堆**，见 [13-堆](13-堆.md)。
- **允许 O(m+n)**：双指针走到中点即可，代码短得多。**面试要先确认复杂度要求再选方案。**
- **数组很大且存在外存**：转化为「二分值域 + 统计计数」，只需顺序扫描，适合分布式。
- **为什么 O(log(min(m,n))) 优于要求**：因为二分的对象是较短数组的分割位置，而不是元素总数。这个细节值得主动说出来。
