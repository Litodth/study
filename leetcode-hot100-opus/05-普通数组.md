# 05 · 普通数组（5 题）

## 套路总纲

这五题没有统一的数据结构，共同点是**都需要一个"想到才会"的技巧**。它们代表五种独立的思维工具，值得逐个记住：

| 题 | 核心工具 | 一句话 |
|---|---|---|
| 53 最大子数组和 | **Kadane / DP** | 「前面的和为负就丢掉重开」 |
| 56 合并区间 | **排序 + 扫描** | 按左端点排序后，重叠必相邻 |
| 189 轮转数组 | **三次反转** | 整体反转再分段反转 |
| 238 除自身以外的乘积 | **前缀积 × 后缀积** | 不能用除法 → 拆成两个方向 |
| 41 缺失的第一个正数 | **原地哈希** | 答案必在 `[1, n+1]` → 用下标当哈希槽 |

**两条通用启发**：

1. **要求 O(1) 空间时，想「能不能把答案编码进原数组」**——原地哈希（41）、原地标记（[06-矩阵](06-矩阵.md) 的 73）都是这个思路。
2. **看到「不能用除法」「不能用额外数组」这类限制，它就是在指路**——限制往往正是提示。

### 53. 最大子数组和（中等）

**题意**  求具有最大和的**连续**子数组的和（子数组至少含一个元素）。

**暴力**  枚举左右端点 O(n²)（配前缀和），或三层循环 O(n³)。n ≤ 10⁵ 时 O(n²) = 10¹⁰，超时。

**关键洞察**

**Kadane 算法**。定义 `f[i]` = 「以 `i` 结尾的最大子数组和」。为什么要以 `i` 结尾？因为这样才能建立递推——任何子数组都必有一个结尾，枚举结尾就覆盖了所有子数组。

转移只有两个选择：

```
f[i] = max(f[i-1] + nums[i],   // 接在前面那段后面
           nums[i])            // 自己单开一段
```

化成一句人话：**如果前面累积的和是负数，它只会拖累我，那就丢掉从我重开**。所以等价写法是 `if (cur < 0) cur = 0;`。

`f` 只依赖 `f[i-1]`，滚动成一个变量即可，空间 O(1)。答案是 `max(f[0..n-1])`——**不是 `f[n-1]`**，因为最优子数组不一定在末尾结束。

**最优解（C++）**

```cpp
class Solution {
public:
    int maxSubArray(vector<int>& nums) {
        int cur = nums[0], best = nums[0];    // cur = 以当前位置结尾的最大和
        for (int i = 1; i < nums.size(); ++i) {
            cur = max(cur + nums[i], nums[i]);   // 要么接上，要么重开
            best = max(best, cur);               // 全局答案在过程中取 max
        }
        return best;
    }
};
```

**复杂度**  时间 O(n)，空间 O(1)。

**边界与坑**
- **全负数组**（如 `[-2,-1,-3]`）答案是 `-1`，不是 0。所以 `best` 必须初始化为 `nums[0]` 而不是 0，`cur` 也一样。用 0 初始化是本题最经典的错误。
- 子数组不能为空，所以不存在「返回 0」的情形。
- 别忘了 `best` 要在循环内每步更新，不能只在最后取 `cur`。
- 循环从 `i = 1` 开始（`i = 0` 已作为初值处理）。若从 0 开始，要把 `cur` 初始化为 0 并小心全负情形。

**追问 / 变体**
- **返回子数组的边界**：记录 `start`（在 `cur` 重开时更新为 `i`）和最优时的 `[start, i]`。
- **分治解法** O(n log n)：`[l, r]` 的答案 = max(左半、右半、跨中点)。跨中点部分从中间向两边扫。虽然更慢，但是**线段树维护区间最大子段和**的基础，面试追问「如果数组会被修改并多次查询」时就该给分治/线段树答案。
- **152 乘积最大子数组**：同一个 DP 骨架，但要**同时维护最大和最小**（负负得正），见 [15-动态规划](15-动态规划.md)。
- **918 环形子数组最大和**：分「不跨界」（本题）和「跨界」（总和 − 最小子数组和）两种情况。
- **子数组长度至少 k**：前缀和 + 单调队列。

### 56. 合并区间（中等）

**题意**  给定若干区间 `[start, end]`，合并所有重叠的区间，返回不重叠的区间列表。

**暴力**  反复两两比较、发现重叠就合并，直到无变化。O(n³) 量级且实现繁琐。

为什么不够：区间在输入里是乱序的，"谁和谁可能重叠"没有结构可循。

**关键洞察**

**排序创造结构**。按左端点升序排序后，得到一个关键性质：

> 若区间 `A` 和 `C` 重叠（`A` 在 `C` 之前），那么它们之间的所有区间也都与 `A` 重叠。

也就是说，**可合并的区间在排序后必然连续**。于是一次线性扫描就够：维护当前正在累积的区间 `cur`，

- `intervals[i].start <= cur.end` → 有重叠，把 `cur.end` 扩展为 `max(cur.end, intervals[i].end)`；
- 否则 → `cur` 已经封闭，推入答案，`cur` 换成新区间。

**为什么 `end` 要取 `max`**：可能出现完全包含的情形（`[1,10]` 后面跟 `[2,3]`），此时直接赋值 `cur.end = intervals[i].end` 会把区间**缩小**。这是本题最常见的 bug。

**最优解（C++）**

```cpp
class Solution {
public:
    vector<vector<int>> merge(vector<vector<int>>& intervals) {
        sort(intervals.begin(), intervals.end());     // 默认按 [0] 升序，[0] 相同再按 [1]
        vector<vector<int>> ans;
        for (auto& iv : intervals) {
            if (!ans.empty() && iv[0] <= ans.back()[1])
                ans.back()[1] = max(ans.back()[1], iv[1]);  // 重叠：扩展右端（必须 max）
            else
                ans.push_back(iv);                          // 不重叠：开一个新区间
        }
        return ans;
    }
};
```

**复杂度**  时间 O(n log n)（排序主导），空间 O(log n) 排序栈 + O(n) 输出。

**边界与坑**
- **`max` 不能省**，见上。用 `[[1,4],[2,3]]` 测一下就知道，错误答案会是 `[[1,3]]`。
- **相邻是否算重叠？** 本题 `[1,4]` 和 `[4,5]` 要合并成 `[1,5]`，所以判断用 `<=`。如果题目说端点不算重叠（区间是开的），则用 `<`。**读清题目**。
- `vector<vector<int>>` 的 `sort` 用字典序比较，正好满足「先按左端点」的需求，不必写 lambda。要写也可以：`[](auto&a, auto&b){ return a[0] < b[0]; }`。
- 直接在 `ans.back()` 上修改，比维护 `curStart/curEnd` 两个变量再收尾更短，也不会漏掉最后一个区间——**用变量版的话，循环结束后别忘了 push 最后一段**。
- 空输入返回空，代码天然处理。

**追问 / 变体**
- **57 插入区间**：已排序的区间列表插入一个新区间。可以 O(n) 线性扫（三段：完全在左、重叠、完全在右）。
- **252/253 会议室 I/II**：判断是否有重叠 / 求最多同时重叠数。253 用「差分 + 排序」或「最小堆存结束时间」。
- **435 无重叠区间**（删最少区间使无重叠）：改为**按右端点排序 + 贪心**——注意排序键变了，这是区间贪心的另一大类，见 [14-贪心算法](14-贪心算法.md) 的 763。
- **区间总覆盖长度**：合并后累加长度。

### 189. 轮转数组（中等）

**题意**  把数组元素向右轮转 `k` 个位置（`k` 可能大于 `n`）。要求原地、O(1) 额外空间。

**暴力**  轮转 1 位重复 k 次，O(n·k)，`k` 大时超时。或者用额外数组 `tmp[(i+k)%n] = nums[i]` 再拷回，O(n) 时间但 O(n) 空间——**面试先给这个**，它正确又好写，然后再攻 O(1) 空间。

**关键洞察**

先做一步必要的预处理：`k %= n`。轮转 `n` 次等于不变，所以只有 `k % n` 有效。

O(1) 空间的经典解法是**三次反转**：

```
原数组:        [1,2,3,4,5,6,7],  k = 3
① 整体反转:     [7,6,5,4,3,2,1]
② 反转前 k 个:   [5,6,7,|4,3,2,1]
③ 反转后 n-k 个: [5,6,7,|1,2,3,4]   ✓
```

**为什么成立**：轮转的效果是把数组切成 `A|B` 两段，变成 `B|A`。而 `reverse(A|B)` 得到 `reverse(B)|reverse(A)`；再分别把两段各自反转回来，就得到 `B|A`。用公式表达：`B A = reverse(reverse(A) reverse(B))`。

这个「三次反转实现循环移位」是**必背技巧**，字符串题里也常考。

**最优解（C++）**

```cpp
class Solution {
public:
    void rotate(vector<int>& nums, int k) {
        int n = nums.size();
        k %= n;                                        // k 可能远大于 n
        if (k == 0) return;
        reverse(nums.begin(), nums.end());             // ① 整体反转
        reverse(nums.begin(), nums.begin() + k);       // ② 前 k 个
        reverse(nums.begin() + k, nums.end());         // ③ 后 n-k 个
    }
};
```

**对照解法（环状替换 / 循环轮换，O(1) 空间的另一种）**

```cpp
class Solution {
public:
    void rotate(vector<int>& nums, int k) {
        int n = nums.size();
        k %= n;
        int count = 0;                       // 已归位的元素数
        for (int start = 0; count < n; ++start) {
            int cur = start, val = nums[start];
            do {
                int next = (cur + k) % n;
                swap(nums[next], val);       // 把 val 放到 next，同时取出原来的值
                cur = next;
                ++count;
            } while (cur != start);          // 回到起点则本环结束
        }
    }
};
```

环的个数是 `gcd(n, k)`，所以外层要换起点。这个解法巧妙但易错，**面试给三次反转就够**。

**复杂度**  时间 O(n)，空间 O(1)。三次反转共移动约 2n 次元素。

**边界与坑**
- **`k %= n` 必须做**。`k = 10^5`、`n = 3` 时不取模会越界（`nums.begin() + k` 直接跑飞）。
- `k == 0` 时三次 `reverse` 也无害（第二次反转空区间），但显式 return 更清晰。
- `reverse` 的第二个参数是**尾后迭代器**：`nums.begin() + k` 表示反转 `[0, k)` 共 `k` 个元素，不是 `k+1` 个。
- **向左轮转 k 位** = 向右轮转 `n - k` 位，别搞反方向。
- 题目要求「原地修改」，返回 `void`——别不小心返回新数组。

**追问 / 变体**
- **向左轮转**：`k = n - k % n` 后套同样代码。
- **字符串轮转**（剑指 Offer 58）：同样三次反转；「翻转单词顺序」也是先整体反转再逐词反转。
- **要求最少交换次数**：环状替换版恰好每个元素只移动一次（n 次赋值），比三次反转的 2n 次更少。
- **396 旋转函数**：轮转 + 数学优化，是另一类题。

### 238. 除自身以外数组的乘积（中等）

**题意**  返回 `answer`，其中 `answer[i]` 等于 `nums` 中除 `nums[i]` 之外所有元素的乘积。**不能用除法**，要求 O(n)，且进阶要求 O(1) 额外空间（输出数组不计）。

**暴力**  对每个 `i` 乘一遍其他元素，O(n²)。n ≤ 10⁵ 时超时。

**为什么不能用除法**（题目的核心限制）：`总积 / nums[i]` 一行搞定，但有两个致命问题——① 数组含 **0** 时除零；② 即使处理 0，浮点/整数除法在有多个 0 时逻辑变复杂。题目禁用除法正是为了逼出下面的思路。

**关键洞察**

「除自身以外的乘积」= **左边所有数的积 × 右边所有数的积**。

```
answer[i] = (nums[0] * ... * nums[i-1]) * (nums[i+1] * ... * nums[n-1])
              \______ 前缀积 ______/       \______ 后缀积 ______/
```

于是两次扫描：从左到右算前缀积，从右到左算后缀积，相乘。这需要两个辅助数组，O(n) 空间。

**优化到 O(1) 空间**：把前缀积直接写在输出数组 `ans` 里；然后第二遍从右往左扫时，用**一个变量** `suffix` 滚动维护后缀积，边走边乘进 `ans[i]`。因为 `ans[i]` 只需要一次「前缀 × 后缀」，而后缀是从右往左递推的，正好能就地完成。

**最优解（C++）**

```cpp
class Solution {
public:
    vector<int> productExceptSelf(vector<int>& nums) {
        int n = nums.size();
        vector<int> ans(n);

        ans[0] = 1;                                   // 下标 0 左边没有元素，前缀积为 1
        for (int i = 1; i < n; ++i)
            ans[i] = ans[i - 1] * nums[i - 1];        // ans[i] = 左边所有数的积

        int suffix = 1;                               // 滚动的后缀积
        for (int i = n - 1; i >= 0; --i) {
            ans[i] *= suffix;                         // 左积 × 右积
            suffix *= nums[i];                        // 再把自己并入后缀
        }
        return ans;
    }
};
```

**复杂度**  时间 O(n)，空间 O(1) 额外（输出数组不计）。

**边界与坑**
- **`ans[i] = ans[i-1] * nums[i-1]`——注意是 `nums[i-1]` 不是 `nums[i]`**。前缀积不含自己，差一错误在这里高发。
- 同理第二遍循环中，**先 `ans[i] *= suffix` 再更新 `suffix`**。顺序反了就把自己乘进去了。
- **含 0 的情形自动正确**：只有一个 0 时，其他位置的答案是 0（乘到了那个 0），0 那个位置得到其余数之积；有两个及以上 0 时全为 0。不需要特判——这是本解法比除法优雅的地方。
- 题目保证结果在 `int` 范围内，所以不必用 `long long`（中间的前缀积也被保证在范围内）。别人写的题解如果用 `long long` 是保险，不是必需。
- `n == 1` 时输入不合法（题目保证 `n >= 2`），但代码也会返回 `[1]`。

**追问 / 变体**
- **允许除法怎么写**：`total / nums[i]`，但要统计 0 的个数：0 的个数 ≥ 2 → 全 0；恰好 1 个 → 只有那一位是非零积，其余 0；无 0 → 直接除。面试常让你对比两种写法。
- **除自身以外的和**：`total - nums[i]`，平凡。
- **前缀积/前缀和 + 后缀** 这个双向扫描套路很通用：42 接雨水的前缀数组解法、[06-矩阵](06-矩阵.md) 的部分题、以及「左右两侧最值」类问题都在用它。
- **二维版**（除自身所在行列外的积）：行积 × 列积，同一思路。

### 41. 缺失的第一个正数（困难）

**题意**  找出未排序数组中**没有出现的最小正整数**。要求时间 O(n)、空间 O(1)。

**暴力**  排序后扫描，O(n log n)；或用 `unordered_set` 装下所有数再从 1 试到 n+1，O(n) 时间但 O(n) 空间。**两个都违反约束**，但都该作为铺垫说出来。

**关键洞察**

两步，第二步是本题的精华。

**第一步：答案的范围是有限的。**
数组长度为 `n`，最多容纳 `n` 个不同的正整数。所以答案一定在 `[1, n+1]` 之间——最好的情况是数组恰好装着 `1..n`，那答案是 `n+1`；否则 `1..n` 中必有缺失。**范围外的数（≤ 0 或 > n）完全无关**，可以无视。

**第二步：既然只关心 `1..n`，就用数组下标当哈希槽——原地哈希。**
目标状态：让 `nums[i] == i + 1`（即数值 `v` 待在下标 `v-1` 处）。达成后再扫一遍，第一个不满足的下标 `i` 就给出答案 `i+1`。

怎么达成？遍历每个位置，只要当前值 `v` 在 `[1,n]` 内且没在正确位置上，就把它 `swap` 到它该去的地方 `v-1`。换过来的新值继续检查（所以用 `while` 不是 `if`）。

**为什么总步数是 O(n)**：每次成功的 `swap` 都让**至少一个数字归位**，而归位后不会再被移动。总归位次数 ≤ n，所以 `while` 的总执行次数 ≤ n，均摊 O(1)。这个论证和 [01-哈希](01-哈希.md) 的 128 题同源。

**最优解（C++，原地交换）**

```cpp
class Solution {
public:
    int firstMissingPositive(vector<int>& nums) {
        int n = nums.size();
        for (int i = 0; i < n; ++i) {
            // 把 nums[i] 换到它该在的位置 nums[i]-1，直到当前位置的值无处可去
            while (nums[i] > 0 && nums[i] <= n && nums[nums[i] - 1] != nums[i])
                swap(nums[i], nums[nums[i] - 1]);
        }
        for (int i = 0; i < n; ++i)
            if (nums[i] != i + 1) return i + 1;    // 第一个"空槽"
        return n + 1;                              // 1..n 全在，答案是 n+1
    }
};
```

**复杂度**  时间 O(n) 均摊，空间 O(1)。

**边界与坑**
- **循环条件必须写 `nums[nums[i]-1] != nums[i]`，不能写 `nums[i] != i+1`**。后者在遇到重复值时会死循环：`[1,1]` 中 `i=1`，`nums[1]=1` 想去下标 0，但那里已经是 1，交换后数组不变 → 无限循环。用「目标位置上的值是否已经正确」作为终止条件，重复值自然被跳过。**这是本题唯一的致命坑**。
- `swap(nums[i], nums[nums[i]-1])` 里 `nums[i]` 在交换过程中会被修改——C++ 的 `std::swap` 接收引用，两个引用在调用前就绑定好了，所以**这样写是安全的**。但如果手写三行交换 `int t = nums[i]; nums[i] = nums[nums[i]-1]; ...` 就会因为 `nums[i]` 已变而出错。建议直接用 `std::swap`，或先把 `nums[i]` 存进局部变量。
- 负数和 0 会留在原地不动，最后一遍扫描时它们所在的下标就是缺失位置，正确。
- 数组可能含 `INT_MIN`/`INT_MAX`，但因为只对 `[1,n]` 内的值做 `nums[v-1]` 索引，不会越界。

**追问 / 变体**
- **标记法（另一种 O(1) 空间解法）**：先把所有非正数改成 `n+1`，然后对每个 `v ∈ [1,n]` 把 `nums[v-1]` 标成负数表示"出现过"，最后找第一个正数的位置。不用交换，逻辑更线性，但需要三遍扫描。这两种解法都值得会。
- **448 找到所有数组中消失的数字** / **442 数组中重复的数据** / **287 寻找重复数**：都是「值域是 `[1,n]`」→ 原地哈希家族。287 因为不能修改数组，改用**快慢指针找环**，见 [17-技巧](17-技巧.md)。
- **允许 O(n) 空间**：`vector<bool> seen(n+2)` 一遍标记，五行搞定。面试可以先给这个再优化。
- **求缺失的第一个正数，但数组已排序**：二分查找 `nums[i] != i+1` 的第一个位置，O(log n)。
