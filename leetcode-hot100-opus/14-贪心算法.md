# 14 · 贪心算法（4 题）

## 套路总纲

贪心 = **每一步都选当前看起来最好的，且不回头**。它比 DP 快（通常 O(n) 且 O(1) 空间），但**正确性需要证明**——这是贪心最难也最关键的地方。

**贪心 vs DP 的判别**

| | 贪心 | DP |
|---|---|---|
| 决策 | 局部最优 → 直接定下，不回头 | 枚举所有可能，靠状态记录 |
| 前提 | 有**贪心选择性质**（局部最优能导出全局最优） | 只需最优子结构 |
| 复杂度 | 通常 O(n) / O(n log n) | 通常 O(n²) 或更高 |
| 风险 | **可能是错的**，必须证明 | 只要状态定义对就一定对 |

**判断能否贪心的两个实用办法**：

1. **尝试构造反例**。想不出反例，再尝试证明。
2. **交换论证（exchange argument）**：假设有一个最优解和贪心解不同，证明可以把最优解中的某个选择**换成**贪心的选择而不变差 → 贪心解也是最优的。这是证明贪心的标准套路，面试被追问"为什么贪心是对的"时就用这个。

**本专题的四道题各自的贪心内核**

| 题 | 贪心内核 | 一句话 |
|---|---|---|
| 121 买卖股票 | 维护历史最低价 | 卖出日固定时，买入日当然选之前最便宜的那天 |
| 55 跳跃游戏 | 维护**能到达的最远边界** | 只关心"够不够得到"，不关心怎么跳 |
| 45 跳跃游戏 II | **区间分层 BFS** | 当前这一步能覆盖的范围内，选下一步能跳最远的 |
| 763 划分字母区间 | 维护**当前段必须延伸到的终点** | 段内所有字母的最后出现位置的最大值 |

**共同模式：一次遍历 + 维护一个"边界/极值"变量。** 四道题都是 O(n) 时间 O(1) 空间，代码都在十行以内。**贪心题的代码短，难的是想清为什么对。**

**一个高频陷阱**：贪心不等于"排序后从大到小拿"。很多题需要**先按某个规则排序**才能贪心（如 [56 合并区间](05-普通数组.md) 按左端点排序，435 无重叠区间按**右**端点排序）。**排序的键选错，贪心就错。**

**难度递进**：121 是最直白的"维护最小值" → 55 是"维护可达边界"的思维跳跃 → 45 在 55 基础上加计步 → 763 需要预处理 + 区间合并思维。

### 121. 买卖股票的最佳时机（简单）

**题意**  `prices[i]` 是第 `i` 天的股价。**只能买卖一次**（先买后卖），求最大利润；无法获利返回 0。

**暴力**  双层循环枚举所有 `(买入日 i, 卖出日 j)` 且 `i < j`，取 `max(prices[j] - prices[i])`。O(n²)，n = 10⁵ 时超时。

浪费在哪：对每个卖出日 `j`，内层循环都在**重新扫描**它之前的所有价格找最小值——而这个最小值完全可以边走边维护。

**关键洞察**

**关键转换：固定卖出日，问"买入日该选哪天"。**

如果第 `j` 天卖出，那么买入日显然应该选 `[0, j-1]` 中**股价最低**的那一天——这是显然的，不需要证明（同样的卖价，买得越便宜利润越高）。

于是「历史最低价」这个量可以**一边遍历一边维护**：

```
minPrice = min(minPrice, prices[i])      // 到今天为止的最低价
best     = max(best, prices[i] - minPrice)  // 今天卖出能获得的最大利润
```

**一趟遍历，两个变量，O(1) 空间。**

**顺序很重要**：更严格地说，应当**先用旧的 `minPrice` 算利润，再更新 `minPrice`**——因为不能同一天买入又卖出。但实际上**两种顺序结果相同**：如果 `prices[i]` 就是新的最低价，那么用它算出的利润是 0，不会影响 `max`（因为 `best` 初值是 0）。**知道这一点能避免纠结，但面试时按"先算后更新"写更能体现严谨。**

**另一个视角：这题等价于「最大子数组和」**。把每日涨跌 `diff[i] = prices[i] - prices[i-1]` 算出来，答案就是 `diff` 的最大子数组和（[53 题](05-普通数组.md)）——因为连续持有若干天的总收益就是这段涨跌之和。**这个联系很漂亮，面试提出来是加分项。**

**最优解（C++）**

```cpp
class Solution {
public:
    int maxProfit(vector<int>& prices) {
        int minPrice = INT_MAX, best = 0;
        for (int p : prices) {
            best = max(best, p - minPrice);      // 今天卖出的最大利润（用之前的最低价）
            minPrice = min(minPrice, p);         // 更新历史最低价
        }
        return best;
    }
};
```

**DP 视角（为后续的股票系列铺路）**

```cpp
int maxProfit(vector<int>& prices) {
    int hold = INT_MIN, sold = 0;        // hold: 持股状态的最大收益；sold: 不持股
    for (int p : prices) {
        hold = max(hold, -p);            // 保持持股 或 今天买入（只能买一次，所以是 -p 不是 sold-p）
        sold = max(sold, hold + p);      // 保持空仓 或 今天卖出
    }
    return sold;
}
```

**这个状态机写法是股票系列（121/122/123/188/309/714）的统一框架**，值得一起掌握——121 的特殊之处是「只能买一次」，所以买入时是 `-p` 而不是 `sold - p`。

**复杂度**  时间 O(n)，空间 O(1)。

**边界与坑**
- **`best` 初值必须是 0**，不是 `INT_MIN`。价格单调递减时（如 `[7,6,4,3,1]`）无法获利，答案是 0 而不是负数。**这是本题最常见的错误。**
- **`minPrice` 初值用 `INT_MAX`**。用 `prices[0]` 也对（然后从 `i=1` 开始遍历），但要先判空数组。
- **`p - minPrice` 不会溢出**：本题价格范围 `[0, 10^4]`，安全。若价格可为负或范围很大，`INT_MAX - (负数)` 会溢出——用 `long long` 或先判 `minPrice != INT_MAX`。
- **必须先买后卖**（`i < j`）。上面的写法天然满足：算利润时 `minPrice` 只包含**今天及之前**的价格。
- 空数组或单元素返回 0。
- **不要排序**！排序破坏了时间顺序，`[3,1]` 排序后变成 `[1,3]` 会错答 2（实际无法获利）。**这是"贪心不等于排序"的好例子。**

**追问 / 变体**
- **122 买卖股票 II**（可以买卖**多次**）：贪心变得更简单——**只要今天比昨天贵就"赚这一段"**，`ans += max(0, prices[i] - prices[i-1])`。因为多次交易可以把任意上升段拆成逐日累加。
- **123 买卖股票 III**（最多 2 次）/ **188 最多 k 次**：贪心失效，必须用状态机 DP（`dp[i][k][持股?]`）。**"交易次数受限就得 DP"是这个系列的分水岭。**
- **309 含冷冻期 / 714 含手续费**：状态机 DP 加一个状态或在转移里减去手续费。
- **53 最大子数组和**：见上文的等价转换，[05-普通数组](05-普通数组.md)。
- **返回买卖的具体日期**：额外记录 `minPrice` 对应的下标，以及更新 `best` 时的下标。
- **只能在指定日期之后卖**：加约束后仍可一次遍历，改一下 `minPrice` 的更新起点。

### 55. 跳跃游戏（中等）

**题意**  `nums[i]` 表示在下标 `i` 处**最多**能向前跳的步数（可以跳更少）。判断能否从下标 0 到达最后一个下标。

**暴力**  从 0 开始 DFS/BFS 枚举所有跳法，最坏 O(2ⁿ)。或者 DP：`reach[i]` 表示 `i` 是否可达，`reach[j] |= reach[i] && (j <= i + nums[i])`，O(n²)。n = 10⁴ 时 O(n²) 勉强能过，但有 O(n) 解。

**关键洞察**

**关键转换：不要想"怎么跳"，只想"最远能到哪"。**

这是本题的思维跳跃。跳跃的**具体路径**完全不重要——如果下标 `i` 可达，那么 `[i, i + nums[i]]` 范围内的**所有**下标都可达（因为可以跳更少的步数）。所以只需维护一个变量：

> **`maxReach` = 目前为止能到达的最远下标。**

遍历过程：

- 走到 `i` 时，**先检查 `i > maxReach`**——如果成立说明 `i` 根本到不了，后面的更到不了，**直接返回 false**。
- 否则 `i` 可达，用它更新边界：`maxReach = max(maxReach, i + nums[i])`。
- 一旦 `maxReach >= n - 1`，就可以提前返回 true。

**为什么"可达的下标构成一个连续前缀"**：因为在 `i` 处可以跳 1 到 `nums[i]` 中的任意步数，所以从可达的 `i` 能到达 `i+1, i+2, ..., i+nums[i]` 全部。**这个"连续性"是能用单个变量表示可达集合的根本原因**，也是本题贪心成立的证明。

**最优解（C++）**

```cpp
class Solution {
public:
    bool canJump(vector<int>& nums) {
        int n = nums.size(), maxReach = 0;
        for (int i = 0; i < n; ++i) {
            if (i > maxReach) return false;              // i 不可达 → 卡住了
            maxReach = max(maxReach, i + nums[i]);       // 用可达的 i 扩展边界
            if (maxReach >= n - 1) return true;          // 提前成功
        }
        return true;
    }
};
```

**从后往前的贪心（另一个视角）**

```cpp
bool canJump(vector<int>& nums) {
    int need = nums.size() - 1;             // 当前需要到达的目标下标
    for (int i = nums.size() - 2; i >= 0; --i)
        if (i + nums[i] >= need) need = i;  // i 能跳到目标 → 目标前移到 i
    return need == 0;
}
```

思路：**倒推「要到终点，必须先到哪」**。如果 `i` 能跳到当前目标，那么问题缩小为"能否到达 `i`"。最后看目标是否缩到了 0。**这个"倒推目标"的思路在 45 题里也有用。**

**复杂度**  时间 O(n)，空间 O(1)。

**边界与坑**
- **`if (i > maxReach) return false` 必须在更新之前**。顺序反了会用不可达的 `i` 去扩展边界，把答案错判成 true。**这是本题头号 bug**，测试用例 `[3,2,1,0,4]` 专卡这个：走到 `i=4` 时 `maxReach` 只有 3，必须判 false。
- **`i > maxReach` 用严格大于**。`i == maxReach` 表示恰好能到达 `i`，是合法的。写成 `>=` 会在第一步（`i=0, maxReach=0`）就返回 false。
- **`maxReach >= n - 1` 用 `n - 1`**（最后一个**下标**），不是 `n`。写成 `n` 会漏掉刚好到终点的情况。
- **`i + nums[i]` 理论上可能溢出**：本题 `nums[i] <= 10^5`、`n <= 10^4`，安全。
- **`nums[i]` 可以是 0**，表示在这一格无法移动。`[0]`（单元素）应返回 **true**（起点就是终点，不需要跳）——本代码在 `i=0` 时 `maxReach = 0 >= n-1 = 0` 立即返回 true，正确。
- **不要试图"每次跳最远"**！`[2,3,1,1,4]`：从 0 跳最远到 2（`nums[2]=1`），再到 3，再到 4 —— 恰好能到。但把数据改成 `[2,3,0,1,4]`，跳最远到下标 2（值 0）就卡死了，而跳到下标 1 却能成功。**"每步跳最远"是错的贪心，正确的贪心是"维护可达边界"。这个区别是本题最深刻的一课。**
- 遍历完整个数组还没返回 false，说明全程可达，返回 true。

**追问 / 变体**
- **45 跳跃游戏 II**（求最少跳跃次数）：见下题。
- **1306 跳跃游戏 III**（可左右跳，判可达）：贪心失效（可达集合不再连续），改用 **BFS/DFS**。**这个对比很重要：只能向前时可达集合连续 → 贪心；能双向时不连续 → 搜索。**
- **1696 跳跃游戏 VI**（每步最多跳 k，求路径最大得分）：需要 **DP + 单调队列**优化。
- **返回一条具体路径**：记录每次更新 `maxReach` 时的来源下标。
- **步数必须恰好等于 `nums[i]`**（不能跳更少）：可达集合不再连续，贪心失效，必须 DP/BFS。**这说明"可以跳更少"这个条件是贪心成立的关键前提。**
- **概率/代价版本**：每格有过路费，求最小花费 → DP。

### 45. 跳跃游戏 II（中等）

**题意**  同 55 的规则，但**保证一定能到达**最后一个下标，求**最少跳跃次数**。

**暴力**  DP：`dp[i]` = 到达 `i` 的最少步数，`dp[j] = min(dp[j], dp[i] + 1)` 对所有 `j <= i + nums[i]`。O(n²)，n = 10⁴ 能过但有 O(n) 解。

**关键洞察**

在 55 的「可达边界」基础上加一层：**把下标按"最少需要跳几次才能到达"分层**。

- **第 0 层**：只有下标 0（跳 0 次）
- **第 1 层**：从下标 0 一步能到的范围，即 `[1, nums[0]]`
- **第 2 层**：从第 1 层任意位置再跳一步能覆盖的最远范围
- ……

**这本质上是 BFS 分层！** 层数就是跳跃次数。而由于可达范围是**连续区间**（见 55 的分析），每一层可以用一个区间 `[curStart, curEnd]` 表示，不需要真的用队列。

于是算法变成：

```
遍历 i，同时维护：
  curEnd  = 当前层能覆盖的最远下标（这一步的边界）
  farthest = 从当前层任意位置出发能到的最远下标（下一层的边界）

当 i == curEnd 时（走完了当前层）：
  ++jumps            // 必须再跳一次
  curEnd = farthest  // 进入下一层
```

**关键点：只在 `i == curEnd`（到达当前层的边界）时才计一次跳跃。** 这保证了每一层只计一次，跳跃次数最少。

**为什么这个贪心是对的**：第 `k` 层覆盖的区间是「跳 k 次能到达的所有下标」的**完整**集合（由连续性保证）。所以终点第一次落入哪一层，那个层号就是最少跳跃次数——**这就是 BFS 求最短路的正确性**。

**循环到 `n - 1` 而不是 `n`**：走到最后一个下标时不需要再跳了。**写成 `i < n` 会多算一次**（在 `i == n-1 == curEnd` 时又 `++jumps`），这是本题头号 bug。

**最优解（C++）**

```cpp
class Solution {
public:
    int jump(vector<int>& nums) {
        int n = nums.size();
        int jumps = 0, curEnd = 0, farthest = 0;
        for (int i = 0; i < n - 1; ++i) {                 // 注意：到 n-2 为止
            farthest = max(farthest, i + nums[i]);        // 下一层能到的最远处
            if (i == curEnd) {                            // 走到当前层边界，必须跳一次
                ++jumps;
                curEnd = farthest;                        // 进入下一层
            }
        }
        return jumps;
    }
};
```

只有六行，但每一行都需要理解才能写对。

**显式 BFS 分层版（更能看出"层"的结构）**

```cpp
int jump(vector<int>& nums) {
    int n = nums.size();
    if (n <= 1) return 0;
    int jumps = 0, l = 0, r = 0;                  // 当前层区间 [l, r]
    while (r < n - 1) {
        int next = 0;
        for (int i = l; i <= r; ++i)              // 扫当前层，求下一层边界
            next = max(next, i + nums[i]);
        l = r + 1;                                // 下一层从 r+1 开始
        r = next;
        ++jumps;
    }
    return jumps;
}
```

这个版本的**分层结构一目了然**，虽然是双层循环但每个下标只被扫一次，仍是 O(n)。**面试建议先讲这个版本（好理解），再优化成单循环版。**

**复杂度**  时间 O(n)，空间 O(1)。

**边界与坑**
- **循环上界是 `n - 1`（即 `i` 到 `n - 2`）**。写成 `i < n` 时，若 `curEnd` 恰好等于 `n - 1`，会在终点又 `++jumps`，答案多 1。**这是本题最经典的错误。**
- **`++jumps` 只在 `i == curEnd` 时执行**，不是每步都加。
- **`farthest` 的更新在 `if` 之前**。反了会用还没更新的值设置 `curEnd`。
- **`curEnd` 和 `farthest` 是两个不同的量**，别用一个变量。`curEnd` 是"当前层边界"，`farthest` 是"下一层边界"，**混用会让层次错乱**。
- 单元素数组 `[0]` 返回 0（循环不执行）。这是 `i < n - 1` 的又一个好处：天然处理了 n=1。
- **题目保证一定能到达**，所以不需要判 false。若不保证，要加 `if (i > curEnd) return -1;`（同 55）。
- **不要用"每次跳最远"的朴素贪心**：`[2,3,1,1,4]` 从 0 跳到下标 2（跳最远）需要 3 步，而跳到下标 1 只需 2 步。**正确的贪心是"在当前层的覆盖范围内选下一层边界最远的"，而不是"每步跳最远"。** 这个区别和 55 的坑是同一个道理。
- BFS 版的 `if (n <= 1) return 0` 不能漏（否则 `r < n-1` 在 n=1 时是 `0 < 0` 为假，恰好也返回 0——但显式写出更清楚）。

**追问 / 变体**
- **55 跳跃游戏**（只判可达）：见上题，去掉计数即可。
- **1306 跳跃游戏 III**：能左右跳，用 BFS。
- **返回具体的跳跃路径**：记录每层选择的那个"跳最远的下标"。
- **每次跳跃有不同代价**：贪心失效，改 DP + 单调队列/堆。
- **1024 视频拼接 / 1326 灌溉花园的最少水龙头**：**同构题**！都是"用最少的区间覆盖 `[0, n]`"，把每个位置的覆盖范围算出来后用完全一样的分层贪心。**认出这三题是同一个模型，是本题最大的收获。**
- **为什么这是 BFS 而不是 DP**：因为边权全为 1（每次跳跃代价相同），BFS 的分层天然给出最短路。若代价不同就要 Dijkstra 或 DP。**这个判断和 [994 腐烂的橘子](09-图论.md) 是同一条原则。**

### 763. 划分字母区间（中等）

**题意**  把字符串划分成尽可能多的片段，要求**同一个字母只能出现在一个片段中**。返回各片段的长度列表。

**暴力**  枚举所有分割方案检查合法性，指数级。或者：对每个可能的分割点，检查左右两侧是否有共同字母，O(n² · 26)。

**关键洞察**

**核心认识：如果字母 `c` 出现在当前片段里，那么这个片段必须一直延伸到 `c` 的最后一次出现位置。**

因为 `c` 不能出现在两个片段中——一旦切在 `c` 的最后出现位置之前，后面还会再出现 `c`，就违规了。

所以贪心策略是：

1. **预处理**：先扫一遍字符串，记录每个字母**最后出现的下标** `last[c]`。
2. **遍历时维护 `end`** = 当前片段必须延伸到的最远位置 = 「片段内所有已出现字母的 `last` 的最大值」。
3. **当 `i == end` 时**，说明片段内所有字母都已完整包含，**可以且应该在此切断**（贪心：尽早切断才能得到最多片段）。

**为什么"尽早切断"是最优的（贪心的正确性）**：走到 `i == end` 时，`[start, i]` 内所有字母的最后出现位置都 ≤ `i`，所以切在这里**合法**。而如果不切、继续延伸，只会让片段更少。用交换论证：任何合法方案的第一个切点都不可能早于我们的 `end`（否则违规），所以我们的切点是**最早可能的合法切点** → 后续能切出的片段数最多。**这是标准的"最早截止时间优先"贪心。**

**这题也可以看成区间合并**：把每个字母看成区间 `[first[c], last[c]]`，答案就是**合并所有重叠区间**后的结果（[56 合并区间](05-普通数组.md)）。**两种视角都对，"维护 end"的写法更短。**

**最优解（C++）**

```cpp
class Solution {
public:
    vector<int> partitionLabels(string s) {
        int last[26] = {0};
        for (int i = 0; i < (int)s.size(); ++i)
            last[s[i] - 'a'] = i;                    // 记录每个字母最后出现的下标

        vector<int> ans;
        int start = 0, end = 0;
        for (int i = 0; i < (int)s.size(); ++i) {
            end = max(end, last[s[i] - 'a']);        // 片段必须延伸到这里
            if (i == end) {                          // 所有字母都已完整包含 → 切断
                ans.push_back(i - start + 1);
                start = i + 1;
            }
        }
        return ans;
    }
};
```

**只用一个变量的写法（不记 start，用差值）**

```cpp
vector<int> partitionLabels(string s) {
    int last[26] = {0};
    for (int i = 0; i < (int)s.size(); ++i) last[s[i] - 'a'] = i;
    vector<int> ans;
    int end = 0, prevEnd = -1;
    for (int i = 0; i < (int)s.size(); ++i) {
        end = max(end, last[s[i] - 'a']);
        if (i == end) { ans.push_back(end - prevEnd); prevEnd = end; }
    }
    return ans;
}
```

**复杂度**  时间 O(n)（两趟遍历），空间 O(1)（`last` 是固定 26 个元素，与 n 无关）。

**边界与坑**
- **`last[c]` 要记录最后一次出现，所以直接覆盖赋值即可**（`last[s[i]-'a'] = i`，不需要 `max`）——因为 `i` 递增，后写入的必然更大。写成 `if (!last[...]) last[...] = i` 会记成**第一次**出现，答案全错。
- **片段长度是 `i - start + 1`**，不是 `i - start`。**这个 +1 是最常见的错误**（同 [84 的宽度计算](12-栈.md) 一样容易错）。
- **切断后 `start = i + 1`**，不是 `start = i`。
- **必须先完整预处理 `last` 再开始划分**。边走边记录是不行的——你无法知道后面还会不会出现这个字母。**"需要未来的信息 → 先预处理一遍"是很常用的手法。**
- **`end` 不能在切断时重置为 0**。虽然 `max(0, last[...])` 恰好也对（因为下一个字母的 `last` 一定 ≥ 当前 `i`），但语义上 `end` 应该自然地被下一个字母的 `last` 更新，不重置更清晰、更不易错。
- `last[26] = {0}` 的初始化：`= {0}` 不能省。未出现的字母 `last` 是 0，但它们永远不会被访问到（只查询出现过的字母），所以无害。
- 单字符串 `"a"` 返回 `[1]`。
- **题目保证只含小写字母**。含大小写或 Unicode 时把 `last` 换成 `unordered_map<char,int>`。

**追问 / 变体**
- **56 合并区间**：本题的等价形式（见上文"区间合并"视角），见 [05-普通数组](05-普通数组.md)。
- **返回各片段的内容而非长度**：`s.substr(start, i - start + 1)`。
- **435 无重叠区间 / 452 用最少箭引爆气球**：经典的「**按右端点排序**后贪心」题。**注意：这类"选最多不重叠区间"的题必须按右端点排序，按左端点排序是错的**——这是区间贪心最重要的一条规则，值得和本题一起记。
- **允许某些字母跨片段**：约束放松后变成一般的区间覆盖问题，可能需要 DP。
- **求划分成恰好 k 段的方案**：贪心失效（贪心给出的是最多段数），需要 DP。**"求最多/最少段数用贪心，求恰好 k 段用 DP"是很好的判别经验。**
- **字符集很大（如百万种字符）**：`last` 用哈希表，空间变 O(字符种类数)，时间仍 O(n)。
